모든 능력을 '도구'로 통일

한 줄 요약

에이전트의 강력함은 "모든 능력을 같은 도구 형태로 통일" 하는 데서 옵니다. 문서 검색(RAG), DB 조회, 재고 확인, 웹 검색, 코드 실행 — 전부 "호출하면 결과를 주는 도구"로 만들면, 에이전트가 자유롭게 조합해 씁니다.

1. 통일된 인터페이스

지금까지 배운 능력들을 떠올려 봅시다.

5강: 함수 도구 (재고 조회)
9강: 웹 검색 도구
10강: 코드 실행 도구
16~17강: RAG 검색 도구

겉보기엔 다 다른 일입니다. 하지만 에이전트에게는 모두 같은 형태입니다.

모든 도구 = 입력을 주면 → 결과(문자열)를 돌려주는 함수

이 "통일된 형태(인터페이스)"가 핵심입니다. 도구가 무슨 일을 하든, 에이전트는 "호출하고 결과를 받는다"는 동일한 방식으로 다룹니다.

비유: 만능 공구함과 같습니다. 망치·드라이버·렌치는 하는 일이 다르지만, 모두 "손잡이를 잡고 쓰는 도구"라는 공통 형태죠. 에이전트는 그 손잡이(도구 인터페이스)만 알면 됩니다.

2. 통일의 그림

질문 이 AGENT(ReAct) 로 들어오면, 질문을 분해해 필요한 도구를 호출합니다. 에이전트가 다루는 도구는 모두 같은 형태입니다.

도구 출처
policy_search RAG / 문서
get_order_status DB / orders
get_stock 재고

세 도구가 "출처"는 다르지만(문서/DB/재고), 에이전트에겐 똑같은 도구 3개입니다. 에이전트는 질문에 맞는 걸 골라 쓰죠.

3. 통일이 주는 자유

모든 능력을 도구로 통일하면, 자유로운 조합이 가능해집니다.

# 도구를 자유롭게 조합
tools = [policy_search, get_order_status, get_stock]          # CS 에이전트
tools = [policy_search, run_pandas, web_search]               # 분석 에이전트
tools = [get_order_status, cancel_order, refund]             # 처리 에이전트

도구를 리스트에 넣고 빼는 것만으로 에이전트의 능력을 바꿀 수 있죠. 새 능력이 필요하면 도구를 추가하고, 필요 없으면 빼면 됩니다. 레고 블록처럼 조립하는 거죠.

이 "도구를 조합해 에이전트를 만든다"는 발상이 에이전트 설계의 핵심입니다(28강 설계에서 다룸).

4. RAG를 도구로 보는 관점 전환

13~16강에서 RAG는 "특별한 파이프라인"처럼 보였습니다. 로드→청킹→임베딩→검색→생성, 복잡했죠. 하지만 17강에서 관점이 바뀌었습니다.

13~16강 관점: RAG = 복잡한 검색·생성 파이프라인 (특별함)
17~18강 관점: RAG = 도구의 하나 (평범함)

create_retriever_tool로 RAG를 도구로 포장하니, 다른 도구와 똑같이 다룰 수 있게 됐습니다. 이 "복잡한 걸 단순한 도구로 추상화"하는 게 중요합니다. 내부는 복잡해도(검색·생성), 밖에서 보면 그냥 "호출하면 답 주는 함수"니까요.

5. 통일의 힘 — 확장성

"모든 능력을 도구로"의 가장 큰 장점은 확장성입니다.

새 능력 추가 = 새 도구 추가 = tools 리스트에 한 줄
  • 환불 정책이 바뀜 → RAG 인덱스만 갱신 (에이전트 코드 그대로)
  • 새 데이터 소스 추가 → 새 도구 함수 작성 후 리스트에 추가
  • 능력 제거 → 리스트에서 빼기

에이전트의 핵심 로직(ReAct 루프)은 그대로 두고, 도구만 갈아끼우며 능력을 확장합니다. 이게 잘 설계된 에이전트의 모습이죠.

핵심 정리

  • 에이전트의 강력함은 모든 능력을 같은 도구 형태로 통일하는 데서 온다.
  • 문서·DB·재고·검색·코드 — 전부 "호출하면 결과 주는 함수".
  • 통일하면 도구를 자유롭게 조합해 에이전트를 만들 수 있다.
  • RAG도 create_retriever_tool로 평범한 도구가 됐다.
  • 통일의 힘은 확장성 — 도구만 추가하면 능력 확장.
  • 다음 절에서 멀티스텝 처리를 봅니다.
