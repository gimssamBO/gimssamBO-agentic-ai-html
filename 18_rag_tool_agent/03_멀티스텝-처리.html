멀티스텝 처리

한 줄 요약

복합 질문이 오면 에이전트는 분해 → 순차 호출 → 종합의 멀티스텝으로 처리합니다. "환불 절차 + 주문 상태"를 두 도구(RAG, DB)로 차례로 풀고, 두 결과를 모아 하나의 답으로 종합합니다.

1. 복합 질문의 처리 흐름

"환불 절차랑 내 주문 O000902 상태 알려줘"라는 질문은 한 도구로 못 끝납니다. 에이전트는 이렇게 처리합니다.

질문: "환불 절차 + 주문 O000902 상태"

  1. Step 1 — policy_search("환불 절차") — 생각: "환불 절차는 정책 문서에 있겠다" / 관찰: "물류센터 도착 후 영업일 3일 내 환불…"
  2. Step 2 — get_order_status("O000902") — 생각: "주문 상태는 DB를 봐야겠다" / 관찰: "배송완료"
  3. Step 3 — 종합 — "환불 절차는 … 이고, 주문 O000902는 '배송완료' 상태입니다."

세 단계입니다 — 분해(질문을 둘로), 순차 호출(도구 2개), 종합(두 결과를 하나로).

2. 분해 — 질문을 나누기

에이전트는 복합 질문을 부분 질문들로 분해합니다.

"환불 절차랑 내 주문 O000902 상태 알려줘" 를 두 부분으로 분해합니다.

  • 부분①: "환불 절차" → 정책 문서 검색이 필요
  • 부분②: "주문 O000902 상태" → DB 조회가 필요

우리가 "이건 정책, 저건 DB"라고 나눠 주지 않았습니다. 에이전트가 질문을 읽고 스스로 분해했죠. 그리고 각 부분에 맞는 도구를 골랐습니다(라우팅, 12·17강).

3. 순차 호출 — 도구를 차례로

분해한 부분들을 각각 도구로 처리합니다. 7강 ReAct 루프가 반복되는 거죠.

[1번째 루프] policy_search 호출 → 환불 절차 획득
[2번째 루프] get_order_status 호출 → 주문 상태 획득
[3번째 루프] 더 부를 도구 없음 → 최종 답

create_agent가 이 루프를 내부에서 돌립니다(8강). 각 루프에서 도구를 하나씩 호출하고, 결과를 관찰해 다음을 정하죠. 이게 7강에서 손으로 짠 ReAct 루프의 자동화입니다.

4. 종합 — 결과를 하나로

마지막에 에이전트는 여러 도구의 결과를 종합해 하나의 자연스러운 답을 만듭니다.

두 도구의 결과를 종합합니다.

  • policy_search 결과: "환불은 물류센터 도착 후 3일 내…"
  • get_order_status 결과: "주문 O000902 배송완료"

→ 종합 답변: "환불 절차는 상품 수령 후 7일 이내 신청하시면 물류센터 도착 후 3일 내 환불됩니다. 주문 O000902(이어버드)는 현재 '배송완료' 상태이므로 환불 신청이 가능합니다."

두 정보를 그냥 나열하는 게 아니라, 맥락에 맞게 엮어 답합니다. "배송완료 상태이므로 환불 가능"처럼 두 정보를 연결하는 추론까지 하죠. 이게 에이전트가 단순 조회 도구보다 똑똑한 점입니다.

5. 실행 과정 관찰

pretty_print로 멀티스텝을 직접 볼 수 있습니다.

out = agent.invoke({"messages": [{"role": "user", "content": q}]})
for m in out["messages"]:
    m.pretty_print()

예상 출력

Human: 환불 절차랑 내 주문 O000902 상태 알려줘
Ai: Tool Calls: policy_search({'query': '환불 절차'})        ← Step 1
Tool: 환불은 상품 수령 후 7일 이내 신청 가능하며...
Ai: Tool Calls: get_order_status({'order_id': 'O000902'})    ← Step 2
Tool: 주문 O000902: 상태='배송완료'...
Ai: [종합 답변] 환불 절차는... 주문 O000902는 배송완료 상태...  ← Step 3

policy_search(RAG) → get_order_status(DB) 순서로 두 도구가 호출되고, 마지막에 종합됐습니다. 12강 멀티툴 연쇄 호출과 같은 구조인데, 이번엔 RAG 도구가 섞인 게 차이죠.

6. 멀티스텝의 힘

멀티스텝 처리 덕분에, 사용자는 자연스럽게 한 문장으로 복잡한 요청을 할 수 있습니다.

사용자: "환불 절차랑 주문 상태 알려줘" (한 문장)
  → 에이전트가 알아서 분해·순차·종합

vs.

사용자가 일일이: "환불 절차 알려줘" (답 받고) → "주문 상태도 알려줘" (또 답 받고)

사용자가 질문을 쪼개 여러 번 물을 필요 없이, 한 번에 복합 요청을 하면 에이전트가 다 처리합니다. 이게 멀티스텝 에이전트의 사용자 경험상 가치입니다.

핵심 정리

  • 복합 질문은 분해 → 순차 호출 → 종합의 멀티스텝으로 처리.
  • 분해: 질문을 부분들로 나눔(스스로).
  • 순차 호출: 각 부분을 도구로(ReAct 루프 반복).
  • 종합: 여러 결과를 맥락에 맞게 엮어 하나의 답으로.
  • RAG 도구가 섞인 12강 연쇄 호출과 같은 구조.
  • 사용자는 한 문장으로 복잡한 요청 가능.
  • 다음 절에서 도구 설계 원칙을 봅니다.
