따라하기 — RAG와 도구를 동시에 쓰는 질문

목표

정책 검색(RAG)과 데이터 조회(DB) 도구 세 개를 한 에이전트에 묶고, 두 출처가 섞인 복합 질문을 처리합니다. RAG 파트의 종착점입니다.

1. 한 에이전트에 묶기

세 도구를 같은 목록에 넣습니다. 이게 이 강의 핵심입니다(01·02번).

from langchain.agents import create_agent
from common import get_chat

# RAG 도구(문서) + DB 도구 2종(주문·재고)을 '같은 목록'에
tools = [build_policy_tool(), get_order_status, get_stock]
llm = get_chat(temperature=0)
agent = create_agent(
    llm,
    tools=tools,
    system_prompt=(
        "너는 승승장구몰 CS 에이전트다. 정책은 policy_search로 검색하고, "
        "주문 상태는 get_order_status, 재고는 get_stock으로 조회해 종합해 답하라."
    ),
)

build_policy_tool()(RAG)과 get_order_status, get_stock(DB)이 한 리스트에 들어갔습니다. 에이전트에겐 똑같은 도구 3개죠. 시스템 프롬프트에 각 도구의 역할을 적어, 라우팅을 돕습니다.

2. 복합 질문 던지기

두 출처가 섞인 질문을 던집니다.

q = "어제 받은 이어버드 환불하고 싶은데 절차랑, 내 주문 O000902 상태 알려줘"
out = agent.invoke({"messages": [{"role": "user", "content": q}]})
for m in out["messages"]:
    m.pretty_print()
print("\n[최종 답변]\n", out["messages"][-1].content)

예상 출력

Human: 어제 받은 이어버드 환불하고 싶은데 절차랑, 내 주문 O000902 상태 알려줘

Ai: Tool Calls: policy_search({'query': '환불 절차'})            ← RAG 도구
Tool: 환불은 상품 수령 후 7일 이내 신청 가능하며, 물류센터 도착 후 3일 내...

Ai: Tool Calls: get_order_status({'order_id': 'O000902'})        ← DB 도구
Tool: 주문 O000902: 상품='승승 무선 블루투스 이어버드 SE', 상태='배송완료'...

Ai: [최종 답변]
환불 절차는 상품 수령 후 7일 이내에 신청하시면, 반품 상품이 물류센터에 도착한 후
영업일 기준 3일 이내에 환불됩니다. 주문 O000902(이어버드, 수량 1)은 현재
'배송완료' 상태이므로 환불 신청이 가능합니다.

3. 무슨 일이 일어났나

03번 멀티스텝이 그대로 작동했습니다.

1. 분해: "환불 절차"(문서) + "주문 상태"(DB)로 나눔
2. 순차: policy_search(RAG) → get_order_status(DB) 차례로 호출
3. 종합: "환불 절차는... 주문은 배송완료 상태이므로 환불 가능"

특히 마지막 종합이 인상적입니다. 에이전트가 두 정보를 단순 나열이 아니라 "배송완료 상태이므로 환불 신청 가능" 이라고 연결했죠. 정책(절차)과 데이터(상태)를 엮어 추론한 겁니다. RAG 도구와 DB 도구를 한 에이전트가 함께 쓰니 이런 종합이 가능합니다.

4. 핵심 — RAG가 다른 도구와 섞였다

이 출력의 핵심은 policy_search(RAG)와 get_order_status(DB)가 한 흐름에서 호출됐다는 것입니다.

17강: RAG 도구만 (정책)
12강: DB 도구만 (주문·재고)
18강: RAG 도구 + DB 도구 함께!  ← 이게 종착점

13~16강에서 복잡했던 RAG가, 17강에서 도구가 되고, 18강에서 다른 도구들과 자연스럽게 섞였습니다. 에이전트에겐 셋 다 "호출하면 결과 주는 함수"니까요(02번). 이게 "모든 능력을 도구로 통일"의 결실입니다.

5. RAG 파트의 완성

13강부터 18강까지의 여정이 여기서 끝납니다.

13강 RAG 개념 → 14강 임베딩 → 15강 벡터DB → 16강 RAG QA
→ 17강 RAG를 도구로 → 18강 RAG + 데이터 도구 통합 ✓

이제 여러분은 진짜 사내 문서 기반 상담봇을 만들 수 있습니다. 정책 문서의 지식과 실시간 DB 데이터를 함께 다루는, 실전에 쓸 수 있는 에이전트죠. 1부(도구)와 2부 RAG가 하나로 합쳐진 것입니다.

6. 다음은? 쓰기 도구

지금까지 도구는 모두 읽기(조회) 였습니다. 안전했죠. 하지만 진짜 CS는 "환불 실행", "주문 취소" 같은 상태 변경(쓰기) 도 해야 합니다. 그건 위험합니다 — 잘못하면 돈이 나가고 되돌리기 어렵죠. 다음 절(08번)에서 쓰기 도구의 위험성과 안전장치를 배웁니다.

핵심 정리

  • RAG 도구 + DB 도구를 한 목록에 넣어 에이전트 구성.
  • 복합 질문을 분해 → 순차(RAG→DB) → 종합으로 처리.
  • 에이전트가 두 정보를 연결·추론("배송완료라 환불 가능").
  • RAG가 다른 도구와 자연스럽게 섞임(02번 통일의 결실).
  • 13~18강 RAG 파트가 완성 — 진짜 사내 상담봇.
  • 다음 절에서 위험한 쓰기 도구를 배웁니다.
