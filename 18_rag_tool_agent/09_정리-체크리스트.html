정리 & 체크리스트

18강에서 배운 것

18강에서 RAG 파트가 완성됐습니다 — 문서 검색과 실시간 데이터를 한 에이전트에.

  • 통합: RAG도 도구의 하나로 보고 데이터 도구와 같은 목록에.
  • 모든 능력을 도구로 통일: 문서·DB·재고 모두 "호출하면 결과 주는 함수".
  • 멀티스텝: 복합 질문을 분해 → 순차 호출 → 종합.
  • 도구 설계 원칙: 명확한 설명·입력 검증·결정적 반환·부작용 최소화.
  • 읽기 vs 쓰기: 조회는 안전, 상태 변경은 2단계 확인으로 신중히.

체크리스트

  • [ ] 실전 CS가 정책(문서)과 실시간 데이터를 함께 다뤄야 함을 안다.
  • [ ] RAG도 도구의 하나로 보고 데이터 도구와 같은 목록에 넣는다.
  • [ ] 복합 질문이 분해→순차→종합으로 처리됨을 관찰했다.
  • [ ] 도구 설계 4원칙을 적용했다.
  • [ ] 읽기/쓰기 도구의 차이와 쓰기 안전장치(2단계 확인)를 안다.

한 줄 핵심

모든 능력을 도구로 통일하면, RAG와 데이터 조회가 한 에이전트에서 자연스럽게 섞인다. 단, 상태를 바꾸는 쓰기 도구는 2단계 확인으로 신중히 다룬다.

🎉 2부(RAG·도구 통합)를 마치며

13~18강으로 RAG와 도구를 다루는 능력이 완성됐습니다. 이제 여러분은 사내 문서 지식과 실시간 데이터를 함께 쓰는 진짜 상담봇을 만들 수 있습니다.

다음 강 예고

지금까지 에이전트는 대화를 기억하지 못했습니다. "방금 말한 주문번호로 환불해줘"라고 하면 "어떤 주문번호요?"라고 되묻죠. 19강 Agent Memory에서는 에이전트에게 단기 기억을 줍니다. thread_id로 대화를 이어, 사람처럼 맥락을 기억하는 상담봇을 만듭니다.
