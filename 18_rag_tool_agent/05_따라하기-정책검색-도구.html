2. 정책 검색 도구 만들기

17강의 build_retriever + create_retriever_tool을 합쳐, 정책 검색 도구를 만듭니다.

from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import FAISS
from langchain_core.tools.retriever import create_retriever_tool

def build_policy_tool():
    """정책 문서를 인덱싱해 RAG 검색 도구로 변환."""
    docs = []
    for f in ["환불교환정책.pdf", "멤버십정책.pdf"]:
        docs.extend(PyPDFLoader(str(DOCS / f)).load())
    chunks = RecursiveCharacterTextSplitter(
        chunk_size=500, chunk_overlap=50).split_documents(docs)
    retriever = FAISS.from_documents(chunks, get_embeddings()).as_retriever(
        search_kwargs={"k": 4})
    # retriever를 'policy_search' 도구로 변환 (설명이 라우팅 기준)
    return create_retriever_tool(
        retriever,
        "policy_search",
        "승승장구몰 환불/교환/멤버십 정책 문서를 검색한다. 정책·절차·규정 질문에 사용.")

13~17강에서 배운 모든 게 이 한 함수에 모였습니다.

  • 로드·청킹(13강): PDF → 청크
  • 임베딩·인덱싱(14·15강): FAISS.from_documents
  • retriever(16강): as_retriever
  • 도구화(17강): create_retriever_tool

이게 RAG 5단계를 하나의 "도구"로 압축한 모습입니다. 밖에서 보면 그냥 policy_search라는 도구 하나죠(02번 추상화).

3. description이 라우팅 기준

도구의 description을 다시 봅시다.

"승승장구몰 환불/교환/멤버십 정책 문서를 검색한다. 정책·절차·규정 질문에 사용."

18강에서는 도구가 여러 개(정책+주문+재고)라, 이 설명이 다른 도구와 구별되어야 합니다(6강 "비슷한 도구 구분"). "정책·절차·규정 질문에"라고 명시해, 에이전트가 "정책 질문 → 이 도구"라고 라우팅하게 합니다. 주문·재고 도구와 헷갈리지 않도록요.

4. 도구 단독 테스트

만든 도구를 직접 호출해 봅니다.

policy_tool = build_policy_tool()
print(policy_tool.invoke("환불 절차"))

예상 출력

환불은 상품 수령 후 7일 이내 신청 가능하며, 반품 상품이 물류센터에 도착한 후
영업일 기준 3일 이내에 환불됩니다 ...

policy_tool.invoke("환불 절차")가 정책 문서에서 관련 청크를 찾아 돌려줍니다. 이게 RAG 검색이 "도구 하나"로 작동하는 모습입니다. 16강의 복잡한 LCEL 체인이 이제 invoke 한 번으로 줄었죠.

5. RAG 도구의 위치

이 도구(policy_search)가 다룰 질문:
  "환불 며칠?", "교환 절차?", "VIP 등급?"  → 정책 문서

다음 절의 도구들이 다룰 질문:
  "주문 O000902 상태?"  → get_order_status (DB)
  "이어버드 재고?"      → get_stock (DB)

policy_search는 "문서에 답이 있는 질문"을 담당합니다. 다음 절에서 "DB에 답이 있는 질문"을 위한 데이터 도구들을 만들고, 07번에서 셋을 한 에이전트에 합칩니다.

핵심 정리

  • build_policy_tool은 RAG 5단계를 하나의 도구로 압축.
  • 13~17강(로드·청킹·임베딩·검색·도구화)이 이 함수에 모임.
  • description을 명확히 써 다른 도구와 구별(라우팅 정확도).
  • policy_tool.invoke("환불 절차")로 단독 테스트.
  • RAG 검색이 이제 도구 하나(invoke 한 번)로 작동.
  • 다음 절에서 실시간 데이터 도구를 만듭니다.
