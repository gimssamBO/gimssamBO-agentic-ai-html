따라하기 — 실시간 데이터 도구 (DB/CSV)

목표

주문 상태·재고를 조회하는 실시간 데이터 도구 두 개를 만듭니다. 04번의 설계 원칙(입력 검증·예외 처리·결정적 반환)을 적용합니다.

1. 주문 상태 조회 도구

orders.csv에서 주문번호로 상태를 조회합니다.

import pandas as pd
from langchain_core.tools import tool
from common import DATA

orders = pd.read_csv(DATA / "orders.csv")

@tool
def get_order_status(order_id: str) -> str:
    """주문번호(order_id)로 주문 상태/상품/날짜를 조회한다. 예: 'O000902'"""
    # 없는 주문번호여도 예외로 죽지 않고 안내 문자열을 돌려준다(결정적·안전)
    row = orders[orders["order_id"] == order_id.strip()]
    if row.empty:
        return f"주문번호 {order_id} 를 찾을 수 없습니다."
    r = row.iloc[0]
    return (f"주문 {order_id}: 상품='{r['product_name']}', 상태='{r['status']}', "
            f"주문일={r['order_date']}, 수량={r['quantity']}")

04번 원칙들이 다 들어 있습니다.

  • 명확한 설명: "예: 'O000902'" 입력 형식 명시
  • 입력 검증: .strip()으로 공백 제거
  • 예외 처리: 없으면 안내 메시지(안 죽음)
  • 결정적: 같은 주문번호 → 같은 결과

2. 재고 조회 도구

products.csv에서 상품명으로 재고를 조회합니다.

products = pd.read_csv(DATA / "products.csv")

@tool
def get_stock(product_name: str) -> str:
    """상품명으로 현재 재고 수량을 조회한다. 예: '무선 이어버드'"""
    # str.contains: 정확히 일치가 아니라 '포함'으로 찾는다(고객이 일부만 말해도 매칭)
    row = products[products["product_name"].str.contains(product_name.strip(), na=False)]
    if row.empty:
        return f"'{product_name}' 상품을 찾을 수 없습니다."
    r = row.iloc[0]
    return f"'{r['product_name']}' 재고: {r['stock']}개"

str.contains로 부분 일치 검색을 합니다(5강 복습). 고객이 "이어버드"라고만 해도 "승승 무선 블루투스 이어버드 SE"를 찾죠. 정확한 전체 이름을 몰라도 되게요.

3. 두 도구 모두 '읽기 전용'

중요한 점: 이 두 도구는 모두 읽기(조회) 입니다. 데이터를 바꾸지 않습니다.

get_order_status("O000902")  → 조회만 (orders.csv 안 바뀜)
get_stock("이어버드")        → 조회만 (products.csv 안 바뀜)

그래서 안전합니다 — 에이전트가 잘못 호출해도 데이터가 훼손되지 않죠(04번 멱등성). "상태 변경"은 일부러 안 넣었습니다. 쓰기 도구의 위험성은 08번에서 따로 다룹니다.

4. 도구 단독 테스트

에이전트에 붙이기 전 각각 테스트합니다.

print(get_order_status.invoke({"order_id": "O000902"}))
print(get_stock.invoke({"product_name": "이어버드"}))

# 없는 경우도 테스트
print(get_order_status.invoke({"order_id": "X9999"}))   # 안전한 안내

예상 출력

주문 O000902: 상품='승승 무선 블루투스 이어버드 SE', 상태='배송완료', 주문일=2024-03-29, 수량=1
'승승 무선 블루투스 이어버드 SE' 재고: 225개
주문번호 X9999 를 찾을 수 없습니다.

정상 케이스는 데이터를 돌려주고, 없는 케이스(X9999)는 안전한 안내를 합니다. 04번 원칙이 작동하는 거죠.

5. 세 도구가 모였다

이제 세 도구가 준비됐습니다.

도구 출처 담당 질문
policy_search (05번) 정책 문서(RAG) "환불 절차?", "VIP 등급?"
get_order_status (06번) orders.csv(DB) "주문 상태?"
get_stock (06번) products.csv(DB) "재고?"

출처는 제각각(문서/DB)이지만, 에이전트에겐 똑같은 도구 3개입니다(02번). 다음 절에서 이 셋을 한 에이전트에 합쳐, RAG와 DB를 동시에 쓰는 질문을 처리합니다.

핵심 정리

  • get_order_status, get_stock은 CSV 조회 도구.
  • 04번 원칙 적용: 입력 검증·예외 처리·결정적 반환.
  • str.contains로 부분 일치(고객이 일부만 말해도 매칭).
  • 두 도구 모두 읽기 전용(데이터 안 바꿈, 안전).
  • policy_search(RAG) + 데이터 도구 2개 = 세 도구 준비 완료.
