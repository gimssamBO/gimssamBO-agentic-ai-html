정리 & 체크리스트

14강에서 배운 것

14강에서는 텍스트를 의미를 담은 벡터로 바꾸는 임베딩을 배웠습니다.

  • 임베딩: 텍스트 → 고정 길이 숫자 벡터(768차원). 의미가 비슷하면 벡터도 비슷.
  • 코사인 유사도: 두 벡터의 방향 닮음(-1~1, 1에 가까울수록 유사).
  • 임베딩 vs 채팅 모델: 임베딩은 검색용(쌈), 채팅은 생성용(비쌈).
  • 의미 검색: 단어가 안 겹쳐도("돈 돌려받기") 의미로 찾음("환불").
  • 긴 문서: 청킹 후 청크별 임베딩으로 필요한 조각만 검색.

한눈에 보는 핵심 코드

from common import get_embeddings
from sklearn.metrics.pairwise import cosine_similarity

emb = get_embeddings()                          # gemini-embedding-001, 768차원

# 인덱싱: 문서들을 배치 임베딩
doc_vectors = emb.embed_documents(["환불은 언제?", "배송 얼마나?", ...])

# 질의: 질문 임베딩 → 유사도 검색
q_vec = emb.embed_query("돈 돌려받기")
sims = cosine_similarity([q_vec], doc_vectors)[0]
top_k = sims.argsort()[::-1][:3]                # 상위 3개 인덱스

체크리스트

  • [ ] 임베딩이 텍스트를 고정 길이 벡터로 바꾼다는 것을 안다(768차원).
  • [ ] 코사인 유사도가 1에 가까울수록 의미가 비슷함을 이해했다.
  • [ ] embed_query(1개)와 embed_documents(배치)를 구분해 쓴다.
  • [ ] 단어가 안 겹쳐도 의미로 검색되는 것을 확인했다.
  • [ ] 긴 문서는 청킹 후 청크별 임베딩해야 함을 안다.

한 줄 핵심

임베딩은 텍스트를 의미 좌표(벡터)로 바꾼다. 코사인 유사도로 가까운 벡터를 찾으면, 단어가 달라도 의미로 검색할 수 있다.

다음 강 예고

14강에서는 벡터를 메모리에 보관해 numpy로 검색했습니다. 하지만 문서가 수만 개면 매번 임베딩하고 전체를 비교하는 건 너무 느리고 비쌉니다. 15강 벡터 데이터베이스(FAISS) 에서는 벡터를 디스크에 영속 저장하고 대량·고속으로 검색하는 법을 배웁니다. 한 번 인덱싱하면 두고두고 쓰는 진짜 RAG 인프라죠.
