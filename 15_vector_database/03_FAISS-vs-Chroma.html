FAISS vs Chroma

한 줄 요약

FAISS는 가볍고 빠른 라이브러리(읽기 위주·단순·고속에 적합), Chroma는 메타데이터 필터·컬렉션 관리가 강한 임베디드 DB입니다. 이 과정은 FAISS를 주력으로 하고, 필터가 필요할 때 Chroma를 씁니다.

1. 두 벡터스토어 비교

FAISS Chroma
형태 라이브러리(인메모리 인덱스) 임베디드 DB(메타데이터·필터 강함)
영속화 save_local / load_local(파일) persist_directory(자동 저장)
장점 매우 빠름, 의존성 가벼움 메타데이터 필터·컬렉션 관리 편함
추천 상황 읽기 위주·단순·고속 문서 갱신·필터·다중 컬렉션

2. FAISS — 가볍고 빠른 라이브러리

FAISS(Facebook AI Similarity Search)는 Meta가 만든 벡터 검색 라이브러리입니다.

from langchain_community.vectorstores import FAISS

vs = FAISS.from_documents(chunks, emb)   # 인덱스 생성
vs.save_local("faiss_index")             # 파일로 저장
vs2 = FAISS.load_local("faiss_index", emb, allow_dangerous_deserialization=True)  # 로드

장점:
- 매우 빠름: 대량 벡터 검색에 최적화
- 가벼움: 의존성이 적어 설치·배포가 간단
- 영속화가 명확: save_local/load_local로 파일에 저장/로드

적합한 상황: 문서가 자주 안 바뀌고, 빠른 검색이 중요하고, 복잡한 필터가 필요 없을 때. 대부분의 RAG에 충분합니다.

3. Chroma — 메타데이터에 강한 DB

Chroma는 메타데이터 필터링과 컬렉션 관리가 강한 임베디드 데이터베이스입니다.

from langchain_community.vectorstores import Chroma

vs = Chroma.from_documents(chunks, emb, persist_directory="chroma_db")  # 자동 저장
# 메타데이터 필터로 특정 문서 안에서만 검색
results = vs.similarity_search("질문", k=3, filter={"source": "멤버십정책.pdf"})

장점:
- 메타데이터 필터: filter={"source": "..."}로 특정 조건의 청크만 검색
- 자동 영속화: persist_directory만 주면 알아서 저장
- 컬렉션 관리: 여러 문서 그룹을 따로 관리

적합한 상황: "특정 문서 안에서만 검색", "최신 문서만 검색" 같은 필터링이 필요할 때. (07번에서 실습)

4. 무엇을 언제 쓰나

복잡한 메타데이터 필터가 필요한가?(특정 문서/날짜/카테고리만 검색)

  • 아니오 → FAISS (가볍고 빠름) — 대부분 이걸로 충분
  • 예 → Chroma (필터 강함)

대부분의 경우 FAISS로 충분합니다. "정책 문서 전체에서 의미 검색"이면 FAISS가 빠르고 간단하죠. "멤버십 문서 안에서만" 처럼 정밀한 필터가 필요할 때만 Chroma를 씁니다.

5. similarity_search의 점수

검색 결과의 "유사도 점수"를 볼 때 주의할 점이 있습니다. FAISS는 거리(distance) 를 씁니다.

scored = vs.similarity_search_with_score(query, k=2)
for d, score in scored:
    print(f"거리 {score:.3f} | {d.page_content[:50]}")

중요: FAISS 점수는 "거리"라서 작을수록 가깝습니다(코사인 유사도와 반대 방향!). 14강 코사인 유사도는 "클수록 가까움"이었는데, FAISS 거리는 "작을수록 가까움"입니다. 헷갈리기 쉬우니 기억해 두세요. (벡터스토어마다 점수 의미가 다를 수 있어, 문서를 확인하는 게 안전합니다.)

6. 더 큰 벡터DB들

FAISS와 Chroma 외에도 많은 벡터DB가 있습니다 — Pinecone, Weaviate, Milvus, pgvector 등. 이들은 분산·대규모·클라우드 환경을 위한 것입니다.

소규모·로컬     → FAISS, Chroma (이 과정)
대규모·클라우드  → Pinecone, Weaviate, Milvus, pgvector

원리는 모두 같습니다 — "벡터를 저장하고 유사도로 검색". 규모와 운영 방식이 다를 뿐이죠. 이 과정은 원리 학습이 목적이라 가벼운 FAISS/Chroma로 충분합니다. 실무에서 규모가 커지면 큰 벡터DB로 갈아타되, 개념은 그대로 적용됩니다.

핵심 정리

  • FAISS: 가볍고 빠른 라이브러리, save_local/load_local, 대부분의 RAG에 충분.
  • Chroma: 메타데이터 필터·자동 영속화에 강함, 정밀 필터 필요 시.
  • 대부분 FAISS로 충분, 필터가 필요할 때만 Chroma.
  • FAISS 점수는 거리라 작을수록 가까움(코사인과 반대).
  • 큰 규모는 Pinecone·Milvus 등 — 원리는 같다.
