실습문제와 해답

직접 코드를 고쳐 보며 15강 내용을 손에 익힙니다. 먼저 스스로 풀어 본 뒤 해답을 펼쳐 보세요. (이 실습은 GOOGLE_API_KEY가 필요합니다.)

문제 1 — FAISS 인덱스 생성·저장

data/docs/멤버십정책.pdf를 청킹·임베딩하여 FAISS 인덱스를 만들고 data/faiss_index/membership에 save_local하세요.

  • 기대 결과: 저장 폴더에 index.faiss, index.pkl이 생성되고, 저장된 청크 개수를 출력하면 성공.
해답 보기 
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_embeddings, DOCS, DATA
from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import FAISS

INDEX_DIR = str(DATA / "faiss_index" / "membership")

if __name__ == "__main__":
    # 로드 + 청킹
    docs = PyPDFLoader(str(DOCS / "멤버십정책.pdf")).load()
    chunks = RecursiveCharacterTextSplitter(
        chunk_size=500, chunk_overlap=50).split_documents(docs)
    print(f"페이지 {len(docs)} → 청크 {len(chunks)}개")

    # 인덱싱 + 저장
    emb = get_embeddings()
    vs = FAISS.from_documents(chunks, emb)
    vs.save_local(INDEX_DIR)
    print(f"인덱스 저장 완료 → {INDEX_DIR}")
    print("저장 파일: index.faiss, index.pkl")
**예상 출력** 
페이지 2 → 청크 6개
인덱스 저장 완료 → .../data/faiss_index/membership
저장 파일: index.faiss, index.pkl
**해설**: 13강(로드·청킹) + 14강(임베딩) + 15강(저장)을 합친 인덱싱 파이프라인입니다. `save_local`이 폴더에 두 파일(`index.faiss`=벡터, `index.pkl`=텍스트·메타데이터)을 만듭니다. 이게 "배치로 한 번 실행하는 build_index.py"의 모습이죠. 이제 이 인덱스를 로드만 하면 재임베딩 없이 검색할 수 있습니다(문제 2).

문제 2 — load 후 검색 검증

문제 1에서 저장한 인덱스를 load_local로 불러와 "VIP 적립률"을 검색하세요.

  • 사용 파일: data/faiss_index/membership
  • 기대 결과: 적립률 정보가 든 청크가 top-1으로 검색되고, 새로 만들지 않고 로드만으로 검색됨을 확인하면 성공.
해답 보기 
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_embeddings, DATA
from langchain_community.vectorstores import FAISS

INDEX_DIR = str(DATA / "faiss_index" / "membership")

if __name__ == "__main__":
    emb = get_embeddings()

    # 저장된 인덱스 로드 (재임베딩 없음!)
    vs = FAISS.load_local(
        INDEX_DIR, emb,
        allow_dangerous_deserialization=True,   # 내가 만든 신뢰된 인덱스만!
    )
    print("인덱스 로드 완료 (재임베딩 없이)")

    # 검색
    query = "VIP 적립률"
    results = vs.similarity_search(query, k=2)
    print(f"\n[검색] {query}")
    for i, d in enumerate(results, 1):
        print(f"[{i}] {d.page_content[:80]} ...")
**예상 출력** 
인덱스 로드 완료 (재임베딩 없이)

[검색] VIP 적립률
[1] 등급별 적립률: 일반 1%, 실버 2%, 골드 3%, VIP 5% ...
[2] VIP 등급은 연 100만원 이상 구매 시 부여되며 ...
**해설**: `load_local`로 문제 1에서 저장한 인덱스를 **재임베딩 없이** 불러왔습니다. `from_documents`(임베딩 발생)를 호출하지 않았는데도 검색이 됩니다 — 저장된 벡터를 그대로 읽었으니까요. "VIP 적립률" 질문에 적립률 표가 든 청크가 1위로 나왔죠. 이게 "서버 기동 시 1회 로드하고 요청마다 검색만"하는 service.py의 모습입니다. 인덱싱(문제1)과 서비스(문제2)를 분리한 게 핵심입니다. ⚠️ `allow_dangerous_deserialization=True`는 **내가 직접 만든 인덱스**에만 쓰세요. 외부 인덱스는 절대 금물입니다.

정리

  • 문제 1로 인덱싱 + 저장(build_index.py)을 만들었습니다.
  • 문제 2로 로드 + 검색(service.py)을 만들어 둘을 분리했습니다.

이것으로 15강을 마칩니다. 다음 16강에서 검색 결과로 답하는 RAG QA를 완성합니다!
