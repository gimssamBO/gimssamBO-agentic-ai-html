정리 & 체크리스트

16강에서 배운 것

16강에서 RAG가 완성됐습니다 — 검색한 문서를 근거로 답하고 출처를 밝히는 QA 시스템.

  • LCEL 체인: {context, question} | 프롬프트 | LLM | 파서로 검색→생성을 한 줄에.
  • 환각 억제: "문서 근거로만, 없으면 모른다, 추측 금지" 프롬프트가 RAG의 핵심.
  • 출처 반환: retriever로 문서를 먼저 뽑아 {answer, sources} dict로.
  • 모듈화: answer(q) -> dict로 백엔드에 바로 연결.
  • 검색 품질: k값 딜레마 + LLM 재정렬(rerank).

한눈에 보는 핵심 코드

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

PROMPT = ChatPromptTemplate.from_template(
    "아래 [문서]만 근거로 답하라. 없으면 '찾을 수 없습니다'.\n[문서]\n{context}\n[질문] {question}")

def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

retriever = vs.as_retriever(search_kwargs={"k": 4})
chain = ({"context": retriever | format_docs, "question": RunnablePassthrough()}
         | PROMPT | llm | StrOutputParser())

def answer(q):                              # 출처까지 묶어 반환
    docs = retriever.invoke(q)
    text = (PROMPT | llm | StrOutputParser()).invoke(
        {"context": format_docs(docs), "question": q})
    sources = [{"source": d.metadata["source"].split("/")[-1],
                "page": d.metadata.get("page")} for d in docs]
    return {"answer": text, "sources": sources}

🎉 RAG 파이프라인이 완성됐습니다! 사내 문서를 근거로 답하는 진짜 QA 시스템을 만들 수 있게 됐습니다.

체크리스트

  • [ ] RAG QA = retriever + 프롬프트 + LLM을 LCEL로 연결한다.
  • [ ] 환각 억제 프롬프트("문서만, 없으면 모른다")의 중요성을 안다.
  • [ ] 답변과 함께 출처(파일명·페이지)를 반환한다.
  • [ ] answer(q) -> dict로 모듈화해 백엔드에 연결할 수 있다.
  • [ ] k값과 재정렬로 검색 품질을 높일 수 있다.

한 줄 핵심

RAG QA = 검색 + "문서 근거로만 답하라" 제약 + 출처 표시. 검색만 붙인다고 RAG가 아니라, 제약과 출처가 신뢰를 만든다.

다음 강 예고

지금까지 RAG는 "항상 검색"했습니다. 하지만 "안녕하세요" 같은 인사에도 굳이 문서를 검색할 필요가 있을까요? 17강 Knowledge Agent에서는 RAG를 도구로 만들어, LLM이 "정책 질문엔 검색, 일상 대화엔 검색 안 함"을 스스로 판단하게 합니다. RAG와 에이전트(5~12강)가 만나는 지점입니다.
