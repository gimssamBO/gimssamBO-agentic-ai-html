긴 대화 메시지 관리

한 줄 요약

대화가 길어지면 메시지가 무한히 쌓여 토큰·비용·지연이 폭발합니다. 두 해법이 있습니다 — (a) 트리밍: 최근 N개만 남기기, (b) 요약 압축: 오래된 대화를 한 줄로 요약. 둘 다 "입력을 줄여 비용을 통제"하는 기법입니다.

1. 대화가 길어지면 생기는 문제

02번에서 배웠듯, 기억은 "이전 대화를 매번 누적 주입"하는 것입니다. 그래서 대화가 길어지면:

1턴: 메시지 1개 보냄
10턴: 메시지 19개 보냄
100턴: 메시지 199개 보냄!  → 토큰 폭발, 비용·지연 증가

매 호출에 전체 대화를 보내니, 대화가 길수록 입력 토큰이 선형으로 증가합니다(7강 토큰 관리와 같은 문제). 100턴쯤 가면 인사 한마디에도 199개 메시지를 보내야 하죠. 비효율적이고 비쌉니다.

2. 두 가지 해법

이 문제를 푸는 두 방법이 있습니다. (실습 파일: sections/19_agent_memory/06_긴-대화-메시지-관리.py)

(a) 트리밍(trimming): 오래된 메시지를 잘라 버린다 — "버리기"
(b) 요약(summarization): 오래된 대화를 한 줄로 압축한다 — "압축하기"

7강에서 본 trim_history의 발전된 버전입니다.

3. 해법 (a) — 트리밍

최근 N개 메시지만 남기고 나머지는 버립니다. LangChain의 trim_messages를 씁니다.

from langchain_core.messages import trim_messages

def trim_recent(messages, keep=4):
    """최근 메시지만 남긴다(시스템 메시지는 항상 유지)."""
    return trim_messages(
        messages,
        max_tokens=keep,          # 여기선 '개수'로 해석(token_counter=len)
        strategy="last",          # 최근(last) 우선 보존
        token_counter=len,        # 메시지 '개수' 기준
        include_system=True,      # 시스템 메시지는 항상 유지
        start_on="human",         # 사람 메시지에서 시작하도록 경계 정리
    )

핵심 옵션:
- strategy="last": 최근 것을 우선 보존
- include_system=True: 시스템 메시지(역할 지침)는 항상 유지 — 이게 사라지면 봇이 정체성을 잃음
- token_counter=len: 토큰 대신 메시지 개수로 자름(간단)

예상 출력

[원본] 메시지 13개 → [트리밍] 5개 (시스템 1 + 최근 4)

13개가 5개로 줄었습니다. 다음 호출부터 입력이 줄어 비용·지연이 감소하죠.

4. 해법 (b) — 요약 압축

트리밍은 오래된 정보를 완전히 버립니다. 하지만 그 안에 중요한 게 있었다면? 그래서 요약으로 압축하는 방법이 있습니다.

def summarize_old(messages, keep_recent=4):
    """최근 keep_recent개는 그대로, 그 이전 대화를 LLM으로 한 줄 요약해 치환."""
    sys_msgs = [m for m in messages if isinstance(m, SystemMessage)]
    convo = [m for m in messages if not isinstance(m, SystemMessage)]
    if len(convo) <= keep_recent:
        return messages

    old, recent = convo[:-keep_recent], convo[-keep_recent:]
    # 오래된 대화를 텍스트로 합쳐 LLM에 요약 요청
    transcript = "\n".join(f"{'사용자' if isinstance(m, HumanMessage) else '상담원'}: {m.content}"
                           for m in old)
    summary = get_chat(temperature=0).invoke(
        "다음 상담 대화를 한국어 한 문장으로 요약하라.\n\n" + transcript).content
    # 오래된 N개를 '요약 1개'로 치환 → 길이는 줄고 맥락은 유지
    압축 = SystemMessage(content=f"[이전 대화 요약] {summary}")
    return sys_msgs + [압축] + recent

오래된 대화를 LLM이 한 문장으로 요약해, 그 요약 한 줄로 대체합니다. 최근 대화는 그대로 두고요.

예상 출력

[압축] 메시지 13개 → 6개
  - SystemMessage: 너는 승승장구몰 CS 상담원이다.
  - SystemMessage: [이전 대화 요약] 고객이 배송·환불·멤버십·쿠폰에 대해 문의함.
  - HumanMessage: (최근 4개)
  ...

오래된 6턴이 "[이전 대화 요약] 배송·환불·멤버십 문의" 한 줄로 압축됐습니다. 길이는 줄었지만 맥락은 유지되죠.

5. 트리밍 vs 요약

방법 하는 일 장점 단점
트리밍 오래된 것 버리기 간단·빠름·공짜 정보 손실
요약 오래된 것 압축 맥락 보존 LLM 호출 비용
  • 트리밍: 최근 대화만 중요할 때(예: 단순 Q&A). 간단하고 공짜.
  • 요약: 오래된 맥락도 중요할 때(예: 긴 상담). 맥락 보존하지만 요약에 LLM 호출 비용.

상황에 맞게 고릅니다. 보통 "최근 N개는 그대로 + 그 이전은 요약"을 섞어 쓰면 균형이 좋죠.

6. InMemorySaver와의 관계

이 강의 InMemorySaver는 대화를 자동 누적합니다. 편하지만, 길어지면 위 문제가 생기죠. 실무에서는:

InMemorySaver로 자동 누적 (편함)
  + 일정 길이 넘으면 트리밍/요약 적용 (비용 통제)

자동 누적의 편리함을 쓰되, 길어지면 트리밍·요약으로 입력을 줄입니다. 7강(반복 방지·토큰 관리), 19강(메모리)의 교훈이 합쳐지는 거죠 — "기억하되, 비용을 통제한다."

핵심 정리

  • 대화가 길어지면 토큰·비용·지연 폭발(매번 전체 전송).
  • (a) 트리밍: 최근 N개만 남기기(trim_messages, 시스템 메시지는 유지).
  • (b) 요약: 오래된 대화를 LLM이 한 줄로 압축(맥락 보존).
  • 트리밍은 간단·공짜(정보 손실), 요약은 맥락 보존(LLM 비용).
  • 실무: 자동 누적 + 길어지면 트리밍/요약(비용 통제).
