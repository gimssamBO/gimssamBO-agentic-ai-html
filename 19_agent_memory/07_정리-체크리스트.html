정리 & 체크리스트

19강에서 배운 것

19강에서는 에이전트에게 단기 기억을 줘서, 대화 맥락을 유지하게 했습니다.

  • LLM은 stateless: 매 호출이 백지. "기억"은 앱이 대화를 매번 주입하는 것.
  • InMemorySaver: 대화를 자동 저장·복원하는 체크포인터(수동 관리의 자동화).
  • thread_id: "어느 대화인가"를 구분. 같으면 이어지고, 다르면 격리.
  • 세션 격리: 같은 에이전트라도 thread_id별로 대화가 완전 분리(멀티 사용자).
  • 긴 대화 관리: 트리밍(버리기)·요약(압축)으로 토큰·비용 통제.

한눈에 보는 핵심 코드

from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

# checkpointer 한 줄로 기억 활성화
agent = create_agent(llm, tools=[], system_prompt="...",
                     checkpointer=InMemorySaver())

# config의 thread_id로 세션 식별
cfg = {"configurable": {"thread_id": "user-A"}}
agent.invoke({"messages": [{"role": "user", "content": "내 이름은 민준"}]}, cfg)
agent.invoke({"messages": [{"role": "user", "content": "내 이름 뭐랬지?"}]}, cfg)
# → "민준님!" (같은 thread_id라 기억)

print(result["messages"][-1].text)   # .content 아닌 .text (Gemini 블록 대응)

이 강에서 설치한 라이브러리

추가 설치 없음 — InMemorySaver는 이미 설치된 langgraph에 포함.

체크리스트

  • [ ] LLM이 stateless라서 맥락을 앱이 매번 주입해야 함을 안다.
  • [ ] checkpointer=InMemorySaver()와 config(thread_id)로 멀티턴을 구현했다.
  • [ ] 같은 thread_id는 기억하고 다른 thread_id는 격리됨을 확인했다.
  • [ ] InMemorySaver가 인메모리(재시작 시 소멸)임을 안다.
  • [ ] 긴 대화는 트리밍/요약으로 토큰을 관리한다.

한 줄 핵심

LLM은 기억 못 한다. checkpointer가 대화를 자동 누적·주입해 "기억하는 것처럼" 만들고, thread_id로 사용자별 대화를 격리한다.

다음 강 예고

19강의 InMemorySaver는 단기 기억입니다 — 서버를 재시작하면 다 사라지죠. 하지만 "임도현 고객은 무향 제품을 선호함" 같은 정보는 영구히 기억해야 합니다. 20강 Long-Term Memory에서는 사용자 프로필을 파일(JSON·SQLite)에 영속 저장해, 세션과 재시작을 넘어 기억하는 장기 기억을 만듭니다.
