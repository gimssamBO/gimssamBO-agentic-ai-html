따라하기 — 같은 세션 vs 다른 세션

목표

thread_id가 다르면 같은 에이전트라도 기억이 완전히 분리됨을 확인합니다. 이게 멀티 사용자 서비스에서 대화를 안전하게 격리하는 핵심 메커니즘입니다.

1. 시나리오 설계

같은 에이전트에 두 개의 thread_id(A, B)로 대화해 봅니다.

agent = build_agent()
cfg_a = {"configurable": {"thread_id": "user-A"}}   # 세션 A
cfg_b = {"configurable": {"thread_id": "user-B"}}   # 세션 B

A에 정보를 알려주고, B에서 물어보고, 다시 A로 돌아가 확인합니다. A와 B가 격리되는지 보는 거죠.

2. 세션 A에 정보 입력

chat(agent, "내 이름은 민준이야.", cfg_a)
final, _ = chat(agent, "내가 좋아하는 카테고리는 전자기기야. 기억해.", cfg_a)
print("[세션 A] 봇:", final["messages"][-1].text)

예상 출력

[세션 A] 봇: 네, 민준님. 전자기기를 선호하신다고 기억해 두겠습니다.   ← 이름(앞 턴)도 기억

세션 A에서 "민준"과 "전자기기"를 알려줬습니다. 봇이 둘 다 기억하죠(앞 턴의 이름까지).

3. 다른 세션 B에서 물어보기

이제 다른 thread_id(B)로 같은 정보를 물어봅니다.

final_b, _ = chat(agent, "내 이름이 뭐라고 했지?", cfg_b)
print("[세션 B] 봇:", final_b["messages"][-1].text)

예상 출력

[세션 B] 봇: 죄송하지만 아직 성함을 알려주지 않으셨어요.   ← 세션이 달라 모름!

세션 B는 "민준"을 모릅니다. 같은 에이전트 객체인데도요! thread_id가 다르니, A의 기록과 완전히 격리됐기 때문이죠. B는 A에서 무슨 대화가 오갔는지 전혀 모릅니다.

4. 세션 A로 복귀

다시 thread_id A로 돌아가 확인합니다.

final_a, msgs_a = chat(agent, "내 이름이랑 좋아하는 카테고리 다시 말해줘.", cfg_a)
print("[세션 A 복귀] 봇:", final_a["messages"][-1].text)

예상 출력

[세션 A 복귀] 봇: 민준님이시고, 선호 카테고리는 전자기기입니다.   ← 여전히 기억!

A로 돌아오니 여전히 기억합니다. B에 갔다 왔어도 A의 대화는 그대로 보존됐죠. 각 thread_id가 독립적인 대화를 유지하니까요.

5. 관찰 포인트 — 같은 에이전트, 격리된 기억

이 실험의 핵심은:

같은 에이전트 객체인데도, thread_id가 다르면 기억이 완전히 분리된다.

하나의 agent 객체가 thread_id별로 대화를 따로 보관합니다.

  • thread_id="user-A" → [민준, 전자기기, …] (A의 대화)
  • thread_id="user-B" → [] (B의 대화, A와 무관)

에이전트는 하나지만, InMemorySaver가 thread_id별로 대화를 따로따로 저장합니다. 그래서 A와 B가 섞이지 않죠.

6. 멀티 사용자 서비스의 핵심

이 격리가 멀티 사용자 서비스의 필수 요소입니다.

사용자 1000명이 동시에 채팅 → thread_id 1000개
  → 에이전트는 하나, 대화는 1000개로 격리
  → A 사용자의 정보가 B 사용자에게 절대 새어 나가지 않음

만약 격리가 안 되면, A 사용자에게 "당신 이름은 민준"이라고 했는데 B 사용자에게도 "당신 이름은 민준"이라고 답하는 개인정보 유출 사고가 납니다. thread_id 격리가 이를 막죠. 그래서 thread_id를 사용자별로 정확히 부여하는 게 보안상 매우 중요합니다.

7. 대화 기록 들여다보기

chat이 돌려준 메시지 리스트로 누적된 대화를 볼 수 있습니다.

print("user-A 누적 메시지 수:", len(msgs_a))   # 턴이 쌓일수록 증가
print("마지막 메시지:", msgs_a[-1].text[:40], "...")

예상 출력

user-A 누적 메시지 수: 8
마지막 메시지: 민준님이시고, 선호 카테고리는 전자기기입니다 ...

턴이 진행될수록 메시지가 쌓입니다. 이게 02번에서 본 "기억 = 누적"의 실체죠. 그리고 이게 길어지면 토큰 문제가 생겨, 다음 절에서 관리법을 배웁니다.

핵심 정리

  • 같은 에이전트라도 thread_id가 다르면 기억이 완전 격리.
  • 세션 A의 정보를 세션 B는 모름(독립적 대화).
  • InMemorySaver가 thread_id별로 대화를 따로 저장.
  • 멀티 사용자 서비스에서 개인정보 유출을 막는 핵심.
  • thread_id를 사용자별로 정확히 부여해야 안전.
  • 다음 절에서 긴 대화의 메시지 관리를 배웁니다.
