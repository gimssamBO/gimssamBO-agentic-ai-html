문제 1 — thread_id로 대화 이어가기

InMemorySaver를 단 에이전트를 만들고, 같은 thread_id="u1"로 "내 이름은 지표야" → "내 이름 뭐야?"를 연달아 호출하세요.

  • 기대 결과: 두 번째 답에 "지표"가 포함되면 성공.

code/ch19_memory_ex01.py

해답 보기 
import pathlib
import sys

# 1. pathlib.path -> pathlib.Path 교정
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver  # inmemorysaver -> InMemorySaver (파스칼케이스 교정)

# 2. 체크포인터(단기기억)가 포함된 에이전트 생성
agent = create_agent(
    get_chat(temperature=0.3),
    tools=[],
    system_prompt="너는 친절한 상담원이다. 한국어 존댓말로 답하라.",
    checkpointer=InMemorySaver(),  # 인메모리 대화 저장소
)

# 3. 동일 대화 세션을 식별하기 위한 thread_id 설정
cfg = {"configurable": {"thread_id": "u1"}}

# 1턴: 이름 정보 전달
agent.invoke({"messages": [{"role": "user", "content": "내 이름은 지표야."}]}, cfg)

# 2턴: 동일 thread_id로 이전 대화 내용 질문 (단기기억 작동)
out = agent.invoke({"messages": [{"role": "user", "content": "내 이름 뭐야?"}]}, cfg)

# 4. 답변 추출 (m.text 대신 표준 속성인 m.content 사용)
answer = out["messages"][-1].content

print("봇:", answer)
print("'지표' 포함?", "지표" in answer)
**예상 출력** 
봇: 지표님이라고 하셨습니다!
'지표' 포함? true
**해설**:
`checkpointer=InMemorySaver()`와 같은 `thread_id="u1"` 덕분에, 1턴의 "지표"를 2턴에서 기억합니다.
우리가 대화 기록을 직접 관리하지 않았는데도요.
`checkpointer`가 매 호출 끝에 대화를 저장하고, 같은 thread_id의 다음 호출 때 자동 복원하기 때문이죠.

문제 2 — 스레드 격리 확인

위 코드에 thread_id="u2"로 "내 이름 뭐야?"를 한 번 더 호출하는 부분을 추가하세요.

  • 기대 결과: u2에서는 이름을 모른다고 답해, thread_id별로 기억이 분리됨을 검증하면 성공.

code/ch19_memory_ex02.py

해답 보기 
import pathlib
import sys

# 1. pathlib.path -> pathlib.Path 교정
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver  # inmemorysaver -> InMemorySaver 파스칼케이스 교정

# 2. 인메모리 체크포인터(단기기억)가 연결된 에이전트 생성
agent = create_agent(
    get_chat(temperature=0.3),
    tools=[],
    system_prompt="너는 친절한 상담원이다. 한국어 존댓말로 답하라.",
    checkpointer=InMemorySaver(),  # 세션별 대화 기록을 격리 저장하는 체크포인터
)

# =====================================================================
# 세션 1 (u1): 사용자 정보 등록 및 기억 확인
# =====================================================================
cfg1 = {"configurable": {"thread_id": "u1"}}

# 1-1턴: 세션 u1에 이름 저장
agent.invoke({"messages": [{"role": "user", "content": "내 이름은 지표야."}]}, cfg1)

# 1-2턴: 세션 u1에서 이름 질문 (기억 확인)
out1 = agent.invoke({"messages": [{"role": "user", "content": "내 이름 뭐야?"}]}, cfg1)
ans1 = out1["messages"][-1].content  # text -> content 속성 교정
print("[u1] 봇:", ans1)


# =====================================================================
# 세션 2 (u2): 다른 thread_id로 접속 시 격리 여부 확인
# =====================================================================
cfg2 = {"configurable": {"thread_id": "u2"}}

# 2-1턴: 세션 u2에서 이름 질문 (u1의 정보를 모르는지 테스트)
out2 = agent.invoke({"messages": [{"role": "user", "content": "내 이름 뭐야?"}]}, cfg2)
ans2 = out2["messages"][-1].content  # text -> content 속성 교정
print("[u2] 봇:", ans2)


# =====================================================================
# 세션 간 메모리 격리 결과 검증
# =====================================================================
print("\n[격리 확인]")
print("  u1은 '지표' 앎:", "지표" in ans1)
print("  u2는 '지표' 모름:", "지표" not in ans2)
**예상 출력** 
[u1] 봇: 지표님이라고 하셨습니다!
[u2] 봇: 죄송하지만 아직 성함을 알려주지 않으셨어요.

격리 확인:
  u1은 '지표' 앎: true
  u2는 '지표' 모름: true
**해설**: 같은 에이전트 객체인데, u1은 "지표"를 알고 u2는 모릅니다.
thread_id가 다르니 대화가 **완전히 격리**됐기 때문이죠.
InMemorySaver는 thread_id별로 대화를 따로 저장하니까요.
이 격리가 멀티 사용자 서비스의 핵심입니다 — u1 사용자의 정보가 u2 사용자에게 새어 나가지 않습니다.
만약 격리가 안 되면 개인정보 유출 사고가 나죠.

정리

  • 문제 1로 thread_id로 대화가 이어짐을 확인했습니다.
  • 문제 2로 thread_id별 격리(멀티 사용자 안전)를 검증했습니다.
