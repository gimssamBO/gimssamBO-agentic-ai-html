InMemorySaver와 thread_id

한 줄 요약

InMemorySaver는 대화 기록을 자동으로 저장·복원하는 체크포인터(checkpointer) 입니다. thread_id는 "어느 대화인가"를 구분하는 키죠. 같은 thread_id면 기억이 이어지고, 다른 thread_id면 완전히 새 대화로 격리됩니다.

1. 두 가지 부품

단기 기억은 두 부품으로 구성됩니다.

  • InMemorySaver (체크포인터): 대화 상태(메시지들)를 저장하는 엔진. 호출이 끝날 때마다 현재 대화를 스냅샷으로 저장하고, 다음 호출 때 자동 복원.
  • thread_id: "어느 대화인가"를 구분하는 식별자. 같은 thread_id로 호출하면 이전 기록이 이어짐.

InMemorySaver(저장소) 가 thread_id별로 대화를 보관합니다.

  • thread_id="user-A" → [민준, 반갑습니다, …]
  • thread_id="user-B" → [서윤, 안녕하세요, …]

호출 시 thread_id로 해당 대화를 복원합니다.

  • agent.invoke(..., config={"thread_id": "user-A"}) → A 대화 복원
  • agent.invoke(..., config={"thread_id": "user-B"}) → B 대화 복원

2. 체크포인터가 하는 일

02번에서 직접 history 리스트를 관리하던 걸, 체크포인터가 자동으로 합니다.

직접 구현(02번):           체크포인터(InMemorySaver):
  history.append(...)        매 호출 끝에 자동 저장
  llm.invoke(history)        다음 호출 때 자동 복원
  history.append(...)        우리는 신경 쓸 필요 없음!

checkpointer=InMemorySaver() 한 줄만 붙이면, 대화 누적·저장·복원이 전부 자동입니다. 우리가 메시지를 일일이 append 할 필요가 없죠. 8강의 create_agent가 ReAct 루프를 자동화한 것처럼, InMemorySaver가 메모리 관리를 자동화합니다.

3. thread_id = 세션 라우팅

thread_id는 "어느 사용자의 어느 대화를 이어갈지"를 결정합니다.

agent.invoke({"messages": [...]}, {"configurable": {"thread_id": "user-A"}})
# thread_id="user-A" → A의 대화 맥락을 이어 간다.
  • 같은 thread_id → 그 대화의 이전 기록이 이어짐
  • 다른 thread_id → 완전히 새 대화(격리)

이게 멀티 사용자 서비스의 핵심입니다. 사용자마다 다른 thread_id를 주면, 사용자별 대화가 안전하게 분리됩니다. A의 대화가 B에게 새어 나가지 않죠.

4. 백엔드 매핑

thread_id는 여러분 서비스의 세션ID/사용자ID와 1:1로 매핑하면 됩니다.

항목 의미 백엔드 매핑
checkpointer 상태 저장 엔진 세션 스토어(메모리/DB)
thread_id 대화 식별자 세션ID 또는 사용자ID
InMemorySaver 인메모리 체크포인터 프로세스 재시작 시 사라짐
(영속) DB 체크포인터 디스크 저장 Redis/Postgres(운영) 
# 로그인 사용자
config = {"configurable": {"thread_id": f"user-{user_id}"}}

# 비로그인 채팅 (세션 토큰)
config = {"configurable": {"thread_id": session_token}}

"이 요청은 어떤 사용자의 어떤 대화인가"를 thread_id 하나로 라우팅합니다. 백엔드 세션 관리와 똑같죠.

5. InMemorySaver의 한계 — 인메모리

이름 그대로 InMemorySaver는 메모리에 저장합니다. 중요한 한계가 있습니다.

⚠️ 프로세스가 재시작되면 모든 대화가 사라진다!

서버를 껐다 켜면 모든 대화 기록이 날아갑니다. 메모리에만 있었으니까요. 그래서:

  • 학습·단일 프로세스 데모 → InMemorySaver (간단)
  • 운영 서비스 → DB 기반 체크포인터 (영속)

운영에서는 langgraph-checkpoint-sqlite, Postgres, Redis 같은 DB 체크포인터로 교체합니다. 그러면 서버를 재시작해도 대화가 유지되죠. 이 강은 학습용이라 InMemorySaver를 쓰고, 영속 사용자 정보는 20강에서 다룹니다.

6. 단기 기억 vs 장기 기억 (예고)

  • 단기 기억(이 강): 한 대화 세션 안의 맥락. 세션이 끝나면 사라짐(InMemorySaver는 프로세스 재시작 시 소멸).
  • 장기 기억(20강): "어제 말한 것"까지 영구 저장. 세션을 넘어 유지.

InMemorySaver는 단기 기억입니다. "지금 이 대화"는 기억하지만, 서버 재시작이나 새 세션에서는 잊죠. 사용자 프로필(이름·선호)을 영구히 기억하려면 20강의 장기 기억이 필요합니다.

핵심 정리

  • InMemorySaver = 대화를 자동 저장·복원하는 체크포인터(02번 수동 관리의 자동화).
  • thread_id = "어느 대화인가"를 구분하는 키(세션ID/사용자ID와 매핑).
  • 같은 thread_id는 이어지고, 다른 thread_id는 격리.
  • InMemorySaver는 인메모리 — 재시작 시 사라짐(학습용).
  • 운영은 DB 체크포인터(영속), 장기 기억은 20강.
  • 다음 절에서 기억하는 상담봇을 만듭니다.
