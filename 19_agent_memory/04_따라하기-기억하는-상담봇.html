목표

create_agent에 checkpointer=InMemorySaver()를 붙이고, 호출할 때마다 config로 thread_id를 넘겨 멀티턴 대화를 구현합니다. 실제 파일은 code/ch19_memory.py 입니다.

0. 실습 준비

8강 이후와 동일한 LangChain/LangGraph 환경입니다. 추가 설치는 없습니다. InMemorySaver는 이미 설치된 langgraph에 포함돼 있습니다.

conda activate agentic
python code/common.py   # GOOGLE_API_KEY: True 확인

1. 메모리 붙인 에이전트

create_agent에 checkpointer=InMemorySaver()를 추가합니다. 이 한 줄이 전부입니다.

import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver   # 인메모리 체크포인터

def build_agent():
    """단기기억(InMemorySaver)을 붙인 상담 에이전트를 생성한다."""
    llm = get_chat(temperature=0.3)
    agent = create_agent(
        llm,
        tools=[],  # 이번 강은 '기억'에 집중 — 도구 없음
        system_prompt="너는 승승장구몰의 친절한 CS 상담원이다. 한국어 존댓말로 답하라.",
        checkpointer=InMemorySaver(),   # ← 이 한 줄로 기억 활성화!
    )
    return agent

8강부터 써 온 create_agent에 checkpointer 인자 하나만 추가됐습니다. 그러면 대화 상태(메시지들)가 매 호출 끝에 자동 저장/복원됩니다. 우리가 메시지를 누적할 필요가 없죠.

2. 대화 함수 — config로 thread_id 전달

호출할 때마다 config로 thread_id를 넘깁니다.

def chat(agent, text: str, config: dict):
    """한 번의 대화 턴. config의 thread_id로 같은 세션을 식별한다."""
    # config의 thread_id가 같으면 이전 대화가 자동으로 이어진다(직접 append 불필요)
    result = agent.invoke({"messages": [{"role": "user", "content": text}]}, config)
    return result, result["messages"]

핵심: agent.invoke의 두 번째 인자로 config를 넘깁니다. 이 config의 thread_id가 같으면, 이전 대화가 자동으로 이어지죠. 우리는 새 메시지 하나만 보내면, InMemorySaver가 이전 기록을 붙여 줍니다.

3. 멀티턴 대화 실행

같은 thread_id로 여러 번 호출하면 대화가 이어집니다.

agent = build_agent()
cfg = {"configurable": {"thread_id": "user-A"}}

# 1턴: 이름 알려주기
chat(agent, "내 이름은 민준이야.", cfg)

# 2턴: 같은 thread_id로 물어보기 → 기억함!
result, _ = chat(agent, "내 이름 뭐랬지?", cfg)
print(result["messages"][-1].text)

예상 출력

민준님이라고 하셨습니다! 무엇을 도와드릴까요?

01번의 "금붕어 봇"이 이제 기억합니다! 2턴에서 "내 이름 뭐랬지?"라고 물으니 "민준님"이라고 답하죠. checkpointer 한 줄과 같은 thread_id 덕분입니다. 우리가 대화 기록을 직접 관리하지 않았는데도요.

4. .text vs .content 주의

답변을 꺼낼 때 .content 대신 .text 를 쓴 데 주목하세요.

result["messages"][-1].text       # ← 항상 문자열 (안전)
# result["messages"][-1].content  # ← Gemini에서 리스트일 수 있음 (위험)

LangChain v1에서 AIMessage의 .content는 모델에 따라 문자열이 아니라 content blocks(리스트) 로 올 수 있습니다(Gemini는 thought signature 등을 블록으로 반환). 항상 문자열을 안전하게 얻으려면 .text를 쓰세요. 특히 슬라이싱([:40])이나 문자열 연결에서 .content가 리스트면 오류가 납니다. 작은 차이지만 실무에서 자주 만나는 함정이죠.

5. 무엇이 바뀌었나

8강부터 써 온 코드와 비교하면 차이는 딱 두 가지입니다.

# 1. checkpointer 추가
agent = create_agent(llm, tools=[], system_prompt=..., checkpointer=InMemorySaver())

# 2. invoke에 config(thread_id) 전달
agent.invoke({"messages": [...]}, {"configurable": {"thread_id": "user-A"}})

이 두 가지만으로 stateless 에이전트가 기억하는 에이전트가 됐습니다. 복잡한 메모리 관리 코드 없이, 프레임워크가 다 해 주죠. 이게 LangGraph의 편리함입니다.

핵심 정리

  • checkpointer=InMemorySaver() 한 줄로 기억 활성화.
  • invoke의 두 번째 인자로 config(thread_id) 전달.
  • 같은 thread_id면 이전 대화가 자동으로 이어짐(직접 append 불필요).
  • 답변은 .content 대신 .text(Gemini 블록 대응).
  • 두 가지(checkpointer + config)만으로 기억 구현.
  • 다음 절에서 세션 격리를 확인합니다.
