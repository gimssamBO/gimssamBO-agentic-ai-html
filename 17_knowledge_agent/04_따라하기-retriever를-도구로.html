이번 강은 환불교환정책.pdf, 직원핸드북.pdf, 멤버십정책.pdf 세 문서를 통합합니다.

1. 여러 문서 통합 인덱스

세 정책 문서를 하나의 인덱스로 묶습니다(15강 복습).

import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat, get_embeddings, DOCS
from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import FAISS

def build_retriever():
    """환불정책+핸드북+멤버십을 하나의 인덱스로 통합."""
    files = ["환불교환정책.pdf", "직원핸드북.pdf", "멤버십정책.pdf"]
    docs = []
    for f in files:
        docs.extend(PyPDFLoader(str(DOCS / f)).load())   # 세 문서를 한 인덱스로
    chunks = RecursiveCharacterTextSplitter(
        chunk_size=500, chunk_overlap=50).split_documents(docs)
    vs = FAISS.from_documents(chunks, get_embeddings())
    return vs.as_retriever(search_kwargs={"k": 4})

환불·핸드북·멤버십 세 문서가 한 인덱스에 들어갑니다. 그래서 "환불 규정"도, "연차 휴가"도, "VIP 등급"도 한 도구로 검색할 수 있죠.

2. retriever를 도구로

create_retriever_tool로 검색 도구를 만듭니다(03번).

from langchain_core.tools.retriever import create_retriever_tool

retriever = build_retriever()
# [핵심] description이 라우팅 규칙 — 에이전트는 이 설명을 읽고 "언제 검색할지" 판단
policy_tool = create_retriever_tool(
    retriever,
    name="company_policy_search",
    description="승승장구몰 환불/교환/멤버십/직원 규정 사내 문서를 검색한다. "
                "정책·규정·등급·반품·휴가 등 회사 규정 관련 질문에 사용하라.",
)

description에 "정책·규정·등급·반품·휴가" 라고 구체적으로 적었습니다. 이게 에이전트가 "이 질문이 정책 검색 대상인가?"를 판단하는 근거입니다.

3. 에이전트 구성

from langchain.agents import create_agent

llm = get_chat(temperature=0)
agent = create_agent(
    llm,
    tools=[policy_tool],
    system_prompt="너는 승승장구몰의 친절한 상담원이다. 회사 규정은 반드시 도구로 검색해 답하라.",
)

시스템 프롬프트에 "회사 규정은 반드시 도구로 검색해 답하라" 라고 명시했습니다. 이게 "규정 질문엔 환각하지 말고 꼭 문서를 찾아라"라는 지침이죠. 일상 질문은 언급 안 했으니, 그건 에이전트가 알아서 검색 없이 답합니다.

4. 검색 여부 확인 함수

에이전트가 검색했는지 확인하는 헬퍼를 만듭니다(02번).

def ask(q):
    out = agent.invoke({"messages": [{"role": "user", "content": q}]})
    msgs = out["messages"]
    # tool_calls가 하나라도 있으면 = 검색 도구를 호출했다는 뜻
    used = any(getattr(m, "tool_calls", None) for m in msgs)
    return msgs[-1].content, used   # (최종 답변, 도구 사용 여부)

ask는 답변과 함께 검색했는지 여부(used)를 돌려줍니다. 이걸로 "일상 질문엔 검색 안 하고, 정책 질문엔 검색하는지"를 다음 절에서 확인합니다.

5. 통합 인덱스의 장점

세 문서를 한 인덱스에 넣은 게 핵심입니다. 그래서 하나의 검색 도구로 모든 정책을 커버합니다.

company_policy_search 도구 하나로:
  "환불 며칠?"   → 환불교환정책 청크 검색
  "연차 며칠?"   → 직원핸드북 청크 검색
  "VIP 조건?"    → 멤버십정책 청크 검색

문서마다 도구를 따로 만들 필요 없이, 통합 인덱스 + 도구 하나면 됩니다. 의미 검색이 알맞은 문서의 청크를 알아서 찾으니까요(15강). 도구가 적을수록 에이전트의 라우팅도 쉽습니다(6강).

핵심 정리

  • 여러 문서를 하나의 인덱스로 통합 → 검색 도구 하나로 커버.
  • create_retriever_tool로 검색 도구 생성(description 명확히).
  • 시스템 프롬프트에 "규정은 반드시 검색" 명시.
  • tool_calls로 검색 여부를 확인하는 헬퍼 작성.
  • 통합 인덱스 + 도구 하나면 모든 정책 질문 처리.
  • 다음 절에서 일상/정책 질문의 검색 여부를 비교합니다.
