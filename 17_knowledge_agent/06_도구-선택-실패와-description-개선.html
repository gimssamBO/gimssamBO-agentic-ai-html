도구 선택 실패와 description 개선

한 줄 요약

검색 도구의 description은 에이전트의 라우팅 규칙입니다. 모호한 설명("문서 검색")은 일상 질문("오늘 날씨 어때?")에도 검색을 호출하는 실패를 부릅니다. description을 "무엇을, 언제 쓰는지" 구체적으로 못 박으면 오호출이 줄어듭니다.

1. 모호한 description의 실패

description을 대충 쓰면 에이전트가 헷갈립니다. (실습 파일: sections/17_knowledge_agent/06_도구-선택-실패와-description-개선.py)

# 나쁨 — 모호한 description
policy_tool = create_retriever_tool(
    retriever,
    name="company_policy_search",
    description="문서 검색",   # ← 너무 모호! "무슨 문서? 언제 쓰는데?"
)

"문서 검색" 이라고만 하면, 에이전트는 "아무 질문이나 문서 검색해야 하나?"라고 헷갈립니다. 그래서 일상 질문에도 검색을 남발하죠.

2. 실패 사례 — 오호출

모호한 description으로 여러 질문을 던져 봅니다.

QUESTIONS = [
    "오늘 날씨 어때?",                    # 일상 — 검색하면 안 됨
    "단순 변심 반품하면 배송비 누가 내요?",  # 정책 — 검색해야 함
    "VIP 등급 조건이 뭐예요?",            # 정책 — 검색해야 함
    "2 더하기 3은?",                      # 계산 — 검색하면 안 됨
]

예상 출력 (모호한 description "문서 검색")

[실패 사례 — 모호한 description]
[1] (검색함)   오늘 날씨 어때?           ← 잘못! 날씨에 정책 검색?
[2] (검색함)   단순 변심 반품 배송비?     ← 맞음
[3] (검색함)   VIP 등급 조건?            ← 맞음
[4] (검색함)   2 더하기 3은?             ← 잘못! 계산에 정책 검색?

일상 질문(날씨)과 계산(2+3)에도 검색을 호출했습니다(오호출). description이 모호해서 "언제 안 써야 하는지"를 몰랐던 거죠.

3. 개선 — 구체적 description

description에 "무엇을, 언제, 그리고 언제 쓰지 말지" 를 명확히 적습니다.

# 좋음 — 구체적 description
description = (
    "승승장구몰의 환불/교환/멤버십 등급/직원 규정 등 '사내 정책' 질문에만 사용한다. "
    "날씨·잡담·계산처럼 사내 문서와 무관한 질문에는 절대 사용하지 마라."
)

세 가지를 담았습니다.

  • 무엇을: "환불/교환/멤버십/직원 규정 사내 정책"
  • 언제: "정책 질문에만"
  • 언제 쓰지 말지: "날씨·잡담·계산엔 절대 사용 금지" ← 핵심!

특히 부정 조건("~엔 사용하지 마라")이 강력합니다(6강 복습). "언제 안 써야 하는지"를 명시하면 오호출이 크게 줍니다.

예상 출력 (구체적 description)

[개선 사례 — 구체적 description]
[1] (검색안함)  오늘 날씨 어때?           ← 맞음! 검색 안 함
[2] (검색함)    단순 변심 반품 배송비?     ← 맞음
[3] (검색함)    VIP 등급 조건?            ← 맞음
[4] (검색안함)  2 더하기 3은?             ← 맞음! 검색 안 함

이제 정확합니다 — 정책 질문에만 검색하고, 일상·계산엔 검색 안 합니다.

4. description = 라우팅 규칙

이 실험이 주는 교훈:

description은 단순한 설명이 아니라 에이전트의 "라우팅 규칙"이다.

같은 retriever인데 description 문구만 바꿨더니 에이전트의 행동이 완전히 달라졌습니다. description이 "이 도구를 언제 쓸지"를 결정하니까요. 6강의 "독스트링 = 도구 성능"이 retriever 도구에서도 그대로입니다.

5. 좋은 description 작성법

retriever 도구의 description을 쓸 때 체크리스트:

  • [ ] 무엇을 검색하는가? ("환불/멤버십 정책 문서")
  • [ ] 언제 쓰는가? ("정책·규정 질문에")
  • [ ] 언제 쓰지 말지? ("날씨·계산엔 사용 금지") ← 강력
  • [ ] 다른 도구와 구별되는가? (18강에서 도구가 늘어남)

특히 세 번째(부정 조건)를 빠뜨리기 쉬운데, 이게 오호출을 막는 핵심입니다. "언제 안 써야 하는지"를 명시하세요.

6. 18강 예고 — 도구가 늘어나면

이 강은 도구가 하나(정책 검색)뿐이라 description 하나만 신경 쓰면 됐습니다. 하지만 18강에서는 정책 검색 + 실시간 데이터 도구들이 함께 있게 됩니다. 그러면 각 도구의 description이 서로 구별되게 써야 합니다(6강 "비슷한 도구 구분"). 도구가 많아질수록 description의 중요성이 커지죠.

핵심 정리

  • 검색 도구의 description = 라우팅 규칙.
  • 모호한 description("문서 검색")은 오호출(일상·계산에도 검색).
  • 개선: 무엇을 + 언제 + 언제 쓰지 말지(부정 조건) 명시.
  • 부정 조건("~엔 사용 금지")이 오호출을 크게 줄인다.
  • 같은 retriever라도 description으로 행동이 완전히 바뀐다.
