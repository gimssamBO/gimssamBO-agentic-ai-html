RAG를 도구로 만들기 (create_retriever_tool)

한 줄 요약

create_retriever_tool(retriever, name, description)은 retriever를 LLM이 호출할 수 있는 검색 도구로 바꿔 줍니다. 핵심은 description — 에이전트는 이 설명을 읽고 "언제 이 도구를 쓸지" 판단합니다.

1. retriever를 도구로 변환

지금까지 retriever는 우리가 직접 retriever.invoke(질문)으로 불렀습니다. 이걸 LLM이 부를 수 있는 도구로 바꿉니다.

from langchain_core.tools.retriever import create_retriever_tool

policy_tool = create_retriever_tool(
    retriever,                          # 변환할 retriever
    name="company_policy_search",       # 도구 이름
    description="승승장구몰의 환불/교환/멤버십/직원 규정 등 사내 정책 문서를 검색한다. "
                "정책·규정·등급·반품 절차 관련 질문에 사용하라.",   # 언제 쓸지!
)

create_retriever_tool은 세 가지를 받습니다.

  • retriever: 13~16강에서 만든 그 검색 객체
  • name: 도구 이름(company_policy_search)
  • description: 이 도구가 무엇을, 언제 쓰는지

이제 policy_tool은 5~6강의 get_stock 같은 평범한 도구처럼, 에이전트에 연결할 수 있습니다.

2. description이 라우팅 규칙이다

6강에서 "독스트링 = 도구 성능"이라고 배웠습니다. retriever 도구도 똑같습니다. description이 곧 "언제 이 도구를 쓸지"를 결정하는 라우팅 규칙입니다.

description="...정책·규정·등급·반품 절차 관련 질문에 사용하라."
# 에이전트가 이 설명을 읽고 "정책 질문엔 이 도구"라고 판단한다.

에이전트는 질문이 오면 이 description을 보고 "이 질문이 이 도구를 써야 하는 상황인가?"를 판단합니다.

  • "환불 규정?" → description의 "정책·반품"과 매칭 → 도구 사용 ✓
  • "안녕하세요" → description과 무관 → 도구 사용 안 함 ✗

그래서 description을 명확하고 구체적으로 써야 합니다. 모호하면 엉뚱한 판단을 하죠(06번에서 실험).

3. 에이전트에 연결

만든 도구를 create_agent에 연결합니다(8강부터 계속 본 패턴).

from langchain.agents import create_agent
from common import get_chat

llm = get_chat(temperature=0)
agent = create_agent(
    llm,
    tools=[policy_tool],   # 검색 도구를 쥔 에이전트
    system_prompt="너는 승승장구몰의 친절한 상담원이다. 회사 규정은 반드시 도구로 검색해 답하라.",
)

이제 에이전트는 ReAct 루프(생각→행동→관찰)를 돌며, 필요하면 company_policy_search를 호출해 근거를 얻고 답합니다. 9강에서 만든 검색 에이전트와 구조가 똑같죠 — 도구가 "웹 검색" 대신 "사내 문서 검색"일 뿐입니다.

4. 전체 구조

질문 이 Knowledge Agent(create_agent)로 들어가면, description을 보고 판단합니다.

  • 정책 질문? → policy_tool → retriever 검색 → 청크
  • 일상 질문? → 바로 답

→ 근거로 답변 생성.

16강의 RAG 검색이 에이전트의 도구 하나로 들어갔습니다. 에이전트가 그 도구를 "언제 쓸지" 스스로 정하죠.

5. 16강 QA 체인과의 차이

코드로 비교하면 차이가 명확합니다.

# 16강 QA 체인 — 항상 검색
def answer(q):
    docs = retriever.invoke(q)         # 무조건 검색
    return generate(docs, q)

# 17강 Knowledge Agent — 필요할 때 검색
tool = create_retriever_tool(retriever, name=..., description=...)
agent = create_agent(llm, tools=[tool], ...)
agent.invoke(...)                       # 에이전트가 검색 여부 판단

16강은 코드가 무조건 검색하고, 17강은 에이전트가 판단합니다. 같은 retriever를 쓰지만, 호출 방식이 다른 거죠. 16강의 RAG 인프라를 그대로 재사용하면서 "판단" 능력을 더한 겁니다.

핵심 정리

  • create_retriever_tool(retriever, name, description) → retriever를 검색 도구로.
  • description이 라우팅 규칙 — 에이전트가 "언제 쓸지" 판단하는 근거.
  • description을 명확·구체적으로 써야 정확히 판단(6강 독스트링 원칙).
  • create_agent(llm, tools=[검색도구])로 연결.
  • 16강 RAG 인프라를 재사용하며 "판단" 능력을 더한 것.
