무한루프와 반복호출 방지

한 줄 요약

ReAct 루프는 모델이 같은 도구를 같은 인자로 끝없이 다시 부르며 토큰·비용을 태우는 사고가 날 수 있습니다. max_steps(횟수 상한)에 더해, (도구명+인자)를 기록해 중복 호출을 감지하면 "절대 무한루프에 빠지지 않는" 루프가 됩니다.

1. 어떤 사고가 나는가

max_steps만으로는 부족할 때가 있습니다. 모델이 진전 없이 같은 행동을 반복하는 경우입니다.

STEP 1: get_stock('스마트워치') → "재고 3개"
STEP 2: get_stock('스마트워치') → "재고 3개"   ← 또 같은 호출!
STEP 3: get_stock('스마트워치') → "재고 3개"   ← 또!
... max_steps까지 같은 짓 반복

이러면 max_steps=6이라도 6번을 다 채우며 쓸데없이 토큰을 6배 씁니다. 모델이 어떤 이유로 "제자리를 도는" 거죠. 이건 진전이 없으니 빨리 끊어야 합니다.

비유: 길을 잃은 사람이 같은 골목을 빙빙 도는 것과 같습니다. "아까 왔던 길이네?"를 알아채면 멈추고 다른 방법을 찾아야지, 계속 돌면 안 됩니다.

2. 두 겹의 안전장치

그래서 안전장치를 두 겹으로 둡니다.

  1. max_steps: 전체 반복 횟수 상한 (아무리 꼬여도 여기서 멈춤) — 03번에서 배움.
  2. 중복 호출 감지: (도구명 + 인자)를 기록해, 같은 호출이 또 나오면 강제 종료.

2번이 새로운 장치입니다. "같은 질문을 같은 도구에 또 던진다 = 진전이 없다"는 신호로 보고 끊습니다.

3. 중복 호출 감지 구현

(실습 파일: code/ch07_agent_loop_ex01.py)

# 실행: python code/ch07_agent_loop.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_openai_client, OPENAI_MODEL, DATA
import pandas as pd
import json

client = get_openai_client()
inv = pd.read_csv(DATA / "inventory.csv")

def get_stock(product_name: str) -> str:
    """상품명(일부만 입력해도 됨)을 받아 현재 재고 수량을 반환한다."""
    row = inv[inv["product_name"].str.contains(product_name, na=False)]
    if row.empty:
        return f"'{product_name}' 재고 정보 없음"
    r = row.iloc[0]
    return f"{r['product_name']} 현재 재고 {int(r['stock'])}개"

def get_reorder_level(product_name: str) -> str:
    """상품명을 받아 재주문 기준 수량(reorder_level)을 반환한다. 재고가 이 값 이하이면 재주문이 필요하다."""
    row = inv[inv["product_name"].str.contains(product_name, na=False)]
    if row.empty:
        return f"'{product_name}' 재주문 기준 정보 없음"
    r = row.iloc[0]
    return f"{r['product_name']} 재주문 기준 {int(r['reorder_level'])}개"

TOOLS = {

    "get_reorder_level": get_reorder_level,

def run_agent(question: str, max_steps: int = 6):
    """질문을 받아 도구를 반복 호출하며 목표를 끝낼 때까지 도는 ReAct 루프."""
    messages = [
        {
            "role": "system",
            "content": (
                "너는 승승장구몰 재고 관리 에이전트다. 도구로 재고와 재주문 기준을 확인하고, "
                "재고가 재주문 기준 이하이면 재주문을 권유하라. 한국어로 답하라."
            ),
        },
        {"role": "user", "content": question},
    ]

    # 이미 실행한 (도구명, 인자) 조합을 기억하는 집합 — 중복 호출 탐지용
    seen_calls = set()

    for step in range(1, max_steps + 1):
        resp = client.chat.completions.create(
            model=OPENAI_MODEL,
            messages=messages,
            tools=TOOL_SCHEMAS,
            temperature=0,
        )
        msg = resp.choices[0].message

        if not msg.tool_calls:
            return msg.content              # 정상 종료

        messages.append(msg)

        for tc in msg.tool_calls:
            func_name = tc.function.name
            args = json.loads(tc.function.arguments)

            # 호출 서명 만들기: args를 정렬된 튜플로 → dict 순서와 무관하게 같은 호출을 같은 키로
            signature = (func_name, tuple(sorted(args.items())))

            if signature in seen_calls:
                # 같은 도구를 같은 인자로 또 부름 → 진전 없는 반복 → 강제 종료
                print("  [경고] 동일한 도구·인자 반복 호출 감지 → 무한루프 방지 강제 종료")
                return None
            seen_calls.add(signature)        # 처음 보는 호출이면 기록

            result = TOOLS[func_name](**args)
            messages.append({
                "role": "tool",
                "tool_call_id": tc.id,
                "name": func_name,
                "content": json.dumps({"result": result}),
            })

    print("[종료] 최대 스텝 도달 — 안전장치 작동")  # 종료 ②: max_steps 초과
    return None

answer = run_agent("이어버드 재고 확인하고 재주문 필요한지 알려줘.")
print(answer)

4. '호출 서명'을 만드는 법

핵심 트릭은 호출을 하나의 비교 가능한 키(서명) 로 만드는 것입니다.

OpenAI = 모델이 인자를 JSON 문자열(tc.function.arguments) 형태로 반환 

signature = (tc.function.name, tuple(sorted(json.loads(tc.function.arguments).items())))
# (함수명, 인자를 정렬해 만든 튜플) → 같은 호출인지 비교할 지문(signature)
  • tc.function.name: 함수 이름 ("get_stock")
  • (func_name, tuple(sorted(args.items()))): 인자를 정렬된 튜플로 변환

Gemini = 모델이 파싱된 인자를 딕셔너리 형태의 객체(fc.args)로 제공

signature = (fc.name, tuple(sorted(dict(fc.args).items())))
# (함수명, 인자를 정렬해 만든 튜플) → 같은 호출인지 비교할 지문(signature)
  • fc.name: 함수 이름 ("get_stock")
  • tuple(sorted(dict(fc.args).items())): 인자를 정렬된 튜플로 변환

인자를 정렬하는 이유는, {'a': 1, 'b': 2}와 {'b': 2, 'a': 1}이 같은 호출인데 dict 순서만 다를 수 있기 때문입니다. 정렬하면 순서와 무관하게 같은 호출을 같은 키로 인식합니다. 이 서명이 set에 이미 있으면 "본 적 있는 호출" = 반복으로 판단합니다.

set을 쓰는 이유: in 검사가 매우 빠르고(평균 O(1)), 중복을 자동으로 걸러 주기 때문입니다.

5. 정상 vs 반복 케이스 비교

# 정상: 서로 다른 도구를 차례로 → 중복 없이 정상 종료
run_agent("스마트워치 재고를 확인하고, 재주문이 필요하면 알려줘.")

# 반복 유발: max_steps를 작게(2) 줘서 다 끝나기 전에 안전장치가 작동함을 시연
run_agent("스마트워치와 이어버드 재고를 모두 확인하고 각각 재주문이 필요한지 알려줘.", max_steps=2)

정상 케이스는 get_stock → get_reorder_level로 서로 다른 호출이라 중복이 안 걸리고 잘 끝납니다. 반면 작업이 큰데 max_steps가 작으면 안전장치가 먼저 작동해 끊습니다.

6. 실무에서의 의미

이 두 안전장치는 실무 에이전트의 기본 골격입니다.

  • max_steps: 비용 상한선 (절대 넘지 않음)
  • 중복 감지: 진전 없는 반복을 조기에 차단

LangChain 같은 프레임워크(8강~)는 이런 안전장치를 내부에 이미 갖추고 있습니다. 우리가 직접 만들어 보면, 프레임워크가 안에서 무슨 일을 하는지 이해하게 됩니다.

핵심 정리

  • max_steps만으로 부족 — 모델이 같은 호출을 반복하면 토큰 낭비.
  • (도구명+인자) 서명을 set에 기록해 중복 호출을 감지·차단한다.
  • 인자는 정렬된 튜플로 만들어 순서와 무관하게 같은 호출을 인식한다.
  • 두 겹(횟수 상한 + 중복 감지)이면 무한루프에 절대 안 빠진다.
  • 다음 절에서 대화 기록이 쌓이며 토큰이 느는 문제를 다룹니다.
