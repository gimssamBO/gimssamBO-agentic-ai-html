한 번 묻고 끝나지 않는 일

한 줄 요약

5·6강의 도구 호출은 한 방(one-shot) 이었습니다 — 질문 → 도구 1번 → 답. 하지만 현업의 일은 보통 여러 단계입니다. "행동 → 결과를 보고 → 다음 행동을 다시 정하는" 일을 목표가 끝날 때까지 반복하는 구조가 바로 Agent Loop입니다.

1. one-shot의 한계

지금까지 만든 도구 호출은 한 번에 끝났습니다.

ask("이어버드 재고 있어?")
# → get_stock 1번 호출 → "225개 있습니다" → 끝

질문 하나, 도구 하나, 답 하나. 깔끔하죠. 하지만 이런 질문은 어떨까요?

"스마트워치 재고 확인하고, 재고가 부족하면 재주문이 필요한지 알려줘."

이건 한 번에 못 끝납니다. 단계를 밟아야 합니다.

  1. 먼저 재고를 조회한다 (행동 1) → "재고 3개"
  2. 그 결과를 본다 (관찰) → "어, 3개밖에 없네?"
  3. 부족한지 판단하려면 재주문 기준을 확인한다 (행동 2) → "기준은 30개"
  4. 비교해 결론을 낸다 (생각) → "3개 < 30개, 재주문 필요!"

행동 1의 결과를 봐야 행동 2를 할지 정할 수 있습니다. 한 방에는 불가능하죠.

2. 그래서 '반복'이 필요하다

핵심은 "행동 → 결과를 보고 → 다음 행동을 다시 정하는" 일을 반복하는 것입니다.

질문: "스마트워치 재고 확인하고 재주문 필요한지 알려줘"

  1. 재고 조회 → 관찰: "3개" → 더 알아봐야 함
  2. 재주문 기준 조회 → 관찰: "30개" → 이제 판단 가능
  3. 판단: 3 < 30 → "재주문 필요!" → 최종 답, 종료

이 반복 구조가 Agent Loop이고, 에이전트를 진짜 에이전트로 만드는 심장입니다. 1강에서 외운 그 문장 — "LLM이 목표를 보고, 도구를 정해 실행하고, 결과를 관찰해 다음 행동을 다시 정하는 일을 목표가 끝날 때까지 반복" — 이 여기서 코드가 됩니다.

비유: 요리와 같습니다. "국 끓여"라는 목표 하나로 끝나지 않죠. 간을 보고(관찰) → 싱거우면 소금 넣고(행동) → 다시 간을 보고(관찰) → 됐으면 끝. 맛을 봐 가며 조절하는 이 반복이 Agent Loop입니다.

3. 이미 배운 것들이 모인다

놀랍게도 Agent Loop는 새로운 게 아니라 지금까지 배운 것의 조합입니다.

단계 어디서 배웠나
Thought(생각) — 다음에 뭘 할지 4강 CoT (단계적 추론)
Action(행동) — 도구 호출 5강 Function Calling
여러 도구 중 선택 6강 Tool 시스템
결정→실행→결과 전달 5강 수동 루프

7강은 이것들을 while 루프로 묶는 강의입니다. 5강의 수동 루프(결정→실행→전달)를 한 번만 하지 않고, 여러 번 반복하는 거죠.

4. 이 강에서 만들 것

재고 관리 에이전트를 만듭니다. 도구는 둘로 나눕니다.

  • get_stock(product_name): 현재 재고 조회
  • get_reorder_level(product_name): 재주문 기준 조회

도구를 일부러 둘로 나눈 이유가 있습니다. 그래야 모델이 "재고 확인 → 기준 확인 → 판단"처럼 두 도구를 차례로 부르게 되어, 다단계 루프가 자연스럽게 만들어집니다. (data/inventory.csv의 스마트워치 Fit 5는 재고 3개, 기준 30개라 재주문이 필요한 사례입니다.)

핵심 정리

  • 5·6강의 도구 호출은 한 방, 현업의 일은 여러 단계.
  • 여러 단계 = "행동 → 관찰 → 다음 행동"의 반복 = Agent Loop.
  • Agent Loop는 4강(생각) + 5강(행동) + 6강(선택)의 조합이다.
