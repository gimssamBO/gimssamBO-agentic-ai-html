ReAct 패턴 — 생각·행동·관찰

한 줄 요약

ReAct는 Reason(추론) + Act(행동) 의 합성어입니다. 매 스텝마다 모델이 생각(Thought) → 행동(Action) → 관찰(Observation) 을 거치고, 그 관찰 결과를 다음 입력으로 되돌려 반복합니다. 이 "관찰을 되돌리기"가 ReAct의 핵심입니다.

1. ReAct의 세 박자

매 스텝마다 모델은 세 가지를 거칩니다.

단계 하는 일 연관 강
Thought (생각) "지금 무엇을 해야 하나?" 4강 CoT
Action (행동) "get_stock을 '스마트워치'로 부르자" 5·6강
(우리가 도구 실행) 모델이 정한 도구를 실제로 호출 —
Observation (관찰) "재고 3개" — 도구가 돌려준 결과 —

그리고 "충분한가?" 를 판단합니다 — 아니면 다시 Thought 로 돌아가 반복하고, 충분하면 Final Answer(최종 답변) 를 내놓습니다.

  • Thought: 모델이 "다음에 뭘 할지" 추론합니다(4강 CoT의 응용).
  • Action: 어떤 도구를 어떤 인자로 부를지 정합니다(5·6강 Function Calling).
  • Observation: 우리가 도구를 실행한 결과입니다.

그리고 "충분한가?"를 판단해, 아니면 다시 Thought로 돌아가 반복합니다.

2. 핵심은 "관찰을 되돌리기"

ReAct에서 가장 중요한 건, Observation(관찰 결과)을 다음 입력으로 다시 모델에 넣는 것입니다.

  • 1스텝: 질문 → 모델 → "get_stock 호출" → 실행 → "재고 3개"
  • 2스텝: 질문 + "재고 3개"(관찰 결과를 되돌려 넣음) → 모델 → "재고가 적네, 기준도 봐야겠다" → …

2스텝에서 모델은 "재고 3개"라는 관찰 결과를 보고 다음 행동을 정합니다. 만약 이 결과를 안 넣어 주면, 모델은 "방금 뭘 봤는지" 기억하지 못해 같은 행동을 반복하거나 엉뚱한 판단을 합니다.

비유: 탐정 수사와 같습니다. 단서 하나(관찰)를 찾으면 그걸 수첩에 적고(되돌리기), 그 단서를 바탕으로 다음 수사 방향(행동)을 정합니다. 단서를 적지 않으면 같은 곳을 계속 뒤지겠죠.

3. 왜 도구를 둘로 나눴나

이 강에서는 재고 도구를 둘로 나눕니다: get_stock(재고)과 get_reorder_level(재주문 기준).

def get_stock(product_name: str) -> str:
    """상품명을 받아 현재 재고 수량을 반환한다."""
    ...

def get_reorder_level(product_name: str) -> str:
    """상품명을 받아 재주문 기준 수량을 반환한다. 재고가 이 값 이하이면 재주문이 필요하다."""
    ...

만약 두 정보를 한 도구로 묶었다면, 모델은 한 번 호출로 끝내고 루프가 안 돕니다. 일부러 나눠 모델이 "재고 확인 → (관찰) → 기준 확인 → (관찰) → 판단"의 여러 스텝을 밟게 만든 겁니다. 다단계 루프를 연습하기 위한 설계죠.

4. ReAct와 4·5·6강의 관계

ReAct는 사실 지금까지 배운 모든 걸 한 루프에 모은 것입니다.

  • Thought = 4강에서 배운 "단계적으로 생각하기"(CoT)
  • Action = 5강에서 배운 "도구 호출 결정"
  • 도구 선택 = 6강에서 배운 "여러 도구 중 고르기"
  • 반복 = 5강 수동 루프를 while로 여러 번

그래서 7강이 1부(2~7강)의 종착점입니다. 다음 절에서 이걸 실제 while 루프 코드로 만듭니다.

핵심 정리

  • ReAct = 생각(Thought) → 행동(Action) → 관찰(Observation) 의 반복.
  • 핵심은 관찰 결과를 다음 입력으로 되돌리는 것.
  • 도구를 둘로 나눠 모델이 여러 스텝을 밟게 설계했다.
  • ReAct는 4강(생각)·5강(행동)·6강(선택)의 종합이다.
  • 다음 절에서 루프의 종료 조건을 설계합니다.
