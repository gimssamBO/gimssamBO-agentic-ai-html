정리 & 체크리스트

7강에서 배운 것

7강에서는 에이전트의 심장 — Agent Loop를 직접 만들었습니다.

  • ReAct 패턴: 생각(Thought) → 행동(Action) → 관찰(Observation)의 반복.
  • 핵심 원리: 관찰 결과를 history에 누적해 다음 입력으로 되돌린다.
  • 종료 조건: 모델이 도구를 안 부름(정상) + max_steps(안전장치).
  • 무한루프 방지: (도구명+인자) 서명을 set에 기록해 반복 호출 차단.
  • 토큰 관리: history가 쌓이면 토큰↑ → 트리밍으로 잘라낸다(첫 질문은 보존).

한눈에 보는 핵심 코드

OpenAI

def run_agent(question, max_steps=6):
    history = [
        {"role": "system", "content": "너는 재고 관리 에이전트다 ..."},
        {"role": "user", "content": question},
    ]
    seen = set()                                     # 반복 방지

    for step in range(1, max_steps + 1):
        resp = client.chat.completions.create(
            model=OPENAI_MODEL,
            messages=history,
            tools=TOOL_SCHEMAS,
            temperature=0,
        )
        msg = resp.choices[0].message
        if not msg.tool_calls:                       # 종료①: 최종 답
            return msg.content
        history.append(msg)
        for tc in msg.tool_calls:
            func_name = tc.function.name
            args = json.loads(tc.function.arguments)
            sig = (func_name, tuple(sorted(args.items())))
            if sig in seen:                          # 반복 호출 차단
                return None
            seen.add(sig)
            result = TOOLS[func_name](**args)        # 우리가 실행 (Observation)
            history.append({
                "role": "tool",
                "tool_call_id": tc.id,
                "name": func_name,
                "content": json.dumps({"result": result}),
            })
    return None                                      # 종료②: max_steps 초과                                      # 종료②: max_steps 초과

Gemini

def run_agent(question, max_steps=6):
    config = types.GenerateContentConfig(
        tools=list(TOOLS.values()),
        automatic_function_calling=types.AutomaticFunctionCallingConfig(disable=True),
        system_instruction="너는 재고 관리 에이전트다 ...", temperature=0)
    history = [types.Content(role="user", parts=[types.Part(text=question)])]
    seen = set()                                     # 반복 방지

    for step in range(1, max_steps + 1):
        resp = client.models.generate_content(model=GEMINI_MODEL, contents=history, config=config)
        if not resp.function_calls:                  # 종료①: 최종 답
            return resp.text
        history.append(resp.candidates[0].content)
        for fc in resp.function_calls:
            sig = (fc.name, tuple(sorted(dict(fc.args).items())))
            if sig in seen:                          # 반복 호출 차단
                return None
            seen.add(sig)
            result = TOOLS[fc.name](**dict(fc.args)) # 우리가 실행 (Observation)
            history.append(types.Content(role="user", parts=[
                types.Part.from_function_response(name=fc.name, response={"result": result})]))
    return None                                      # 종료②: max_steps 초과

체크리스트

  • [ ] ReAct(생각→행동→관찰 반복) 구조를 그림으로 설명할 수 있다.
  • [ ] 관찰 결과를 from_function_response로 되돌려야 한다는 것을 이해했다.
  • [ ] for 루프로 미니 에이전트를 직접 구현했다.
  • [ ] 종료 조건(최종 답·max_steps)을 두는 이유를 안다.
  • [ ] 반복 호출 감지와 history 트리밍으로 비용 사고를 막을 수 있다.

한 줄 핵심

에이전트 = 생각·행동·관찰을 반복하는 루프. 관찰을 되돌려 다음 행동을 정하고, max_steps·반복감지·트리밍으로 안전하고 싸게 돌린다.

1부를 마치며

여기까지가 1부(2~7강) 입니다. raw SDK(google-genai)로 LLM 호출부터 도구·루프까지 에이전트의 원리를 손으로 만들어 봤습니다. 이제 그 원리를 알았으니, 8강부터는 LangChain·LangGraph 같은 프레임워크로 같은 일을 더 적은 코드로 합니다. 원리를 알고 프레임워크를 쓰면, 프레임워크가 안에서 무슨 일을 하는지 훤히 보입니다.

다음 강 예고

8강에서는 Planning Agent를 만듭니다. ReAct가 "한 스텝씩 즉흥적으로" 움직였다면, Planning은 "먼저 전체 계획을 세우고 실행"하는 방식입니다. 그리고 여기서 LangChain 프레임워크와 구조화 출력(Pydantic) 을 처음 도입합니다.
