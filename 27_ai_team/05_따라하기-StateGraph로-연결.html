따라하기 — StateGraph로 연결

목표

04번에서 만든 세 노드를 StateGraph로 등록·연결해 실행 가능한 팀(그래프)으로 컴파일하고, stream으로 진행 상황을 보며 최종 리포트를 얻습니다.

1. 그래프 조립

세 노드를 등록하고 엣지로 순서를 잇습니다.

def build_team():
    """세 에이전트를 노드로 등록하고 순서대로 엣지를 이어 팀(그래프)을 컴파일한다."""
    g = StateGraph(TeamState)              # State 모양으로 그래프 시작
    g.add_node("researcher", researcher)   # 노드 = 에이전트 등록
    g.add_node("analyst", analyst)
    g.add_node("writer", writer)

    g.add_edge(START, "researcher")     # 시작 → 리서처
    g.add_edge("researcher", "analyst") # 리서처 → 분석가
    g.add_edge("analyst", "writer")     # 분석가 → 작성자
    g.add_edge("writer", END)           # 작성자 → 끝
    return g.compile()                  # 실행 가능한 그래프로 컴파일

START → researcher → analyst → writer → END

흐름이 이 함수 한 곳에 그림처럼 선언됐습니다. 단계를 추가하거나 순서를 바꾸려면 여기 엣지만 고치면 되죠.

  • add_node("이름", 함수) — 노드 등록. 첫 인자는 그래프 안에서 부를 이름.
  • add_edge(A, B) — "A 다음엔 B" 라는 연결.
  • START/END — 그래프의 진입·종료 지점(LangGraph 내장 상수).
  • g.compile() — 그래프를 실행 가능한 객체로 만듦.

2. 실행 — stream으로 진행 보기

def main():
    team = build_team()
    # 초기 상태: raw 에 원천 텍스트를 넣고, 나머지 칸은 빈 문자열로 시작
    initial = {"raw": load_competitor_text(), "analysis": "", "report": ""}

    print("AI 팀 가동: Researcher → Analyst → Writer\n")
    final = initial
    for state in team.stream(initial, stream_mode="values"):
        final = state                  # 매번 최신 누적 상태를 잡아둠(마지막이 최종 결과)
        done = [k for k in ("analysis", "report") if state.get(k)]
        print(f"  [진행] 누적 상태: {', '.join(done) if done else '시작'}")

    print("\n" + "=" * 60)
    print(final["report"])


if __name__ == "__main__":
    main()

초기 상태가 중요합니다. raw에 원천 텍스트를 넣고, 아직 안 채워진 analysis·report는 빈 문자열로 시작합니다. 그래프가 돌면서 빈 칸들이 차례로 채워집니다.

3. stream_mode="values" — 진행과 결과를 한 번에

for state in team.stream(initial, stream_mode="values"):
    final = state

stream(stream_mode="values")는 매 노드 실행 후 누적된 전체 상태를 하나씩 내보냅니다.

researcher 끝 → {raw: 정리본, analysis: "",    report: ""}
analyst 끝    → {raw: 정리본, analysis: 분석,   report: ""}
writer 끝     → {raw: 정리본, analysis: 분석,   report: 리포트}   ← 마지막 = 최종

final = state로 매번 최신 상태를 잡아두면, 루프가 끝났을 때 final에 최종 결과가 들어 있습니다.

⚠️ 왜 stream을 한 번만 쓰나 — 진행 상황은 stream으로 보고 결과는 invoke로 또 받으면, 파이프라인이 두 번 실행되어 LLM 호출 비용이 그대로 2배가 됩니다. 그래서 final 변수에 마지막 상태를 잡아두는 방식으로 딱 한 번만 실행합니다. (실무 비용 감각 — 2강 토큰·비용.)

5. 단계를 바꿔보기 — 그래프의 장점

만약 Analyst 앞에 'Critic(비평가)' 노드를 넣고 싶다면?

g.add_node("critic", critic)
g.add_edge("researcher", "critic")   # researcher → critic
g.add_edge("critic", "analyst")      # critic → analyst (기존 researcher→analyst 대체)

그래프(엣지)만 수정하면 됩니다. 노드 함수들은 그대로죠. 흐름이 한 곳에 선언돼 있어 확장이 명확합니다. 06번에서는 여기에 조건부 분기(검수 후 되돌리기)를 더해, "왜 그래프인가"를 제대로 체감합니다.

핵심 정리

  • build_team(): add_node로 노드 등록 → add_edge로 순서 연결 → compile().
  • 초기 상태는 raw에 원천 텍스트, 나머지 칸은 빈 문자열로 시작.
  • stream(stream_mode="values"): 매 노드 후 누적 상태를 내보냄 → final에 잡아두면 최종 결과.
  • stream은 한 번만 — invoke를 또 부르면 파이프라인이 2번 돌아 비용 2배.
  • 단계 추가·순서 변경은 그래프(엣지)만 고치면 됨.
  • 다음 절에서 조건부 분기로 품질 재검토 루프를 더합니다.
