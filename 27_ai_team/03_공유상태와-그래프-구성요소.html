공유 상태(State)와 그래프 구성요소

한 줄 요약

StateGraph의 핵심은 공유 상태(State) 입니다. 모든 노드가 하나의 서류철(State) 을 돌려 보며 자기 칸을 채웁니다. State는 TypedDict로 "어떤 칸이 있는지"를 미리 정의하고, 노드는 바꿀 칸만 dict로 반환하면 LangGraph가 알아서 병합합니다.

1. 공유 상태 = 팀의 서류철

세 역할이 데이터를 주고받는 방법은 하나의 공유 문서(State) 입니다.

from typing import TypedDict

class TeamState(TypedDict):
    """팀이 공유하는 상태. 각 노드가 자기 칸을 채워 다음 노드로 넘긴다."""
    raw: str        # Researcher 산출물(정리된 사실)
    analysis: str   # Analyst 산출물(강약점 분석)
    report: str     # Writer 산출물(최종 리포트)

TeamState(서류철)는 세 칸으로 구성되고, 각 노드가 자기 칸을 채웁니다.

칸 내용 채우는 노드
raw "…" Researcher
analysis "…" Analyst
report "…" Writer

각 노드는 이 서류철을 받아 자기 칸만 채우고 다음 노드로 넘깁니다.

2. 왜 TypedDict인가

TypedDict는 딕셔너리의 "모양(어떤 키에 어떤 타입)" 을 미리 정의합니다.

# TypedDict 없이 그냥 dict 를 쓰면?
state = {"raw": "...", "analiss": "..."}   # 오타(analiss)를 못 잡음 → 런타임에 터짐

# TypedDict 로 정의하면 — 키·타입이 '계약'으로 고정
class TeamState(TypedDict):
    raw: str
    analysis: str    # 편집기가 오타·타입을 잡아줌
    report: str

노드 간에 주고받는 데이터의 계약(contract) 을 명확히 해, "어떤 칸이 오가는지"를 코드로 못박습니다. 8강의 구조화 출력(Pydantic)과 같은 정신 — 형식을 강제해 실수를 줄인다 입니다.

백엔드 개발자에게 State는 요청 컨텍스트나 DTO(Data Transfer Object) 와 같습니다.

3. 노드는 "바꿀 칸만" 반환한다

가장 중요한 규칙입니다. 노드 함수는 state 전체를 다시 만들지 않고, 자기가 바꿀 칸만 dict로 반환합니다.

def analyst(state: TeamState) -> dict:
    out = llm.invoke([...]).content
    return {"analysis": out}      # analysis 칸만 반환 → LangGraph가 기존 state에 병합

들어온 state:  {raw: "사실...", analysis: "",     report: ""}
analyst 반환:  {analysis: "분석..."}                       ← 이 칸만
병합된 state:  {raw: "사실...", analysis: "분석...", report: ""}

raw나 report를 건드리지 않아도 됩니다. 반환한 칸만 갱신되고 나머지는 그대로 유지되죠. 덕분에 노드는 자기 일에만 집중합니다.

4. 그래프의 4가지 구성요소

StateGraph는 네 가지로 이뤄집니다.

구성요소 역할 비유(백엔드)
State (TypedDict) 단계 간 주고받는 데이터 묶음 요청 컨텍스트 / DTO
노드(node) state를 받아 일부를 갱신하는 함수 핸들러 / 미들웨어
엣지(edge) 다음에 실행할 노드 지정 라우팅 규칙
START / END 그래프의 시작 / 끝 지점 진입점 / 종료

START →(edge) [node:researcher] →(edge) [node:analyst] →(edge) [node:writer] →(edge) END

각 노드는 실행되며 state의 한 칸을 갱신합니다 — researcher는 raw, analyst는 analysis, writer는 report.

  • 노드 = 일하는 사람(에이전트 함수).
  • 엣지 = "이 노드 다음엔 저 노드" 라는 연결선.
  • START/END = 어디서 시작해 어디서 끝나는지.

이 네 가지만 조합하면, 일직선 파이프라인부터 분기·루프가 있는 복잡한 워크플로우까지 모두 선언할 수 있습니다.

5. 전체 그림 미리보기

다음 절들에서 만들 코드의 뼈대입니다.

g = StateGraph(TeamState)          # ① State 모양으로 그래프 시작
g.add_node("researcher", researcher)   # ② 노드 등록
g.add_node("analyst", analyst)
g.add_node("writer", writer)
g.add_edge(START, "researcher")    # ③ 엣지로 흐름 연결
g.add_edge("researcher", "analyst")
g.add_edge("analyst", "writer")
g.add_edge("writer", END)
team = g.compile()                 # ④ 실행 가능한 그래프로 컴파일

네 단계: State 정의 → 노드 등록 → 엣지 연결 → 컴파일. 04번에서 노드(역할 함수)를, 05번에서 엣지 연결과 실행을 다룹니다.

핵심 정리

  • 노드들은 하나의 공유 State(서류철) 를 돌려 보며 자기 칸을 채운다.
  • TypedDict 로 State의 키·타입을 미리 정의 → 노드 간 데이터 계약을 명확히.
  • 노드는 바꿀 칸만 dict로 반환 → LangGraph가 기존 State에 병합(전체 재생성 불필요).
  • 그래프 4요소: State · 노드 · 엣지 · START/END.
