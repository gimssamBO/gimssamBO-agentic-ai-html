정리 & 체크리스트

이번 강에서 배운 것

27강은 여러 에이전트를 LangGraph StateGraph로 잇는 AI 팀 협업을 다뤘습니다.

  • 왜 그래프인가 (01번) — for/if로 흐름을 제어하면 갈림길이 늘수록 스파게티가 됩니다. StateGraph는 흐름을 노드·엣지로 선언해 한눈에 보이게 합니다. 일직선이면 for, 갈림길이면 StateGraph.
  • 파이프라인 (02번) — Researcher(사실) → Analyst(분석) → Writer(보고서) 직렬 협업. 각 역할은 앞 단계 산출물만 받습니다(느슨한 결합).
  • 공유 상태 (03번) — TypedDict로 State의 칸을 정의하고, 노드는 바꿀 칸만 dict로 반환하면 LangGraph가 병합합니다. 그래프 4요소: State·노드·엣지·START/END.
  • 노드 정의 (04번) — 세 역할 모두 "앞 칸 꺼내기 → llm.invoke → 자기 칸 반환" 패턴. SystemMessage로 역할 고정.
  • 그래프 연결 (05번) — add_node → add_edge → compile. stream(stream_mode="values") 한 번으로 진행과 결과를 함께(invoke 또 부르면 비용 2배).
  • 조건부 분기 (06번) — add_conditional_edges로 검수 후 갈림길(부실→재조사 루프 / 충분→진행). retries 카운터 + MAX_RETRIES로 무한루프 방지. 여기서 그래프의 진가가 드러남.
  • 중간 산출물 저장 (07번) — 저장 래퍼 노드로 각 단계 결과를 reports/에 파일로 남겨 디버깅·재현·감사에 활용.

핵심 코드 한눈에

# 1) 공유 상태
class TeamState(TypedDict):
    raw: str; analysis: str; report: str

# 2) 노드 = 앞 칸 꺼내 → invoke → 자기 칸 반환
def analyst(state) -> dict:
    out = llm.invoke([SystemMessage("너는 분석가다..."),
                      HumanMessage(f"[사실]\n{state['raw']}")]).content
    return {"analysis": out}

# 3) 그래프 = 노드 등록 + 엣지 연결 + 컴파일
g = StateGraph(TeamState)
g.add_node("researcher", researcher); g.add_node("analyst", analyst); g.add_node("writer", writer)
g.add_edge(START, "researcher"); g.add_edge("researcher", "analyst")
g.add_edge("analyst", "writer"); g.add_edge("writer", END)
team = g.compile()

# 4) 조건부 분기 (06번)
g.add_conditional_edges("check", route_after_check, {"redo": "redo", "ok": "writer"})

# 5) 실행 — stream 한 번
final = initial
for state in team.stream(initial, stream_mode="values"):
    final = state

체크리스트

  • [ ] for 루프 대신 StateGraph를 쓰는 이유(흐름 선언·갈림길)를 설명할 수 있다.
  • [ ] Researcher/Analyst/Writer가 앞 단계 산출물만 받는 구조를 안다.
  • [ ] TypedDict State에서 노드가 바꿀 칸만 반환한다는 규칙을 안다.
  • [ ] add_node·add_edge·compile로 파이프라인을 조립할 수 있다.
  • [ ] stream을 한 번만 써야 비용이 2배 안 된다는 걸 안다.
  • [ ] add_conditional_edges로 분기·루프를 만들고 무한루프를 막을 수 있다.

한 줄 핵심

"흐름이 일직선이면 for 루프, 갈림길이 생기면 StateGraph." — 노드(작업)와 엣지(연결)로 협업을 선언하면, 분기·반복도 한눈에 보인다.

27강까지로 개별 기술(도구·RAG·메모리·멀티에이전트·워크플로우)을 다 갖췄습니다. 28강부터는 이걸 실제 제품으로 묶는 설계로 넘어갑니다. "바로 코딩"이 왜 망하는지, 요구사항을 어떻게 기능으로 분해하는지, RAG·멀티에이전트를 언제 도입할지 트레이드오프로 판단하는 법을 배웁니다. 즉, "만들 줄 안다"에서 "무엇을 어떻게 만들지 정한다" 로 한 단계 올라섭니다.
