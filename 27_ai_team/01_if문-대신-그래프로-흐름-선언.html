if문 대신 그래프로 흐름을 선언한다

한 줄 요약

26강에서는 파이썬 for 루프로 에이전트들의 흐름을 직접 제어했습니다. 단계가 2~3개면 괜찮지만, "결과가 나쁘면 되돌아가 재시도", "조건에 따라 단계 건너뛰기" 같은 갈림길이 생기면 if·while이 얽혀 금세 엉망이 됩니다. LangGraph의 StateGraph 는 흐름을 노드(작업)와 엣지(연결)로 선언해, 복잡한 협업도 한눈에 보이게 만듭니다.

1. 26강의 방식 — 코드로 흐름을 "제어"

26강 오케스트레이터는 이렇게 흐름을 직접 짰습니다.

# 26강 — for 루프로 흐름 제어
subtasks = plan(llm_plan, brief_text)          # 1단계
outputs = []
for t in subtasks:                             # 2단계
    outputs.append((t, work(llm_work, brief_text, t)))
report = take(outputs)                          # 3단계

흐름이 일직선(계획 → 실행 → 취합)이라 for 루프로 충분했습니다. 깔끔하죠.

2. 흐름에 "갈림길"이 생기면?

그런데 실무 요구가 이렇게 늘어난다고 해봅시다.

- "분석이 부실하면 → 다시 조사하게 되돌려라"   (되돌아가기)
- "리포트 품질이 미달이면 → Writer를 다시 돌려라"  (반복)
- "급한 건이면 → 분석 단계를 건너뛰어라"        (건너뛰기)

이걸 for/if/while로 짜기 시작하면:

# 갈림길이 늘어난 코드 (점점 엉킴)
while True:
    analysis = analyst(raw)
    if is_good(analysis):
        break
    elif retries < 2:
        raw = research_again(); retries += 1
    else:
        break
if urgent:
    report = writer(raw)        # 분석 건너뛰기
else:
    report = writer(analysis)
# ... 조건이 더 늘면? 분기가 코드 곳곳에 흩어져 스파게티가 된다

흐름이 코드 곳곳에 흩어져 전체 그림이 안 보입니다. "지금 어디서 어디로 가지?"를 코드를 다 읽어야 알 수 있죠. 단계를 하나 추가하려면 여러 군데를 고쳐야 합니다.

3. StateGraph — 흐름을 "선언"

StateGraph는 발상을 바꿉니다. "어떻게 제어할지"를 코드로 짜는 대신, "무엇이 무엇으로 이어지는지"를 그래프로 선언합니다.

# 흐름을 한 곳에 그래프로 선언
g.add_edge(START, "researcher")        # 시작 → 리서처
g.add_edge("researcher", "analyst")    # 리서처 → 분석가
g.add_edge("analyst", "writer")        # 분석가 → 작성자
g.add_edge("writer", END)              # 작성자 → 끝

START → researcher → analyst → writer → END

흐름이 한 곳에 그림처럼 모여 있습니다. 누가 봐도 "리서처 다음 분석가, 그다음 작성자"임이 보이죠. 갈림길이 필요하면 add_conditional_edges 한 줄로 "검수 → (부실)되돌리기 / (충분)진행" 을 선언합니다(06번에서 실습).

4. 비유 — 순서도를 그대로 코드로

[ for/if 방식 ]   "어떻게 갈지" 매 갈림길마다 코드로 명령
                  → 흐름이 코드에 녹아 안 보임

[ StateGraph ]    "어디서 어디로" 지도를 먼저 그림
                  → 노드(역)와 엣지(선로)가 그대로 보임

백엔드 개발자라면 상태 기계(State Machine) 나 워크플로우 엔진(DAG) 과 같다고 보면 됩니다. 흐름(라우팅)을 선언적으로 표현하는 것이죠.

5. 이번 강에서 만들 것 — AI 팀

27강에서는 진짜 "AI 팀"을 만듭니다. 세 명의 전문가가 공유 문서(State) 를 차례로 채워 갑니다.

Researcher(사실 정리) → Analyst(강약점 분석) → Writer(보고서 작성)

승승장구몰의 경쟁사 데이터(competitor_data.csv) 를 입력으로, 경쟁사 분석 리포트(마크다운) 를 자동 생성하는 팀입니다. 먼저 가장 단순한 일직선 파이프라인으로 StateGraph 사용법을 익히고(04·05번), 그다음 조건부 분기(06번)를 더해 "왜 그래프인가"를 체감합니다.

⚖️ 솔직한 안내 — 이번 일직선 예제는 사실 26강 for 루프로도 충분합니다. StateGraph의 진가는 분기·되돌아가기·반복이 생길 때 나옵니다. 그래서 이 강은 "단순한 형태로 그래프 문법을 익히고 → 분기를 더해 진가를 보는" 순서로 설계했습니다. 흐름이 일직선이면 for, 갈림길이 생기면 StateGraph — 이 한 줄을 기억하세요.

핵심 정리

  • 26강은 for/if로 흐름을 제어 — 일직선엔 충분하지만 갈림길이 늘면 스파게티가 됨.
  • StateGraph는 흐름을 노드·엣지로 선언 — 전체 그림이 한 곳에 보이고 유지보수가 쉬움.
  • 이번 강은 Researcher → Analyst → Writer AI 팀을 그래프로 만든다.
  • 흐름이 일직선이면 for, 갈림길이 생기면 StateGraph.
