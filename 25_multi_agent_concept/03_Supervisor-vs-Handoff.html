Supervisor vs Handoff

한 줄 요약

멀티에이전트의 협업 구조는 크게 둘입니다. Supervisor(감독자) 는 가운데 라우터가 질문을 알맞은 전문가에게 보내는 방식(API Gateway), Handoff(인계) 는 에이전트끼리 직접 넘기는 방식입니다. 이번 강은 가장 흔하고 이해하기 쉬운 Supervisor 라우팅을 구현합니다.

1. Supervisor(감독자) 패턴 — 가운데 라우터

사용자 질문 → [Supervisor] "이건 누구 일?"(라우터)이 알맞은 전문가에게 위임합니다.

  • → [추천 에이전트] (+추천 도구)
  • → [정책 에이전트] (+RAG 도구)
  • → [주문 에이전트] (+조회 도구)

→ 위임받은 전문가가 최종 답변.

  • Supervisor가 질문을 보고 어느 전문 에이전트에게 보낼지 결정합니다.
  • 백엔드의 API Gateway / 리버스 프록시와 똑같은 역할이죠.
  • 라우터는 (a) 규칙(키워드) 또는 (b) LLM 분류로 구현합니다(05·06번).

장점: 흐름이 중앙에서 통제돼 추적·관리가 쉽습니다. "이 질문이 어디로 갔는지" Supervisor 한 곳만 보면 알죠.

2. Handoff(인계) 패턴 — 에이전트끼리 넘김

  1. 사용자 질문 → [추천 에이전트]: "어, 이건 환불 질문이네. 정책팀에 넘길게"
  2. 인계 → [정책 에이전트] 가 답변
  • 한 에이전트가 자기 일이 아니라고 판단하면 다른 에이전트에게 직접 인계합니다.
  • 중앙 라우터 없이 동작합니다.
  • 26·27강의 순차 파이프라인도 일종의 "정해진 handoff"입니다.

단점: 중앙 통제가 없어 흐름 추적이 어려울 수 있습니다. "A가 B에게, B가 다시 C에게..." 넘기다 보면 어디서 무슨 일이 있었는지 따라가기 복잡해지죠.

3. 둘의 비교

Supervisor Handoff
구조 중앙 라우터가 위임 에이전트끼리 직접 인계
비유 API Gateway 서비스 간 호출
흐름 추적 쉬움(중앙 집중) 어려움(분산)
유연성 라우터가 병목/단일 통제 자유롭지만 통제 어려움
적합 명확한 역할 구분 동적·연쇄적 협업

운영에서는 Supervisor가 흔합니다. 흐름이 명확하고 디버깅이 쉬우니까요. Handoff는 더 자유롭지만, 통제가 어려워 신중히 써야 합니다.

4. 에이전트 간 통신 방식 4가지

협업 구조를 더 넓게 보면, 에이전트들이 소통하는 방식은 네 가지입니다.

방식 설명 비유(백엔드)
순차 파이프라인 A→B→C 정해진 순서로 결과 전달 배치 파이프라인
Supervisor 라우팅 라우터가 1명을 골라 위임 API Gateway
Handoff 에이전트가 서로 넘김 서비스 간 호출
상태 공유 그래프 공유 State로 협업 공유 DB/큐 
- 순차 파이프라인 → 26강(Planner/Worker), 27강(AI팀)
- Supervisor 라우팅 → 이번 25강
- 상태 공유 그래프 → 27강 (LangGraph StateGraph)

각 강에서 하나씩 다룹니다. 25강은 그 출발점인 Supervisor죠.

5. 무엇을 주고받는가

협업의 핵심은 에이전트 사이에 무엇을 전달하느냐입니다. 보통 세 가지를 주고받죠.

1. 사용자 질문        — 원래 요청 그대로
2. 직전 에이전트의 산출물 — 파이프라인에서 앞 단계 결과
3. 공유 상태(State)    — 모두가 함께 읽고 쓰는 데이터 (27강)

이번 25강 Supervisor는 주로 (1) 사용자 질문을 전달합니다. Supervisor가 질문을 받아, 그대로 알맞은 에이전트에게 넘기죠. 27강에서는 (3) 공유 State를 LangGraph StateGraph로 정식화해, 여러 에이전트가 하나의 상태를 함께 채우는 협업을 만듭니다.

6. 왜 Supervisor부터 배우나

이번 강이 Supervisor를 먼저 다루는 이유:

- 가장 직관적 (안내데스크 = 라우터, 이해 쉬움)
- 운영에서 가장 흔함 (대부분의 멀티에이전트가 이 형태)
- 흐름 추적이 쉬워 디버깅 친화적
- 라우팅 개념(규칙 vs LLM)을 깔끔히 배울 수 있음

Supervisor의 핵심은 라우팅입니다 — "이 질문을 누구에게 보낼까?"를 결정하는 것. 04번에서 전문 에이전트 2개를 만들고, 05번에서 이들을 잇는 Supervisor 라우터를 구현합니다. 그리고 06번에서 규칙 라우터와 LLM 라우터를 비교하죠.

핵심 정리

  • Supervisor: 중앙 라우터가 질문을 알맞은 전문가에게 위임(API Gateway).
  • Handoff: 에이전트끼리 직접 인계(중앙 통제 없음, 추적 어려움).
  • 통신 방식 4가지: 순차 파이프라인·Supervisor·Handoff·상태 공유 그래프.
  • 전달 대상: 사용자 질문·직전 산출물·공유 State(27강).
  • 운영에서는 추적 쉬운 Supervisor가 흔함 → 이번 강의 주제.
