따라하기 — Supervisor 라우터

목표

04번의 두 전문 에이전트를 잇는 Supervisor 라우터를 만듭니다. 질문을 보고 추천/정책 중 알맞은 에이전트에게 위임하죠. 라우터를 규칙(키워드) 과 LLM(의미 이해) 두 방식으로 구현합니다.

1. Supervisor의 역할

Supervisor는 "이 질문을 누구에게 보낼까?" 를 결정하는 라우터입니다.

질문 → [Supervisor: 분류] → "policy" 또는 "sales" → 해당 에이전트에 위임 → 답변

분류 방법은 두 가지입니다.

(A) 규칙 라우터 — 키워드 매칭 (빠름·공짜)
(B) LLM 라우터 — 의미 이해 (정확하지만 비용)

먼저 규칙으로 만들고, 규칙이 못 잡는 애매한 질문을 LLM으로 보완합니다.

2. (A) 규칙 기반 라우터 — 빠르고 공짜

정책 관련 키워드 목록을 만들고, 질문에 그 단어가 있으면 정책으로 보냅니다.

# supervisor: 여러 에이전트 중 '어디로 보낼지'를 결정하는 라우팅 담당.
POLICY_WORDS = ["환불", "교환", "배송", "취소", "적립", "포인트", "무료배송", "회원", "등급"]


def route_rule(question: str) -> str:
    """질문을 'policy' 또는 'sales' 로 분류한다(규칙 기반, 비용 0).

    [왜 규칙 라우터] 키워드 매칭은 LLM 호출이 없어 빠르고 공짜다.
    명확한 정책 단어가 있으면 굳이 LLM에 물어볼 필요가 없다.
    """
    return "policy" if any(w in question for w in POLICY_WORDS) else "sales"

작동 방식

"환불은 며칠 안에?" → '환불' 포함 → "policy"
"전자기기 추천해줘"  → 정책 단어 없음 → "sales" (기본값)

any(w in question for w in POLICY_WORDS) — 정책 단어 중 하나라도 있으면 True. 없으면 기본값 "sales"로 보냅니다. LLM 호출이 없어 0초·0원이죠. 명확한 키워드는 이걸로 충분합니다.

3. (B) LLM 기반 라우터 — 애매한 질문까지

키워드로 안 잡히는 질문은 LLM의 의미 이해로 분류합니다.

def route_llm(llm, question: str) -> str:
    """LLM에게 분류만 시킨다. 'policy' 또는 'sales' 한 단어만 받는다.

    [왜 LLM 라우터] '가성비 좋은 거'처럼 키워드로 안 잡히는 애매한 질문은
    LLM의 의미 이해로 분류한다(비용은 들지만 정확). 규칙→LLM 2단계 전략.
    """
    msg = (
        "다음 고객 질문을 한 단어로 분류하라. "
        "환불/배송/교환/적립 등 정책이면 'policy', 상품 추천이면 'sales'.\n"
        f"질문: {question}\n분류(policy/sales):"
    )
    ans = llm.invoke(msg).content.strip().lower()
    return "policy" if "policy" in ans else "sales"

작동 방식

"주문한 거 무를 수 있어?" → 키워드 '취소' 없지만 LLM은 의미로 이해 → "policy"
"가성비 좋은 거 없을까?"   → LLM이 추천 질문으로 이해 → "sales"

LLM이 분류만 하게 한 단어("policy"/"sales") 로 답하도록 프롬프트를 좁혔습니다. "policy" in ans로 결과를 파싱하죠. 호출 1회 비용이 들지만, 규칙이 못 잡는 애매한 질문을 정확히 분류합니다.

4. Supervisor — 분류 후 위임

두 라우터를 골라 쓰고, 분류 결과로 알맞은 에이전트에게 위임합니다.

def supervisor(llm, sales_agent, policy_agent, question: str, use_llm: bool = False) -> str:
    """질문을 분류해 적절한 전문 에이전트에 위임하고 답을 돌려준다(라우팅의 핵심)."""
    target = route_llm(llm, question) if use_llm else route_rule(question)  # 라우터 선택
    agent = policy_agent if target == "policy" else sales_agent             # 위임 대상 결정
    print(f"  [Supervisor] '{question}' → {target} 에이전트로 라우팅")
    result = agent.invoke({"messages": [{"role": "user", "content": question}]})
    return result["messages"][-1].content   # 위임받은 에이전트의 최종 답변

흐름

1. use_llm 플래그로 규칙/LLM 라우터 선택
2. 라우터가 "policy" 또는 "sales" 반환
3. 분류 결과로 위임 대상(policy_agent/sales_agent) 결정
4. 그 에이전트에게 질문을 넘겨 실행
5. 에이전트의 최종 답변 반환

use_llm=False(기본)면 규칙 라우터, True면 LLM 라우터를 씁니다. 라우팅 로그([Supervisor] ... → ...)를 찍어 어디로 갔는지 보이게 했죠.

5. 실행

def main():
    llm, sales_agent, policy_agent = build_agents()
    questions = [
        "전자기기 카테고리에서 뭐 살만한 거 추천해줘",
        "환불은 며칠 안에 신청해야 해?",
        "무료배송 기준이 어떻게 돼?",
    ]
    for q in questions:
        print("=" * 60)
        print("고객:", q)
        print("답변:", supervisor(llm, sales_agent, policy_agent, q))      # 규칙 라우터
    print("=" * 60)
    print("고객: 가성비 좋은 거 없을까?")
    print("답변:", supervisor(llm, sales_agent, policy_agent,
                            "가성비 좋은 거 없을까?", use_llm=True))         # LLM 라우터


if __name__ == "__main__":
    main()

관찰 포인트

  • 같은 질문 풀인데 서로 다른 전문 에이전트가 처리합니다.
  • 규칙 라우터는 '환불'·'무료배송' 키워드로 정확히 정책으로 보냈죠.
  • "가성비 좋은 거"는 키워드가 없어 LLM 라우터(use_llm=True)로 분류했습니다.

6. 하이브리드 전략 — 규칙 먼저, 안 잡히면 LLM

실무에서는 두 라우터를 2단계로 결합하는 게 흔합니다.

def route_hybrid(llm, question: str) -> str:
    """규칙으로 1차 거르고, 애매하면 LLM으로 2차 분류 (정확도·비용 둘 다 잡기)."""
    # 명확한 정책 키워드가 있으면 LLM 호출 없이 즉시 결정 (공짜)
    if any(w in question for w in POLICY_WORDS):
        return "policy"
    # 키워드가 없으면 애매할 수 있으니 LLM에게 (비용 발생, 정확)
    return route_llm(llm, question)

"환불 기간?"        → 규칙이 즉시 policy (LLM 호출 0)
"주문 무를 수 있어?" → 규칙 못 잡음 → LLM이 policy (LLM 호출 1)

명확한 질문은 공짜로 거르고, 애매한 질문만 LLM에 물어 비용과 정확도를 동시에 잡습니다. 06번에서 두 라우터의 정확도·비용을 실제로 측정해 이 전략의 근거를 봅니다.

핵심 정리

  • Supervisor: 질문을 분류해 알맞은 전문 에이전트에 위임하는 라우터.
  • 규칙 라우터(route_rule): 키워드 매칭, 빠름·공짜, 명확한 질문에 충분.
  • LLM 라우터(route_llm): 의미 이해, 정확하지만 비용, 애매한 질문 처리.
  • supervisor(): 라우터 선택 → 분류 → 위임 → 답변, 라우팅 로그 출력.
  • 실무는 하이브리드(규칙 먼저, 안 잡히면 LLM)로 비용·정확도 동시 확보.
