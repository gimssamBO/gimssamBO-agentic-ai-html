정리 & 체크리스트

25강에서 배운 것

25강에서는 단일 에이전트를 역할별 전문 에이전트 + Supervisor 라우터로 재구성하는 멀티에이전트 개념을 배웠습니다.

  • 단일의 한계: 프롬프트 비대·도구 과다 → 도구 선택 혼동·수정 위험.
  • 멀티에이전트: 역할별 프롬프트·도구 분리 + 흐름(라우팅) 설계.
  • Supervisor vs Handoff: 중앙 라우터(API Gateway) vs 에이전트 간 인계.
  • 역할별 에이전트: 추천(sales)·정책(policy), 각자 다른 프롬프트·도구.
  • 두 라우터: 규칙(키워드, 공짜)·LLM(의미 이해, 비용).
  • [신규] 라우터 비교: 정확도·호출 횟수 측정 → 하이브리드 2단계 전략.

한눈에 보는 핵심 코드

from langchain_core.tools import tool
from langchain.agents import create_agent

# 1) 역할별 도구·에이전트
@tool
def search_products(category: str) -> str: ...   # 추천 도구
@tool
def search_faq(keyword: str) -> str: ...         # 정책 도구

sales_agent  = create_agent(llm, tools=[search_products], system_prompt="상품 추천 전문")
policy_agent = create_agent(llm, tools=[search_faq],      system_prompt="정책/FAQ 전문")

# 2) 라우터 (규칙 / LLM)
POLICY_WORDS = ["환불", "교환", "배송", "취소", "적립", ...]
def route_rule(q):  return "policy" if any(w in q for w in POLICY_WORDS) else "sales"
def route_llm(llm, q):  return "policy" if "policy" in llm.invoke(f"분류:{q}").content.lower() else "sales"

# 3) Supervisor — 분류 후 위임
def supervisor(llm, sales, policy, q, use_llm=False):
    target = route_llm(llm, q) if use_llm else route_rule(q)
    agent = policy if target == "policy" else sales
    return agent.invoke({"messages": [{"role": "user", "content": q}]})["messages"][-1].content

체크리스트

  • [ ] 단일 에이전트의 한계(프롬프트 비대·도구 과다)를 설명할 수 있다.
  • [ ] Supervisor와 Handoff 패턴의 차이를 안다.
  • [ ] 역할별로 프롬프트·도구를 분리해 에이전트를 만들 수 있다.
  • [ ] 규칙/LLM 두 가지 라우팅을 구현하고 장단점을 안다.
  • [ ] 라우터 정확도·비용을 측정해 하이브리드 전략을 설명할 수 있다.

한 줄 핵심

멀티에이전트는 역할별로 프롬프트·도구를 나누고 라우터로 잇는 것이다. 명확한 질문은 규칙(공짜)으로, 애매한 질문만 LLM(비용)으로 분류해 정확도와 비용을 둘 다 잡는다.

다음 강 예고

26강 역할 기반 에이전트(Planner/Worker) 에서는 "무엇을 할지(Planner)와 어떻게 할지(Worker)를 나누는" 협업 구조를 배웁니다. Planner가 작업을 분해하면 Worker들이 실행하고, 오케스트레이터가 취합하죠. Worker 실패 처리와 재시도도 다룹니다.
