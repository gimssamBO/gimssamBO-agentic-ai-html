[신규] 규칙 라우터 vs LLM 라우터 비교

한 줄 요약

라우팅은 정답이 있는 분류 문제입니다. 정답 라벨을 붙인 테스트셋으로 두 라우터의 정확도와 LLM 호출 횟수(비용) 를 나란히 측정합니다. 규칙 라우터는 호출 0회(빠름·공짜)지만 애매한 질문을 놓치고, LLM 라우터는 질문당 1회(비용)지만 정확하죠. 결론은 "규칙 먼저, 안 잡히면 LLM" 2단계 전략입니다.

1. 왜 측정하나

05번에서 두 라우터를 만들었지만, "어느 게 얼마나 정확한지" 는 감으로만 알았습니다. 운영 결정을 하려면 숫자가 필요하죠.

- 규칙 라우터는 정말 빠르고 공짜인가? → LLM 호출 0회 확인
- 규칙 라우터는 얼마나 놓치나? → 정확도 측정
- LLM 라우터는 얼마나 정확한가? → 정확도 측정
- 비용은 얼마나 차이나나? → 호출 횟수 비교

라우팅은 분류 문제라, 정답 라벨을 붙이면 정확도를 객관적으로 잴 수 있습니다(3강 정확도 측정 정신).

2. 정답 라벨 테스트셋

policy/sales를 섞고, 특히 키워드로 안 잡히는 애매한 질문을 일부러 넣어 규칙 라우터의 한계를 드러냅니다.

# 실행: python "sections/25_multi_agent_concept/06_규칙라우터-vs-LLM라우터-비교.py"
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parents[2] / "code"))
from common import get_chat, DATA
from ch25_multi_agent import route_rule, route_llm, build_agents   # 두 라우터 재사용

# [핵심] 라우팅은 '정답이 있는 분류 문제' → 정답 라벨을 붙이면 정확도를 잴 수 있다.
TESTSET = [
    ("환불은 며칠 안에 신청해야 해?", "policy"),     # 키워드 '환불' → 규칙도 맞춤
    ("무료배송 기준이 어떻게 돼?", "policy"),          # '무료배송'
    ("포인트 적립은 언제 돼?", "policy"),              # '적립/포인트'
    ("교환하려면 어떻게 해?", "policy"),               # '교환'
    ("전자기기 추천 좀 해줘", "sales"),                # 명확한 추천
    ("패션의류 인기상품 뭐 있어?", "sales"),           # 명확한 추천
    ("선물용으로 좋은 거 골라줘", "sales"),             # 키워드 없음 → 규칙은 sales(기본)로 맞음
    ("가성비 좋은 거 없을까?", "sales"),               # 애매 — 규칙은 sales(기본)로 우연히 맞음
    ("주문한 거 무를 수 있어?", "policy"),             # '취소' 동의어 → 규칙이 놓치기 쉬움
    ("이거 며칠이면 받아볼 수 있어?", "policy"),       # 배송 의미지만 '배송' 단어 없음 → 규칙 한계
]

마지막 두 질문이 핵심 함정입니다.

"주문한 거 무를 수 있어?" → 의미는 '취소'(policy)지만 '취소' 단어가 없음
"이거 며칠이면 받아?"     → 의미는 '배송'(policy)지만 '배송' 단어가 없음
   → 규칙 라우터는 키워드가 없어 sales로 잘못 보냄 (오분류!)
   → LLM 라우터는 의미를 이해해 policy로 정확히 보냄

3. 평가 함수

두 라우터를 같은 질문셋에 돌려 정확도와 호출 횟수를 집계합니다.

def evaluate():
    """두 라우터를 같은 질문셋에 돌려 정확도와 LLM 호출 횟수를 집계한다."""
    llm, _, _ = build_agents()   # route_llm 에 넘길 분류용 LLM

    rule_correct = llm_correct = 0
    rule_calls = 0   # 규칙 라우터의 LLM 호출 횟수(항상 0이어야 함)
    llm_calls = 0    # LLM 라우터의 호출 횟수(질문당 1회)

    print(f"  {'질문':<26} | 정답  | 규칙   | LLM")
    print("  " + "-" * 56)
    for q, gold in TESTSET:
        r = route_rule(q)            # LLM 호출 없음 → rule_calls 증가 안 함
        l = route_llm(llm, q)        # 질문당 LLM 1회
        llm_calls += 1

        rule_ok, llm_ok = (r == gold), (l == gold)
        rule_correct += rule_ok
        llm_correct += llm_ok

        mark = lambda ok: "O" if ok else "X"
        qshort = (q[:24] + "…") if len(q) > 25 else q
        print(f"  {qshort:<26} | {gold:<6}| {r:<5}{mark(rule_ok)} | {l:<5}{mark(llm_ok)}")

    n = len(TESTSET)
    print(f"\n  규칙 라우터 : 정확도 {rule_correct}/{n} ({rule_correct/n*100:.0f}%), "
          f"LLM 호출 {rule_calls}회 (빠름·공짜)")
    print(f"  LLM  라우터 : 정확도 {llm_correct}/{n} ({llm_correct/n*100:.0f}%), "
          f"LLM 호출 {llm_calls}회 (정확하지만 비용)")


if __name__ == "__main__":
    evaluate()

핵심 측정 포인트

  • rule_calls는 항상 0 — 규칙 라우터는 LLM을 안 부릅니다(키워드 매칭만).
  • llm_calls는 질문 수만큼(여기선 10) — 매 질문마다 LLM 1회 호출.
  • 정확도는 예측 == 정답 카운트로 계산(3강).

  무료배송 기준이 어떻게 돼?       | policy| policyO | policyO
  포인트 적립은 언제 돼?          | policy| policyO | policyO
  교환하려면 어떻게 해?           | policy| policyO | policyO
  전자기기 추천 좀 해줘           | sales | sales O | sales O
  패션의류 인기상품 뭐 있어?       | sales | sales O | sales O
  선물용으로 좋은 거 골라줘        | sales | sales O | sales O
  가성비 좋은 거 없을까?          | sales | sales O | sales O

  이거 며칠이면 받아볼 수 있어?    | policy| sales X | policyO   ← 규칙 놓침!

  규칙 라우터 : 정확도 8/10 (80%), LLM 호출 0회 (빠름·공짜)
  LLM  라우터 : 정확도 10/10 (100%), LLM 호출 10회 (정확하지만 비용)

관찰 포인트

- 규칙 라우터: 80% 정확, LLM 호출 0회 → 명확한 질문은 완벽, 애매한 2개를 놓침
- LLM 라우터: 100% 정확, LLM 호출 10회 → 다 맞췄지만 매번 비용

마지막 두 질문("무를 수 있어?", "며칠이면 받아?")에서 규칙 라우터가 키워드가 없어 놓쳤습니다. LLM 라우터는 의미를 이해해 맞췄죠.

5. 결론 — 2단계 하이브리드

이 측정이 알려주는 운영 전략은 명확합니다.

규칙 라우터:  빠름·공짜  but  애매한 질문 놓침
LLM 라우터:  정확        but  매 질문 비용
        ↓ 둘의 장점만
하이브리드:  명확한 질문은 규칙(공짜)으로, 애매한 질문만 LLM으로

def route_hybrid(llm, question: str) -> str:
    if any(w in question for w in POLICY_WORDS):   # 명확한 키워드 → 공짜로 즉시
        return "policy"
    return route_llm(llm, question)                 # 애매한 것만 LLM(비용)

대부분의 질문(80%)은 규칙으로 공짜 처리하고, 나머지 애매한 20%만 LLM에 물으면:

- 정확도: ~100% (LLM이 애매한 것 처리)
- 비용: ~20% (질문 10개 중 2개만 LLM 호출)

정확도와 비용을 둘 다 잡습니다. 이게 측정 기반 의사결정의 힘이죠 — 감이 아니라 숫자로 전략을 정합니다.

6. 측정의 일반 교훈

이 비교가 주는 더 큰 교훈:

- "정확한가?"는 측정해야 안다 (감 ❌, 정답 라벨 + 정확도 ✅)
- "비용은?"도 측정해야 안다 (LLM 호출 횟수 카운트)
- 트레이드오프(정확도 vs 비용)는 숫자로 봐야 결정할 수 있다

라우터뿐 아니라 모든 AI 컴포넌트(분류·검색·추천)에 적용됩니다. "이 방식이 더 나을 것 같다"가 아니라 "측정해보니 N% 정확하고 M원 든다" 로 말하는 게 엔지니어링이죠.

핵심 정리

  • 라우팅은 정답 있는 분류 문제 → 정답 라벨로 정확도 측정 가능.
  • 규칙 라우터: 80% 정확, LLM 호출 0회(애매한 질문 놓침).
  • LLM 라우터: 100% 정확, LLM 호출 10회(매번 비용).
  • 함정 질문(키워드 없는 정책 질문)에서 규칙의 한계가 드러남.
  • 결론: 하이브리드(규칙 먼저, 안 잡히면 LLM) → 정확도·비용 동시 확보.
  • 교훈: 정확도·비용은 감이 아니라 측정으로 — 모든 AI 컴포넌트에 적용.
