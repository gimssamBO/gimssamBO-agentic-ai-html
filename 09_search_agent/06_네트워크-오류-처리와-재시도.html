네트워크 오류 처리와 재시도

한 줄 요약

웹 검색은 네트워크·호출 제한으로 일시 실패가 잦습니다. 한 번 실패했다고 포기하지 말고, 지수 백오프(1→2→4초)로 재시도하고, 끝내 실패하면 폴백 메시지를 돌려줘 프로그램이 죽지 않게 합니다.

1. 검색은 자주 실패한다

검색은 외부 서버에 의존하므로, 우리 잘못이 아니어도 실패합니다.

  • 일시적 타임아웃: 네트워크가 잠깐 느림
  • 호출 제한(rate limit): 짧은 시간에 너무 많이 요청
  • 빈 결과: 검색은 됐지만 결과가 없음

중요한 건, 이런 실패의 상당수는 잠깐 기다렸다 다시 하면 성공한다는 것입니다. 그래서 재시도가 효과적입니다.

비유: 전화가 통화 중이면, 끊고 잠깐 기다렸다 다시 거는 것과 같습니다. 한 번 통화 중이라고 포기하지 않죠. 그리고 다시 걸 때 점점 간격을 두면(바로 또 걸지 않고) 상대도 받을 여유가 생깁니다.

2. 지수 백오프 — 점점 간격을 늘리는 재시도

지수 백오프(exponential backoff) 는 재시도 간격을 점점 늘리는 기법입니다: 1초 → 2초 → 4초.

1차 시도 실패 → 1초 기다림 → 2차 시도
2차 시도 실패 → 2초 기다림 → 3차 시도
3차 시도 실패 → 4초 기다림 → (최종 실패 시 폴백)

왜 간격을 늘릴까요? 서버가 과부하라 막혔는데 바로 또 때리면 상황이 더 나빠집니다. 간격을 두면 서버가 회복할 틈을 줍니다.

3. robust_search — 견고한 검색

(실습 파일: 코드리뷰만) — 이 패턴은 29강의 robust_invoke를 검색에 적용한 것입니다.

import time
from langchain_community.tools import DuckDuckGoSearchResults

search = DuckDuckGoSearchResults()

def robust_search(message: str, max_retries: int = 3) -> str:
    """검색을 재시도 + 지수 백오프 + 폴백으로 감싼다."""
    for attempt in range(1, max_retries + 1):
        try:
            print(f"검색 시도 {attempt}/{max_retries}: {message}")
            result = search.invoke(message)
            if not result or not str(result).strip():
                raise ValueError("빈 검색 결과")          # 빈 결과도 실패로 보고 재시도
            return result                                 # 성공!
        except Exception as e:
            wait = 2 ** (attempt - 1)                     # 지수 백오프: 1, 2, 4초
            print(f"실패({attempt}회): {e} → {wait}초 후 재시도")
            time.sleep(wait)
    # 끝까지 실패 — 예외로 죽지 않고 폴백 문구를 돌려준다
    return "죄송합니다. 일시적인 네트워크 오류로 검색하지 못했습니다. 잠시 후 다시 시도해 주세요."

세 가지가 핵심입니다.

  • for attempt in range(1, max_retries+1): 최대 3번 시도
  • wait = 2 ** (attempt-1): 1, 2, 4초로 간격 증가 (time.sleep(wait))
  • 폴백: 끝까지 실패해도 예외로 죽지 않고 안내 문구 반환

4. 왜 빈 결과도 실패로 보나

if not result or not str(result).strip():
    raise ValueError("빈 검색 결과")   # 빈 결과도 재시도 대상

검색이 "성공"했지만 결과가 비어 있을 수 있습니다. 일시적 문제로 빈 결과가 올 때가 있거든요. 이걸 그냥 두면 "검색 결과 없음"으로 잘못 답할 수 있으니, 빈 결과도 실패로 간주해 재시도합니다.

5. 폴백 — 죽지 않는 게 핵심

가장 중요한 건 끝까지 실패해도 프로그램이 죽지 않는 것입니다.

# 재시도 다 실패 → 예외를 던지면? → 프로그램 중단 (나쁨)
# 재시도 다 실패 → 폴백 문구 반환 → 사용자에게 안내 (좋음)
return "죄송합니다. 일시적인 네트워크 오류로 ..."

5강의 도구 오류 처리와 같은 철학입니다 — 에이전트는 실패해도 멈추지 않고 안내해야 합니다. 콜센터 상담원이 시스템 오류로 전화를 끊으면 안 되는 것처럼요.

6. 실행 — 정상과 실패 둘 다 시연

# 정상: 재시도 래퍼로 안전하게 검색
print(search_and_summarize("무선 이어버드 인기 트렌드"))

# 강제 실패: 항상 실패하는 가짜 검색으로 백오프·폴백 확인
class _AlwaysFail:
    def invoke(self, q):
        raise ConnectionError("네트워크 연결 실패(시뮬레이션)")

search = _AlwaysFail()
print(robust_search("연결되지 않는 검색", max_retries=3))

예상 출력 (강제 실패)

검색 시도 1/3 → 실패 → 1초 후 재시도
검색 시도 2/3 → 실패 → 2초 후 재시도
검색 시도 3/3 → 실패 → 4초 후 재시도
[종료] 검색 최종 실패 — 폴백 응답 반환
죄송합니다. 일시적인 네트워크 오류로 검색하지 못했습니다. 잠시 후 다시 시도해 주세요.

지수 백오프로 1→2→4초씩 기다리며 3번 시도하고, 끝내 실패하자 폴백 문구로 우아하게 마무리합니다. 프로그램은 죽지 않았죠.

핵심 정리

  • 검색은 네트워크·호출 제한으로 일시 실패가 잦다 → 재시도가 효과적.
  • 지수 백오프(1→2→4초)로 서버에 회복할 틈을 준다.
  • 빈 결과도 실패로 간주해 재시도한다.
  • 끝까지 실패해도 폴백 문구로 프로그램이 죽지 않게 한다.
  • 이 robust_search 패턴은 29강 robust_invoke의 검색 버전이다.
