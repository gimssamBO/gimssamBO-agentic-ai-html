검색으로 보강하기

한 줄 요약

검색 에이전트는 "LLM이 검색이 필요하다고 판단 → 검색어 생성 → 웹 검색 → 결과를 읽고 요약"의 흐름으로 동작합니다. 우리는 검색어를 짜 주지 않습니다 — LLM이 스스로 검색어를 만들고 결과를 해석합니다.

1. 검색 에이전트의 동작 흐름

사용자 질문: "요즘 인기 무선 이어버드 트렌드?"

  1. ① 검색 필요 판단 — LLM: "이건 최신 정보네. 검색하자" → 검색어 생성: "2026 무선 이어버드 인기 트렌드"
  2. ② 웹 검색 — DuckDuckGo 검색 도구 → 결과(스니펫): "ANC 강화, 멀티포인트 …"
  3. ③ 관찰 후 답변 — LLM: 결과를 읽고 한국어로 요약 → "트렌드 3가지: 1) ANC 경쟁 2) 멀티포인트 3) 공간음향"

이건 7강의 ReAct 루프와 똑같은 구조입니다 — 생각(검색 필요?) → 행동(검색) → 관찰(결과) → 답변. 도구가 "검색"으로 바뀌었을 뿐이죠.

2. 핵심 — LLM이 검색어를 만든다

가장 중요한 점입니다. 우리는 "이 검색어로 검색해"라고 말하지 않습니다. LLM이 질문을 보고 스스로 적절한 검색어를 만듭니다.

# 우리가 주는 것: 질문 (자연어)
"요즘 인기 있는 무선 이어버드 트렌드를 조사해줘"

# LLM이 만드는 것: 검색어
"2026 무선 이어버드 인기 트렌드"  ← LLM이 알아서 생성!

이게 검색 에이전트의 묘미입니다. 사용자는 일상 언어로 묻고, LLM이 그걸 검색에 적합한 키워드로 변환합니다.

비유: 도서관 사서에게 "요즘 건강하게 사는 법 좀 알려줘"라고 하면, 사서가 알아서 "2026 웰니스 트렌드", "건강 라이프스타일" 같은 검색어로 자료를 찾아 주는 것과 같습니다.

3. DuckDuckGoSearchResults — 키 불필요 검색 도구

이 강에서는 DuckDuckGo 검색을 씁니다. 이유는:

  • 무료: 비용이 없습니다.
  • API 키 불필요: 별도 가입·인증이 없습니다(Google 검색 API는 키가 필요).
  • LangChain 기본 도구: @tool을 안 써도 그 자체로 도구입니다.
from langchain_community.tools import DuckDuckGoSearchResults

search = DuckDuckGoSearchResults()   # 이게 곧 LangChain 도구!
# 단독 테스트
print(search.invoke("무선 이어버드 트렌드"))
# → [snippet: ..., title: ..., link: ...] 형태의 검색 결과

4. 검색의 주의점 (미리 알기)

검색은 강력하지만 조심할 점이 있습니다. 이 강 후반(05·06번)에서 자세히 다룹니다.

  • 신뢰성: 검색 결과는 사실이 아닐 수 있습니다(광고·오래된 글·낚시). 그대로 믿으면 환각을 사실처럼 전달하게 됩니다 → 05번 재검증.
  • 네트워크 의존: 인터넷 연결이 필요하고, 호출 제한으로 일시 실패할 수 있습니다 → 06번 재시도.

즉, "검색을 붙이면 끝"이 아니라, 검색 결과를 신중히 다루는 게 진짜 실력입니다.

핵심 정리

  • 검색 에이전트 = "검색 필요 판단 → 검색어 생성 → 검색 → 요약"의 ReAct 흐름.
  • 핵심은 LLM이 스스로 검색어를 만든다는 것.
  • DuckDuckGoSearchResults는 무료·키 불필요한 LangChain 기본 도구.
  • 검색 결과는 신뢰성·네트워크 문제가 있어 신중히 다뤄야 한다(05·06번).
  • 다음 절에서 검색 도구를 에이전트에 붙입니다.
