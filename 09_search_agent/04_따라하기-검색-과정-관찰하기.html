따라하기 — 검색 과정 관찰하기

목표

stream으로 에이전트가 "검색어 생성 → 검색 → 결과 관찰 → 요약"하는 과정을 단계별로 봅니다. 그리고 네트워크 오류에 대비한 예외 처리를 적용합니다.

1. invoke vs stream

8강에서는 invoke로 최종 답만 받았습니다. stream을 쓰면 에이전트가 일하는 중간 과정을 단계별로 볼 수 있습니다.

# invoke — 최종 답만 (과정 안 보임)
result = agent.invoke({"messages": [...]})

# stream — 매 단계를 순서대로 (과정 보임)
for step in agent.stream({"messages": [...]}, stream_mode="values"):
    step["messages"][-1].pretty_print()

stream_mode="values"는 "매 단계마다 현재까지의 전체 메시지 상태를 내놓아라"는 뜻입니다. 그래서 검색 도구 호출, 검색 결과, 최종 요약이 차례로 출력됩니다.

2. 과정을 보며 실행하기

네트워크 오류에 대비해 try/except로 감쌉니다.

q = "요즘 인기 있는 무선 이어버드 트렌드를 조사해서 핵심만 3가지로 요약해줘."

try:
    for step in search_agent.stream(
        {"messages": [{"role": "user", "content": q}]}, stream_mode="values"
    ):
        step["messages"][-1].pretty_print()
except Exception as e:
    # 네트워크/검색 호출 제한 등으로 실패할 수 있어 안내 메시지로 감싼다
    print("검색 중 오류가 발생했습니다:", e)
    print("네트워크 상태를 확인하거나 잠시 후 다시 시도하세요. (ddgs 설치 여부도 확인)")

3. 출력 읽는 법

pretty_print()는 각 메시지를 보기 좋게 출력합니다.

예상 출력

================================ Human Message =================================
요즘 인기 있는 무선 이어버드 트렌드를 조사해서 핵심만 3가지로 요약해줘.

================================== Ai Message ==================================
Tool Calls:
  duckduckgo_results_json
   Args:
     query: 2026 무선 이어버드 인기 트렌드          ← LLM이 만든 검색어!

================================= Tool Message =================================
[snippet: ANC(액티브 노이즈 캔슬링) 강화, ... link: ...]   ← 검색 결과(관찰)

================================== Ai Message ==================================
무선 이어버드 트렌드 핵심 3가지:                          ← 최종 요약
1) 능동 소음 차단(ANC) 성능 경쟁 심화
2) 멀티포인트 동시 연결 등 편의 기능 보편화
3) 공간음향·저지연 게이밍 모드 확대

네 개의 메시지가 순서대로 보입니다.

  1. Human Message: 사용자 질문
  2. Ai Message (Tool Calls): LLM이 만든 검색어 — query: 2026 무선 이어버드 인기 트렌드
  3. Tool Message: 검색 도구가 돌려준 결과(스니펫)
  4. Ai Message: 결과를 읽고 만든 최종 요약

7강에서 손으로 찍던 STEP 로그를, LangChain stream이 자동으로 보여 주는 셈입니다.

4. 무엇을 관찰했나

이 출력에서 두 가지를 확인하세요.

  • LLM이 검색어를 만들었다: 우리가 "이어버드 트렌드"라고 물었는데, LLM이 "2026 무선 이어버드 인기 트렌드"라는 검색에 적합한 키워드로 변환했습니다.
  • 결과를 읽고 요약했다: 검색 스니펫(원본은 어수선함)을 읽고 깔끔한 3가지로 정리했습니다.

이게 검색 에이전트의 핵심 가치입니다 — 사용자는 일상 언어로 묻고, 에이전트가 검색·해석·요약을 다 합니다.

5. 왜 try/except가 필수인가

검색은 외부 네트워크에 의존합니다. 인터넷이 끊기거나, DuckDuckGo가 호출 제한을 걸면 실패합니다. 이때 예외를 안 잡으면 프로그램이 죽어 버립니다.

try:
    # 검색 실행
except Exception as e:
    print("검색 중 오류:", e)   # 죽지 않고 안내

이건 5강의 "도구 오류 처리"와 같은 원칙입니다. 외부에 의존하는 도구는 항상 실패에 대비해야 합니다. 06번에서 이걸 재시도까지 포함해 더 견고하게 만듭니다.

핵심 정리

  • stream(stream_mode="values")으로 검색 과정을 단계별로 본다.
  • 출력은 Human → Ai(검색어) → Tool(결과) → Ai(요약) 순서.
  • LLM이 검색어를 스스로 생성하고 결과를 요약하는 게 핵심.
  • 외부 의존 도구는 try/except로 실패에 대비(필수).
  • 다음 절에서 검색 결과의 신뢰성을 검증하는 법을 배웁니다.
