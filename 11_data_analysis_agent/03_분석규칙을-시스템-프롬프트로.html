분석 규칙을 시스템 프롬프트로

한 줄 요약

데이터 함정(02번)을 에이전트가 알아서 피하게 하려면, 분석 규칙을 시스템 프롬프트에 명시합니다. "매출 집계 시 취소/환불 제외", "이상치 처리" 같은 규칙을 미리 가르치면, 에이전트가 그 규칙을 지키는 코드를 만듭니다.

1. 규칙을 가르치는 곳 — 시스템 프롬프트

3강에서 시스템 지시(프롬프트)가 모델의 "행동 규칙"이라고 배웠습니다. 데이터 분석 규칙도 여기에 넣습니다.

SYSTEM = (
    "너는 승승장구몰의 데이터 분석가다. 계산은 반드시 run_pandas 도구로만 하라.\n"
    "규칙:\n"
    "1) 매출(amount) 집계 시 status가 '취소','환불'인 행은 제외한다.\n"
    "2) quantity=999 처럼 비정상적으로 큰 값과 음수 amount는 이상치이므로,\n"
    "   집계 전에 적절히 제외하거나 사용자에게 언급한다.\n"
    "3) 최종 답변은 한국어로 간결하게, 숫자는 천단위 콤마를 붙여 설명한다."
)

이 규칙들을 시스템 프롬프트에 넣으면, 에이전트가 매번 자동으로 지킵니다. 분석가에게 회사 규칙을 한 번 가르쳐 두면 계속 지키는 것과 같죠.

2. 규칙이 코드로 반영되는 모습

규칙을 가르치면, LLM이 만드는 pandas 식에 그 규칙이 반영됩니다.

# 규칙 없이 "카테고리별 매출" 물으면:
orders.groupby('category')['amount'].sum()
#  ↑ 취소/환불도 포함 → 매출 부풀려짐

# 규칙("취소/환불 제외")을 가르치면:
orders[~orders['status'].isin(['취소','환불'])].groupby('category')['amount'].sum()
#  ↑ 취소/환불 제외 → 정확한 매출!

우리가 매번 "취소/환불 빼고"라고 안 말해도, 시스템 프롬프트에 규칙이 있으니 LLM이 알아서 status 필터를 넣습니다.

3. 규칙 주입의 두 곳 — 시스템 프롬프트 vs 도구 docstring

사실 규칙을 가르칠 수 있는 곳이 두 군데입니다.

① 시스템 프롬프트 (에이전트의 행동 규칙)

SYSTEM = "...매출 집계 시 취소/환불 제외..."
agent = create_agent(llm, tools=[run_pandas], system_prompt=SYSTEM)

② 도구 docstring (도구 사용법·데이터 설명)

@tool
def run_pandas(expr: str) -> str:
    """...
    분석 주의사항:
      * 매출(amount) 집계는 보통 status가 '취소','환불'인 건을 제외한다.
      * amount 에 음수나 quantity=999 같은 이상치가 섞여 있을 수 있다.
    ..."""

둘 다 쓰는 게 좋습니다. 시스템 프롬프트는 "분석가로서 지킬 규칙"을, docstring은 "이 데이터/도구의 특성"을 알려 줍니다. 서로 보강하죠.

4. 규칙이 있고 없고의 차이 (A/B 비교)

규칙의 효과는 직접 비교하면 명확합니다.

# 규칙 있는 에이전트 vs 규칙 없는 에이전트
agent_with_rule = create_agent(llm, tools=[run_pandas], system_prompt=SYSTEM)
agent_no_rule = create_agent(llm, tools=[run_pandas], system_prompt="너는 분석가다.")

q = "카테고리별 총 매출은?"
# agent_with_rule → 취소/환불 제외한 정확한 매출
# agent_no_rule   → 취소/환불 포함한 부풀려진 매출 (더 큼)

규칙을 뺀 쪽은 취소/환불까지 더해 매출이 더 크게 나옵니다. 그 차이가 곧 "취소/환불 금액"이죠. (이건 09번 연습문제로 직접 측정합니다.)

5. 규칙 주입의 한계

시스템 프롬프트 규칙은 강력하지만 100% 보장은 아닙니다. LLM이 가끔 규칙을 놓칠 수 있습니다. 그래서 중요한 분석에서는:

  • 규칙을 명확하고 구체적으로 씁니다(애매하면 안 지킴).
  • 결과를 검증합니다(06번 데이터 품질 체크로 사전 점검).
  • 중요한 집계는 사람이 확인합니다.

규칙 주입은 "분석가에게 가이드라인을 주는 것"이지, "절대 안 틀리게 만드는 것"은 아닙니다.

핵심 정리

  • 데이터 분석 규칙을 시스템 프롬프트에 명시하면 에이전트가 자동으로 지킨다.
  • 규칙이 LLM이 만드는 pandas 식에 반영된다(status 필터 등).
  • 규칙은 시스템 프롬프트 + 도구 docstring 둘 다에 두면 좋다.
  • 규칙 주입은 강력하지만 100%는 아니라 검증이 필요하다.
  • 다음 절에서 분석 도구와 전처리를 실제로 만듭니다.
