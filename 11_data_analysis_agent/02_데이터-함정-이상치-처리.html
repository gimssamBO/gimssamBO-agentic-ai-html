데이터 함정 — 이상치 처리

한 줄 요약

매출 분석에는 함정이 있습니다. 취소·환불 건을 매출에 넣으면 과대 계상되고, quantity=999 같은 이상치 한 건이 평균을 망치고, 음수 금액이 합계를 왜곡합니다. 분석 전에 이 함정들을 반드시 처리해야 합니다.

1. 세 가지 데이터 함정

orders.csv를 분석할 때 조심해야 할 함정들입니다.

함정 문제 처리
status='취소'/'환불' 매출에 포함하면 과대 계상 매출 집계 시 제외
quantity=999 입력 실수 이상치 거르거나 사용자에 고지
음수 amount(환불 오류) 합계 왜곡 환불 분석 외엔 제외

하나씩 봅시다.

2. 함정 ① — 취소·환불 건

주문에는 여러 상태가 있습니다.

status 값: 배송완료 / 배송중 / 결제완료 / 취소 / 환불

"이번 달 매출"을 구할 때 취소·환불된 주문을 매출에 넣으면 안 됩니다. 고객이 취소한 주문은 실제 매출이 아니니까요. 그런데 단순히 amount를 다 더하면 취소 건까지 포함되어 매출이 부풀려집니다.

# 잘못된 매출 (취소/환불 포함 → 과대 계상)
orders['amount'].sum()

# 올바른 매출 (배송완료만)
orders[orders['status'] == '배송완료']['amount'].sum()

보통 매출로 잡을 때는 배송완료(필요시 배송중, 결제완료 포함)만 쓰고, 취소·환불은 뺍니다.

3. 함정 ② — quantity 이상치

누군가 주문 수량을 입력하다 실수로 999를 넣었다고 합시다. 이 한 건이 평균·합계를 완전히 망칩니다.

# 정상 주문: quantity 1~5개
# 이상치: quantity 999개 (입력 실수)

orders['quantity'].mean()   # 이상치 하나 때문에 평균이 확 뛴다!

비유: 반 평균 키를 구하는데, 한 명의 키가 실수로 "999cm"로 적혀 있다면? 평균이 말도 안 되게 높아집니다. 그 한 명을 빼야 진짜 평균이 나오죠.

이상치는 거르거나, 적어도 사용자에게 "이상치가 있습니다"라고 알려야 합니다.

4. 함정 ③ — 음수 금액

환불이 음수 amount로 기록되는 경우가 있습니다(환불 = 돈이 나감 = 마이너스). 이게 일반 매출 합계에 섞이면 합계가 왜곡됩니다.

# amount에 음수(환불)가 섞이면
orders['amount'].sum()   # 음수 환불이 매출을 깎아 실제와 다름

# 환불 분석이 아니라면 음수 제외
orders[orders['amount'] >= 0]['amount'].sum()

물론 "환불 분석"을 할 때는 음수가 필요합니다. 함정은 "일반 매출 분석에 음수가 섞일 때" 입니다. 분석 목적에 따라 다르게 다뤄야 하죠.

5. 왜 이게 중요한가

데이터 함정을 무시하면 틀린 보고서가 나옵니다. "이번 달 매출 1억!"이라고 보고했는데 알고 보니 취소 건이 2천만원 포함된 거라면? 잘못된 의사결정으로 이어집니다.

데이터 분석에서 "쓰레기를 넣으면 쓰레기가 나온다(Garbage In, Garbage Out)" 는 격언이 있습니다. 아무리 분석을 잘해도, 데이터가 더러우면 결과도 틀립니다. 그래서 분석 전 데이터 정제가 분석만큼 중요합니다.

6. 에이전트에게 함정을 가르치려면?

이 함정들을 에이전트가 알아서 피하게 하려면 어떻게 할까요? 두 가지 방법이 있습니다.

  1. 규칙을 가르친다: 시스템 프롬프트에 "취소/환불은 제외하라"고 명시 → 03번
  2. 미리 진단한다: 분석 전에 데이터 품질을 사람이 점검 → 06번

다음 절에서 첫 번째 방법(규칙 주입)을 배웁니다.

핵심 정리

  • 매출 분석의 세 함정: 취소/환불 포함, quantity 이상치, 음수 금액.
  • 함정을 무시하면 매출이 부풀려지거나 왜곡된다(틀린 보고서).
  • "쓰레기를 넣으면 쓰레기가 나온다" — 분석 전 데이터 정제가 필수.
  • 에이전트에게 규칙을 가르치거나(03번) 미리 진단(06번)해야 한다.
  • 다음 절에서 분석 규칙을 시스템 프롬프트로 주입합니다.
