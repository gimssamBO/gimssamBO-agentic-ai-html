분석 전 데이터 품질 체크

한 줄 요약

분석을 시작하기 전에, 데이터에 어떤 문제가 있는지 먼저 진단해야 합니다. 결측치·중복·음수 매출·이상치를 pandas로 한눈에 보는 "품질 리포트"를 만듭니다. 이건 LLM 없이 코드만으로 합니다.

1. "분석 전에 데이터를 봐라"

좋은 분석가의 첫 번째 습관은 "바로 분석하지 않고 데이터부터 살펴보는 것" 입니다. 02번에서 데이터 함정을 배웠지만, "이 데이터에 실제로 함정이 몇 개나 있는지"는 직접 봐야 압니다.

# 나쁜 습관: 데이터를 안 보고 바로 집계
orders['amount'].mean()   # 이상치가 있는지도 모르고 평균을 냄

# 좋은 습관: 먼저 데이터 품질을 진단
data_quality_report(orders)   # 결측·이상치·중복을 먼저 확인!

비유: 요리하기 전에 재료를 살펴보는 것과 같습니다. 상한 재료가 있는지, 양이 충분한지 먼저 확인하고 요리를 시작하죠. 데이터도 마찬가지입니다.

2. 품질 리포트 함수

(실습 파일: sections/11_data_analysis_agent/06_분석전-데이터-품질-체크.py) — LLM 없이 pandas만으로, 분석 전 점검할 6가지를 출력합니다.

import pandas as pd

def data_quality_report(df: pd.DataFrame) -> None:
    """주문 DataFrame을 받아 분석 전에 확인할 품질 지표를 표로 출력한다."""
    # ① 총 행수
    print("[1] 총 행수:", f"{len(df):,}행")

    # ② 컬럼별 결측치 수
    print("[2] 컬럼별 결측치 수")
    for col, cnt in df.isnull().sum().items():
        mark = "  <-- 결측 있음" if cnt > 0 else ""
        print(f"  - {col:<14}: {cnt:>5,}개{mark}")

    # ③ 중복행 수
    print("[3] 중복행 수:", f"{int(df.duplicated().sum()):,}행")

    # ④ 음수 amount 수
    neg = int((df["amount"] < 0).sum())
    print("[4] 음수 amount 행:", f"{neg:,}행  [경고] 집계 전 제외 검토")

    # ⑤ quantity 이상치
    outlier = df[df["quantity"] >= 999]
    print("[5] quantity 이상치(999 이상):", f"{len(outlier):,}행")

    # ⑥ status 값 분포
    print("[6] status 값 분포")
    for status, cnt in df["status"].value_counts(dropna=False).items():
        print(f"  - {str(status):<8}: {cnt:>6,}건 ({cnt/len(df)*100:5.1f}%)")

3. 6가지 점검 항목 해설

각 항목이 무엇을 잡아내는지 봅시다.

항목 pandas 무엇을 진단
① 총 행수 len(df) 데이터 규모 파악
② 결측치 df.isnull().sum() 빈 값이 있는 컬럼
③ 중복행 df.duplicated().sum() 완전히 같은 행
④ 음수 매출 (df['amount']<0).sum() 환불·오류로 인한 음수
⑤ 이상치 df[df['quantity']>=999] 입력 실수 같은 극단값
⑥ status 분포 value_counts() 취소/환불 비중

특히 ⑥(status 분포)이 유용합니다. "취소·환불이 전체의 몇 %인지" 미리 보면, 매출 집계에서 얼마나 제외해야 할지 감이 옵니다.

4. 실행 결과

orders = pd.read_csv(DATA / "orders.csv", encoding="utf-8-sig")
data_quality_report(orders)

예상 출력

[1] 총 행수: 2,400행
[2] 컬럼별 결측치 수
  - order_id      :     0개
  - amount        :     0개
  ...
[3] 중복행 수: 0행

[5] quantity 이상치(999↑): 1행
[6] status 값 분포

한눈에 보입니다 — 음수 매출 1건, 이상치 1건, 그리고 취소+환불이 약 7.5%. 이걸 보면 "매출 집계 시 7.5%를 제외해야 한다" 는 결론이 바로 나오죠.

5. 왜 LLM 없이 코드로 하나

이 품질 체크는 LLM을 쓰지 않습니다. 이유가 있습니다.

  • 정확성: 결측·중복·이상치 카운트는 정확해야 하는 계산입니다. pandas가 정확히 셉니다(LLM은 셀 필요도 없죠).
  • 비용: 데이터 진단에 LLM을 부를 이유가 없습니다. 빠르고 공짜인 pandas로 충분합니다.
  • 재사용: 한 번 만든 data_quality_report는 어떤 데이터에도 재사용할 수 있습니다.

"모든 걸 LLM에게 시키지 말고, 코드로 충분한 건 코드로" — 이게 효율적인 에이전트 설계의 원칙입니다(10강 "계산은 코드"의 연장).

핵심 정리

  • 좋은 분석가는 분석 전에 데이터를 먼저 진단한다.
  • data_quality_report로 결측·중복·음수·이상치·status 분포를 한눈에 본다.
  • 특히 status 분포로 취소/환불 비중을 미리 파악한다.
  • 이런 진단은 LLM 없이 pandas로 (정확·저렴·재사용).
  • 다음 절에서 분석 결과를 차트로 시각화합니다.
