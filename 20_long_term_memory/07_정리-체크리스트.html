정리 & 체크리스트

20강에서 배운 것

20강에서는 사용자 정보를 영속 저장하는 장기 기억을 만들었습니다.

  • 단기 vs 장기: 단기는 세션 맥락(메모리), 장기는 사용자 프로필(파일·DB).
  • 도구로서의 장기 기억: get_profile(읽기)·update_profile(쓰기)로 구현.
  • 영속성: 새 에이전트(재시작)에도 파일에 쓴 정보가 살아남음.
  • 저장 계층 교체: 도구 시그니처 고정, 내부만 JSON→SQLite(의존성 역전).
  • SQLite 보안: 컬럼명 화이트리스트, 값 ? 파라미터(인젝션 방지).

한눈에 보는 핵심 코드

import json
from langchain_core.tools import tool
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

@tool
def get_profile(customer_id: str) -> str:
    """프로필 조회(읽기)."""
    return json.dumps(_load().get(customer_id, {}), ensure_ascii=False)

@tool
def update_profile(customer_id: str, field: str, value: str) -> str:
    """프로필 갱신(쓰기, 영속)."""
    data = _load(); data.setdefault(customer_id, {})[field] = value
    _save(data)                      # ← 파일에 쓰기 = 장기 기억
    return f"저장했습니다."

# 장기(도구) + 단기(InMemorySaver) 함께
agent = create_agent(llm, tools=[get_profile, update_profile],
                     system_prompt="선호 말하면 update_profile로 저장, 응대 전 get_profile로 확인",
                     checkpointer=InMemorySaver())

이 강에서 설치한 라이브러리

추가 설치 없음 — json, sqlite3는 파이썬 표준 라이브러리입니다.

기억의 전체 그림

구분 단기 기억 (19강) 장기 기억 (20강)
저장소 InMemorySaver 파일/DB (JSON → SQLite)
기억 대상 "방금 말한 것" "사용자 프로필"
지속성 재시작 시 소멸 영속 (재시작에도 유지)

→ 둘을 함께 쓰면 진짜 상담봇이 됩니다.

체크리스트

  • [ ] 단기 기억(세션)과 장기 기억(영속)의 차이를 표로 설명할 수 있다.
  • [ ] get_profile/update_profile 도구로 파일에 읽고 쓰는 장기 기억을 구현했다.
  • [ ] 에이전트를 새로 만들어도 파일에 저장된 정보가 유지됨을 확인했다.
  • [ ] 저장 계층(JSON→SQLite) 교체 시 도구 시그니처는 유지함을 안다.
  • [ ] SQLite에서 컬럼명 화이트리스트·? 파라미터로 인젝션을 막는다.

한 줄 핵심

단기 기억은 세션 맥락(메모리, 휘발), 장기 기억은 사용자 프로필(파일·DB, 영속). 도구로 구현하면 저장소를 자유롭게 갈아탈 수 있다.

🎉 3부(RAG·메모리)를 마치며

13~20강으로 지식(RAG)과 기억(메모리) 을 다루는 능력이 완성됐습니다. 이제 에이전트는 사내 문서를 검색하고, 대화 맥락을 유지하고, 사용자를 영구히 기억합니다. 진짜 사람 같은 상담봇이죠.
