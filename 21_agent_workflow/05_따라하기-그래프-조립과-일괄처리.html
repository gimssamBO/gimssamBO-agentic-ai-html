따라하기 — 그래프 조립과 일괄 처리

목표

04번의 세 노드를 StateGraph로 조립하고, CSV의 티켓들을 일괄 처리합니다. 같은 입력이면 항상 같은 결과가 나오는 결정적 워크플로우를 확인합니다.

1. 그래프 조립

노드를 등록하고 엣지로 순서를 고정합니다(03번 API).

from langgraph.graph import StateGraph, START, END

def build_workflow():
    g = StateGraph(TicketState)              # 상태 스키마로 그래프 생성
    g.add_node("classify", classify_node)    # 노드 등록(이름 → 함수)
    g.add_node("priority", priority_node)
    g.add_node("assign", assign_node)
    # 엣지로 실행 순서를 '고정'한다. 결정적 흐름: 분류 → 우선순위 → 배정
    g.add_edge(START, "classify")
    g.add_edge("classify", "priority")
    g.add_edge("priority", "assign")
    g.add_edge("assign", END)
    return g.compile()                       # 실행 가능한 워크플로우로 컴파일

네 단계입니다.

  1. StateGraph(TicketState): 상태로 그래프 생성
  2. add_node: 세 노드 등록
  3. add_edge: START→분류→우선순위→배정→END 순서 고정
  4. compile(): 실행 가능하게 변환

엣지 4줄이 흐름을 한눈에 보여 줍니다 — "분류 다음 우선순위, 그 다음 배정"이라고요. 이게 03번에서 말한 "선언적 흐름"입니다.

2. 워크플로우 실행

invoke에 초기 상태(content)만 넣으면, 세 노드가 차례로 실행됩니다.

workflow = build_workflow()
result = workflow.invoke({"content": "결제가 안 돼요. 계속 오류가 납니다."})
print(result)

예상 출력

{
  "content": "결제가 안 돼요. 계속 오류가 납니다.",
  "category": "결제",    ← classify_node가 채움
  "priority": "긴급",    ← priority_node가 채움
  "team": "결제지원팀"   ← assign_node가 채움
}

처음에 content만 넣었는데, 워크플로우를 거치며 category, priority, team이 차례로 채워졌습니다. 세 노드가 State를 함께 완성한 거죠.

3. State가 채워지는 과정

invoke({"content": "결제가 안 돼요"}) 가 노드를 거치며 State가 채워집니다.

  1. START → classify → {content: "결제가 안 돼요", category: "결제"} (category 추가)
  2. priority → {…, category: "결제", priority: "긴급"} (priority 추가)
  3. assign → {…, priority: "긴급", team: "결제지원팀"} (team 추가)
  4. END → 최종 State 반환

각 노드가 State에 한 칸씩 채워 넣는 게 보입니다. 빈 양식(content만)이 노드들을 거치며 완성된 양식(전부 채워짐)이 되죠.

4. CSV 일괄 처리

여러 티켓을 한 번에 처리합니다.

with open(DATA / "support_tickets.csv", encoding="utf-8-sig") as f:
    tickets = list(csv.DictReader(f))

print(f"{'티켓':<7}{'분류':<7}{'우선순위':<7}{'담당팀':<10}내용")
print("-" * 70)
for t in tickets:
    result = workflow.invoke({"content": t["content"]})   # 한 티켓 처리
    print(f"{t['ticket_id']:<7}{result['category']:<7}"
          f"{result['priority']:<7}{result['team']:<10}{t['content'][:20]}")

예상 출력

티켓     분류     우선순위   담당팀      내용
----------------------------------------------------------------------
TK001  결제     긴급     결제지원팀    결제가 안 돼요. 계속 오류가...
TK002  기타     보통     일반상담팀    상품 색상 문의드립니다.
TK003  배송     긴급     물류팀      배송이 일주일째 안 와요...
TK005  교환     높음     물류팀      받은 상품이 파손되어 왔습니다...
TK007  기술지원  긴급     기술지원팀    앱이 자꾸 튕겨요.

각 티켓이 분류→우선순위→배정을 거쳐 깔끔하게 처리됐습니다. utf-8-sig는 엑셀 CSV의 BOM(보이지 않는 문자)을 제거해 읽는 인코딩입니다.

5. 결정적 — 항상 같은 결과

이 워크플로우의 핵심 특징: 같은 입력이면 항상 같은 결과입니다.

"결제가 안 돼요" → 항상 결제/긴급/결제지원팀
  (분류 LLM은 temperature=0, 우선순위·배정은 규칙)

분류 LLM은 temperature=0이라 일관되고, 우선순위·배정은 규칙이라 결정적이죠. 그래서 업무 규칙(분류→우선순위→배정)이 코드로 강제되고, 검증·감사가 쉽습니다(02번). "이 티켓이 왜 이 팀에 갔지?"를 노드 단위로 추적할 수 있죠.

6. 배치 잡으로 확장

이 워크플로우는 그대로 배치 잡이나 큐 컨슈머로 감쌀 수 있습니다.

들어온 티켓마다 → workflow.invoke({"content": ...})
  → 결과(team)에 따라 메시지 큐로 라우팅
  → 노드 단위라 단계별 로깅·예외처리·재시도 깔끔

실시간으로 들어오는 티켓을 큐에서 꺼내 워크플로우에 넣고, 결과 팀으로 보내는 식이죠. 노드가 작게 나뉘어 있어 운영에 붙이기 좋습니다(07번 예외처리).

핵심 정리

  • add_node + add_edge로 그래프 조립, compile()로 완성.
  • invoke({"content": ...})에 초기 상태만 넣으면 전체 실행.
  • 노드들이 State를 한 칸씩 채워 완성.
  • 같은 입력 → 항상 같은 결과(결정적, 검증·감사 쉬움).
  • 그대로 배치 잡·큐 컨슈머로 확장 가능.
  • 다음 절에서 조건부 분기를 추가합니다.
