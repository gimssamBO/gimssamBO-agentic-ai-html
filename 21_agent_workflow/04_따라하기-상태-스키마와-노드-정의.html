따라하기 — 상태 스키마와 노드 정의

목표

티켓 처리 워크플로우의 상태(TypedDict)와 세 노드(분류·우선순위·배정)를 만듭니다. 분류만 LLM, 나머지는 규칙으로요. 실제 파일은 code/ch21_workflow.py 입니다.

0. 실습 준비

8강 이후와 동일한 LangGraph 환경입니다. 추가 설치 없음. 데이터는 data/support_tickets.csv(ticket_id, content, ...)를 씁니다.

conda activate agentic
python code/common.py

1. 공통 시작부 + 상태 스키마

import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat, DATA
import csv
from typing import TypedDict
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END

class TicketState(TypedDict):
    # 모든 노드가 공유하는 상태. 각 노드는 일부 필드만 채워 dict로 반환하면 자동 병합
    content: str    # 티켓 원문 (입력)
    category: str   # 분류 노드가 채움
    priority: str   # 우선순위 노드가 채움
    team: str       # 배정 노드가 채움

State에 4개 필드를 선언했습니다. content는 입력이고, 나머지 셋은 노드들이 차례로 채울 빈칸이죠.

2. 노드 1 — 분류 (LLM)

자연어 이해가 필요하니 LLM을 씁니다.

llm = get_chat(temperature=0)
CATEGORIES = ["결제", "배송", "환불", "교환", "회원", "기술지원", "기타"]

def classify_node(state: TicketState) -> dict:
    """[노드1] 티켓 내용을 카테고리로 분류한다. (LLM)"""
    msg = [
        SystemMessage(f"다음 CS 티켓을 {CATEGORIES} 중 하나로만 분류하라. 카테고리 단어만 출력."),
        HumanMessage(state["content"]),
    ]
    out = llm.invoke(msg).text.strip()
    category = next((c for c in CATEGORIES if c in out), "기타")  # 목록에 없으면 '기타' 폴백
    return {"category": category}   # 채운 필드만 반환 → 상태에 자동 병합

뜯어보면:

  • state["content"]로 티켓 내용을 읽음
  • LLM으로 7개 카테고리 중 하나로 분류(3강 분류 복습)
  • next((c for c in CATEGORIES if c in out), "기타"): 결과가 목록에 없으면 "기타"로 폴백
  • {"category": category}만 반환 → State에 자동 병합

temperature=0으로 분류가 일관되게 합니다(같은 티켓 → 같은 분류).

3. 노드 2 — 우선순위 (규칙)

키워드 규칙이면 충분하니 LLM 없이 처리합니다.

URGENT_WORDS = ["결제", "오류", "안 돼", "파손", "안와", "안 와"]
HIGH_WORDS = ["환불", "교환", "튕"]

def priority_node(state: TicketState) -> dict:
    """[노드2] 카테고리/키워드로 우선순위를 정한다. (규칙)"""
    text = state["content"]
    if state["category"] == "결제" or any(w in text for w in URGENT_WORDS):
        priority = "긴급"
    elif state["category"] in ("환불", "교환") or any(w in text for w in HIGH_WORDS):
        priority = "높음"
    else:
        priority = "보통"
    return {"priority": priority}

이 노드는 LLM을 안 씁니다. 키워드 매칭(any(w in text ...))이면 충분하거든요. 빠르고 공짜이고 정확하죠(02번 분업). "결제 카테고리거나 긴급 단어가 있으면 긴급" 같은 규칙을 코드로 명확히 표현합니다.

state["category"]를 읽는 게 포인트입니다 — 앞 노드(분류)가 채운 값을 이 노드가 활용하죠. State를 통해 노드들이 협력하는 모습입니다.

4. 노드 3 — 배정 (규칙)

카테고리 → 팀 매핑도 규칙이면 충분합니다.

TEAM_MAP = {
    "결제": "결제지원팀", "환불": "정산팀", "교환": "물류팀",
    "배송": "물류팀", "회원": "회원관리팀", "기술지원": "기술지원팀",
}

def assign_node(state: TicketState) -> dict:
    """[노드3] 카테고리에 맞는 담당팀을 배정한다. (규칙)"""
    team = TEAM_MAP.get(state["category"], "일반상담팀")  # 없으면 일반상담팀
    return {"team": team}

딕셔너리 매핑 한 줄이면 끝입니다. "결제→결제지원팀" 같은 매핑은 LLM이 필요 없죠. .get(..., "일반상담팀")으로 매핑에 없는 카테고리는 "일반상담팀"으로 폴백합니다.

5. 노드의 공통 패턴

세 노드를 보면 공통 패턴이 있습니다.

def 노드(state: TicketState) -> dict:
    값 = state["입력_필드"]를 읽어서 처리
    return {"출력_필드": 결과}   # 채운 것만 반환
  • 입력: state에서 필요한 필드를 읽음
  • 처리: LLM 또는 규칙으로 계산
  • 출력: 자기가 채운 필드만 dict로 반환

이 패턴이 모든 노드의 골격입니다. 노드는 작고 단일 책임을 가지죠 — 분류 노드는 분류만, 배정 노드는 배정만. 그래서 디버깅이 쉽습니다(02번).

핵심 정리

  • State는 TypedDict로 4필드(content + 채울 3개) 선언.
  • 분류 노드는 LLM(자연어 이해), 우선순위·배정은 규칙(분업).
  • 각 노드는 state 읽고 채운 필드만 반환(자동 병합).
  • 뒷 노드가 앞 노드의 결과(state["category"])를 활용.
  • 노드는 작고 단일 책임(디버깅 쉬움).
  • 다음 절에서 노드를 그래프로 조립합니다.
