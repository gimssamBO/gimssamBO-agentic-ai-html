정리 & 체크리스트

21강에서 배운 것

21강에서는 정해진 흐름을 가진 워크플로우를 LangGraph로 만들었습니다.

  • 에이전트 vs 워크플로우: 자유로운 에이전트 vs 정해진 워크플로우(예측·검증 쉬움).
  • StateGraph 3요소: State(공유 데이터)·Node(채우는 함수)·Edge(순서).
  • 분업: 분류만 LLM, 우선순위·배정은 규칙(코드).
  • 조건부 분기: add_conditional_edges로 상황별 길 가르기.
  • 노드 실패 처리: 검증·보정·예외 기록으로 견고하게.

한눈에 보는 핵심 코드

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class TicketState(TypedDict):
    content: str; category: str; priority: str; team: str

def classify_node(state) -> dict:   # LLM
    return {"category": ...}
def priority_node(state) -> dict:   # 규칙
    return {"priority": ...}

g = StateGraph(TicketState)
g.add_node("classify", classify_node)
g.add_node("priority", priority_node)
g.add_edge(START, "classify")
g.add_edge("classify", "priority")
# 조건부 분기
g.add_conditional_edges("priority", route_fn, {"escalate": "escalate", "assign": "assign"})
workflow = g.compile()

result = workflow.invoke({"content": "결제 오류"})

이 강에서 설치한 라이브러리

추가 설치 없음 — langgraph는 8강에서 설치한 것 사용.

체크리스트

  • [ ] 자유 에이전트와 고정 워크플로우의 차이를 설명할 수 있다.
  • [ ] StateGraph + TypedDict 상태로 노드·엣지를 구성했다.
  • [ ] 노드를 LLM(분류)과 규칙(우선순위·배정)으로 분업했다.
  • [ ] add_conditional_edges로 조건부 분기를 만들었다.
  • [ ] 노드 실패를 검증·보정·기록으로 견고하게 처리했다.

한 줄 핵심

정해진 순서의 업무는 자유 에이전트보다 워크플로우가 맞다. StateGraph로 흐름을 선언하고, 분기·검증으로 견고하게 만든다.
