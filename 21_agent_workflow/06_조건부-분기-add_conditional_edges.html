조건부 분기 (add_conditional_edges)

한 줄 요약

지금까지는 노드들이 일직선으로 흘렀습니다. 하지만 "긴급하면 에스컬레이션, 아니면 일반 배정"처럼 상황에 따라 길이 갈려야 할 때가 있습니다. add_conditional_edges로 상태를 보고 다음 노드를 고르는 갈림길(분기) 을 만듭니다.

1. 일직선의 한계

05번 워크플로우는 모든 티켓이 같은 길을 갔습니다.

모든 티켓: 분류 → 우선순위 → 배정 → 끝 (일직선)

하지만 현실은 다릅니다. 긴급 티켓은 일반 배정 큐를 거치면 늦죠.

  • 긴급 티켓: 분류 → 우선순위 → 즉시 에스컬레이션! → 끝
  • 일반 티켓: 분류 → 우선순위 → 일반 배정 → 끝

우선순위 단계 뒤에서 길이 갈려야 합니다.

우선순위가 "긴급"이냐 아니냐에 따라 다른 노드로 가야 합니다. 이게 조건부 분기입니다.

2. add_conditional_edges — 갈림길

add_conditional_edges는 상태를 보고 다음 노드를 동적으로 고릅니다. (실습 파일: sections/21_agent_workflow/06_조건부-분기-add_conditional_edges.py)

def route_by_priority(state: TicketState) -> str:
    """우선순위를 보고 다음 노드 이름을 반환하는 라우터 함수."""
    return "escalate" if state["priority"] == "긴급" else "assign"

이게 라우터 함수입니다. State를 받아 "다음에 갈 노드 이름"을 문자열로 돌려주죠. "긴급이면 escalate, 아니면 assign"이라고요. add_conditional_edges가 이 반환값으로 다음 노드를 정합니다.

3. 분기 노드 만들기

두 갈래의 노드를 만듭니다.

def escalate_node(state: TicketState) -> dict:
    """[긴급 분기] 즉시 상위팀으로 에스컬레이션한다."""
    return {
        "team": "긴급대응팀",
        "route": "긴급에스컬",
        "action": "SLA 30분 내 즉시 에스컬레이션(담당자 호출)",
    }

def assign_route_node(state: TicketState) -> dict:
    """[일반 분기] 카테고리에 맞는 담당팀으로 일반 배정한다."""
    upd = assign_node(state)          # 기존 배정 규칙 재사용
    upd["route"] = "일반배정"
    upd["action"] = f"{upd['team']} 일반 배정(SLA 24시간)"
    return upd

escalate_node는 긴급용(30분 SLA), assign_route_node는 일반용(24시간 SLA)입니다. 긴급은 빠른 경로로, 일반은 보통 경로로 가는 거죠.

4. 조건부 엣지 연결

add_conditional_edges로 분기를 그래프에 연결합니다.

g.add_edge(START, "classify")
g.add_edge("classify", "priority")

# 선형 엣지 대신 조건부 분기: priority 다음은 라우터 함수가 정한다
g.add_conditional_edges(
    "priority",                                       # 이 노드 다음에
    route_by_priority,                                # 라우터 함수가 다음을 정함
    {"escalate": "escalate", "assign": "assign"},     # 반환값 → 실제 노드 매핑
)
g.add_edge("escalate", END)
g.add_edge("assign", END)

add_conditional_edges(노드, 라우터, 매핑):

  • 노드: "priority" — 이 노드 다음에 분기
  • 라우터: route_by_priority — 다음 노드 이름을 결정하는 함수
  • 매핑: {"escalate": "escalate", ...} — 라우터 반환값을 실제 노드로 연결

이러면 priority 노드 다음에 라우터가 작동해, 긴급이면 escalate로, 아니면 assign으로 갑니다.

5. 흐름 그림

  • START → [classify] → [priority] → route_by_priority(라우터)
  • 라우터가 우선순위를 보고 갈림:
  • 긴급? → [escalate] → END
  • 아니면 → [assign] → END

priority 다음에 갈림길이 생겼습니다. 라우터가 우선순위를 보고 둘 중 하나로 보내죠.

6. 실행 결과

for t in tickets:
    result = workflow.invoke({"content": t["content"]})
    print(f"{t['ticket_id']} {result['priority']} {result['route']} {result['team']} {result['action']}")

예상 출력

TK001  긴급   긴급에스컬   긴급대응팀   SLA 30분 내 즉시 에스컬레이션
TK002  보통   일반배정     일반상담팀   일반상담팀 일반 배정(SLA 24시간)
TK003  긴급   긴급에스컬   긴급대응팀   SLA 30분 내 즉시 에스컬레이션
TK005  높음   일반배정     물류팀       물류팀 일반 배정(SLA 24시간)

긴급 티켓(TK001, TK003)은 에스컬레이션 경로로, 나머지는 일반 배정 경로로 갔습니다. 같은 워크플로우인데 우선순위에 따라 다른 길을 탄 거죠.

7. 조건부 분기의 가치

조건부 분기로 워크플로우가 훨씬 유연해집니다.

선형(05번): 모든 케이스가 같은 처리 (단순하지만 경직)
분기(06번): 케이스별 다른 처리 (긴급↔일반, 정상↔오류 등)

분기를 쓰면 "긴급은 빠르게, 일반은 보통대로", "정상은 진행, 오류는 재시도" 같은 상황별 처리가 가능합니다. 27강(AI 팀)에서는 분기로 "품질 부족하면 되돌아가기" 같은 루프도 만들죠. 분기는 워크플로우를 진짜 업무 흐름에 가깝게 만듭니다.

핵심 정리

  • 일직선 워크플로우는 상황별 처리를 못 함.
  • add_conditional_edges 로 상태를 보고 다음 노드를 동적 선택.
  • 라우터 함수(state -> 노드이름)가 분기를 결정.
  • add_conditional_edges(노드, 라우터, 매핑)으로 연결.
  • 긴급↔일반, 정상↔오류 같은 상황별 처리 가능.
  • 다음 절에서 노드 실패 처리를 배웁니다.
