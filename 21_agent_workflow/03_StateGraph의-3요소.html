StateGraph의 3요소

한 줄 요약

LangGraph의 StateGraph는 세 요소로 구성됩니다 — State(상태): 워크플로우가 공유하는 데이터, Node(노드): 상태를 읽고 일부를 채우는 함수, Edge(엣지): 노드 간 실행 순서. 이 셋으로 흐름을 "선언"합니다.

1. 세 요소 한눈에

노드들이 Edge(화살표)로 이어지며, 각 노드가 공유 State를 채워 갑니다.

START → [분류 노드] → [우선순위 노드] → [배정 노드] → END

이때 모든 노드는 하나의 State {content, category, priority, team}를 공유하며, 각자 자기 칸을 읽고 채웁니다.

  • State: 모든 노드가 공유하는 데이터(가운데 박스)
  • Node: 상태를 읽고 일부를 채우는 함수(분류·우선순위·배정)
  • Edge: 노드를 잇는 화살표(실행 순서)

2. State — 공유 상태 (TypedDict)

State는 워크플로우 전체가 공유하는 데이터입니다. TypedDict로 구조(스키마)를 정의합니다.

from typing import TypedDict

class TicketState(TypedDict):
    content: str    # 티켓 원문 (입력)
    category: str   # 분류 노드가 채움
    priority: str   # 우선순위 노드가 채움
    team: str       # 배정 노드가 채움

State는 "노드들이 함께 채워 가는 양식 서류"입니다. 처음엔 content(입력)만 있고, 노드들이 차례로 category, priority, team을 채웁니다. 각 노드가 한 칸씩 채워 다음 노드로 넘기는 거죠.

TypedDict는 "dict인데 키와 타입이 정해진 것"입니다. 일반 dict처럼 쓰지만, 어떤 키가 있어야 하는지 미리 선언하죠. 8강의 Pydantic처럼 구조를 명시하는 도구입니다.

3. Node — 상태를 채우는 함수

Node는 state -> dict 함수입니다. 상태를 읽고, 자기가 담당한 필드만 채워 dict로 반환합니다.

def classify_node(state: TicketState) -> dict:
    """티켓 내용을 카테고리로 분류한다."""
    category = ...   # state["content"]를 보고 분류
    return {"category": category}   # 채운 필드만 반환!

핵심: 노드는 자기가 채운 필드만 반환합니다({"category": ...}). 전체 State를 돌려줄 필요 없죠. LangGraph가 이 부분 결과를 기존 State에 자동 병합합니다.

classify_node가 {"category": "결제"} 반환
  → State에 category="결제"가 자동으로 합쳐짐 (다른 필드는 그대로)

4. Edge — 실행 순서

Edge는 노드를 잇는 화살표(실행 순서) 입니다.

g.add_edge(START, "classify")      # 시작 → 분류
g.add_edge("classify", "priority") # 분류 → 우선순위
g.add_edge("priority", "assign")   # 우선순위 → 배정
g.add_edge("assign", END)          # 배정 → 끝

add_edge(A, B)는 "A 다음에 B를 실행하라"는 뜻입니다. START에서 시작해 END로 끝나죠. 이 엣지들이 흐름을 고정합니다 — 항상 분류→우선순위→배정 순서로요.

START와 END는 시작·종료를 나타내는 가상 노드입니다. START는 "여기서 시작", END는 "여기서 끝".

5. 핵심 API

API 역할
StateGraph(State) 상태 스키마로 그래프 생성
add_node("name", fn) 노드 등록(이름 → 함수)
add_edge(A, B) A 다음에 B 실행
START / END 시작/종료 가상 노드
graph.compile() 실행 가능한 워크플로우로 컴파일 
from langgraph.graph import StateGraph, START, END

g = StateGraph(TicketState)        # 1. 상태로 그래프 생성
g.add_node("classify", classify_node)  # 2. 노드 등록
g.add_edge(START, "classify")      # 3. 엣지로 순서
workflow = g.compile()             # 4. 컴파일 → 실행 가능

compile()이 그래프를 실행 가능한 워크플로우로 만듭니다. 그러면 workflow.invoke(초기상태)로 실행할 수 있죠(05번).

6. "흐름을 선언한다"

StateGraph의 철학은 "흐름을 선언적으로 표현" 하는 것입니다.

if문으로 흐름 짜기(명령형):       StateGraph로 선언하기:
  result1 = classify(input)        g.add_edge(START, "classify")
  result2 = priority(result1)      g.add_edge("classify", "priority")
  result3 = assign(result2)        g.add_edge("priority", "assign")
  → 흐름이 코드 순서에 숨음          → 흐름이 엣지로 한눈에 보임

if문으로 짜면 흐름이 코드 곳곳에 숨지만, StateGraph는 엣지로 흐름을 명시합니다. "분류→우선순위→배정"이 엣지 선언에 또렷이 보이죠. 복잡한 흐름(분기·반복, 06·27강)일수록 이 선언적 방식의 가치가 커집니다.

핵심 정리

  • StateGraph 3요소: State(공유 데이터)·Node(채우는 함수)·Edge(순서).
  • State: TypedDict로 정의, 노드들이 함께 채우는 양식.
  • Node: state -> dict, 채운 필드만 반환(자동 병합).
  • Edge: add_edge(A, B)로 순서 고정, START~END.
  • compile()로 실행 가능한 워크플로우 생성.
  • 흐름을 선언적으로 표현(엣지로 한눈에).
  • 다음 절에서 상태·노드를 직접 정의합니다.
