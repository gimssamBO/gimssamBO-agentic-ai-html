왜 프롬프트가 중요한가 — "AI는 시키는 대로가 아니라, 말한 대로 한다"

한 줄 요약

같은 모델이라도 어떻게 물어보느냐(프롬프트) 에 따라 결과가 크게 달라집니다. 프롬프트를 잘 설계하면 결과의 정확도·일관성·형식을 통제할 수 있습니다. 이걸 다루는 기술이 프롬프트 엔지니어링입니다.

1. 현장의 문제

승승장구몰에는 매일 수십 건의 고객 문의가 쏟아집니다. 상담원이 일일이 읽고 "이건 환불, 저건 배송" 분류하는 데만도 시간이 듭니다. LLM에게 맡기면 좋겠는데, 그냥 "이 문의 분류해줘"라고 던지면 결과가 들쭉날쭉합니다.

# 막 던진 프롬프트 — 결과가 제멋대로
ask("이 문의 분류해줘: 카드가 두 번 청구됐어요")
# 어떤 땐 → "결제 관련 문의로 보입니다."
# 어떤 땐 → "이 고객은 환불을 원하는 것 같습니다. (긴급)"
# 어떤 땐 → "이중 청구 문제네요!"

문제가 두 가지입니다.

  • 형식이 제각각이라 코드로 받아 쓸 수가 없습니다. (한 번은 문장, 한 번은 괄호…)
  • 우리가 정한 7개 카테고리가 아니라 마음대로 새 카테고리를 만들어 냅니다.

2. 문제는 모델이 아니라 '지시'다

흔히 "모델이 멍청해서 그래"라고 생각하지만, 대부분은 지시(프롬프트)가 부실해서 입니다. 같은 모델도 지시를 잘 주면 정확도가 확 올라갑니다.

# 잘 설계한 프롬프트 — 결과가 안정적
classify("카드가 두 번 청구됐어요")
# → "결제"   (항상 7개 중 하나, 한 단어로)

비유: LLM은 유능하지만 눈치 없는 신입사원입니다. "알아서 잘 분류해줘"라고 하면 제각각 하지만, "이 7개 중 하나로, 한 단어만 답해. 예시는 이거야"라고 명확히 지시하면 칼같이 해냅니다.

3. 이 강에서 배울 4가지 무기

무기 효과 목차
프롬프트 4요소 출력을 안정시키는 기본 골격 02
few-shot 예시 분류·판단 정확도를 끌어올림 03
JSON 강제 출력 답을 코드로 바로 쓰게 만듦 04
인젝션 방어 악의적 입력으로부터 역할 보호 05

그리고 06번에서 이 무기들로 고객 문의 60건을 자동 분류하고 정확도를 측정합니다. 07번에서는 틀린 사례를 분석해 더 개선합니다.

4. 실습에서 쓸 데이터

이번 강은 data/cs_inquiries.csv(고객 문의 60건)를 씁니다. 핵심 컬럼은:

  • content: 고객 문의 내용
  • category_hint: 정답 카테고리 (우리 분류가 맞았는지 채점하는 기준)
import pandas as pd
df = pd.read_csv("data/cs_inquiries.csv", encoding="utf-8-sig")
print(df[["content", "category_hint"]].head(3).to_string(index=False))

category_hint라는 정답이 있어서, 우리가 만든 분류기의 정확도를 숫자로 측정할 수 있습니다. 이게 이 강의 묘미입니다.

핵심 정리

  • 결과가 들쭉날쭉한 건 모델이 아니라 프롬프트 탓일 때가 많다.
  • 프롬프트를 잘 설계하면 정확도·일관성·형식을 통제할 수 있다.
  • 정답 라벨(category_hint)이 있으면 정확도를 측정하며 개선할 수 있다.
