문제 1 — 경쟁사 데이터 기반 리포트 (검색 없이 CSV로)

code/ch22_research.py를 참고해 code/ch22_ex_competitor.py를 만드세요. 웹 검색 대신 data/competitor_data.csv(company, main_category, rating, strength, weakness)를 pandas로 읽어 표 문자열로 만든 뒤, 그 표를 프롬프트에 넣어 "## 개요 / ## 경쟁사별 강약점 / ## 시사점" 구조의 마크다운 리포트를 생성하게 하세요.

  • 결과를 reports/competitor_report.md로 저장.
  • 기대 결과: 저장된 파일에 5개 경쟁사 company 이름이 모두 등장.

# -*- coding: utf-8 -*-
# 실행: python code/ch22_ex_competitor.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat, DATA
import pandas as pd

def make_competitor_report(csv_path: pathlib.Path) -> str:
    """경쟁사 CSV를 표로 만들어 LLM에게 리포트를 작성시킨다(검색 불필요)."""
    df = pd.read_csv(csv_path, encoding="utf-8-sig")     # 엑셀 BOM 대비
    table = df.to_markdown(index=False)                  # 데이터프레임 → 마크다운 표
    llm = get_chat(temperature=0.3)
    prompt = (
        "너는 승승장구몰의 시장 조사 애널리스트다. 아래 경쟁사 표를 근거로 "
        "한국어 마크다운 리포트를 작성하라. "
        "'## 개요', '## 경쟁사별 강약점', '## 시사점' 세 섹션을 정확히 이 머리말로 포함하라. "
        "표에 있는 모든 경쟁사를 빠짐없이 언급하라.\n\n"
        f"{table}"
    )
    return llm.invoke(prompt).text

if __name__ == "__main__":
    body = make_competitor_report(DATA / "competitor_data.csv")
    out = pathlib.Path(__file__).resolve().parent.parent / "reports"
    out.mkdir(exist_ok=True)
    path = out / "competitor_report.md"
    path.write_text("# 경쟁사 분석 리포트\n\n" + body, encoding="utf-8")
    print(body[:500], "...")
    print("[저장 완료]", path)

## 개요
승승장구몰의 주요 경쟁사 5곳을 평점·강점·약점 기준으로 비교했다. ...
## 경쟁사별 강약점
- A몰: 빠른 배송이 강점, 높은 가격이 약점 ...
- B마트: ...
...
## 시사점
가격 경쟁력과 배송 속도를 동시에 ... 차별화 권장.
[저장 완료] /Users/.../reports/competitor_report.md
**해설**: 핵심은 **검색 도구 없이도** 리서치 패턴(데이터 수집→요약→리포트)이 그대로 적용된다는 점입니다. 데이터 출처가 웹 검색이냐 CSV냐만 다를 뿐, "사실을 모아 LLM이 서술"하는 구조는 같죠. `df.to_markdown()`으로 표를 만들어 프롬프트에 넣으면, LLM이 표를 읽고 분석합니다. "모든 경쟁사를 빠짐없이 언급하라"를 명시해야 누락 없이 5곳이 다 들어갑니다. > `to_markdown()`은 `tabulate` 패키지가 필요할 수 있습니다: `pip install -U tabulate`. 없으면 `df.to_string(index=False)`로 대체하세요.

문제 2 — 다중 하위 질의 통합

code/ch22_research.py의 research()를 수정해, 하나의 주제를 2~3개 하위 질의(예: "ANC 트렌드", "가격대 동향")로 나눠 각각 호출·요약한 뒤 하나의 리포트로 합치게 하세요. (06번의 deep_research를 직접 구현해 보는 문제입니다.)

  • 검증: 콘솔에 하위 질의별 진행 로그가 찍히고, 최종 리포트에 각 하위 주제 내용이 모두 반영됐는지 확인.

# -*- coding: utf-8 -*-
# 실행: python code/ch22_ex_multiquery.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat
from langchain_community.tools import DuckDuckGoSearchResults

def search_one(query: str) -> str:
    """하위 질의 하나를 검색(실패 시 LLM 지식 폴백)."""
    try:
        return DuckDuckGoSearchResults().invoke(query)
    except Exception as e:
        print(f"  [경고] 검색 실패 → LLM 폴백: {e}")
        return get_chat(temperature=0.3).invoke(
            f"'{query}' 핵심 사실 3가지를 한국어로 정리하라.").content

def research_multi(topic: str, subtopics: list[str]) -> str:
    """주제를 하위 질의로 나눠 각각 검색·종합한다."""
    findings = []
    for i, sub in enumerate(subtopics):
        q = f"{topic} {sub}"
        print(f"[검색 {i}] {q} ...")                  # 진행 로그
        findings.append((sub, search_one(q)))
    blocks = "\n\n".join(f"[{s}]\n{r[:1000]}" for s, r in findings)
    llm = get_chat(temperature=0.3)
    prompt = (
        f"주제: {topic}\n아래 하위 주제별 검색 결과를 종합해 한국어 마크다운 리포트를 작성하라.\n"
        "'## 개요', '## 핵심 동향', '## 시사점' 세 섹션을 포함하고, "
        "각 하위 주제 내용을 모두 반영하라.\n\n"
        f"{blocks}"
    )
    return llm.invoke(prompt).text

if __name__ == "__main__":
    topic = "무선이어버드 시장"
    subtopics = ["ANC 노이즈캔슬링 트렌드", "가격대 동향", "주요 제조사 점유율"]
    print(f"[조사 시작] {topic} — {len(subtopics)}개 하위 질의")
    body = research_multi(topic, subtopics)
    print("=" * 60)
    print(body[:600], "...")
**예상 출력** 
[조사 시작] 무선이어버드 시장 — 3개 하위 질의
[검색 0] 무선이어버드 시장 ANC 노이즈캔슬링 트렌드 ...
[검색 1] 무선이어버드 시장 가격대 동향 ...
[검색 2] 무선이어버드 시장 주요 제조사 점유율 ...
============================================================
## 개요
무선이어버드 시장을 기술·가격·점유율 세 측면에서 종합했다. ...
## 핵심 동향
- (ANC) 프리미엄 기능의 중저가 확산
- (가격) 5만원대 가성비 라인 성장
- (점유율) 상위 3사 과점 ...
## 시사점
...
**해설**: 핵심은 **하위 질의를 따로 검색해 모은 뒤(`findings`), 한 번에 종합**하는 흐름입니다. 진행 로그(`[검색 i]`)를 찍어 어디까지 됐는지 보이게 하고, 각 결과를 `r[:1000]`으로 잘라 토큰을 관리합니다. 종합 프롬프트에 "각 하위 주제 내용을 모두 반영하라"를 넣어야 한 측면도 빠지지 않죠. 06번 `deep_research`는 여기에 "LLM이 하위 질의를 자동 생성(`split_topic`)"하는 단계를 더한 버전입니다 — 이 문제는 하위 질의를 직접 지정했고, 06번은 그것도 LLM에게 맡깁니다.

정리

  • 문제 1로 검색 없는 데이터 기반 리포트(CSV → 표 → 요약)를 만들었습니다.
  • 문제 2로 다중 하위 질의 통합(분해 → 검색 → 종합)을 구현했습니다.

두 문제 모두 리서치 패턴(수집→요약→리포트)의 응용입니다. 데이터 출처(웹/CSV)와 질의 수(단일/다중)만 달라질 뿐, 핵심 구조는 같죠.
