정리 & 체크리스트

22강에서 배운 것

22강에서는 9강의 웹 검색을 발전시켜, 시장 정보를 조사하고 마크다운 리포트를 자동 생성하는 리서치 에이전트를 만들었습니다.

  • 리서치 패턴: 검색 → 수집 → 요약 → 리포트 4단계.
  • 검색 도구 에이전트: create_agent에 DuckDuckGoSearchResults를 붙여 스스로 검색·요약.
  • 마크다운 저장: 본문에 헤더를 붙여 reports/*.md로 저장(research/save_report 분리).
  • 네트워크 폴백: 검색 실패 시 LLM 지식만으로 임시 리포트(서비스가 죽지 않게).
  • [신규] 하위 질의 분해: 큰 주제를 3~4개로 쪼개 깊이 있게 조사(Plan-and-Execute).
  • [신규] 교차 검증: 다른 검색어 2개로 재검색해 신뢰도(높음/보통/낮음) 판정.

한눈에 보는 핵심 코드

from langchain_community.tools import DuckDuckGoSearchResults
from langchain.agents import create_agent

# 1) 검색 도구 붙인 리서치 에이전트
agent = create_agent(
    get_chat(temperature=0.3),
    tools=[DuckDuckGoSearchResults()],
    system_prompt="...시장 조사 애널리스트... '## 개요/## 핵심 동향/## 시사점' 포함",
)

# 2) 조사 + 폴백
def research(topic):
    try:
        r = agent.invoke({"messages": [{"role": "user", "content": f"{topic} 리포트 써줘"}]})
        return r["messages"][-1].text
    except Exception as e:
        return get_chat().invoke(f"{topic} 리포트(검색 없이, 최신 아닐 수 있음 경고 포함)").text

# 3) 저장
def save_report(topic, body):
    path = REPORTS / f"research_{datetime.date.today().isoformat()}.md"
    path.write_text(f"# 시장 조사 리포트 — {topic}\n\n" + body, encoding="utf-8")
    return path

# [신규] 하위 질의 분해 (구조화 출력)
class SubQueries(BaseModel):
    queries: list[str] = Field(description="3~4개의 구체적 하위 검색 질의")
queries = get_chat().with_structured_output(SubQueries).invoke(prompt).queries

# [신규] 교차 검증
class Verdict(BaseModel):
    agree: str; confidence: str; reason: str
v = get_chat(temperature=0).with_structured_output(Verdict).invoke(compare_prompt)

체크리스트

  • [ ] 리서치 패턴(검색→수집→요약→리포트)을 설명할 수 있다.
  • [ ] DuckDuckGoSearchResults를 에이전트 도구로 붙였다.
  • [ ] 결과를 마크다운 .md 파일로 저장했다.
  • [ ] 검색 실패 시 폴백(예외처리)이 동작함을 이해했다.
  • [ ] 큰 주제를 하위 질의로 분해해 깊이 있게 조사했다.
  • [ ] 교차 검증으로 핵심 주장의 신뢰도를 표시했다.

한 줄 핵심

리서치 에이전트는 "검색→요약→리포트" 파이프라인이다. 외부 검색은 반드시 폴백으로 감싸고, 큰 주제는 쪼개고, 핵심 주장은 교차 검증해 신뢰도를 표시한다.
