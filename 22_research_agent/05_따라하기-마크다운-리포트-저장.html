따라하기 — 마크다운 리포트 저장

목표

04번에서 만든 리포트 본문을 헤더와 함께 .md 파일로 저장합니다. 조사(research)와 저장(save_report)을 분리해, 배치·API에서 재사용하기 쉬운 구조를 완성합니다.

1. 저장 함수 만들기

code/ch22_research.py에 save_report를 추가합니다.

def save_report(topic: str, body: str) -> pathlib.Path:
    """리포트 본문을 헤더와 함께 reports/ 폴더에 .md로 저장하고 경로를 반환한다.

    [왜 research/save 분리] 재사용·테스트를 쉽게 하려는 모듈화.
    배치는 research→save 만 호출하면 되고, API는 research() 결과를 바로 응답할 수 있다.
    """
    out_dir = pathlib.Path(__file__).resolve().parent.parent / "reports"
    out_dir.mkdir(exist_ok=True)        # reports/ 폴더가 없으면 생성
    today = datetime.date.today().isoformat()
    path = out_dir / f"research_{today}.md"
    header = f"# 시장 조사 리포트 — {topic}\n\n> 생성일: {today} (자동 생성)\n\n"
    path.write_text(header + body, encoding="utf-8")   # 한글 깨짐 방지 위해 utf-8 명시
    return path

짚어 둘 점

  • out_dir.mkdir(exist_ok=True) — reports/ 폴더가 없으면 만들고, 있으면 그냥 둡니다(exist_ok=True라 에러 안 남).
  • datetime.date.today().isoformat() — 2026-06-07 형태의 날짜 문자열. 파일명·헤더에 씁니다.
  • header — 본문 위에 제목·생성일을 붙여 누가 봐도 무슨 리포트인지 알게 합니다.
  • encoding="utf-8" — 한글이 깨지지 않게 인코딩을 명시합니다(매우 중요).

2. 전체 실행 코드

research(04번) → save_report(이번)를 이어 붙입니다.

if __name__ == "__main__":
    topic = "경쟁 무선이어버드 시장 동향"
    print(f"[조사 시작] {topic}")
    body = research(topic)              # 검색→요약(또는 폴백) → 리포트 본문
    path = save_report(topic, body)     # .md 파일로 저장
    print("=" * 60)
    print(body[:600], "...")            # 미리보기
    print("=" * 60)
    print("[저장 완료]", path)

3. 저장된 파일 확인

생성된 .md를 열어 봅니다.

cat reports/research_2026-06-07.md

파일 내용(예시)

# 시장 조사 리포트 — 경쟁 무선이어버드 시장 동향

> 생성일: 2026-06-07 (자동 생성)

## 개요
무선이어버드 시장은 ANC(능동소음제거)와 ...

## 핵심 동향
- 프리미엄 ANC 보편화, 중저가 모델로 확산
- 멀티포인트 연결·공간음향 기능 경쟁 심화
...

## 시사점
승승장구몰 자체 PB 이어버드는 ANC와 멀티포인트를 ... 강화 필요.

헤더(제목·생성일)와 본문(세 섹션)이 합쳐진 완성된 리포트가 저장됐습니다. 이 .md는 그대로 사내 위키에 올리거나, HTML/PDF로 변환하거나, 메일로 보낼 수 있죠.

4. 왜 research와 save를 나눴나

함수를 둘로 나눈 건 재사용·테스트 때문입니다.

[배치 스케줄러]  매주 월요일 → research(topic) → save_report(...) → 파일 저장
[API 엔드포인트] GET /research?topic=... → research(topic) → JSON으로 바로 응답 (저장 안 함)
[테스트]         research() 결과만 검증 (파일 I/O 없이 빠르게)

research()는 "본문 문자열 생성"만, save_report()는 "저장"만 합니다. 한 가지 일만 하는 함수로 나누면 상황별로 조합해 쓰기 쉽죠(단일 책임 원칙). 만약 한 함수에 다 넣었다면, API에서 "저장은 필요 없는데 저장 코드가 끼어 있는" 어색한 구조가 됩니다.

5. 운영 모니터링 팁

리포트 생성을 배치로 돌릴 때, 다음을 로그로 남기면 좋습니다.

- 검색 호출 수·소요 시간 (성능 추적)
- 폴백 발생 여부 (검색이 자주 막히는지 모니터링)
- 생성된 파일 경로·크기 (산출물 확인)

import time
t0 = time.time()
body = research(topic)
elapsed = time.time() - t0
fallback = body.startswith("> ⚠️")     # 폴백 리포트인지 간단 판별
path = save_report(topic, body)
print(f"[로그] 소요={elapsed:.1f}s 폴백={fallback} 파일={path}")

이런 로그가 쌓이면 "검색이 자꾸 막히네 → 재시도/캐시 도입해야겠다" 같은 운영 판단을 데이터로 할 수 있습니다(29강 배포).

핵심 정리

  • save_report()는 본문에 헤더(제목·생성일) 를 붙여 reports/*.md로 저장.
  • mkdir(exist_ok=True)로 폴더 자동 생성, encoding="utf-8"로 한글 보존.
  • research(생성)와 save_report(저장)를 분리 → 배치·API·테스트에서 재사용.
  • 저장된 .md는 위키·HTML·메일 등으로 그대로 활용 가능.
  • 소요 시간·폴백 발생을 로깅하면 운영 모니터링이 쉬움.
  • 다음 절에서 복잡한 주제를 하위 질의로 쪼개 더 깊이 조사합니다.
