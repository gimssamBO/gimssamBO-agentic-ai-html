리서치 에이전트 패턴

한 줄 요약

리서치 에이전트는 검색 → 수집 → 요약 → 리포트 4단계로 동작합니다. 이번 강에서는 create_agent에 검색 도구를 붙여, 에이전트가 스스로 검색하고 요약하게 한 뒤 결과를 .md로 저장합니다.

1. 4단계 패턴

리서치 에이전트의 표준 흐름은 다음과 같습니다.

조사 주제가 들어오면 검색 → 수집 → 요약 → 리포트 순서로 흐릅니다.

단계 하는 일 구현
검색 키워드로 웹 질의 DuckDuckGoSearchResults
수집 결과 스니펫/링크 모음 도구 반환값
요약 잡음 제거·핵심 정리 LLM
리포트 사람이 읽을 문서화 마크다운 + 파일 저장

핵심은 검색(사실 수집)과 요약(글쓰기)을 분업한다는 점입니다. 검색은 도구가, 요약은 LLM이 담당하죠.

2. 누가 검색을 결정하나 — 에이전트의 자율성

여기서 중요한 설계 선택이 있습니다. "검색을 언제, 몇 번 할지"를 누가 정하느냐입니다.

[방법 A] 사람이 코드로 강제: 검색() → 요약()  (07강 수동 루프 스타일)
[방법 B] 에이전트가 스스로 판단: create_agent에 도구만 주고 맡김  ← 이번 강

이번 강은 방법 B입니다. create_agent에 검색 도구를 넘기면, 에이전트가 스스로 "이 주제는 검색이 필요하군 → 검색 → 결과를 보니 부족하군 → 한 번 더 검색 → 이제 요약하자"를 반복합니다(7강 ReAct 루프). 우리는 주제만 던지면 됩니다.

from langchain_community.tools import DuckDuckGoSearchResults
from langchain.agents import create_agent

agent = create_agent(
    llm,
    tools=[DuckDuckGoSearchResults()],   # 검색 도구를 주면
    system_prompt="...시장 조사 애널리스트...",
)
# 검색 → 요약은 에이전트가 알아서 (우리는 주제만 던진다)
result = agent.invoke({"messages": [{"role": "user", "content": "...리포트 작성해줘"}]})

3. 시스템 프롬프트로 역할·출력 형식 고정

에이전트가 "아무 글"이나 쓰면 곤란합니다. 항상 같은 양식의 리포트가 나오도록 시스템 프롬프트로 역할과 출력 형식을 못박습니다(2강·3강).

system_prompt=(
    "너는 승승장구몰의 시장 조사 애널리스트다. "
    "주어진 주제를 웹에서 검색해 핵심 사실을 수집하고, "
    "한국어 마크다운 리포트로 정리하라. "
    "리포트는 '## 개요 / ## 핵심 동향 / ## 시사점' 섹션을 포함한다."
)

이렇게 하면 어떤 주제를 넣어도 개요·핵심 동향·시사점 세 섹션을 갖춘 리포트가 나옵니다. 출력 형식을 고정하는 건 자동화의 기본이죠 — 뒷단에서 파싱·저장·비교하기 쉬워지니까요.

4. 9강과 무엇이 다른가

9강에서도 검색 도구를 붙인 에이전트를 만들었습니다. 22강은 그걸 리포트 생산으로 발전시킵니다.

[9강]  질문 → 검색 → 답변 (일회성 Q&A, 화면 출력)
[22강] 주제 → 검색 → 요약 → 마크다운 리포트 → 파일 저장 (재사용 가능한 산출물)
        + 폴백(03번) + 하위질의 분해(06번) + 교차검증(07번)

9강이 "물어보면 검색해서 답하는 챗봇"이었다면, 22강은 "주제를 주면 보고서를 만들어 파일로 떨어뜨리는 자동 애널리스트" 입니다. 산출물(.md)이 남고, 배치로 돌릴 수 있다는 게 결정적 차이죠.

5. 전체 그림

이번 강에서 만들 코드의 구조를 미리 봅니다.

  • build_research_agent() — 검색 도구 붙인 에이전트 생성
  • research(topic) — 에이전트 호출(검색·요약 자동), 실패 시 폴백
  • save_report(topic, body) — 결과를 reports/*.md 로 저장

함수를 세 개로 분리한 이유는 재사용·테스트 때문입니다. 배치 스케줄러는 research → save_report만 호출하면 되고, API는 research() 결과를 바로 JSON으로 응답할 수 있죠. 모듈화는 운영의 기본입니다.

핵심 정리

  • 리서치 에이전트 = 검색 → 수집 → 요약 → 리포트 4단계.
  • 검색은 도구(사실 수집), 요약은 LLM(글쓰기)으로 분업.
  • create_agent에 도구를 주면 에이전트가 스스로 검색·요약(ReAct 루프).
  • 시스템 프롬프트로 역할·출력 형식(섹션 구조)을 고정 → 자동화에 유리.
  • 9강 Q&A를 재사용 가능한 리포트 산출물로 발전시킨 것.
  • 다음 절에서 네트워크 의존성과 폴백을 다룹니다.
