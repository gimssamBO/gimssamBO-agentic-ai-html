따라하기 — 리서치 에이전트와 폴백

목표

검색 도구를 붙인 리서치 에이전트를 만들고, 주제를 던지면 검색→요약으로 마크다운 리포트를 생성하게 합니다. 검색 실패 시에는 LLM 지식만으로 임시 리포트를 만드는 폴백을 붙입니다.

0. 실습 준비

conda activate agentic
pip install -U ddgs                 # DuckDuckGo 검색 백엔드 (이미 있으면 생략)
pip install -U langchain langchain-community langchain-google-genai
python code/common.py              # 환경/키 점검

⚠️ 이 실습은 인터넷 연결이 필요합니다. 오프라인이거나 검색이 차단된 환경에서는 아래 코드의 폴백 분기가 실행되어, 검색 없이 LLM 지식만으로 임시 리포트를 생성합니다. (즉, 네트워크가 없어도 코드는 끝까지 돌아갑니다.)

  • ddgs: DuckDuckGoSearchResults가 내부적으로 쓰는 검색 패키지. API 키가 필요 없습니다.
  • GOOGLE_API_KEY: .env에 있어야 LLM(Gemini)이 동작합니다.

1. 검색 도구를 붙인 에이전트

code/ch22_research.py를 만듭니다. 먼저 임포트와 에이전트 빌더입니다.

# -*- coding: utf-8 -*-
# 실행: python code/ch22_research.py
import sys, pathlib, datetime
sys.path.append(str(pathlib.Path(__file__).resolve().parent))  # code/ 를 import 경로에
from common import get_chat

# DuckDuckGoSearchResults: 키가 필요 없는 무료 웹 검색 도구(ddgs 패키지 기반).
#   [왜 검색 도구] LLM은 학습 시점 이후의 '최신 정보'를 모른다(지식 컷오프).
#   웹 검색으로 실시간 사실을 끌어와 답을 '사실에 근거(grounding)'시킨다.
from langchain_community.tools import DuckDuckGoSearchResults
from langchain.agents import create_agent   # LLM+도구를 묶어 스스로 도구를 쓰는 에이전트 생성


def build_research_agent():
    """웹 검색 도구를 붙인 리서치 에이전트를 만들어 반환한다.

    create_agent 에 검색 도구를 넘기면, 에이전트가 스스로
    '검색 → 결과 수집 → 요약'을 반복해 리포트를 만든다.
    """
    llm = get_chat(temperature=0.3)   # [왜 0.3] 사실 수집이지만 리포트 서술력도 필요해 약간 높임
    search = DuckDuckGoSearchResults()  # 검색 도구 인스턴스(키 불필요)
    agent = create_agent(
        llm,
        tools=[search],                 # 이 도구를 언제 쓸지는 LLM이 스스로 판단
        system_prompt=(                 # 역할·출력형식을 고정하는 시스템 프롬프트
            "너는 승승장구몰의 시장 조사 애널리스트다. "
            "주어진 주제를 웹에서 검색해 핵심 사실을 수집하고, "
            "한국어 마크다운 리포트로 정리하라. "
            "리포트는 '## 개요 / ## 핵심 동향 / ## 시사점' 섹션을 포함한다."
        ),
    )
    return agent

짚어 둘 점

  • DuckDuckGoSearchResults() — 키 없이 바로 쓰는 검색 도구. ddgs 패키지가 백엔드.
  • temperature=0.3 — 분류(0.0)와 달리 리포트는 서술이 필요해 약간 높였습니다. 너무 높이면 사실에서 벗어나니 0.3 정도가 적당.
  • tools=[search] — 검색을 언제 할지는 LLM이 판단합니다(7강 ReAct). 우리는 도구만 쥐여 주죠.

2. 조사 실행 + 폴백 처리

검색은 외부 네트워크라 실패할 수 있습니다. try/except로 감싸고, 실패 시 검색 없는 LLM으로 폴백합니다(03번).

def research(topic: str) -> str:
    """주제를 조사해 마크다운 리포트 본문(문자열)을 반환한다.

    [왜 try/except] 검색은 외부 네트워크에 의존한다. 단절·rate limit 으로
    실패할 수 있으므로, 실패해도 서비스가 죽지 않도록 폴백 분기를 둔다.
    """
    try:
        agent = build_research_agent()
        # 에이전트 호출: messages 에 사용자 요청을 담아 보낸다(검색→요약은 내부에서 자동).
        result = agent.invoke({"messages": [{"role": "user",
                              "content": f"'{topic}' 주제로 시장 동향 리포트를 작성해줘."}]})
        return result["messages"][-1].text   # 마지막 메시지 = 최종 리포트 본문
    except Exception as e:
        # 네트워크/검색 실패 → 검색 없이 LLM 지식만으로 임시 리포트(폴백)
        print(f"[경고] 웹 검색 실패 → 오프라인 폴백 사용: {e}")
        llm = get_chat(temperature=0.3)
        prompt = (f"'{topic}'에 대해 아는 범위에서 한국어 마크다운 리포트를 작성하라. "
                  "본문에 '## 개요', '## 핵심 동향', '## 시사점' 세 섹션을 정확히 이 머리말로 포함하라"
                  "(머리말을 중복해서 붙이지 말 것). "
                  "맨 위에 최신 정보가 아닐 수 있다는 주의문구 한 줄을 넣어라.")
        return llm.invoke(prompt).text

result["messages"][-1].text 가 핵심입니다. 에이전트는 대화 메시지 리스트를 돌려주는데, 마지막 메시지가 최종 리포트입니다. .text로 본문 문자열만 꺼냅니다.

.text vs .content: Gemini 응답은 내부적으로 여러 블록(content parts)으로 올 수 있어, 본문 텍스트만 안전하게 꺼내려면 .text를 씁니다(19강에서 다룬 차이). 에이전트가 돌려준 메시지에서도 같은 원리입니다.

3. 실행해 보기

아직 save_report는 05번에서 붙입니다. 일단 본문 생성까지 확인합니다.

if __name__ == "__main__":
    topic = "경쟁 무선이어버드 시장 동향"
    print(f"[조사 시작] {topic}")
    body = research(topic)        # 검색→요약(또는 폴백) → 리포트 본문
    print("=" * 60)
    print(body[:600], "...")      # 앞부분만 미리보기
    print("=" * 60)

관찰 포인트: 검색이 되면 최신 스니펫을 요약한 리포트가, 안 되면 폴백 리포트(경고 문구 포함)가 나옵니다. 어느 쪽이든 코드는 죽지 않고 결과를 돌려줍니다. 이게 폴백의 가치죠.

4. 에이전트가 내부에서 하는 일

research() 한 줄 뒤에서 에이전트는 이런 ReAct 루프를 돕니다.

사용자: "경쟁 무선이어버드 시장 동향 리포트 써줘"

  1. [생각] 최신 정보가 필요하다 → 검색하자
  2. [행동] DuckDuckGoSearchResults("무선이어버드 시장 동향 2026")
  3. [관찰] 스니펫 5개 수집 (ANC, 가격, 점유율 …)
  4. [생각] 정보가 충분하다 → 이제 섹션별로 요약하자
  5. [행동] 개요/핵심동향/시사점 마크다운 작성
  6. 최종 메시지 = 리포트 본문 → research()가 이걸 반환

우리는 도구와 주제만 줬는데, 검색 횟수·검색어·요약 시점을 에이전트가 알아서 정했습니다. 이게 "자율 에이전트"의 힘이죠(반면 06번에서는 우리가 검색을 더 통제합니다).

핵심 정리

  • pip install ddgs 후 DuckDuckGoSearchResults()로 키 없는 검색 도구 사용.
  • create_agent(llm, tools=[search], system_prompt=...)로 리서치 에이전트 생성.
  • temperature=0.3 — 사실 기반이되 서술력도 필요해 약간 높임.
  • result["messages"][-1].text — 마지막 메시지가 최종 리포트 본문.
  • try/except 폴백: 검색 실패 시 LLM 지식만으로 임시 리포트(경고 명시).
