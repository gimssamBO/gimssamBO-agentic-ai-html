[신규] 복잡한 주제를 하위 질의로 쪼개기

한 줄 요약

"무선이어버드 시장 동향"처럼 큰 주제를 검색어 하나로 던지면 결과가 얕습니다. LLM이 주제를 3~4개 하위 질의(예: "ANC 트렌드", "가격대 동향", "주요 기업")로 분해하고, 각각을 따로 검색해 종합 리포트로 합칩니다. 이를 plan-and-execute 리서치라 합니다.

1. 검색어 하나의 한계

04번 에이전트는 검색을 알아서 했지만, 큰 주제는 한 번 검색으로는 얕게 다뤄집니다.

검색어: "무선이어버드 시장 동향"
  → 결과: 두루뭉술한 개요 기사 몇 개
  → 가격, 기술, 경쟁사 같은 세부는 빠짐

사람 애널리스트는 큰 주제를 만나면 나눠서 조사합니다. "기술 트렌드는 따로, 가격대는 따로, 주요 기업은 따로 찾아보자." 이걸 코드로 옮긴 게 하위 질의 분해입니다.

[큰 주제] 무선이어버드 시장 동향 → LLM이 하위 질의로 분해:

  1. 무선이어버드 ANC 노이즈캔슬링 트렌드
  2. 무선이어버드 가격대 동향 2026
  3. 무선이어버드 주요 제조사 점유율

→ 각각 검색 → [종합] 세 결과를 하나의 리포트로 합침

8강(Plan-and-Execute)에서 배운 "목표를 단계로 쪼개기"를 리서치에 적용한 것이죠.

2. 구조화 출력으로 하위 질의 받기

LLM에게 "질의를 나눠 줘"라고 하면 자유 텍스트로 답해 파싱이 흔들립니다. 8강처럼 Pydantic 구조화 출력으로 리스트를 강제합니다.

pip install -U pydantic            # 이미 8강에서 설치했다면 생략

# 실행: python "sections/22_research_agent/06_복잡한-주제를-하위질의로-쪼개기.py"
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parents[2] / "code"))
from common import get_chat

from pydantic import BaseModel, Field
from langchain_community.tools import DuckDuckGoSearchResults
from ch22_research import save_report   # 리포트 저장은 기존 함수 재사용


class SubQueries(BaseModel):
    """[왜 구조화] LLM이 자유 텍스트로 질의를 내면 파싱이 흔들린다.
    Pydantic으로 '리스트'를 강제해 안정적으로 하위 질의를 받는다."""
    queries: list[str] = Field(description="원주제를 조사하기 위한 3~4개의 구체적 하위 검색 질의")

with_structured_output(SubQueries)를 쓰면, LLM이 무슨 말을 하든 결과가 queries: list[str] 형태로 보장됩니다. 뒷단에서 for q in queries로 바로 돌릴 수 있죠.

3. 주제 분해 함수

def split_topic(topic: str) -> list[str]:
    """큰 주제를 3~4개의 하위 질의로 분해한다(구조화 출력)."""
    llm = get_chat(temperature=0.2)
    structured = llm.with_structured_output(SubQueries)
    prompt = (
        f"너는 승승장구몰의 시장 조사 애널리스트다. 주제 '{topic}'를 깊이 조사하기 위해 "
        "서로 겹치지 않는 구체적 하위 검색 질의 3~4개로 쪼개라. "
        "각 질의는 한국어 검색어 형태로 작성하라."
    )
    try:
        return structured.invoke(prompt).queries[:4]   # 최대 4개로 제한
    except Exception as e:
        # 구조화 실패 시 최소한의 폴백 질의
        print(f"[경고] 질의 분해 실패 → 기본 질의 사용: {e}")
        return [f"{topic} 시장 규모", f"{topic} 최신 동향", f"{topic} 주요 기업"]

짚어 둘 점

  • temperature=0.2 — 질의를 일관되게 나누려고 낮게.
  • "서로 겹치지 않는" — 하위 질의가 비슷하면 같은 결과만 나오니, 다양성을 명시.
  • [:4] — 너무 많이 쪼개면 검색 횟수·비용이 늘어 4개로 상한.
  • 폴백 — 구조화마저 실패하면 기본 질의 3종으로라도 진행(03번 폴백 정신).

4. 하위 질의별 검색 (각각 폴백)

각 하위 질의를 따로 검색합니다. 질의 하나가 실패해도 전체가 멈추면 안 되니, 검색 단위로 폴백을 둡니다.

def search_one(query: str) -> str:
    """하위 질의 하나를 웹 검색해 결과 텍스트를 반환한다(실패 시 폴백)."""
    try:
        return DuckDuckGoSearchResults().invoke(query)
    except Exception as e:
        # [왜 폴백] 한 질의의 네트워크 실패로 전체 조사가 멈추면 안 된다.
        print(f"[경고] 검색 실패('{query}') → LLM 지식으로 대체: {e}")
        llm = get_chat(temperature=0.3)
        return llm.invoke(f"'{query}'에 대해 아는 범위에서 핵심 사실 3가지를 한국어로 정리하라.").content

질의별 폴백의 가치: 4개 중 1개만 검색이 막혀도, 나머지 3개는 정상 검색되고 막힌 1개만 LLM 지식으로 메웁니다. 부분 실패가 전체 실패로 번지지 않죠.

5. 결과 종합 — 하나의 리포트로

질의별 검색 결과를 모아 LLM에게 하나의 리포트로 합치게 합니다.

def synthesize(topic: str, findings: list[tuple]) -> str:
    """하위 질의별 검색 결과들을 하나의 마크다운 리포트로 종합한다."""
    llm = get_chat(temperature=0.3)
    # 각 결과를 1200자로 잘라 붙임(토큰 절약). findings = [(질의, 검색결과), ...]
    blocks = "\n\n".join(f"[하위질의] {q}\n{r[:1200]}" for q, r in findings)
    prompt = (
        f"주제: {topic}\n아래는 하위 질의별 검색 결과다. 이를 종합해 한국어 마크다운 리포트를 작성하라.\n"
        "'## 개요 / ## 핵심 동향 / ## 시사점' 섹션을 정확히 이 머리말로 포함하라.\n\n"
        f"{blocks}"
    )
    return llm.invoke(prompt).content

r[:1200] — 검색 결과를 1200자로 자릅니다. 결과가 길면 토큰이 폭증하니, 핵심만 넣어 비용·속도를 관리합니다(7강 토큰 관리). 4개 질의 × 1200자면 약 5천 자, 한 번에 종합하기 적당하죠.

6. 전체 파이프라인

분해 → 검색 → 종합을 한 함수로 잇습니다.

def deep_research(topic: str) -> str:
    """주제 분해 → 하위 검색 → 종합의 전체 파이프라인."""
    queries = split_topic(topic)                 # 1) 분해
    print(f"[분해] {len(queries)}개 하위 질의:")
    for i, q in enumerate(queries):
        print(f"  [{i}] {q}")
    findings = []
    for i, q in enumerate(queries):              # 2) 질의별 검색
        print(f"[검색 {i}] {q} ...")
        findings.append((q, search_one(q)))
    return synthesize(topic, findings)           # 3) 종합

7. 04번 방식과 비교

04번 (에이전트 자율) 06번 (하위 질의 분해)
검색 통제 에이전트가 알아서 우리가 분해·검색 횟수 통제
깊이 주제에 따라 들쭉날쭉 측면별로 고르게 깊음
비용 예측 어려움(몇 번 검색할지 모름) 쉬움(질의 수 = 검색 수)
적합 가벼운 단발 조사 깊이 있는 정기 리포트

둘 다 쓸모가 있습니다. 가벼운 조사는 04번, 깊이가 필요한 정기 리포트는 06번이 어울리죠.

핵심 정리

  • 큰 주제를 검색어 하나로 던지면 결과가 얕음.
  • LLM이 3~4개 하위 질의로 분해(구조화 출력 with_structured_output) → 각각 검색 → 종합.
  • 8강 Plan-and-Execute를 리서치에 적용한 패턴.
  • 질의별 폴백으로 부분 실패가 전체 실패로 번지지 않게.
  • 검색 결과는 1200자로 잘라 토큰·비용 관리.
  • 04번(자율)보다 비용 예측·측면별 깊이가 좋음. 다음 절에서 결과를 교차 검증합니다.
