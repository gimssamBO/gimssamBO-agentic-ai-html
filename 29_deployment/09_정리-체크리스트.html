정리 & 체크리스트

이번 강에서 배운 것

29강은 데모 코드를 운영 가능한 서비스로 끌어올렸습니다. "내 PC에선 됐는데요"를 막는 4대 요소가 핵심입니다.

  • 운영 4대 요소 (01번) — ① 설정 분리 ② 로깅 ③ 예외/재시도 ④ 비용 관리. 모델만 좋다고 서비스가 되는 게 아니다.
  • 설정 분리 (02번) — 비밀(키)은 .env, 설정(모델·온도)은 config.yaml. 하드코딩 제거 → 코드 수정 없이 환경 전환.
  • 구조적 로깅 (03번) — print 대신 logging. 시각·레벨 + 콘솔·파일 동시. handlers.clear()로 중복 방지.
  • 예외/재시도 (04번) — 지수 백오프(1→2→4초) 재시도 + 폴백 메시지. 끝내 실패해도 서비스는 안 죽는다.
  • 비용·지연 (05번) — 모델 선택·프롬프트 길이·top_k·캐싱으로 토큰=비용 관리.
  • 견고한 래퍼 (06번) — load_config·setup_logging·robust_invoke를 묶은 운영 자산.
  • FastAPI (07번) — POST /chat으로 HTTP 노출. 비즈니스 로직과 전송 계층 분리.
  • 응답 캐싱 (08번) — 반복 질문은 저장된 답으로(0원·즉시). 메모리+파일 영속, 정규화 key.

핵심 코드 한눈에

# 1) 설정 분리
def load_config():
    with open(DATA / "config.yaml", encoding="utf-8") as f:
        return yaml.safe_load(f)

# 2) 구조적 로깅 (콘솔+파일)
logger.handlers.clear()
logger.addHandler(StreamHandler()); logger.addHandler(FileHandler(path))

# 3) 재시도 + 폴백
for attempt in range(1, max_retries + 1):
    try: return llm.invoke(message).content
    except Exception: time.sleep(2 ** (attempt - 1))   # 지수 백오프
return "죄송합니다. 일시적인 오류로 ..."                  # 폴백

# 4) FastAPI 노출
@app.post("/chat")
def chat(body: ChatIn):
    return {"reply": robust_invoke(llm, body.message, logger)}

# 5) 캐싱
hit = cache.get(q)
if hit: return hit                  # 캐시 적중 → LLM 안 부름
ans = robust_invoke(...); cache.set(q, ans)

설치 라이브러리

conda activate agentic
pip install -U pyyaml langchain-google-genai     # 06번 운영 래퍼
pip install -U fastapi uvicorn                    # 07번 HTTP API
# 08번 캐싱은 표준 라이브러리(json, hashlib)만 사용 — 추가 설치 없음
  • pyyaml: config.yaml 로드.
  • fastapi·uvicorn: HTTP 엔드포인트와 서버 구동.
  • 데이터·설정: data/config.yaml, .env(GOOGLE_API_KEY).

한 줄 핵심

"모델이 좋아도 서비스가 되진 않는다." — 설정 분리·로깅·재시도/폴백·비용 관리, 이 운영 품질이 데모와 제품을 가른다.

다음 강 예고 — 30강 (마지막)

드디어 마지막입니다. 28강의 설계와 29강의 운영을 토대로, 지금까지 배운 모든 조각(도구·RAG·메모리)을 하나로 합칩니다. "진짜로 일하는 승승장구몰 통합 CS 에이전트" 를 완성하죠. 1강에서 LLM이 "답 못 했던" 질문 — "내 주문 O000123 어디까지 왔어?" — 을 30강의 에이전트는 실제 데이터를 조회해 답합니다. 30강에서 이 래퍼·캐싱 같은 운영 자산이 완성형 에이전트를 감쌉니다.
