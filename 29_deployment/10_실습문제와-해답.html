문제 1 — 재시도 + 캐싱 + 로깅 강화

요구사항

code/ch29_deploy.py를 복사해 code/ch29_ex_robust.py를 만드세요.

  • robust_invoke에 질문 단위 캐시(dict 또는 functools.lru_cache)를 붙여, 동일 질문 반복 시 LLM을 호출하지 않고 캐시로 답한다.
  • 각 호출마다 logger로 "캐시 적중/미스", 시도 횟수, 소요시간을 기록한다.
  • max_retries는 config.yaml의 llm.max_retries에서 읽는다.
  • 기대 결과: 같은 질문을 두 번 던지면 두 번째에 "캐시 적중" 로그가 찍히고 LLM 재호출이 없다.

해답

# code/ch29_ex_robust.py
# 실행: python code/ch29_ex_robust.py
import sys, pathlib, time
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat
from ch29_deploy import load_config, setup_logging   # 운영 자산 재사용

_CACHE = {}   # 질문 → 답변 (간단한 메모리 캐시)


def robust_invoke_cached(llm, message: str, logger, max_retries: int = 3) -> str:
    """캐시 + 재시도 + 폴백 + 소요시간 로깅을 모두 갖춘 호출 래퍼."""
    # 1) 캐시 확인
    if message in _CACHE:
        logger.info(f"캐시 적중(HIT) — LLM 호출 생략: {message}")
        return _CACHE[message]
    logger.info(f"캐시 미스(MISS) — LLM 호출 시작: {message}")

    # 2) 재시도 + 소요시간 측정
    for attempt in range(1, max_retries + 1):
        t0 = time.time()
        try:
            logger.info(f"LLM 호출 시도 {attempt}/{max_retries}")
            resp = llm.invoke(message)
            elapsed = time.time() - t0
            logger.info(f"LLM 호출 성공 (소요 {elapsed:.2f}초)")
            _CACHE[message] = resp.content        # 3) 결과 캐시 저장
            return resp.content
        except Exception as e:
            wait = 2 ** (attempt - 1)
            logger.warning(f"실패({attempt}회): {e} → {wait}초 후 재시도")
            time.sleep(wait)

    logger.error("최종 실패 — 폴백 응답 반환")
    return "죄송합니다. 일시적인 오류로 답변을 생성하지 못했습니다."


if __name__ == "__main__":
    cfg = load_config()
    logger = setup_logging(cfg)
    llm = get_chat(provider=cfg["llm"]["provider"], temperature=cfg["llm"]["temperature"])
    mr = cfg["llm"]["max_retries"]                 # config에서 재시도 횟수

    q = "승승장구몰 무료배송 기준을 한 문장으로 알려줘."
    print("[1차]", robust_invoke_cached(llm, q, logger, mr))   # MISS → LLM 호출
    print("[2차]", robust_invoke_cached(llm, q, logger, mr))   # HIT  → 캐시

예상 출력 (로그)

... [INFO] 캐시 미스(MISS) — LLM 호출 시작: 승승장구몰 무료배송 기준...
... [INFO] LLM 호출 시도 1/3
... [INFO] LLM 호출 성공 (소요 0.82초)
[1차] 3만원 이상 구매 시 무료배송입니다.
... [INFO] 캐시 적중(HIT) — LLM 호출 생략: 승승장구몰 무료배송 기준...
[2차] 3만원 이상 구매 시 무료배송입니다.

관찰 포인트

  • 2차 호출은 "캐시 적중" 로그만 찍히고 LLM 호출이 없습니다(시도 로그 없음).
  • 소요시간을 time.time()으로 측정해 기록 → 성능 추적 가능.
  • max_retries를 config에서 읽어, 코드 수정 없이 재시도 횟수 조절(02번).

문제 2 — FastAPI 서버 작성

요구사항

code/ch29_ex_api.py를 작성하세요.

  • FastAPI로 POST /ask(body: {"question": "..."}) 엔드포인트를 만든다.
  • 내부에서 robust_invoke로 LLM을 호출하고 {"answer": "..."}를 반환한다.
  • 예외 시 500 대신 {"error": ...} 를 반환한다.
  • 검증: uvicorn ch29_ex_api:app로 띄운 뒤 curl -X POST localhost:8000/ask ... -d '{"question":"무료배송 기준"}'로 정상 JSON 응답 확인.

해답

# code/ch29_ex_api.py
# 실행(서버): uvicorn ch29_ex_api:app --reload   (code/ 폴더에서)
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat
from ch29_deploy import load_config, setup_logging, robust_invoke

from fastapi import FastAPI
from pydantic import BaseModel

# 설정·로거·LLM은 서버 시작 시 1회만 생성
cfg = load_config()
logger = setup_logging(cfg)
llm = get_chat(provider=cfg["llm"]["provider"], temperature=cfg["llm"]["temperature"])

app = FastAPI(title="승승장구몰 Q&A API")


class AskIn(BaseModel):
    question: str               # 입력 자동 검증(없으면 422)


@app.post("/ask")
def ask(body: AskIn):
    """[POST /ask] 질문을 받아 답변을 반환. 예외 시 {'error':...} 반환."""
    try:
        logger.info(f"질문 수신: {body.question}")
        answer = robust_invoke(llm, body.question, logger,
                               max_retries=cfg["llm"]["max_retries"])
        return {"answer": answer}
    except Exception as e:
        # robust_invoke 자체는 폴백을 주지만, 그 외 예외도 500 대신 JSON으로
        logger.error(f"엔드포인트 오류: {e}")
        return {"error": "요청 처리 중 오류가 발생했습니다."}

검증 실행

# 서버 띄우기 (code/ 폴더에서)
uvicorn ch29_ex_api:app --reload

# 다른 터미널에서 호출
curl -X POST localhost:8000/ask -H "Content-Type: application/json" \
     -d '{"question":"무료배송 기준"}'

# 응답
{"answer":"3만원 이상 구매 시 무료배송입니다."}

관찰 포인트

  • POST /ask 가 {"question":...}를 받아 {"answer":...}를 반환 — 깔끔한 JSON 계약.
  • 내부는 06번 robust_invoke 재사용(재시도·폴백 그대로).
  • try/except로 예외를 잡아 500 대신 {"error":...} — 클라이언트가 다루기 쉬운 응답.
  • http://localhost:8000/docs에서 자동 문서로 바로 테스트 가능.
