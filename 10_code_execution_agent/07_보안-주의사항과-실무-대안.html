보안 주의사항과 실무 대안

한 줄 요약

화이트리스트 eval(03번)은 위험을 줄이지만 완벽한 방어는 아닙니다. 외부 사용자 입력을 그대로 실행하지 말고, 실무에서는 별도 샌드박스(격리 환경) 에서 코드를 실행하는 것이 안전합니다.

1. 왜 코드 실행은 본질적으로 위험한가

코드 실행 에이전트는 강력합니다 — 어떤 분석이든 코드만 바꾸면 되니까요. 하지만 그 유연함의 대가가 위험입니다. "임의의 코드를 실행한다"는 건, 악의적 코드도 실행될 수 있다는 뜻이거든요.

# 만약 누군가 이런 식을 주입할 수 있다면?
"파일 삭제", "비밀번호 읽기", "외부로 데이터 전송"

03번의 화이트리스트({"__builtins__": {}} + df, pd만)는 이런 시도를 상당 부분 막습니다. 하지만 보안에서 "상당 부분"은 충분하지 않을 수 있습니다.

2. 화이트리스트의 한계

{"__builtins__": {}}로 빌트인을 막아도, 정교한 우회가 가능할 수 있습니다.

  • pandas 자체의 위험 기능: pandas에도 파일을 읽고 쓰는 기능(df.to_csv, pd.read_csv)이 있습니다. pd를 노출했으니 이론적으로 접근 가능합니다.
  • 객체 탐색을 통한 우회: 파이썬 객체의 속성을 타고 들어가 차단된 기능에 도달하는 고급 기법이 존재합니다.

즉, 화이트리스트는 "실수로 인한 사고"나 "단순한 공격" 은 막지만, 작정한 공격자는 우회할 여지가 있습니다.

비유: 화이트리스트는 현관문 잠금입니다. 일반적인 침입은 막지만, 전문 도둑은 창문을 노릴 수 있죠. 정말 중요한 걸 지키려면 금고(샌드박스) 가 따로 필요합니다.

3. 황금률 — 외부 입력을 그대로 실행하지 마라

가장 중요한 원칙입니다.

신뢰할 수 없는 외부 사용자의 입력을, 코드로 그대로 실행하지 마라.

이 강의 실습은 개발자가 통제하는 환경(우리가 만든 데이터, 우리가 던지는 질문)이라 비교적 안전합니다. 하지만 만약 이 에이전트를 외부 고객에게 공개한다면, 고객이 악의적 프롬프트로 위험한 코드를 유도할 수 있습니다(3강 프롬프트 인젝션 복습).

  • ✅ 사내 분석 도구 (개발자·분석가만 사용) → 화이트리스트 eval로 충분할 수 있음
  • ⚠️ 외부 고객 대상 서비스 → 반드시 샌드박스 필요

4. 실무 대안 ① — 샌드박스

샌드박스(sandbox) 는 코드를 격리된 환경에서 실행하는 것입니다. 그 안에서 무슨 일이 일어나도 바깥(진짜 시스템)에는 영향이 없습니다.

  • 별도 프로세스: 권한을 제한한 별도 프로세스에서 실행 (오류·악성 코드가 메인을 못 건드림)
  • 컨테이너(Docker): 격리된 컨테이너에서 실행, 끝나면 폐기

  • 전용 샌드박스 서비스: 코드 실행 전용 격리 환경 (클라우드 서비스로도 제공됨)

  • 메인 시스템 → (코드 전송) → 샌드박스(격리 환경)

  • 샌드박스에서 코드 실행 — 위험해도 격리돼 있어 본 시스템에 영향 없음
  • 샌드박스 → (결과만) → 메인 시스템 으로 반환

샌드박스가 망가져도 버리고 새로 만들면 되니, 진짜 시스템은 안전합니다.

5. 실무 대안 ② — 더 안전한 실행 방식

eval 자체를 피하는 방법도 있습니다.

  • AST 파싱·검증: 코드를 실행 전에 분석해, 허용된 연산만 있는지 검사한 뒤 실행.
  • 제한된 쿼리 언어: 자유로운 코드 대신, 안전한 쿼리 API(예: pandas의 df.query())나 SQL만 허용.
  • 함수 화이트리스트: 자유 코드 대신, 미리 만든 안전한 분석 함수들 중에서만 고르게 함(5강 방식으로 회귀).

각 방식은 "유연함 ↔ 안전함"의 트레이드오프가 있습니다. 더 안전할수록 할 수 있는 게 줄어들죠.

6. 정리 — 환경에 맞는 안전 수준

환경 권장 안전장치
학습·실습 (이 강의) 화이트리스트 eval
사내 분석 도구 화이트리스트 eval + 입력 검증
외부 공개 서비스 샌드박스 필수 (별도 프로세스/컨테이너)

핵심은 "이 코드가 잘못되면 얼마나 위험한가" 를 따져 안전 수준을 정하는 것입니다. 위험이 클수록 더 강한 격리가 필요합니다.

핵심 정리

  • 화이트리스트 eval은 위험을 줄이지만 완벽하지 않다(pandas 기능·우회 가능).
  • 황금률: 외부 입력을 코드로 그대로 실행하지 마라.
  • 실무 대안: 샌드박스(별도 프로세스·컨테이너)로 격리 실행.
  • 더 안전하게: AST 검증, 제한된 쿼리, 함수 화이트리스트.
  • 환경의 위험 수준에 맞게 안전장치를 고른다.
