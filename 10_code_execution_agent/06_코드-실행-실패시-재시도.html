코드 실행 실패 시 재시도 (self-correcting)

한 줄 요약

LLM이 만든 pandas 식이 항상 맞지는 않습니다(컬럼 오타·잘못된 메서드 등). 실행 실패 시 오류 메시지를 그대로 LLM에 피드백해 식을 고쳐 다시 실행하는 자가교정(self-correcting) 루프를 만듭니다.

1. LLM이 만든 코드도 틀린다

LLM은 pandas 코드를 잘 만들지만 완벽하진 않습니다. 특히 이런 실수를 합니다.

# 존재하지 않는 컬럼
"df['revenue'].sum()"        # → 실행 오류: 'revenue' (컬럼명은 sales인데!)

# 잘못된 메서드
"df['sales'].total()"        # → 실행 오류: 'total' 메서드 없음 (sum()이어야)

# 없는 개념 (요일 컬럼이 없는데 요일별 집계 시도)
"df.groupby('weekday')..."   # → 실행 오류: 'weekday' 없음

이때 그냥 "실행 오류"로 끝내면 사용자는 답을 못 받습니다. 하지만 오류 메시지를 보면 무엇이 틀렸는지 알 수 있죠. 그걸 LLM에게 알려 주면 고칠 수 있습니다.

비유: 사람도 코드를 짜다 오류가 나면, 에러 메시지를 읽고 "아, 컬럼명을 잘못 썼네"하고 고칩니다. LLM에게도 똑같이 에러 메시지를 보여 주면 스스로 고칩니다.

2. 자가교정 루프

핵심 아이디어: 식 생성 → 실행 → 실패하면 오류를 피드백해 다시 생성. 이건 8강의 "계획 검증 → 재계획"과 같은 패턴입니다. (실습 파일: sections/10_code_execution_agent/06_코드-실행-실패시-재시도.py)

1차: 식 생성 → 실행 → 실패 → 오류 메시지 기억
2차: (오류를 보여 주며) 식 다시 생성 → 실행 → 성공!

3. 오류를 피드백하는 식 생성

make_expr에 이전 오류를 함께 넘겨, LLM이 고치게 합니다.

SYSTEM = (
    "너는 승승장구몰의 데이터 분석가다. 일별 매출 DataFrame df(컬럼: date, sales)에 대해 "
    "질문에 답할 pandas 식 '한 줄'만 출력하라. 식 안에서는 df, pd 만 쓸 수 있다. "
    "코드블록·설명 없이 식만 출력하라."
)

def make_expr(question: str, error_feedback: str = "") -> str:
    """질문(과 이전 오류 피드백)을 받아 pandas 식 한 줄을 생성한다."""
    prompt = f"{SYSTEM}\n\n질문: {question}"
    if error_feedback:
        # 직전 실패의 오류 메시지를 그대로 보여주고 고치게 한다 (self-correcting)
        prompt += (
            f"\n\n[직전 시도가 실패했다] 오류: {error_feedback}\n"
            "위 오류를 고쳐 올바른 pandas 식 한 줄을 다시 출력하라. "
            "존재하는 컬럼은 date, sales 뿐임을 명심하라."
        )
    return llm.invoke(prompt).content.strip()

error_feedback이 있으면 "직전 시도가 이 오류로 실패했다. 고쳐라"라고 알려 줍니다. "존재하는 컬럼은 date, sales 뿐"이라는 힌트도 함께 줘서 같은 실수를 막습니다.

4. 재시도 루프

def answer_with_retry(question: str, max_retries: int = 3):
    """식 생성 → 실행 → 실패 시 오류를 피드백해 다시 식을 만드는 자가교정 루프."""
    feedback = ""
    for step in range(1, max_retries + 1):
        expr = make_expr(question, feedback)
        print(f"[STEP {step}] 생성된 식: {expr}")
        result = run_pandas(expr)

        if not result.startswith("실행 오류:"):
            print(f"[STEP {step}] 실행 성공 → 결과: {result}")
            return result               # 성공!

        # 실패 → 오류 메시지를 다음 시도의 피드백으로 넘긴다
        print(f"[STEP {step}] 실행 실패 → {result} (오류를 피드백해 재시도)")
        feedback = result

    print("[종료] 최대 재시도 초과")
    return None

feedback 변수가 핵심입니다. 실패하면 그 오류 메시지를 feedback에 담아 다음 make_expr에 넘깁니다. max_retries는 7·8강에서 배운 안전장치(무한 재시도 방지)입니다.

5. 실패 → 교정 흐름 보기

일부러 존재하지 않는 개념(revenue, 요일)을 끌어내 첫 식이 틀리게 유도합니다.

answer_with_retry("매출(revenue)이 가장 높았던 요일은 무슨 요일이야?")

예상 출력

[STEP 1] 생성된 식: df.groupby(df['date'].dt.dayofweek)['revenue'].sum()...
[STEP 1] 실행 실패 → 실행 오류: 'revenue' (오류를 피드백해 재시도)
[STEP 2] 생성된 식: df.assign(요일=pd.to_datetime(df['date']).dt.day_name()).groupby('요일')['sales'].sum().idxmax()
[STEP 2] 실행 성공 → 결과: Wednesday

1차에서 revenue(없는 컬럼)를 써서 실패했지만, 오류 메시지를 받아 2차에서 올바른 컬럼(sales)으로 고쳐 성공했습니다. LLM이 스스로 디버깅한 거죠.

6. 이 패턴의 중요성

"생성 → 실행 → 오류 피드백 → 재생성"은 AI 에이전트의 핵심 능력 중 하나입니다. 사람 개발자가 에러를 보며 코드를 고치듯, 에이전트도 그렇게 합니다.

  • 8강: 계획 검증 → 재계획
  • 10강: 코드 실행 → 오류 피드백 → 재시도 (지금)
  • 23강: 코딩 에이전트의 재귀적 버그 수정 (더 본격적)

LLM의 첫 시도를 그냥 믿지 않고, 실패하면 이유를 알려 고치게 하는 거죠. 이게 신뢰할 수 있는 에이전트의 조건입니다.

핵심 정리

  • LLM이 만든 코드도 틀릴 수 있다(컬럼 오타·잘못된 메서드).
  • 오류 메시지를 LLM에 피드백해 스스로 고치게 한다(self-correcting).
  • feedback 변수로 직전 오류를 다음 시도에 전달, max_retries로 상한.
  • LLM이 에러를 보며 스스로 디버깅한다.
  • 23강에서 이 자가교정을 더 본격적으로 다룬다.
