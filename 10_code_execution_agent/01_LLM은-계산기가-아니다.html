LLM은 계산기가 아니다

한 줄 요약

LLM에게 "이 600일치 매출 다 더해줘"라고 하면 그럴듯하지만 틀린 숫자를 내놓곤 합니다. LLM은 언어 모델이지 계산기가 아니기 때문입니다. 해결책은 사람과 똑같습니다 — 계산은 계산기(코드)에게 시키는 것.

1. LLM의 계산 약점

4강에서 LLM이 암산을 자주 틀린다고 배웠습니다. 단순 계산도 그런데, 큰 데이터의 집계는 더 심합니다.

ask("이 600일치 일별 매출을 모두 더하면 얼마야? [324560, 198320, ...]")
# → "약 3억 2천만원 정도입니다" (그럴듯하지만 정확하지 않음!)

LLM은 숫자를 하나하나 정확히 더하는 게 아니라, "이 정도 규모면 3억쯤?"이라고 어림짐작합니다. 600개 숫자의 정확한 합계, 정렬, 그룹별 집계 — 이런 건 LLM의 명백한 약점입니다.

비유: LLM은 글을 잘 쓰는 작가입니다. 작가에게 "이 영수증 100장 금액을 정확히 합산해줘"라고 하면, 대충 가늠은 해도 정확한 합계는 계산기로 두드려야 나옵니다. 작가의 일과 계산기의 일은 다르죠.

2. 해결책 — 계산은 코드에게

사람도 정확한 계산이 필요하면 계산기나 엑셀을 씁니다. LLM도 똑같이 하면 됩니다.

나쁜 방법: LLM이 머릿속으로 더함 → 오차·환각 가능
좋은 방법: LLM이 '계산 코드'를 만듦 → 우리가 실행 → 정확한 값

핵심은 역할 분담입니다.

  • LLM: "어떤 계산을 해야 하는가"를 안다 → pandas 코드를 생성
  • 코드(pandas): 그 계산을 정확히 수행
# LLM이 만드는 것: 계산 '방법'(코드)
"df['sales'].sum()"

# 코드가 하는 것: 실제 '계산'
df['sales'].sum()   # → 324286050 (정확!)

LLM은 df['sales'].sum()이라는 올바른 코드를 만들 줄 압니다. 그 코드를 우리가 실행하면 정확한 합계가 나오죠. "무엇을 계산할지는 LLM이, 실제 계산은 코드가" 맡는 겁니다.

3. 5강 도구의 또 다른 형태

이건 사실 5강에서 배운 "도구 호출"의 한 형태입니다. 다만 도구가 "코드를 실행하는 도구" 라는 게 특별합니다.

강 도구가 하는 일
5강 정해진 함수 실행 (get_stock)
9강 웹 검색 (DuckDuckGoSearchResults)
10강 LLM이 만든 코드를 실행 (run_pandas)

5·9강의 도구는 "고정된 기능"이었습니다. 10강의 도구는 LLM이 그때그때 만든 코드를 실행하므로 훨씬 유연합니다 — 어떤 집계든 코드만 바꾸면 되니까요.

4. 이 강에서 만들 것

일별 매출 데이터(data/sales_daily.csv, 컬럼: date, sales)를 분석하는 에이전트를 만듭니다.

"전체 기간 총 매출은?"       → LLM이 df['sales'].sum() 생성 → 실행 → 정확한 합계
"일평균 매출은?"            → LLM이 df['sales'].mean() 생성 → 실행 → 정확한 평균
"매출 최고일은?"           → LLM이 df.loc[df['sales'].idxmax(), 'date'] 생성 → 실행

자연어로 물으면, LLM이 적절한 pandas 코드를 만들고, 우리 도구가 실행해 정확한 답을 돌려줍니다. 단, 코드 실행에는 보안 위험이 따르므로(03번, 07번) 안전장치도 함께 배웁니다.

핵심 정리

  • LLM은 계산기가 아니라 언어 모델 — 큰 데이터 집계에 약하다.
  • 해결책: "무엇을 계산할지는 LLM, 실제 계산은 코드" 로 역할 분담.
  • LLM이 pandas 코드를 생성하고, 도구가 실행해 정확한 값을 얻는다.
  • 이는 5강 도구 호출의 유연한 형태(코드 실행 도구)다.
