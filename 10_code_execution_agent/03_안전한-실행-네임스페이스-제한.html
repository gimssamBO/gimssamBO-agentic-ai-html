안전한 실행 — 네임스페이스 제한

한 줄 요약

LLM이 만든 코드를 eval로 실행하는 건 위험합니다. eval은 임의의 파이썬 코드를 돌릴 수 있어, 잘못하면 파일 삭제 등 시스템을 망가뜨립니다. 빌트인을 차단하고 허용한 객체(df, pd)만 노출하는 화이트리스트 방식으로 위험을 줄입니다.

1. eval의 위험

코드를 실행하려면 파이썬의 eval을 씁니다. eval("df['sales'].sum()")처럼 문자열을 코드로 평가하죠. 그런데 eval은 무엇이든 실행합니다.

eval("df['sales'].sum()")                    # 정상 — 합계 계산
eval("__import__('os').system('rm -rf /')")  # 위험! — 시스템 파일 삭제 시도
eval("open('secret.txt').read()")            # 위험! — 비밀 파일 읽기

만약 LLM이(또는 LLM을 조종한 악의적 사용자가) 이런 위험한 코드를 만들면, 그대로 실행되어 시스템이 망가질 수 있습니다. 이건 심각한 보안 구멍입니다.

비유: eval은 만능 열쇠입니다. 계산도 하지만, 잘못 쓰면 금고도 열고 문서도 태웁니다. 그래서 "계산만 할 수 있는 제한된 열쇠"로 바꿔야 합니다.

2. 안전장치 ① — 빌트인 차단

eval의 세 번째 비밀은 네임스페이스(이름 → 객체 매핑)를 지정할 수 있다는 것입니다. 여기에 {"__builtins__": {}}를 주면, 파이썬 기본 내장 기능을 모두 차단합니다.

eval(expr, {"__builtins__": {}}, {...})
# 두 번째 인자 {"__builtins__": {}} → 빌트인 차단!

__builtins__를 비우면 __import__, open, exec 같은 위험한 내장 함수를 쓸 수 없게 됩니다. __import__('os')로 OS를 건드리려는 시도가 막히는 거죠.

3. 안전장치 ② — 화이트리스트 네임스페이스

빌트인을 막은 다음, 허용할 객체만 명시적으로 노출합니다.

eval(expr, {"__builtins__": {}}, {"df": df, "pd": pd})
# 세 번째 인자 {"df": df, "pd": pd} → df와 pd만 허용

이러면 코드 안에서 df와 pd만 쓸 수 있습니다. 그 외의 것(파일 접근, 네트워크, OS 명령)은 이름 자체를 모르니 접근 불가입니다. "계산에 필요한 것만 주고 나머지는 다 막는" 거죠.

이 "필요한 것만 허용"하는 방식을 화이트리스트라고 합니다. (반대로 "위험한 것만 막기"는 블랙리스트인데, 빠뜨리기 쉬워 위험합니다. 화이트리스트가 더 안전합니다.)

4. 안전한 실행 함수

두 안전장치를 합치고, 잘못된 식에도 죽지 않게 try/except로 감쌉니다.

def run_pandas(expr: str) -> str:
    """pandas 식을 안전하게 실행한다 — df, pd 만 허용."""
    try:
        # 빌트인 차단 + df/pd 화이트리스트
        result = eval(expr, {"__builtins__": {}}, {"df": df, "pd": pd})
    except Exception as e:
        return f"실행 오류: {e}"     # 잘못된 식이어도 죽지 않게 메시지로 반환
    return str(result)

세 겹의 방어입니다.

  1. {"__builtins__": {}}: 내장 함수 차단
  2. {"df": df, "pd": pd}: 허용 객체만 노출
  3. try/except: 잘못된 식에도 프로그램이 안 죽음

5. 안전장치 검증

직접 위험한 식을 넣어 막히는지 확인할 수 있습니다.

print(run_pandas("__import__('os').listdir('.')"))   # → "실행 오류: ..." (차단!)
print(run_pandas("df['sales'].sum()"))               # → "324286050" (정상)

위험한 식(__import__)은 빌트인 차단으로 막히고, 정상 pandas 식은 잘 실행됩니다. 방어가 작동하는 거죠. (이건 09번 연습문제로 직접 해 봅니다.)

6. 그래도 완벽하지 않다

이 화이트리스트 방식은 위험을 크게 줄이지만, 완벽한 방어는 아닙니다. 정교한 우회 기법이 있을 수 있고, pandas 자체로도 일부 위험한 동작이 가능합니다. 진짜 안전하게 하려면 별도 샌드박스(격리 환경) 가 필요합니다. 이 한계와 실무 대안은 07번에서 자세히 다룹니다.

핵심 정리

  • eval은 임의 코드를 실행할 수 있어 그 자체로 위험하다.
  • 안전장치 ①: {"__builtins__": {}}로 내장 함수 차단.
  • 안전장치 ②: {"df": df, "pd": pd}로 허용 객체만(화이트리스트).
  • 안전장치 ③: try/except로 잘못된 식에도 안 죽게.
  • 그래도 완벽하지 않아 실무에선 샌드박스가 필요(07번).
