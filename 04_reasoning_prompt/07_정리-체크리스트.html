정리 & 체크리스트

4강에서 배운 것

4강에서는 LLM에게 "생각하는 법" 을 시키는 추론형 프롬프트를 배웠습니다.

  • CoT(Chain-of-Thought): "단계적으로 풀어라" 한 줄로 계산·다단계 문제 정답률이 크게 오른다(예: 63% → 100%).
  • 원리: 모델은 자기가 쓴 앞 출력을 다음 출력의 작업 공간(근거) 으로 삼는다.
  • 자기검증(검산): 답을 다시 계산시켜 신뢰도를 높인다. 민감한 계산의 보험.
  • CoT의 한계: 단순 질문엔 토큰 낭비, 함정 문제엔 오답 위험. 무조건 켜는 게 아니다.

한눈에 보는 핵심 코드

from common import get_genai_client, GEMINI_MODEL
from google.genai import types
client = get_genai_client()

# 직접 답변 — 빠르지만 다단계 계산에 약함
def ask_direct(q):
    r = client.models.generate_content(
        model=GEMINI_MODEL, contents=f"{q}\n설명 없이 숫자만 답하라.",
        config=types.GenerateContentConfig(temperature=0))
    return r.text

# CoT — 단계적으로 풀게 해서 정답률↑
def ask_cot(q):
    r = client.models.generate_content(
        model=GEMINI_MODEL,
        contents=f"{q}\n단계적으로 풀어라. 마지막 줄에 '정답: <숫자>'.",
        config=types.GenerateContentConfig(temperature=0))
    return r.text

CoT 사용 판단 (가장 중요)

  • 계산 단계가 많은가? → 예: CoT 켜기 (민감한 계산이면 검산까지 추가).
  • 아니오, 단순 사실/상식인가? → 예: CoT 끄기 (직접 답변).

이 강에서 설치한 라이브러리

pip install google-genai python-dotenv pandas   # (앞 강에서 설치했다면 생략 가능)

새로 설치할 라이브러리는 없습니다. re(정규식)는 파이썬 표준 라이브러리입니다.

체크리스트

  • [ ] LLM이 암산(직접 답변)을 자주 틀리는 이유를 설명할 수 있다.
  • [ ] 직접 답변과 CoT의 정답률 차이를 실험으로 확인했다.
  • [ ] "단계적으로 풀어라" 프롬프트와 정답 추출(extract_number)을 작성했다.
  • [ ] 자기검증(검산)으로 답을 한 번 더 확인했다.
  • [ ] CoT가 손해인 경우(단순 질문·함정 문제)를 구분할 수 있다.

한 줄 핵심

"단계적으로 풀어라" 한 줄이 추론 정답률을 끌어올린다. 단, 다단계 문제에만 켜고, 민감하면 검산을 더한다.
