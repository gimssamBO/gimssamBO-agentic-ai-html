자기검증(검산)

한 줄 요약

CoT로 푼 답도 가끔 틀립니다. "위 풀이가 맞는지 다시 계산해 보라" 고 한 번 더 시키면(self-consistency 응용), 모델이 스스로 오류를 잡아 신뢰도가 올라갑니다. 돈·재고처럼 틀리면 안 되는 계산의 보험입니다.

1. CoT도 완벽하지 않다

CoT는 정답률을 크게 높이지만 100%는 아닙니다. 특히 단계가 많거나 숫자가 큰 문제에서는 여전히 틀릴 수 있습니다. 그럼 어떻게 더 믿음직하게 만들까요?

답은 사람이 시험 볼 때 하는 것과 같습니다 — 검산입니다.

비유: 수학 시험에서 답을 다 푼 뒤 "다시 한번 계산해 보는" 그 과정입니다. 한 번 더 보면 실수를 잡을 확률이 올라갑니다.

2. self-consistency란?

원래 self-consistency(자기일관성) 기법은 이렇습니다.

  • 같은 문제를 여러 번 풀게 한다 (temperature를 약간 높여 다양한 풀이 유도).
  • 나온 답들 중 가장 많이 나온 답(다수결) 을 채택한다.

여러 번 풀어도 일관되게 같은 답이 나오면, 그 답을 믿을 수 있다는 아이디어죠. 다만 여러 번 호출하면 비용이 배로 듭니다.

그래서 이 강에서는 더 가벼운 변형인 "검산 한 번" 으로 핵심을 체험합니다.

3. 검산 함수

CoT로 푼 답을 모델에게 다시 검산시킵니다.

from common import get_genai_client, GEMINI_MODEL
from google.genai import types

client = get_genai_client()

def verify(question: str, cot_answer: str) -> str:
    """제출한 풀이를 모델에게 다시 검산시켜 신뢰도를 높인다."""
    resp = client.models.generate_content(
        model=GEMINI_MODEL,
        contents=(
            f"[문제] {question}\n[제출한 풀이]\n{cot_answer}\n\n"
            "위 풀이가 맞는지 다시 계산해 검산하라. "
            "틀렸다면 올바른 값을, 맞다면 그대로 '정답: <숫자>'로 확정하라."
        ),
        config=types.GenerateContentConfig(temperature=0),
    )
    return resp.text

핵심은 이전 풀이를 통째로 보여 주고 "이게 맞는지 다시 계산하라"고 시키는 것입니다. 모델은 그 풀이를 검토하며 오류가 있으면 바로잡습니다.

4. 실행

q = "이어버드를 79000원에 3개 샀는데 10% 쿠폰을 받았습니다. 총 결제액은?"
first = ask_cot(q)          # 1차 풀이
print("[검산 결과]\n", verify(q, first))   # 2차 검산

예상 출력

[검산 결과]
 제출한 풀이를 검토합니다.
 79000 × 3 = 237000 (맞음)
 237000 × 0.1 = 23700 (맞음)
 237000 - 23700 = 213300 (맞음)
 정답: 213300

검산을 통해 답이 확정되었습니다. 만약 1차 풀이에 오류가 있었다면, 이 단계에서 바로잡혔을 것입니다.

5. 언제 검산을 쓰나

검산은 토큰(비용)을 약 2배로 늘립니다. 그래서 항상 쓰는 게 아니라, 틀리면 큰일 나는 계산에 선택적으로 씁니다.

  • ✅ 환불 금액 계산, 재고 발주량, 정산 금액 → 검산 필수
  • ❌ "오늘 날씨 어때?" 같은 단순 질의 → 검산 불필요(낭비)

현업 에이전트는 "민감한 계산엔 검산 한 번"을 기본 정책으로 두기도 합니다. 비용을 조금 더 내고 사고를 예방하는 거죠. 보험과 같은 개념입니다.

핵심 정리

  • CoT 답도 틀릴 수 있어, 검산으로 신뢰도를 높인다.
  • verify()는 이전 풀이를 보여 주고 "다시 계산하라" 고 시킨다.
  • 검산은 비용이 2배지만, 틀리면 안 되는 계산에서는 값진 보험이다.
