문제 1 — 교환신청 도구 추가

요구사항

code/ch30_final.py를 복사해 code/ch30_ex_exchange.py를 만드세요.

  • @tool로 request_exchange(order_id: str, reason: str) -> str 를 정의해,
    교환 접수번호(예: EX- + 난수)를 만들어 반환한다.
  • build_agent의 tools에 추가한다.
  • SYSTEM_PROMPT에 교환 요청 시 이 도구를 쓰라고 명시한다.
  • 기대 결과:
    "주문 O000050 불량이라 교환하고 싶어" 입력 시
    에이전트가 request_exchange를 호출하고 접수번호가 답변에 포함된다.

왜 하나?
지금까지의 도구는 읽기(조회) 만 했습니다.
교환신청은 쓰기(행동) 도구입니다 — 18강에서 배운 "읽기 도구 vs 쓰기 도구"의 실전.
도구를 하나 추가하는 것만으로 에이전트의 능력이 확장됨을 봅니다.

해답

# -*- coding: utf-8 -*-
# 실행: python code/ch30_ex_exchange.py
import sys, pathlib, random, string
sys.path.append(str(pathlib.Path(__file__).resolve().parent))

from common import get_chat, DATA, DOCS
from langchain_core.tools import tool
from langchain_core.messages import HumanMessage
from langgraph.prebuilt import create_react_agent
from langgraph.checkpoint.memory import MemorySaver


# ==================================================================
# 1. 기존 기본 도구 정의
# ==================================================================
@tool
def get_order_status(order_id: str) -> str:
    """[r2] 주문번호로 주문 상태를 조회한다."""
    orders = {"o000050": "배송 완료", "o123456": "배송 중"}
    return orders.get(order_id, f"주문번호 {order_id}를 찾을 수 없습니다.")


@tool
def get_stock(product_name: str) -> str:
    """[r3] 상품명으로 재고 수량을 조회한다."""
    inventory = {"로봇청소기": "15개", "무선이어폰": "3개"}
    return inventory.get(product_name, f"'{product_name}' 상품 재고 정보를 찾을 수 없습니다.")


@tool
def search_faq(keyword: str) -> str:
    """[r4] 키워드로 FAQ 답변을 조회한다."""
    faqs = {"환불": "구매 후 7일 이내 가능합니다.", "교환": "상품 하자 시 무료 교환됩니다."}
    return faqs.get(keyword, "관련 FAQ를 찾지 못했습니다.")


@tool
def policy_search(query: str) -> str:
    """[r1] 정책/멤버십 문서를 검색한다. (PDF RAG)"""
    policies = {"교환": "상품 수령 후 7일 이내 불량 발생 시 무료 교환 가능합니다."}
    return policies.get(query, "해당 정책 문서를 찾지 못했습니다.")


# ==================================================================
# 2. [추가] 교환 접수 도구 정의
# ==================================================================
@tool
def request_exchange(order_id: str, reason: str) -> str:
    """[추가] 주문에 대한 교환을 접수하고 접수번호를 반환한다.

    order_id: 교환할 주문번호, reason: 교환 사유.
    """
    # 접수번호 생성 (ex- + 영숫자 6자리)
    suffix = "".join(random.choices(string.ascii_uppercase + string.digits, k=6))
    ticket = f"ex-{suffix}"
    # (실무에선 여기서 DB에 교환 접수 기록을 INSERT)
    return (f"교환 접수가 완료되었습니다. 접수번호: {ticket}\n"
            f"주문 {order_id} / 사유: {reason}\n"
            f"영업일 기준 1~2일 내 담당자가 연락드립니다.")


# ==================================================================
# 3. 에이전트 빌더 및 실행 진입점
# ==================================================================
system_prompt = (
    "너는 승승장구몰의 통합 CS 상담원이다. 친절한 한국어로 답하라.\n"
    "- 주문 상태는 get_order_status, 재고는 get_stock, 자주 묻는 질문은 search_faq,\n"
    "  환불/교환/멤버십 정책은 policy_search 도구를 사용하라.\n"
    "- 고객이 '교환하고 싶다/교환 신청'을 요청하면 request_exchange 도구로 접수하라.\n"
    "- 정책 질문은 반드시 policy_search 결과로만 답하고, 모르면 모른다고 하라.\n"
    "- 이전 대화 맥락을 기억해 이어서 답하라."
)

memory = MemorySaver()

def build_agent():
    """설정+도구+시스템 프롬프트+메모리를 결합해 LangGraph 에이전트를 생성한다."""
    llm = get_chat(temperature=0.0)
    tools = [
        get_order_status, 
        get_stock, 
        search_faq, 
        policy_search, 
        request_exchange  # ← 교환 도구 추가
    ]
    
    agent = create_react_agent(
        model=llm,
        tools=tools,
        prompt=system_prompt,
        checkpointer=memory
    )
    return agent


# 전역 에이전트 인스턴스 생성
agent = build_agent()


def answer(message: str, thread_id: str = "demo") -> str:
    """외부 노출 단일 진입점. thread_id로 대화 세션을 구분한다."""
    config = {"configurable": {"thread_id": thread_id}}
    result = agent.invoke(
        {"messages": [HumanMessage(content=message)]},
        config=config
    )
    return result["messages"][-1].content


# ==================================================================
# 4. 교환 접수 테스트 실행
# ==================================================================
if __name__ == "__main__":
    print("=== [교환 접수 테스트] ===")
    response = answer("주문 o000050 불량이라 교환하고 싶어. 화면이 안 켜져.", thread_id="ex-1")
    print("상담원 응답:\n", response)

예상 출력 

교환 접수가 완료되었습니다. 
접수번호: ex-k7p2qm
주문 o000050 / 사유: 화면이 안 켜지는 불량
영업일 기준 1~2일 내 담당자가 연락드립니다.

관찰 포인트

  • 에이전트가 "교환하고 싶어"를 보고 request_exchange 도구를 선택했습니다 (시스템 프롬프트 지시 + 도구 독스트링).
  • 도구를 하나 추가하고 프롬프트에 한 줄 더했을 뿐인데 능력이 확장됐습니다.
  • 이건 쓰기(행동) 도구 — 실무에선 DB INSERT가 일어나므로,
    비가역 행동엔 사람 승인(human-in-the-loop)을 두는 게 안전합니다(07번).

문제 2 — 메모리 격리 검증 스크립트

요구사항

code/ch30_ex_memory.py를 작성하세요.

  • answer()를 사용해:
  • ① thread_id="A"로 "내 이름은 오지표야" → "내 이름이 뭐였지?"를 연속 호출 → 두 번째 답에 "오지표"가 들어가는지(메모리 유지).
  • ② thread_id="B"로 "내 이름이 뭐였지?"를 물었을 때는 기억하지 못하는지(스레드 격리).
  • 검증: 콘솔에 "메모리 유지: PASS/FAIL", "스레드 격리: PASS/FAIL" 두 줄 출력.

왜 하나?
메모리가 제대로 작동하는지, 그리고 세션이 격리되는지를 자동으로 검증합니다.
멀티 사용자 서비스에서 "A의 대화가 B에게 새는" 일이 없어야 하죠(19강).

해답

# -*- coding: utf-8 -*-
# code/ch30_ex_memory.py
# 실행: python code/ch30_ex_memory.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))

# 앞서 작성한 교환/통합 에이전트 스크립트에서 answer 함수 불러오기
from ch30_ex_exchange import answer


def test_memory_retention() -> bool:
    """① 같은 thread 안에서 이름을 기억하는가 (단기 기억 유지)."""
    answer("내 이름은 오지표야. 기억해줘.", thread_id="a")     # 이름 알려주기
    reply = answer("내 이름이 뭐였지?", thread_id="a")          # 같은 thread → 기억해야 함
    print(f"  [Thread a] 회상 응답: {reply}")
    return "오지표" in reply


def test_thread_isolation() -> bool:
    """② 다른 thread 에서는 그 이름을 모르는가 (스레드 간 메모리 격리)."""
    reply = answer("내 이름이 뭐였지?", thread_id="b")          # 다른 thread → 몰라야 함
    print(f"  [Thread b] 회상 응답: {reply}")
    return "오지표" not in reply        # 이름이 없으면 격리 성공


if __name__ == "__main__":
    print("=" * 60)
    print("메모리 유지 및 스레드 격리 검증")
    print("=" * 60)
    
    retention = test_memory_retention()
    isolation = test_thread_isolation()
    
    print("-" * 60)
    print(f"메모리 유지 테스트: {'PASS ✅' if retention else 'FAIL ❌'}")
    print(f"스레드 격리 테스트: {'PASS ✅' if isolation else 'FAIL ❌'}")
    print("=" * 60)

예상 출력 

============================================================
메모리 격리 검증
============================================================
  [a] 회상 응답: 고객님의 성함은 오지표님이십니다.
  [b] 회상 응답: 죄송하지만 성함을 알려주신 적이 없습니다. 다시 알려주시겠어요?
------------------------------------------------------------
메모리 유지: pass
스레드 격리: pass

관찰 포인트

  • 메모리 유지(A): 같은 thread에서 이름을 기억 → "오지표" 포함 → PASS.
  • 스레드 격리(B): 다른 thread는 A의 대화를 모름 → "오지표" 없음 → PASS.
  • thread_id로 대화가 완전히 분리됩니다 — 멀티 사용자 서비스의 필수 조건(19강).
  • 이런 자동 검증 스크립트가 평가의 기초입니다(09번 확장의 "평가 자동화").

마무리 — 그리고 수료를 축하합니다 🎉

  • 문제 2: 메모리 유지·스레드 격리를 자동 검증했습니다 — 신뢰할 수 있는 멀티 사용자 서비스의 조건.

에이전트 개발의 전 과정을 직접 구현했습니다.
