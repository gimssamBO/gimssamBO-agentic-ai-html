Supervisor vs Planner/Worker

한 줄 요약

25강 Supervisor는 한 질문을 한 명에게 위임(수평, 전문가 중 택1)했습니다. 26강 Planner/Worker는 한 작업을 여러 단계로 분해(수직, 계획→실행)합니다. 둘은 목적과 협업 형태가 다르며, 실무에서는 함께 쓰이기도 합니다.

1. 항목별 비교

구분 Supervisor (25강) Planner / Worker (26강)
목적 한 질문을 한 명에게 위임 한 작업을 여러 단계로 분해
협업 형태 수평(전문가 중 택1) 수직(계획 → 실행)
산출물 위임된 에이전트의 답 여러 산출물의 취합본
비유 API Gateway 작업 큐 + 워커
에이전트 수 미리 정해진 전문가들 Worker는 작업 수만큼 반복

2. 수평 분리 vs 수직 분리

핵심 차이는 나누는 방향입니다.

[Supervisor — 수평 분리] "누가 할 일인가?"를 결정

  • 질문 → 라우터 → 전문가(추천 / 정책 / 주문) 중 1명만 골라 위임

[Planner/Worker — 수직 분리] "어떤 순서로 무엇을 할 것인가?"를 결정

  • 작업 → Planner가 계획(작업1, 작업2, 작업3) → Worker가 작업1 실행 → 작업2 실행 → 작업3 실행

Supervisor는 선택(여럿 중 하나), Planner/Worker는 분해(하나를 여럿으로). 방향이 정반대죠.

3. 언제 무엇을 쓰나

[Supervisor가 맞는 경우]
   - 질문 유형이 명확히 갈림 (추천 vs 정책 vs 주문)
   - 한 질문은 보통 한 전문가가 처리하면 끝
   - 예: 고객 문의 라우팅

[Planner/Worker가 맞는 경우]
   - 하나의 큰 작업을 여러 단계로 쪼개야 함
   - 단계들이 모여 하나의 산출물을 만듦
   - 예: 캠페인 기획, 리포트 작성, 프로젝트 분해

"이건 누구 일?" 이면 Supervisor, "이걸 어떻게 단계별로?" 면 Planner/Worker입니다. 질문이냐 작업이냐, 선택이냐 분해냐로 구분하죠.

4. 둘은 함께 쓰일 수 있다

실무에서는 두 패턴이 결합되기도 합니다.

[Planner/Worker 안에 Supervisor]
   Planner가 작업을 쪼갬 → [타깃분석, 카피작성, 예산배분]
      ↓ 각 작업마다
   Supervisor가 알맞은 전문 Worker에게 위임
      - 타깃분석 → 데이터분석 전문 에이전트
      - 카피작성 → 카피라이팅 전문 에이전트
      - 예산배분 → 재무 전문 에이전트

Planner가 만든 각 작업을, Supervisor가 알맞은 전문 Worker에게 보내는 거죠. 이번 강에서는 단순화를 위해 같은 Worker가 모든 작업을 처리하지만, 작업별로 전문 Worker를 두고 Supervisor로 라우팅하면 더 강력해집니다.

5. 27강과의 연결

26강의 Planner/Worker는 코드(파이썬 함수)로 흐름을 제어합니다.

subtasks = plan(...)              # 계획
for task in subtasks:             # for 루프로 순차 실행
    outputs.append(work(task))
report = combine(outputs)         # 취합

for 루프와 함수 호출로 흐름을 짰죠. 27강(AI 팀)에서는 이 흐름을 LangGraph StateGraph로 정식화합니다.

[26강] for 루프 + 함수 → 흐름을 코드로 제어
[27강] StateGraph 노드/엣지 → 흐름을 그래프로 선언 (조건 분기·루프·상태 공유)

26강이 "손으로 짠 파이프라인", 27강이 "그래프로 선언한 파이프라인"입니다. 21강에서 배운 StateGraph가 27강에서 멀티에이전트와 만나죠.

6. 협업 패턴 지도

지금까지 배운 멀티에이전트 협업을 정리하면:

25강 Supervisor      : 수평 라우팅 (누구에게?)
26강 Planner/Worker  : 수직 분해 (어떤 단계로?)  ← 이번 강
27강 StateGraph 팀    : 그래프 협업 (상태 공유 + 조건 흐름)

각 강이 멀티에이전트의 한 측면을 다룹니다. 25강이 "고르기", 26강이 "쪼개기", 27강이 "그래프로 엮기"죠. 셋을 알면 대부분의 협업 구조를 설계할 수 있습니다.

핵심 정리

  • Supervisor(25강): 수평 분리, 전문가 중 택1(누구 일?), API Gateway.
  • Planner/Worker(26강): 수직 분리, 하나를 여러 단계로 분해(어떻게?), 작업 큐+워커.
  • 구분: 질문이냐 작업이냐, 선택이냐 분해냐.
  • 둘은 결합 가능 — Planner가 쪼갠 작업을 Supervisor가 전문 Worker에 라우팅.
  • 26강은 코드(for 루프)로 흐름 제어 → 27강은 StateGraph로 정식화.
