무엇을 할지와 어떻게 할지 나누기

한 줄 요약

25강의 Supervisor는 질문을 한 명에게 위임했습니다. 하지만 현실 업무는 보통 여러 단계로 쪼개야 합니다. Planner(설계자) 가 "무엇을 할지"를 정해 할 일 목록을 만들고, Worker(실행자) 가 각 항목을 "어떻게 할지" 처리합니다. 백엔드의 "작업 큐 + 워커" 패턴과 같은 구조죠.

1. 한 번에 다 시키면 어설퍼진다

마케팅 캠페인 하나를 준비한다고 합시다. 필요한 일은:

1. 타깃 고객 분석
2. 광고 카피 작성
3. 채널/예산 배분 제안
4. 셋을 합쳐 실행안으로 정리

이걸 한 번의 LLM 호출에 "캠페인 다 준비해줘" 라고 던지면?

- 일부를 빠뜨림 (카피만 쓰고 예산 배분은 깜빡)
- 각 부분의 품질이 들쭉날쭉 (한 번에 다 하려니 어설픔)
- "왜 이렇게 했는지" 단계가 안 보임 (한 덩어리 출력)

백엔드로 치면 거대한 트랜잭션을 함수 하나에 다 욱여넣은 셈입니다. 한 번에 다 하려다 다 어설퍼지죠.

2. "무엇을"과 "어떻게"를 나누기

해결책은 일을 두 역할로 나누는 것입니다.

[Planner — 무엇을 할지]
   캠페인 브리프를 보고 → "타깃 분석 / 카피 작성 / 예산 배분" 할 일 목록 생성
   (실행은 안 함, 계획만)

[Worker — 어떻게 할지]
   할 일 하나씩 받아 → 각각 구체적으로 실행
   (계획은 안 함, 실행만)

캠페인 1건 이 세 단계를 거칩니다.

  1. [Planner] "어떤 하위 작업이 필요한가?" → [타깃분석, 카피작성, 예산배분]
  2. [Worker] (각 작업을 하나씩) 작업1 실행 → 작업2 실행 → 작업3 실행
  3. [취합] 세 산출물을 모아 최종 실행안

각자 자기 일에만 집중하니 품질이 올라갑니다. Planner는 빠짐없이 쪼개는 데, Worker는 한 작업을 깊이 하는 데 몰두하죠.

3. 왜 나누면 좋은가

[한 LLM이 다 하기]              [Planner / Worker 분리]
"계획도 세우고 실행도 해"    →   Planner는 계획만, Worker는 실행만
- 둘 다 어설픔                   - 각자 잘하는 일에 몰두 → 품질 ↑
- 빠뜨리기 쉬움                  - Planner가 빠짐없이 쪼갬
- 단계 안 보임                  - 작업 단위로 추적·재시도 가능

이건 25강 역할 분리의 연장선입니다. 25강은 "추천 vs 정책"처럼 수평으로 나눴다면, 26강은 "계획 → 실행"처럼 수직(계층) 으로 나눕니다. 둘 다 "한 명에게 다 시키지 말고 역할을 나눠라"는 같은 정신이죠.

4. 백엔드의 "작업 큐 + 워커" 패턴

이 구조는 백엔드 개발자에게 익숙합니다.

[작업 큐 + 워커 패턴]
   생산자(Planner): 할 일을 큐에 넣음 → [작업1, 작업2, 작업3]
   소비자(Worker):  큐에서 하나씩 꺼내 처리
   취합:           처리 결과를 모음

- 작업이 독립적 → 병렬 처리 가능 (Worker 여러 개)
- 한 작업 실패 → 그 작업만 재시도 (07번)
- 작업 추가 쉬움 → 큐에 넣기만

에이전트의 Planner/Worker가 정확히 이 패턴입니다. Planner가 작업을 만들고, Worker가 꺼내 처리하죠. 익숙한 백엔드 패턴을 LLM에 적용한 겁니다.

5. 우리가 만들 것 — 캠페인 기획 자동화

이번 강에서는 marketing_brief.csv의 캠페인 1건으로 기획 자동화 파이프라인을 만듭니다.

marketing_brief.csv(campaign_id, title, category, target, budget, key_offer)에서 캠페인 1건(예: CMP02 신학기 전자기기 프로모션)을 선택해 처리합니다.

  1. [Planner] 하위 작업 3~4개로 분해 (구조화 출력 JSON)
  2. [Worker] 각 작업을 하나씩 실행 (타깃 분석·카피·예산)
  3. [취합] 마크다운 캠페인 실행안

그리고 신규 항목으로 Worker 실패 처리·재시도(07번)를 더해, 한 작업이 실패해도 나머지는 살리는 견고한 파이프라인을 만듭니다.

25강에서 "역할을 수평으로 나누기"를 배웠다면, 26강에서는 "계획과 실행을 수직으로 나누기"를 배웁니다.

핵심 정리

  • 복잡한 업무를 한 번에 다 시키면 빠뜨리고 품질이 어설퍼짐.
  • Planner("무엇을")가 할 일 목록을 만들고, Worker("어떻게")가 각각 실행.
  • 각자 자기 일에 집중해 품질 ↑, 단계별 추적·재시도 가능.
  • 25강 수평 분리(역할별) → 26강 수직 분리(계획→실행).
  • 백엔드의 "작업 큐 + 워커" 패턴과 동일(독립·병렬·재시도).
