[신규] Worker 실패 처리와 재시도

한 줄 요약

06번 run_campaign은 Worker가 한 번이라도 예외를 던지면 전체가 멈춥니다. 실무에선 일시적 오류(타임아웃 등)가 흔하죠. Worker 실패 시 최대 2회 재시도하고, 그래도 실패하면 스킵·기록하고 끝까지 진행하는 견고한 오케스트레이터를 만듭니다.

1. 한 작업의 실패가 전체를 멈춘다

06번 코드의 약점을 봅시다.

for i, t in enumerate(subtasks, 1):
    outputs.append((t, work(llm_work, brief_text, t)))   # work()가 예외 던지면?

work()가 작업 2에서 예외를 던지면(타임아웃·네트워크·rate limit), 전체 for 루프가 죽습니다.

작업 1 성공 → 작업 2 실패(예외!) → 💥 전체 중단
   → 작업 1의 산출물도 못 받고, 작업 3은 시작도 못 함

4개 작업 중 1개가 일시적으로 실패했다고 나머지 3개까지 버리는 건 아깝습니다. 실무에선 일시적 오류가 흔하니, 부분 실패를 허용해야 하죠.

2. 견고화 전략 — 재시도 → 스킵 → 계속

Worker 실패 시:
   1. 재시도 (일시적 오류 흡수) — 최대 2회
   2. 그래도 실패 → 스킵 + 기록
   3. 다음 작업으로 계속 진행 (전체는 안 멈춤)

핵심 철학: 한 작업의 실패가 전체를 멈추면 안 된다(부분 실패 허용). 23강 재귀 수정의 재시도, 24강 예외 처리의 정신을 Worker에 적용합니다.

from ch26_role_agent import load_brief_text, plan, work   # 계획·실행 로직 재사용

MAX_RETRY = 2   # 최초 1회 + 재시도 2회 = 최대 3번 시도

추가 설치 라이브러리는 없습니다(표준 try/except + 기존 함수 재사용).

3. 재시도 래퍼 — work_with_retry

work()를 감싸 최대 MAX_RETRY회 재시도하는 래퍼입니다.

def work_with_retry(llm, brief_text: str, subtask: str, idx: int, total: int):
    """work() 를 감싸 최대 MAX_RETRY 회 재시도. (성공여부, 결과 or 오류메시지) 반환."""
    for attempt in range(1, MAX_RETRY + 2):   # 1, 2, 3 (최초 + 재시도 2회)
        try:
            print(f"   작업 {idx}/{total} 수행 중 (시도 {attempt})...")
            out = work(llm, brief_text, subtask)
            return True, out                  # 성공 → (True, 산출물)
        except Exception as e:                # 타임아웃·네트워크·파싱 등 모든 실패 흡수
            print(f"     [실패] {type(e).__name__}: {e}")
            if attempt <= MAX_RETRY:
                print(f"     → 재시도합니다 ({attempt}/{MAX_RETRY})")
            else:
                print(f"     → 최대 재시도 초과. 이 작업은 스킵합니다.")
                return False, f"{type(e).__name__}: {e}"   # 실패 → (False, 오류메시지)

설계 포인트

  • range(1, MAX_RETRY + 2) → 1, 2, 3: 최초 1회 + 재시도 2회 = 최대 3번 시도.
  • 성공하면 즉시 (True, 산출물) 반환(더 재시도 안 함).
  • 모든 시도 실패하면 (False, 오류메시지) 반환 → 호출부가 스킵 처리.
  • (성공여부, 결과) 튜플 패턴 — 24강 load_facts_safe의 ok 플래그와 같은 정신.

4. 견고한 오케스트레이터

run_campaign을 재시도·스킵을 지원하게 개선합니다.

def run_campaign_robust(brief_text: str, fail_indices=None) -> str:
    """계획 → (재시도 포함) 실행 → 취합. 실패 작업은 스킵하고 끝까지 진행한다."""
    fail_indices = set(fail_indices or [])    # 시연용: 일부러 실패시킬 작업 번호
    llm_plan = get_chat(temperature=0)
    llm_work = get_chat(temperature=0.5)

    subtasks = plan(llm_plan, brief_text)
    total = len(subtasks)
    outputs = []        # (작업, 산출물) — 성공한 것만
    failed = []         # (번호, 작업, 오류) — 스킵한 것

    for i, t in enumerate(subtasks, 1):
        ok, info = work_with_retry(llm_work, brief_text, t, i, total)
        if ok:
            outputs.append((t, info))
            print(f"   작업 {i}/{total} 완료")
        else:
            failed.append((i, t, info))       # 스킵하고 다음 작업으로 진행

    # 취합 — 성공분 + 미완료 목록
    print(f"\n   성공 {len(outputs)}개 / 실패(스킵) {len(failed)}개 / 전체 {total}개")
    report = [f"# 캠페인 실행안\n\n> {brief_text}\n"]
    for i, (t, out) in enumerate(outputs, 1):
        report.append(f"## {i}. {t}\n{out}\n")
    if failed:
        report.append("## ⚠️ 미완료(재시도 후 스킵된) 작업")
        for i, t, err in failed:
            report.append(f"- {t} — {err}")
    return "\n".join(report)

핵심

  • outputs(성공)와 failed(스킵)를 따로 모음.
  • 실패해도 continue처럼 다음 작업으로 진행 → 전체는 안 멈춤.
  • 취합 시 성공분은 정상 섹션으로, 미완료 작업은 ⚠️ 목록으로 명시(투명성).

5. 실행 — 일부러 실패시켜 시연

작업 2를 일부러 매번 실패시켜 재시도·스킵 흐름을 보여줍니다.

if __name__ == "__main__":
    brief_text = load_brief_text("CMP02")
    print("(2번 작업은 일부러 매번 실패시켜 재시도·스킵을 보여줍니다)")

    print(report)

관찰 포인트

  • 작업 2가 3번 시도(최초+재시도 2회) 후 스킵됐지만, 작업 1·3은 정상 완료됐습니다.
  • 한 작업이 죽어도 전체는 살아남아 부분 산출물(2개)을 확보했죠.
  • 실패한 작업은 ⚠️ 목록에 투명하게 기록 — 나중에 사람이 그것만 다시 처리.

6. 왜 부분 실패 허용이 중요한가

[전부 아니면 전무 (all-or-nothing)]
   4개 작업 중 1개 실패 → 0개 산출물 (다 버림)

[부분 실패 허용 (graceful degradation)]
   4개 작업 중 1개 실패 → 3개 산출물 확보 + 1개는 추적

실무에선 "완벽한 0개보다 불완전한 3개" 가 낫습니다. 마케팅 실행안의 4개 섹션 중 3개라도 있으면 일을 시작할 수 있고, 빠진 1개만 따로 처리하면 되죠. 24강 폴백("불완전해도 결과"), 25강 견고성과 같은 정신입니다.

Worker가 독립적이기에 이게 가능합니다(05번). 작업끼리 의존했다면 하나 실패가 연쇄로 무너졌겠죠. 독립성이 견고성의 기반입니다.

핵심 정리

  • 06번은 Worker 한 번 실패에 전체가 멈춤 → 일시적 오류에 취약.
  • 전략: 재시도(일시 오류 흡수) → 스킵·기록 → 끝까지 진행.
  • work_with_retry: 최대 MAX_RETRY회 재시도, (성공여부, 결과) 반환.
  • 견고한 오케스트레이터: 성공/실패를 따로 모아 부분 산출물 확보 + ⚠️ 기록.
  • "완벽한 0개보다 불완전한 3개"(graceful degradation, 24·25강 정신).
  • Worker 독립성이 부분 실패 허용의 기반.
