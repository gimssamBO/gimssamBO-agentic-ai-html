문제 1 — Reviewer 단계 추가하기

요구사항

code/ch26_role_agent.py를 복사해 code/ch26_ex_review.py를 만드세요. 기존 Planner → Worker 흐름 뒤에 Reviewer(검토자) 단계를 추가합니다.

  • REVIEWER_SYSTEM 프롬프트와 review(llm, report) 함수를 만든다.
  • Worker들이 만든 실행안 전체를 보고 누락·개선점 3가지 이상을 제시한다.
  • 최종 결과 끝에 ## 검토 의견 섹션이 붙는다.

왜 하나? 사람 조직에도 "초안 → 검토(리뷰)" 단계가 있죠. Worker는 자기 작업에만 집중하느라 전체적으로 빠진 것(예: KPI 누락, 일정 없음)을 못 봅니다. Reviewer는 전체를 한 번 더 훑어 품질을 끌어올리는 역할입니다. 25·26강의 "역할 분리"를 한 단계 더 적용하는 셈입니다.

해답

# code/ch26_ex_review.py
# 실행: python code/ch26_ex_review.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat

# 기존 26강 로직을 그대로 재사용 (계획·실행)
from ch26_role_agent import load_brief_text, plan, work

from langchain_core.messages import SystemMessage, HumanMessage

# [추가] Reviewer 역할 — '실행은 하지 말고, 전체를 검토만 하라'
REVIEWER_SYSTEM = (
    "너는 마케팅 캠페인 '검토자(Reviewer)'다. "
    "주어진 캠페인 실행안 전체를 읽고, 빠졌거나 더 보완하면 좋을 점을 "
    "구체적으로 3가지 이상 짚어라. 각 항목은 한 문장으로, 실무에 바로 반영할 수 있게 써라. "
    "새 실행안을 작성하지 말고, 검토 의견만 제시하라."
)


def review(llm, report: str) -> str:
    """완성된 실행안을 검토해 개선점 3가지 이상을 반환한다."""
    result = llm.invoke([
        SystemMessage(REVIEWER_SYSTEM),
        HumanMessage(f"[검토할 캠페인 실행안]\n{report}"),
    ])
    return result.content


def run_campaign_with_review(brief_text: str) -> str:
    """계획 → 실행 → 취합 → (추가) 검토."""
    llm_plan = get_chat(temperature=0)
    llm_work = get_chat(temperature=0.5)
    llm_review = get_chat(temperature=0)     # 검토는 일관성 있게 → 0

    # 1) 계획  2) 실행  3) 취합  (26강 06번과 동일)
    subtasks = plan(llm_plan, brief_text)
    outputs = [(t, work(llm_work, brief_text, t)) for t in subtasks]
    report = [f"# 캠페인 실행안\n\n> {brief_text}\n"]
    for i, (t, out) in enumerate(outputs, 1):
        report.append(f"## {i}. {t}\n{out}\n")
    final = "\n".join(report)

    # 4) 검토 단계 추가
    opinion = review(llm_review, final)
    final += f"\n## 검토 의견\n{opinion}\n"
    return final


if __name__ == "__main__":
    brief_text = load_brief_text("CMP02")
    print(run_campaign_with_review(brief_text))

예상 출력 (끝부분)

## 3. 800만원 예산을 채널별로 배분하는 방안을 제안하라
- 인스타/틱톡 광고: 400만원 ...

## 검토 의견
1. 캠페인 성과를 측정할 KPI(전환율·ROAS 등)가 빠져 있어 효과 검증이 어렵다.
2. 채널별 예산은 있으나 집행 일정(주차별 타임라인)이 없어 실행 순서가 불명확하다.
3. 번들 혜택의 재고·물류 확인이 없어, 수요 급증 시 품절 리스크가 있다.

관찰 포인트

  • Reviewer는 새 실행안을 쓰지 않고, 전체를 보고 빠진 것만 짚었습니다(KPI·일정·재고).
  • "실행하지 말고 검토만 하라"는 프롬프트가, Planner의 "실행은 하지 마라"와 같은 역할 경계 장치입니다.
  • 흐름이 Planner → Worker → Reviewer로 늘었지만, 오케스트레이터는 그대로 순서를 코드로 지휘할 뿐입니다.

한 걸음 더 — Reviewer 의견을 다시 Worker에게 넘겨 수정본을 만들면 "검토 → 반영" 루프가 됩니다(23강 재귀 수정의 정신). 다만 무한 반복을 막도록 1~2회로 제한하세요.

문제 2 — 역할별 프롬프트를 YAML로 외부화하기

요구사항

문제 1의 스크립트에서 PLANNER_SYSTEM / WORKER_SYSTEM / REVIEWER_SYSTEM을 코드에 박아두지 말고, data/role_prompts.yaml(키: planner / worker / reviewer)로 분리해 파일에서 로드하도록 리팩터링하세요.

  • 각 프롬프트에 역할의 책임 + 산출물 형식을 구체적으로 명시한다.
  • 검증: YAML 값만 바꿔 재실행했을 때, 코드를 고치지 않고도 각 역할의 말투·동작이 달라지면 성공.

왜 하나? 프롬프트는 자주 바뀝니다("좀 더 공손하게", "5줄 말고 3줄로"). 이걸 코드에 박아두면 수정할 때마다 코드를 건드려야 하죠. 설정(프롬프트)과 코드를 분리하면, 기획자도 YAML만 고쳐 동작을 바꿀 수 있습니다. 29강 "설정 분리(.env vs config)"의 연습이기도 합니다.

해답

(1) 프롬프트 파일 — data/role_prompts.yaml

# data/role_prompts.yaml — 역할별 시스템 프롬프트
# 코드를 고치지 않고 이 파일만 수정해 각 역할의 동작을 바꾼다.
planner: |
  너는 마케팅 캠페인 '기획 설계자(Planner)'다.
  주어진 캠페인 브리프를 보고, 실행에 필요한 하위 작업을 3~4개로 쪼개라.
  작업은 서로 겹치지 않게, 한 문장 명령형으로 작성하라. 실행은 하지 마라.

worker: |
  너는 마케팅 '실무 작업자(Worker)'다.
  주어진 캠페인 브리프 맥락에서, 지정된 '하나의 작업'만 구체적으로 수행하라.
  결과는 5줄 이내로 실무에 바로 쓸 수 있게 작성하라.

reviewer: |
  너는 마케팅 캠페인 '검토자(Reviewer)'다.
  주어진 캠페인 실행안 전체를 읽고, 빠졌거나 더 보완하면 좋을 점을
  구체적으로 3가지 이상 짚어라. 각 항목은 한 문장으로 써라.
  새 실행안을 작성하지 말고, 검토 의견만 제시하라.

(2) 로딩 코드 — code/ch26_ex_yaml.py

# code/ch26_ex_yaml.py
# 실행: python code/ch26_ex_yaml.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_chat, DATA

import yaml                                   # pip install pyyaml
from ch26_role_agent import load_brief_text, Plan   # 데이터 로드·스키마 재사용
from langchain_core.messages import SystemMessage, HumanMessage

# [핵심] 프롬프트를 코드가 아니라 YAML 파일에서 읽는다.
def load_prompts() -> dict:
    with open(DATA / "role_prompts.yaml", encoding="utf-8") as f:
        return yaml.safe_load(f)             # {'planner': ..., 'worker': ..., 'reviewer': ...}


PROMPTS = load_prompts()


def plan(llm, brief_text: str) -> list[str]:
    planner = llm.with_structured_output(Plan)
    result = planner.invoke([
        SystemMessage(PROMPTS["planner"]),          # ← YAML에서 읽은 프롬프트
        HumanMessage(f"[캠페인 브리프]\n{brief_text}"),
    ])
    return result.subtasks


def work(llm, brief_text: str, subtask: str) -> str:
    result = llm.invoke([
        SystemMessage(PROMPTS["worker"]),           # ← YAML에서 읽은 프롬프트
        HumanMessage(f"[브리프]\n{brief_text}\n\n[작업]\n{subtask}"),
    ])
    return result.content


def review(llm, report: str) -> str:
    result = llm.invoke([
        SystemMessage(PROMPTS["reviewer"]),         # ← YAML에서 읽은 프롬프트
        HumanMessage(f"[검토할 캠페인 실행안]\n{report}"),
    ])
    return result.content


def run_campaign(brief_text: str) -> str:
    llm_plan, llm_work, llm_review = get_chat(0), get_chat(temperature=0.5), get_chat(0)
    subtasks = plan(llm_plan, brief_text)
    report = [f"# 캠페인 실행안\n\n> {brief_text}\n"]
    for i, t in enumerate(subtasks, 1):
        report.append(f"## {i}. {t}\n{work(llm_work, brief_text, t)}\n")
    final = "\n".join(report)
    final += f"\n## 검토 의견\n{review(llm_review, final)}\n"
    return final


if __name__ == "__main__":
    print(run_campaign(load_brief_text("CMP02")))

검증 방법

1) 그대로 실행 → 정상 동작 확인.
2) role_prompts.yaml 의 worker 를 "결과는 3줄 이내, 반말로 작성하라" 로 바꿈.
3) 코드는 한 글자도 안 고치고 재실행 → Worker 산출물의 길이·말투가 바뀜.
   → 설정(프롬프트)과 코드가 분리됐다는 증거.

관찰 포인트

  • 프롬프트가 코드 밖(YAML) 으로 나오니, 비개발자도 동작을 바꿀 수 있습니다.
  • 세 역할의 프롬프트가 한 파일에 모여 있어, 역할 정의를 한눈에 비교·관리할 수 있습니다.
  • yaml.safe_load는 YAML을 파이썬 dict로 바꿔 줍니다. |(블록 스칼라)는 여러 줄 문자열을 그대로 보존합니다.

주의 — yaml.load가 아니라 yaml.safe_load 를 쓰세요. safe_load는 신뢰할 수 없는 파일에서 임의 객체가 생성되는 보안 위험을 막아 줍니다.

마무리

  • 문제 1: 역할을 하나 더(Reviewer) 추가해, 초안을 검토하는 단계를 붙였습니다 — 역할 분리의 확장.
  • 문제 2: 프롬프트를 YAML로 외부화해, 코드 수정 없이 동작을 바꾸게 했습니다 — 설정·코드 분리(29강 예고).
  • 둘 다 26강 코드를 재사용해 확장했다는 점이 핵심입니다. 잘 나눠 둔 구조는 이렇게 덧붙이기 쉽습니다.
