따라하기 — 오케스트레이터 취합

목표

Planner(계획)와 Worker(실행)를 하나의 오케스트레이터 함수로 묶고, Worker 산출물을 모아 하나의 캠페인 실행안으로 취합합니다.

1. 오케스트레이터 — 계획 → 실행 → 취합

run_campaign이 전체 흐름을 지휘합니다.

def run_campaign(brief_text: str) -> str:
    """Planner로 쪼개고, Worker로 하나씩 실행해, 결과를 하나의 실행안으로 취합한다."""
    llm_plan = get_chat(temperature=0)      # [왜 0] 계획은 일관성·재현성이 중요
    llm_work = get_chat(temperature=0.5)    # [왜 0.5] 카피 등 창의 작업은 다양성이 도움

    print("[1] Planner 작업 분해 중...")
    subtasks = plan(llm_plan, brief_text)        # 계획 단계
    for i, t in enumerate(subtasks, 1):
        print(f"   서브태스크 {i}: {t}")

    print("\n[2] Worker 실행 중...")
    outputs = []
    for i, t in enumerate(subtasks, 1):          # 하위 작업을 하나씩 순회 실행
        print(f"   - 작업 {i} 수행: {t}")
        outputs.append((t, work(llm_work, brief_text, t)))   # (작업, 산출물) 보관

    print("\n[3] 결과 취합")
    report = [f"# 캠페인 실행안\n\n> {brief_text}\n"]
    for i, (t, out) in enumerate(outputs, 1):
        report.append(f"## {i}. {t}\n{out}\n")
    return "\n".join(report)

세 단계가 한 함수에 흐릅니다.

[1] plan()으로 작업 분해      (Planner, temperature=0)
[2] work()를 작업마다 반복     (Worker, temperature=0.5)
[3] 산출물을 마크다운으로 취합

2. "오케스트레이터"란

run_campaign 같은 함수를 오케스트레이터(orchestrator, 지휘자) 라 부릅니다.

오케스트라 지휘자: 각 연주자(Planner·Worker)에게 언제 무엇을 할지 지시
오케스트레이터 함수: 각 에이전트를 언제 호출할지, 결과를 어떻게 넘길지 제어

오케스트레이터의 책임:

- 순서 제어: Planner 먼저, 그 다음 Worker
- 데이터 전달: Planner 결과(작업 리스트)를 Worker에 넘김
- 취합: Worker 산출물을 모아 최종 결과로

에이전트들은 각자 일만 하고, 흐름은 오케스트레이터가 코드로 제어합니다. 26강에서는 for 루프로, 27강에서는 StateGraph로 이 지휘를 합니다.

5. 단일 호출 vs Planner/Worker 비교

같은 캠페인을 한 번의 LLM 호출로 처리했다면 어땠을까요?

[단일 호출] "캠페인 다 준비해줘"
   → 타깃 분석은 한 줄, 카피는 대충, 예산은 깜빡... (어설픔)

[Planner/Worker]
   → 각 작업을 독립적으로 깊이 처리 → 빠짐없이 균일한 품질

작업을 나눠 각자 집중하니 각 부분의 품질이 고르고 깊습니다. "한 번에 다"보다 "나눠서 차근차근"이 나은 거죠. 이게 Planner/Worker의 가치입니다.

6. 이 구조의 확장성

run_campaign은 작은 함수지만, 확장 여지가 많습니다.

- Worker 병렬화: for 루프 → ThreadPoolExecutor (05번)
- Worker 재시도: 실패 시 다시 (07번 신규)
- Reviewer 추가: 취합 후 검토 단계 (09번 실습)
- 전문 Worker: 작업별 다른 에이전트 (03번 + 25강 Supervisor)
- StateGraph화: for 루프 → 그래프 (27강)

지금은 가장 단순한 순차 버전입니다. 다음 절(07번)에서 실패 처리·재시도를 더해 견고하게 만들고, 27강에서 StateGraph로 발전시킵니다.

핵심 정리

  • run_campaign(): 계획 → 실행 → 취합을 묶은 오케스트레이터.
  • 오케스트레이터 = 흐름 지휘자(순서·데이터 전달·취합을 코드로 제어).
  • 취합: 작업을 섹션(## 1.)으로 묶어 → Planner 계획이 곧 문서 목차.
  • 단일 호출보다 품질이 고르고 깊음(각 작업에 집중).
  • 확장 여지: 병렬화·재시도·Reviewer·전문 Worker·StateGraph화.
  • 다음 절에서 Worker 실패 처리와 재시도를 더합니다.
