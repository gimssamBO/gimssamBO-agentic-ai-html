따라하기 — Planner 작업 분해

목표

캠페인 브리프를 읽어, Planner가 하위 작업 3~4개를 JSON 리스트로 분해하게 만듭니다. 구조화 출력으로 작업 리스트를 안전하게 받습니다.

0. 실습 준비

conda activate agentic
pip install -U langchain langchain-google-genai pydantic pandas
python code/common.py            # GOOGLE_API_KEY: True 확인
  • pydantic: 구조화 출력 스키마(8강).
  • pandas: 캠페인 CSV 읽기(11강).
  • 데이터: data/marketing_brief.csv (campaign_id, title, category, target, budget, key_offer).

1. 시작부와 데이터 로드

code/ch26_role_agent.py를 만듭니다.

# -*- coding: utf-8 -*-
# 실행: python code/ch26_role_agent.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))  # code/ 를 import 경로에
from common import get_chat, DATA

import pandas as pd
from pydantic import BaseModel, Field           # 구조화 출력(JSON 스키마) 정의용
from langchain_core.messages import SystemMessage, HumanMessage

# [왜 Planner/Worker 분리] 한 LLM에게 '계획도 세우고 실행도 하라'고 하면 둘 다 어설퍼진다.
#   Planner(계획 세우는 역할)가 작업을 잘게 쪼개고, Worker(실행 역할)가 한 작업씩
#   집중 수행하면 각자 잘하는 일에만 몰두해 품질이 올라간다. (25강 역할 분리의 연장선)


def load_brief_text(campaign_id: str = "CMP02") -> str:
    """캠페인 ID로 브리프 1건을 읽어 LLM에 넣을 한 줄 텍스트로 만든다."""
    brief = pd.read_csv(DATA / "marketing_brief.csv")
    campaign = brief[brief["campaign_id"] == campaign_id].iloc[0]   # 캠페인 1건 선택
    return (
        f"캠페인명: {campaign.title} / 카테고리: {campaign.category} / "
        f"타깃: {campaign.target} / 예산: {campaign.budget:,}원 / "
        f"핵심혜택: {campaign.key_offer}"
    )

load_brief_text는 CSV의 한 행을 LLM이 읽기 좋은 한 줄 텍스트로 만듭니다. 여러 컬럼을 "캠페인명: ... / 카테고리: ..." 형태로 합치죠.

2. 구조화 출력 스키마

Planner의 출력을 JSON 리스트로 강제할 스키마입니다(02번 원칙).

class Plan(BaseModel):
    """Planner가 만드는 실행 계획(구조화 출력 스키마)."""
    # [왜 구조화 출력] 자유 텍스트가 아니라 list[str] 형태로 강제해, 코드가
    #   결과를 바로 반복(for)할 수 있게 한다. 파싱 실수가 사라진다.
    subtasks: list[str] = Field(description="이 캠페인을 위해 필요한 하위 작업 3~4개")

subtasks: list[str] — 무슨 일이 있어도 결과가 문자열 리스트로 나옵니다. Field(description=...)은 LLM에게 "이 필드에 뭘 채울지" 알려주는 설명이죠.

3. Planner 함수

역할 프롬프트와 with_structured_output으로 작업을 분해합니다.

PLANNER_SYSTEM = (        # Planner 역할 고정 프롬프트 — '쪼개기만, 실행은 금지'
    "너는 마케팅 캠페인 '기획 설계자(Planner)'다. "
    "주어진 캠페인 브리프를 보고, 실행에 필요한 하위 작업을 3~4개로 쪼개라. "
    "작업은 서로 겹치지 않게, 한 문장 명령형으로 작성하라. 실행은 하지 마라."
)


def plan(llm, brief_text: str) -> list[str]:
    """브리프를 보고 하위 작업 리스트(JSON)로 분해한다."""
    planner = llm.with_structured_output(Plan)   # 출력을 Plan 스키마로 강제
    result = planner.invoke([
        SystemMessage(PLANNER_SYSTEM),           # 역할 지시
        HumanMessage(f"[캠페인 브리프]\n{brief_text}"),  # 입력 데이터
    ])
    return result.subtasks                       # 하위 작업 문자열 리스트

핵심

  • llm.with_structured_output(Plan) — 이 LLM은 이제 Plan 스키마로만 답합니다.
  • SystemMessage(역할) + HumanMessage(데이터) — 역할과 입력을 분리(2강 메시지 구조).
  • result.subtasks — .invoke 결과가 Plan 객체라, .subtasks로 리스트를 바로 꺼냄.

4. 실행해 확인

if __name__ == "__main__":
    brief_text = load_brief_text("CMP02")
    print("[브리프]", brief_text)
    print()

    llm_plan = get_chat(temperature=0)    # 계획은 재현성 → 0
    subtasks = plan(llm_plan, brief_text)
    print("[Planner 분해 결과]")
    for i, t in enumerate(subtasks, 1):
        print(f"   {i}. {t}")

예상 출력

[브리프] 캠페인명: 신학기 전자기기 프로모션 / 카테고리: 전자기기 / 타깃: 대학생 / 예산: 8,000,000원 / 핵심혜택: 이어버드+보조배터리 번들

[Planner 분해 결과]
   1. 대학생 타깃의 핵심 니즈와 구매 동기를 분석하라
   2. '이어버드+보조배터리 번들' 혜택을 강조한 광고 카피 3종을 작성하라
   3. 800만원 예산을 채널별로 배분하는 방안을 제안하라
   4. 캠페인 성과를 측정할 핵심 지표(KPI)를 정의하라

관찰 포인트

  • Planner가 캠페인을 3~4개 작업으로 깔끔히 쪼갰습니다. 각 작업은 한 문장 명령형이죠.
  • "실행은 하지 마라"를 지켜, 카피 자체는 안 쓰고 "카피를 작성하라"는 작업만 만들었습니다.
  • 결과가 리스트라 for로 바로 순회 가능 — 05번 Worker 루프에 그대로 넘어갑니다.

5. 구조화 출력의 가치 재확인

만약 구조화 출력 없이 자유 텍스트로 받았다면:

Planner: "먼저 대학생 타깃을 분석하고, 그 다음 번들 혜택 카피를 쓰고,
          예산은 800만원을 채널별로 나누면 됩니다."
   → 이걸 어떻게 ['작업1', '작업2', '작업3']로 쪼개지? (정규식? 줄바꿈? 번호?)
   → 형식이 매번 달라 파싱이 깨짐

with_structured_output(Plan) 덕에 항상 깔끔한 리스트를 받습니다. "LLM이 자유롭게 답하면 코드가 고생한다 → 형식을 강제하자"는 게 핵심이죠(8강). 에이전트 간 데이터 전달의 기본기입니다.

핵심 정리

  • load_brief_text(): 캠페인 CSV 한 행을 LLM용 한 줄 텍스트로.
  • Plan(subtasks: list[str]): 출력을 JSON 리스트로 강제하는 스키마.
  • PLANNER_SYSTEM: "쪼개기만, 실행 금지" + "겹치지 않게, 명령형".
  • llm.with_structured_output(Plan) → .subtasks로 작업 리스트 획득.
  • 구조화 출력 덕에 결과가 항상 리스트 → Worker 루프에 안전 전달.
  • 다음 절에서 Worker가 각 작업을 실행합니다.
