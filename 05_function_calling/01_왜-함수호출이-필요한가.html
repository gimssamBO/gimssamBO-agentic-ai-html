왜 함수 호출이 필요한가 — "두뇌에 손발을 달다"

한 줄 요약

1~4강에서는 LLM의 두뇌를 잘 쓰는 법(프롬프트·추론)을 배웠습니다. 하지만 두뇌만으로는 "내 주문 어디 왔어?", "재고 있어?"에 답할 수 없습니다. 이제 두뇌에 손발(도구) 을 달아, LLM이 실제 데이터를 조회하게 만듭니다. 이게 Function Calling이고, 에이전트로 가는 핵심 전환점입니다.

1. 두뇌만으로는 안 되는 일

1강의 그 문제를 떠올려 봅시다.

ask("승승장구몰 이어버드 지금 재고 있어요?")
# → "죄송하지만 실시간 재고는 확인할 수 없습니다 ..." (또는 환각)

아무리 프롬프트를 잘 짜고(3강) 단계적으로 생각하게 해도(4강), 재고 데이터 자체에 접근할 수단이 없으면 답할 수 없습니다. 두뇌는 똑똑하지만 손발이 없기 때문입니다.

2. 도구(Tool)를 쥐여 주면?

여기서 도구가 등장합니다. 도구는 거창한 게 아니라, 그냥 평범한 파이썬 함수입니다.

def get_stock(product_name: str) -> str:
    """상품명을 받아 현재 재고 수량을 반환한다."""
    # inventory.csv 를 조회해서...
    return "승승 무선 블루투스 이어버드 SE 재고 225개"

이 함수를 LLM에게 "쓸 수 있는 도구"로 쥐여 주면, LLM은 재고 질문이 왔을 때 스스로 이 함수를 호출해서 진짜 데이터를 가져옵니다.

question = "이어버드 재고 있어? 그리고 달러로 환산하려면 환율이 얼마야?"
# → LLM이 get_stock 도구와 get_exchange_rate 도구를 둘 다 호출하고,
#   그 결과로 정확한 답을 만든다.

비유: 1~4강에서 우리는 똑똑한 직원(LLM)을 채용했습니다. 하지만 그 직원에게 창고 열쇠(재고 도구) 와 환율 단말기(환율 도구) 를 주지 않으면, 아무리 똑똑해도 "창고에 가서 확인"할 수 없습니다. Function Calling이 바로 그 열쇠와 단말기를 쥐여 주는 일입니다.

4. 이 강에서 만들 도구

승승장구몰 운영에 필요한 두 가지 도구를 만듭니다.

  • get_stock(product_name): 재고 조회 (data/inventory.csv)
  • get_exchange_rate(currency): 환율 조회 (data/exchange_rates.csv)

이 두 도구를 LLM에 연결하면, "이어버드 재고를 달러로 환산하면?" 같은 복합 질문도 LLM이 알아서 두 도구를 조합해 답합니다.

핵심 정리

  • 1~4강은 두뇌(프롬프트·추론), 5강부터는 손발(도구).
  • 도구 = 평범한 파이썬 함수. LLM에 쥐여 주면 실제 데이터를 조회한다.
  • Function Calling은 LLM의 한계를 깨는 에이전트의 핵심 전환점.
