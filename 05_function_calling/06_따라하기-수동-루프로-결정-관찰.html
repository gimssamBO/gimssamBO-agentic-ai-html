따라하기 — 수동 루프로 모델의 결정 관찰

목표

자동 실행을 끄고, 모델이 "무엇을 호출하려 했는지"를 직접 들여다봅니다. 그리고 그 결정을 우리가 실행하고, 결과를 모델에 되돌려 최종 답을 만듭니다. 이게 7강 Agent Loop의 토대입니다.

1. 자동 실행 끄기

automatic_function_calling=types.AutomaticFunctionCallingConfig(disable=True)로 자동 실행을 끕니다. 그러면 모델은 결정만 하고 멈춥니다.

from common import get_genai_client, GEMINI_MODEL
from google.genai import types

client = get_genai_client()

resp = client.models.generate_content(
    model=GEMINI_MODEL,
    contents="이어버드 재고 알려줘.",
    config=types.GenerateContentConfig(
        tools=[get_stock, get_exchange_rate],
        automatic_function_calling=types.AutomaticFunctionCallingConfig(disable=True),  # 자동 끔
        temperature=0,
    ),
)

2. 모델의 '결정' 들여다보기

이제 resp.function_calls에 모델이 부르려는 함수 목록이 담겨 있습니다. 아직 실행은 안 됐습니다. 우리가 직접 실행합니다.

# 이름 → 함수 매핑 (모델이 고른 함수 이름으로 실제 함수를 찾기 위함)
TOOLS = {"get_stock": get_stock, "get_exchange_rate": get_exchange_rate}

for fc in resp.function_calls:
    print("모델의 결정 → 함수:", fc.name, "| 인자:", dict(fc.args))
    result = TOOLS[fc.name](**dict(fc.args))     # ← 우리가 직접 실행!
    print("우리가 실행한 결과:", result)

예상 출력

모델의 결정 → 함수: get_stock | 인자: {'product_name': '이어버드'}
우리가 실행한 결과: 승승 무선 블루투스 이어버드 SE 재고 225개 (서울물류)

여기서 세 가지를 확인하세요.

  • fc.name: 모델이 고른 함수 이름 ("get_stock")
  • fc.args: 모델이 채운 인자 ({'product_name': '이어버드'})
  • TOOLS[fc.name](**dict(fc.args)): 이름으로 진짜 함수를 찾아 우리가 실행

핵심: 모델은 get_stock을 product_name='이어버드'로 부르라고 결정만 했습니다. 실제 실행은 우리(파이썬)가 했죠. 02번에서 배운 "모델은 결정, 실행은 우리"를 눈으로 확인한 순간입니다.

3. TOOLS 딕셔너리가 왜 필요한가

모델은 함수 이름(문자열) "get_stock"을 줍니다. 그런데 문자열로는 함수를 호출할 수 없죠. 그래서 이름 → 함수 매핑이 필요합니다.

TOOLS = {"get_stock": get_stock, "get_exchange_rate": get_exchange_rate}

name = "get_stock"             # 모델이 준 이름
func = TOOLS[name]             # 이름으로 진짜 함수 객체를 찾음
result = func(product_name="이어버드")   # 호출

이 패턴은 7강 Agent Loop에서 계속 씁니다. 모델이 고른 도구를 이름으로 찾아 실행하는 거죠.

4. 결과를 모델에 되돌려 최종 답 만들기

수동에서 최종 답까지 만들려면, 실행 결과를 function_response로 다시 모델에 넣어야 합니다. 대화 기록을 순서대로 쌓습니다.

fc = resp.function_calls[0]
result = TOOLS[fc.name](**dict(fc.args))

followup = client.models.generate_content(
    model=GEMINI_MODEL,
    # 대화 기록: [사용자 질문] → [모델의 함수호출] → [우리의 실행 결과] 순으로 쌓는다
    contents=[
        types.Content(role="user",
                      parts=[types.Part(text="이어버드 재고 알려줘.")]),
        types.Content(role="model",
                      parts=[types.Part(function_call=fc)]),
        types.Content(role="user",
                      parts=[types.Part.from_function_response(
                          name=fc.name, response={"result": result})]),
    ],
)
print(followup.text)

예상 출력

승승 무선 블루투스 이어버드 SE는 현재 225개 재고가 있습니다(서울물류 보관).

세 개의 Content를 순서대로 쌓은 게 보이시나요?

  1. 사용자 질문 (role="user")
  2. 모델의 함수 호출 결정 (role="model", function_call=fc)
  3. 우리의 실행 결과 (role="user", from_function_response)

이렇게 "관찰 결과"를 모델이 봐야 최종 답을 만들 수 있습니다. 이 "대화 기록을 쌓아 가며 반복"하는 것이 바로 7강 Agent Loop의 핵심입니다.

5. 자동 vs 수동, 무엇을 봤나

  • 자동(05번): tools=[...]만 주면 끝. 편하지만 안이 안 보임.
  • 수동(06번): 자동을 끄고 function_calls를 직접 실행. 모델의 "결정"이 보이고, 중간에 제어를 끼울 수 있음.

7강에서는 이 수동 루프를 while로 감싸, 모델이 "재고 확인 → 부족하면 재주문 기준 조회 → 판단"처럼 여러 단계를 스스로 처리하는 에이전트를 만듭니다.

핵심 정리

  • disable=True로 자동을 끄면 모델은 결정만(function_calls) 하고 멈춘다.
  • TOOLS[fc.name](**dict(fc.args))로 이름→함수를 찾아 우리가 실행한다.
  • 최종 답은 결과를 from_function_response로 되돌려 만든다.
  • 이 "결정→실행→결과 전달" 루프가 7강 Agent Loop의 토대다.
  • 다음 절에서 도구가 실패할 때 우아하게 처리하는 법을 배웁니다.
