도구 실행 오류 처리

한 줄 요약

도구는 항상 성공하지 않습니다. 없는 상품, 없는 통화, 심지어 DB 다운까지 일어납니다. 오류를 try/except로 잡아 친절한 메시지로 바꿔 모델에 돌려주면, 에이전트가 멈추지 않고 사용자에게 자연스럽게 안내합니다.

1. 도구는 왜 실패하는가

실제 운영에서 도구는 다양한 이유로 실패합니다.

  • 없는 데이터: 고객이 "존재하지않는상품XYZ 재고 있어?"라고 물음 → 빈 결과
  • 잘못된 입력: "ZZZ 환율 알려줘" → 지원하지 않는 통화
  • 인프라 장애: 재고 DB가 다운됨 → 연결 실패 예외

이때 도구 함수가 그냥 예외를 던지면, 에이전트 전체가 멈춰 버립니다. 고객은 아무 답도 못 받죠. 이건 서비스로서 실격입니다.

비유: 콜센터 상담원(에이전트)이 재고 조회 단말기(도구)가 먹통이 됐다고 전화를 뚝 끊어 버리면 안 됩니다. "지금 시스템 점검 중이라 잠시 후 확인 가능합니다"라고 안내해야죠.

2. 핵심 전략 — 예외를 친절한 문자열로

방법은 간단합니다. 도구 함수 안에서 try/except로 오류를 잡고, 예외 대신 친절한 안내 문자열을 반환합니다. 그러면 모델이 그 문자열을 보고 사용자에게 안내합니다.

참고: 이건 공식 문서도 권장하는 방식입니다 — "예외를 던지는 대신, 모델이 처리하도록 둘 수 있다(instead of raising the exception, you can let the model handle it)". 

def get_stock(product_name: str) -> str:
    """상품명을 받아 현재 재고 수량을 반환한다."""
    try:
        row = inv[inv["product_name"].str.contains(product_name, na=False)]
        if row.empty:
            # 빈 결과를 '예외'가 아닌 '친절한 안내'로 바꿔 돌려준다
            return f"'{product_name}' 상품을 찾을 수 없습니다. (상품명을 다시 확인해 주세요)"
        r = row.iloc[0]
        return f"{r['product_name']} 재고 {int(r['stock'])}개 ({r['warehouse']})"
    except Exception as e:
        # 장애는 사용자에게 숨기고, 모델이 안내할 수 있는 메시지로 변환
        return f"일시적인 시스템 오류로 재고를 조회하지 못했습니다. 잠시 후 다시 시도해 주세요. (사유: {e})"

두 가지를 처리했습니다.

  • 빈 결과(row.empty): "상품을 찾을 수 없습니다" 안내
  • 예외(except): "일시적 오류, 잠시 후 다시" 안내

3. DB 다운 시뮬레이션

인프라 장애를 흉내 내기 위해, 스위치 하나로 강제 예외를 던지게 해 봅니다. (실습 파일: 아래 소스코드 -> 수강생에게 코드 리뷰만)

def get_stock(product_name: str) -> str:
    """상품명을 받아 현재 재고 수량을 반환한다."""
    try:
        # DB 장애 상황을 강제로 재현하기 위한 플래그
        # (실제 서비스에서는 이 if 블록 대신 진짜 DB 연결 코드가 들어감)
        if DB_DOWN:
            raise ConnectionError("재고 DB 연결 실패(timeout)")   # 장애 흉내
        # ... (정상 조회 로직)
        # DB_DOWN이 False일 때 실행될 실제 재고 조회 로직이 이 자리에 들어감
    except Exception as e:
        # 어떤 예외가 발생하든 프로그램이 중단되지 않고,
        # 모델(또는 호출한 쪽)에게 자연스러운 오류 메시지를 문자열로 반환
        # → function calling 흐름에서 도구 실행 실패를 우아하게 처리하는 패턴
        return f"일시적인 시스템 오류로 재고를 조회하지 못했습니다. (사유: {e})"

4. 오류 결과를 모델에 돌려 최종 안내 만들기

06번의 수동 루프 구조를 그대로 쓰되, 도구가 오류 문자열을 반환해도 그걸 모델에 넘깁니다. 모델은 그 오류를 보고 사과하며 안내합니다.

OpenAI

def run_turn(question: str) -> str:
    resp = client.chat.completions.create(
        model=OPENAI_MODEL,
        messages=[{"role": "user", "content": question}],
        tools=tools,
        temperature=0,
    )
    msg = resp.choices[0].message
    if not msg.tool_calls:
        return msg.content

    history = [
        {"role": "user", "content": question},
        msg,
    ]
    for tc in msg.tool_calls:
        result = TOOLS[tc.function.name](**json.loads(tc.function.arguments))   # 오류는 함수 내부 try/except 가 흡수
        history.append({
            "role": "tool",
            "tool_call_id": tc.id,
            "name": tc.function.name,
            "content": json.dumps({"result": result}),
        })

    # 오류 메시지를 포함한 결과를 모델에 되돌려 최종 안내문을 만든다
    followup = client.chat.completions.create(
        model=OPENAI_MODEL,
        messages=[
            {"role": "system", "content": "너는 승승장구몰 CS 상담원이다. 도구 결과가 오류면 "
                                          "사과하고 다음 행동을 정중히 안내하라."},
            *history,
        ],
        temperature=0.3,
    )
    return followup.choices[0].message.content

Gemini

def run_turn(question: str) -> str:
    resp = client.models.generate_content(
        model=GEMINI_MODEL, contents=question,
        config=types.GenerateContentConfig(
            tools=[get_stock, get_exchange_rate],
            automatic_function_calling=types.AutomaticFunctionCallingConfig(disable=True),
            temperature=0),
    )
    if not resp.function_calls:
        return resp.text

    history = [types.Content(role="user", parts=[types.Part(text=question)])]
    for fc in resp.function_calls:
        result = TOOLS[fc.name](**dict(fc.args))   # 오류는 함수 내부 try/except 가 흡수
        history.append(types.Content(role="model", parts=[types.Part(function_call=fc)]))
        history.append(types.Content(role="user", parts=[types.Part.from_function_response(
            name=fc.name, response={"result": result})]))

    # 오류 메시지를 포함한 결과를 모델에 되돌려 최종 안내문을 만든다
    followup = client.models.generate_content(
        model=GEMINI_MODEL, contents=history,
        config=types.GenerateContentConfig(
            system_instruction="너는 승승장구몰 CS 상담원이다. 도구 결과가 오류면 "
                               "사과하고 다음 행동을 정중히 안내하라.",
            temperature=0.3),
    )
    return followup.text

예상 출력

[1] 없는 상품 조회
A: 죄송합니다, '존재하지않는상품XYZ' 상품을 찾을 수 없습니다. 정확한 상품명을 알려주시면 다시 확인해 드리겠습니다.

[3] DB 다운 시뮬레이션
A: 죄송합니다. 일시적인 시스템 오류로 재고를 조회하지 못했습니다. 잠시 후 다시 시도해 주시거나, 잠시 뒤 문의 주시면 빠르게 도와드리겠습니다.

에이전트가 멈추지 않고 정중하게 안내합니다. 오류가 났는데도 서비스가 살아 있죠.

5. 왜 이게 중요한가

해피 패스(happy path, 모든 게 잘 되는 경우)만 처리하는 에이전트는 장난감입니다. 실제 서비스는 실패를 우아하게 다뤄야 합니다. 이 "예외를 친절한 메시지로 변환" 패턴은 앞으로 모든 도구·에이전트에서 반복됩니다(12강 폴백, 29강 재시도).

핵심 정리

  • 도구는 빈 결과·잘못된 입력·인프라 장애로 실패할 수 있다.
  • try/except로 잡아 예외 대신 친절한 문자열을 반환한다(공식 권장 방식).
  • 모델은 그 오류 문자열을 보고 사과·안내한다 → 에이전트가 멈추지 않는다.
  • 해피 패스만이 아니라 실패 처리가 진짜 서비스의 조건이다.
