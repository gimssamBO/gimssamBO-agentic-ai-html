직접 코드를 고쳐 보며 5강 내용을 손에 익힙니다. 먼저 스스로 풀어 본 뒤 해답을 펼쳐 보세요.

문제 1 — 독스트링 품질 실험

get_stock의 독스트링을 부실하게("""재고.""") 바꾼 버전과 자세한 원래 버전, 두 가지로 "이어버드 남았어?"를 수동 루프로 실행하세요.

  • 매 실행마다 resp.function_calls가 비었는지(도구 미선택), 아니면 get_stock을 골랐는지 출력합니다.
  • 사용 파일: data/inventory.csv
  • 기대 결과: 부실한 독스트링일 때 도구 선택이 흔들리고, 자세한 독스트링일 때 정확히 고르는 차이가 보이면 성공.
해답 보기 
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_genai_client, GEMINI_MODEL, DATA
from google.genai import types
import pandas as pd

client = get_genai_client()
inv = pd.read_csv(DATA / "inventory.csv", encoding="utf-8-sig")

def make_get_stock(doc: str):
    """독스트링만 다른 get_stock 함수를 만들어 돌려준다."""
    def get_stock(product_name: str) -> str:
        row = inv[inv["product_name"].str.contains(product_name, na=False)]
        if row.empty:
            return f"'{product_name}' 재고 정보를 찾지 못했습니다."
        r = row.iloc[0]
        return f"{r['product_name']} 재고 {int(r['stock'])}개"
    get_stock.__doc__ = doc      # 독스트링을 바꿔치기
    return get_stock

def test(doc: str, label: str):
    tool = make_get_stock(doc)
    resp = client.models.generate_content(
        model=GEMINI_MODEL,
        contents="이어버드 남았어?",
        config=types.GenerateContentConfig(
            tools=[tool],
            automatic_function_calling=types.AutomaticFunctionCallingConfig(disable=True),
            temperature=0),
    )
    calls = resp.function_calls or []
    picked = calls[0].name if calls else "(도구 미선택)"
    print(f"[{label}] 독스트링={doc!r} → 모델 선택: {picked}")

test("재고.", "부실")
test("상품명(일부만 입력해도 됨)을 받아 현재 재고 수량을 반환한다.", "자세함")
**예상 출력** 
[부실] 독스트링='재고.' → 모델 선택: (도구 미선택) 또는 흔들림
[자세함] 독스트링='상품명(일부만...)' → 모델 선택: get_stock
**해설**: 모델은 함수 본문을 못 보고 **독스트링만** 봅니다. `"재고."` 처럼 부실하면 "이 도구가 재고 조회에 쓰는 거구나"를 확신하지 못해 도구를 안 고르거나 흔들립니다. 자세한 독스트링은 정확한 선택을 이끕니다. **독스트링이 곧 도구 성능**이라는 6강의 핵심을 미리 체험한 셈입니다.

문제 2 — 환율 자동 처리 + 곱셈 검증

자동 function calling으로 "10000엔이면 원화로 얼마야?"를 실행하세요. 그리고 data/exchange_rates.csv에서 JPY의 krw_per_unit을 직접 읽어 10000 * krw_per_unit을 파이썬으로 계산한 값과, 모델 최종 답의 금액을 나란히 출력해 비교하세요.

  • 사용 파일: data/exchange_rates.csv
  • 기대 결과: 모델 답의 원화 금액과 직접 계산한 금액이 (오차 범위 내) 일치하면 성공.
해답 보기 
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from common import get_genai_client, GEMINI_MODEL, DATA
from google.genai import types
import pandas as pd

client = get_genai_client()
rates = pd.read_csv(DATA / "exchange_rates.csv", encoding="utf-8-sig")

def get_exchange_rate(currency: str) -> str:
    """통화 코드(USD, EUR, JPY 등)를 받아 1단위당 원화(KRW) 환율을 반환한다."""
    row = rates[rates["currency"].str.upper() == currency.upper()]
    if row.empty:
        return f"{currency} 환율 정보가 없습니다."
    return f"1 {currency.upper()} = {float(row.iloc[0]['krw_per_unit']):,.2f} KRW"

# (1) 모델에게 자동 처리 시키기
resp = client.models.generate_content(
    model=GEMINI_MODEL,
    contents="10000엔이면 원화로 얼마야?",
    config=types.GenerateContentConfig(tools=[get_exchange_rate], temperature=0),
)
print("[모델 답]", resp.text)

# (2) 직접 계산해 검증
jpy = float(rates[rates["currency"].str.upper() == "JPY"].iloc[0]["krw_per_unit"])
print(f"[직접 계산] 10000 × {jpy} = {10000 * jpy:,.0f} 원")
**예상 출력** 
[모델 답] 10,000엔은 약 90,000원입니다. (환율 1 JPY = 9.00 KRW 기준)
[직접 계산] 10000 × 9.0 = 90,000 원
**해설**: 모델은 `get_exchange_rate("JPY")`를 호출해 환율(9.00)을 얻고, 거기에 10000을 곱해 답했습니다. 직접 계산한 값과 일치하죠. **주의**: 곱셈 자체는 4강에서 봤듯 LLM이 가끔 틀립니다. 그래서 큰 금액이나 중요한 계산은 도구가 환율을 주고 **곱셈은 코드로** 하는 게 더 안전합니다(10강 코드 실행 에이전트에서 이 방식을 배웁니다).

정리

  • 문제 1로 독스트링이 도구 선택을 좌우한다는 걸 확인했습니다(→ 6강 핵심).
  • 문제 2로 도구 + 계산을 조합하고 직접 계산으로 검증했습니다.

이것으로 5강을 마칩니다. 다음 6강에서는 도구가 여러 개일 때의 "도구 선택" 문제를 다룹니다!
