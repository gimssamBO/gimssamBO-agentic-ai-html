도구 실패 시 폴백(fallback) 처리

한 줄 요약

현실의 도구는 데이터가 없거나 예외를 던지며 빈손으로 돌아올 때가 있습니다. 이때 에이전트가 멈추면 안 됩니다. 도구가 에러/빈 결과를 친절한 문자열로 돌려주고, 시스템 프롬프트로 모델이 대체 안내(폴백) 를 하도록 유도합니다.

1. 폴백이란?

폴백(fallback) 은 "원래 하려던 게 안 될 때의 대비책"입니다. 도구가 실패해도 에이전트가 멈추지 않고 다른 안내를 하는 거죠.

정상: 주문 조회 성공 → 주문 상태 안내
폴백: 주문 조회 실패(없는 고객) → "고객ID를 다시 확인해 주세요" 안내 + 고객센터 연결

5강에서 단일 도구의 오류 처리를 배웠는데, 멀티툴에서는 이게 더 중요합니다. 도구가 많을수록 하나가 실패할 확률이 높아지니까요.

2. 두 단계 폴백

폴백은 두 단계로 만듭니다.

① 도구: 실패를 '신호 문자열'로 반환

예외를 던지지 않고, 모델이 읽을 수 있는 명확한 실패 신호를 돌려줍니다. (실습 파일: sections/12_multi_tool_agent/06_도구-실패시-폴백-처리.py)

@tool
def get_order_status(customer_id: str) -> str:
    """고객 ID의 가장 최근 주문 1건의 상태를 조회한다."""
    df = orders[orders["customer_id"] == customer_id]
    if df.empty:
        # 예외를 던지지 않고, 모델이 읽고 폴백할 수 있는 명확한 문자열을 반환
        return f"[조회실패] {customer_id} 고객의 주문 내역이 없습니다. 고객ID를 다시 확인해 주세요."
    ...

@tool
def get_stock(product_id: str) -> str:
    """product_id의 현재 재고 수량을 조회한다."""
    try:
        df = inventory[inventory["product_id"] == product_id]
        if df.empty:
            return f"[조회실패] {product_id} 의 재고 정보가 없습니다."
        ...
    except Exception as e:
        # 도구 내부 예외도 밖으로 던지지 않고 문자열로 → 루프가 죽지 않는다
        return f"[도구오류] 재고 조회 중 문제가 발생했습니다: {e}"

[조회실패], [도구오류] 같은 태그를 붙이는 게 포인트입니다. 모델이 "아, 이건 실패한 결과구나"를 알아챌 수 있게요.

② 시스템 프롬프트: 실패 시 행동 지시

모델에게 "실패 신호를 받으면 이렇게 행동하라"고 가르칩니다.

SYSTEM = (
    "너는 승승장구몰의 운영 비서다. 도구를 사용해 답하라.\n"
    "도구 결과가 '[조회실패]' 또는 '[도구오류]'로 시작하면, 그 사실을 사용자에게\n"
    "솔직히 알리고 멈추지 말고 대체 안내를 하라. 예: 올바른 입력 형식 안내,\n"
    "다른 식별 정보 요청, 고객센터(1588-0000) 연결 안내. 답은 한국어로 한다."
)

이 지시 덕분에 모델이 [조회실패]를 보면 사과 + 대체 안내를 합니다.

3. 정상 vs 폴백 비교

questions = [
    "C0001 고객의 최근 주문 상태를 알려줘.",   # 정상 (존재하는 고객)
    "C9999 고객의 최근 주문 상태를 알려줘.",   # 폴백 (없는 고객)
]

예상 출력

Q: C0001 고객의 최근 주문 상태를 알려줘.
A: C0001 고객의 최근 주문은 '현미 잡곡'이며 배송완료 상태입니다.

Q: C9999 고객의 최근 주문 상태를 알려줘.
A: 죄송합니다. C9999 고객님의 주문 내역을 찾을 수 없습니다. 고객ID를 다시 확인해
   주시거나, 도움이 필요하시면 고객센터(1588-0000)로 문의해 주세요.

없는 고객(C9999)에 대해 에이전트가 멈추지 않고 정중히 안내했습니다. "주문 내역이 없다"는 사실을 알리고, "고객ID 확인" + "고객센터 연결"이라는 대체 경로를 제시했죠.

4. 왜 예외를 안 던지나

핵심 원칙: 도구는 예외를 던지지 말고 문자열을 반환한다.

# 나쁨 — 예외를 던지면 에이전트 전체가 멈춤
if df.empty:
    raise ValueError("주문 없음")    # 💥 루프 중단

# 좋음 — 문자열로 돌려주면 모델이 읽고 대응
if df.empty:
    return "[조회실패] 주문 내역이 없습니다."   # ✓ 모델이 폴백

예외를 던지면 LangChain 루프가 멈추거나 에러로 끝납니다. 반면 문자열을 돌려주면 모델이 그걸 관찰(Observation) 로 받아 다음 행동(폴백 안내)을 정할 수 있죠. 7강의 "관찰을 되돌리기"가 여기서도 작동합니다.

5. 폴백이 만드는 차이

폴백이 있고 없고는 서비스 품질을 가릅니다.

  • 폴백 없음: 없는 고객ID → 에러로 중단 → 사용자는 아무 답도 못 받음 (나쁨)
  • 폴백 있음: 없는 고객ID → "다시 확인해 주세요" 안내 → 사용자가 다음 행동을 앎 (좋음)

콜센터 상담원이 "그런 고객 없습니다" 하고 전화를 끊으면 안 되죠. "고객님, 혹시 다른 번호로 가입하셨을까요?"라고 이어가야 합니다. 폴백이 그 역할입니다.

핵심 정리

  • 폴백 = 도구가 실패해도 에이전트가 멈추지 않고 대체 안내하는 것.
  • ① 도구는 [조회실패] 같은 신호 문자열을 반환(예외 금지).
  • ② 시스템 프롬프트로 "실패 신호 받으면 대체 안내하라" 지시.
  • 예외를 던지면 루프가 멈추지만, 문자열은 모델이 관찰해 대응한다.
  • 폴백이 장난감과 진짜 서비스를 가른다.
  • 다음 절에서 잘못된 입력을 검증하는 법을 배웁니다.
