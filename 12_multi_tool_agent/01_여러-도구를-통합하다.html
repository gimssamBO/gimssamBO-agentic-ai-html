여러 도구를 통합하다 (1부 종합)

한 줄 요약

지금까지는 도구가 하나(검색 또는 분석)였습니다. 하지만 진짜 상담봇은 주문 조회·재고 확인·매출 분석을 모두 할 수 있어야 합니다. 여러 도구를 한 에이전트에 통합하면, LLM이 질문에 맞는 도구를 스스로 골라 순서대로 호출합니다.

1. 현실의 질문은 도구 하나로 안 끝난다

지금까지 강마다 능력을 하나씩 키웠습니다 — 8강 계획, 9강 검색, 10강 코드 실행, 11강 데이터 분석. 그런데 현실의 질문은 한 가지 도구로 안 끝납니다.

"C0001 고객의 최근 주문 상태와, 그 상품 재고, 그리고 이번 달 전체 매출을 알려줘."

이 한 문장에 세 가지 일이 들어 있습니다.

  1. 주문 조회: C0001의 최근 주문 → "현미 잡곡, product_id=P0025"
  2. 재고 조회: P0025의 재고 → "155개"
  3. 매출 분석: 이번 달 전체 매출 → "약 1천만원"

진짜 상담봇은 이렇게 여러 도구를 손에 쥐고, 질문에 맞춰 골라 쓰며, 결과를 이어붙여 답합니다.

2. 1부의 종합

이번 강은 1부에서 만든 도구들이 하나로 모이는 종합편입니다.

도구 데이터 역할 어디서 배웠나
get_order_status orders.csv 고객 최근 주문 상태 5·6강
get_stock inventory.csv 상품 재고/재주문 5·7강
run_pandas orders.csv 매출 등 집계 분석 10·11강
(선택) 웹 검색 웹 최신 정보 9강

각 도구는 이미 배운 것들입니다. 12강의 새로움은 이것들을 한 에이전트에 통합하는 것이죠.

비유: 지금까지 망치(5강), 드라이버(9강), 줄자(11강)를 따로따로 만들었다면, 이제 하나의 공구함에 다 넣는 겁니다. 그러면 어떤 작업이 와도 적절한 공구를 꺼내 쓸 수 있죠.

3. 핵심 개념 두 가지

이 강의 핵심은 두 가지입니다.

① 도구 라우팅 (02번)

LLM이 각 도구의 docstring을 읽고 "지금 어떤 도구가 필요한가"를 스스로 판단합니다. 우리가 if-else로 짜는 게 아닙니다.

② 연쇄 호출 (05번)

앞 도구의 결과를 다음 도구의 입력으로 이어 씁니다. "주문 조회로 얻은 product_id를 재고 조회에 넣는" 식이죠.

4. 추가로 배울 실무 기법

기본 통합 외에, 실무에 꼭 필요한 두 가지를 더 배웁니다.

  • 폴백 처리(06번): 도구가 실패해도 에이전트가 멈추지 않고 대체 안내를 하게.
  • 입력 검증(07번): 잘못된 입력(c1, 공백 등)을 도구가 미리 걸러내게.

이 두 가지가 "장난감 에이전트"와 "진짜 서비스"를 가르는 차이입니다.

핵심 정리

  • 현실의 질문은 여러 도구가 필요하다(주문+재고+분석).
  • 12강은 1부 도구들을 한 에이전트에 통합하는 종합편.
  • 핵심: 도구 라우팅(LLM이 도구 선택) + 연쇄 호출(결과를 이어 씀).
  • 실무 기법: 폴백(실패 대응) + 입력 검증.
