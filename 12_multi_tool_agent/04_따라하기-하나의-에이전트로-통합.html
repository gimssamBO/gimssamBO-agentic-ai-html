따라하기 — 하나의 에이전트로 통합

목표

03번에서 만든 세 도구를 하나의 에이전트에 통합합니다. 시스템 프롬프트로 도구 선택·연쇄·집계 규칙을 가르칩니다.

1. 도구 목록으로 묶기

세 도구를 리스트에 담습니다. 이게 에이전트에게 쥐여 줄 "공구함"입니다.

# 에이전트에게 쥐여 줄 도구 목록. LLM은 각 docstring을 보고 무엇을 쓸지 라우팅한다.
TOOLS = [get_order_status, get_stock, run_pandas]

도구를 추가하고 싶으면 이 리스트에 넣기만 하면 됩니다. 예를 들어 9강의 웹 검색을 추가하려면 TOOLS = [..., web_search]처럼요.

2. 시스템 프롬프트 — 라우팅·연쇄 규칙

여러 도구를 다룰 때는 시스템 프롬프트에 사용 규칙을 명시합니다.

SYSTEM = (
    "너는 승승장구몰의 운영 비서다. 필요한 도구를 골라 순서대로 사용해 답하라.\n"
    "여러 정보가 필요하면 도구를 여러 번 호출해도 된다. 앞 도구 결과(product_id 등)를\n"
    "다음 도구의 입력으로 이어 써라. 매출 집계 시 취소/환불은 제외하고,\n"
    "답은 한국어로 항목별로 정리한다."
)

세 가지를 지시했습니다.

  • "필요한 도구를 골라 순서대로": 라우팅과 다단계 사용을 허용
  • "앞 도구 결과를 다음 도구 입력으로 이어 써라": 연쇄 호출 유도 (핵심!)
  • "매출 집계 시 취소/환불 제외": 분석 규칙(11강 복습)

특히 "앞 도구 결과를 이어 써라" 가 연쇄 호출의 비결입니다. 이 한 줄이 "주문 조회 → product_id 획득 → 재고 조회"를 가능하게 합니다.

3. 에이전트 생성

agent = create_agent(llm, tools=TOOLS, system_prompt=SYSTEM)

8강부터 계속 본 그 패턴입니다. 도구가 3개로 늘었을 뿐, 코드는 똑같습니다. LangChain이 라우팅·연쇄·반복을 모두 내부에서 처리합니다.

4. 통합 에이전트의 구조

하나의 통합 에이전트(create_agent)가 질문을 받아 처리합니다.

  • 질문 입력 → 에이전트가 각 도구의 docstring을 보고 라우팅.
  • 보유 도구: get_order_status · get_stock · run_pandas — 필요한 만큼 골라 순서대로 실행.
  • 결과를 모아 정리 → 답변 출력.

하나의 에이전트가 세 도구를 다 쥐고, 질문에 맞춰 필요한 걸 골라 씁니다.

5. 간단 실행

q = "C0001 고객의 최근 주문 상태를 알려줘."
result = agent.invoke({"messages": [{"role": "user", "content": q}]})
print(result["messages"][-1].content)

예상 출력

C0001 고객의 최근 주문은 '승승 현미 잡곡 10kg'이며, 2026-03-26에 주문되어
현재 '배송완료' 상태입니다.

이 질문은 주문 도구 하나만 필요했습니다. 에이전트가 "주문 상태" 질문임을 알고 get_order_status만 라우팅했죠. 다음 절에서는 여러 도구가 연쇄되는 복합 질문을 봅니다.

핵심 정리

  • 도구들을 TOOLS 리스트에 담아 create_agent에 넘긴다.
  • 시스템 프롬프트에 "앞 도구 결과를 다음 입력으로 이어 써라"(연쇄 핵심).
  • 도구가 늘어도 create_agent 코드는 똑같다(라우팅은 LangChain이 처리).
  • 단순 질문은 도구 하나만 라우팅된다.
  • 다음 절에서 여러 도구가 연쇄 호출되는 복합 질문을 봅니다.
