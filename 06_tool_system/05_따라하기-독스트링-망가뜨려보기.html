따라하기 — 독스트링 망가뜨려 보기

목표

독스트링이 정말 중요한지, 일부러 망가뜨려 확인합니다. 모호한 설명을 주면 모델이 도구 선택을 흔들거나 실패하는 걸 직접 봅니다. "독스트링 = 도구 성능"을 체감하는 실험입니다.

1. 실험 설계

같은 도구를 두 가지 독스트링으로 준비합니다.

  • 자세한 버전: "상품명을 받아 판매가(원)를 반환한다. 가격/얼마 질문에 사용."
  • 망가진 버전: "정보를 반환한다."

그리고 같은 질문("청바지 얼마야?")을 두 버전으로 돌려, 모델의 선택이 어떻게 달라지는지 봅니다.

2. 코드 — 독스트링만 바꿔 비교

from common import get_genai_client, GEMINI_MODEL, DATA
from google.genai import types
import pandas as pd

client = get_genai_client()
products = pd.read_csv(DATA / "products.csv")

def make_get_price(doc: str):
    """독스트링만 다른 get_price 함수를 만들어 돌려준다."""
    def get_price(product_name: str) -> str:
        row = products[products["product_name"].str.contains(product_name, na=False)]
        if row.empty:
            return f"'{product_name}' 가격 정보를 찾지 못했습니다."
        return f"{row.iloc[0]['product_name']} 판매가 {int(row.iloc[0]['price']):,}원"
    get_price.__doc__ = doc       # 독스트링을 바꿔치기
    return get_price

def which_tool(question, tools):
    resp = client.models.generate_content(
        model=GEMINI_MODEL, contents=question,
        config=types.GenerateContentConfig(
            tools=tools,
            automatic_function_calling=types.AutomaticFunctionCallingConfig(disable=True),
            temperature=0),
    )
    calls = resp.function_calls or []
    picked = calls[0].name if calls else "(도구 미선택)"
    print(f"  → 모델 선택: {picked}")

3. 실행 — 자세함 vs 망가짐

q = "슬림핏 청바지 얼마야?"

print("[자세한 독스트링]")
good_price = make_get_price("상품명을 받아 판매가(원)를 반환한다. 가격/얼마 질문에 사용.")
which_tool(q, [good_price, get_stock])

print("[망가진 독스트링]")
bad_price = make_get_price("정보를 반환한다.")
which_tool(q, [bad_price, get_stock])

예상 출력

[자세한 독스트링]
  → 모델 선택: get_price       ← 정확히 가격 도구를 고름

[망가진 독스트링]
  → 모델 선택: (도구 미선택) 또는 get_stock   ← 헷갈리거나 엉뚱한 선택

망가진 독스트링("정보를 반환한다")을 주니, 모델이 "이 도구가 가격 조회용인지" 확신하지 못해 도구를 안 고르거나 엉뚱한 걸 골랐습니다.

4. 무엇을 배웠나

이 실험은 한 가지를 분명히 보여 줍니다.

함수 코드는 똑같은데, 독스트링만 바꿨더니 모델의 선택이 달라졌다.

모델은 함수 본문을 못 보고 독스트링만 보기 때문입니다(02번). 그러니 독스트링은 "있으면 좋은 주석" 이 아니라 "도구의 성능을 결정하는 핵심 코드" 입니다.

5. 실무 팁 — 독스트링 점검 체크리스트

도구를 만들 때 독스트링을 이렇게 점검하세요.

  • [ ] 무엇을 하는가가 한 문장으로 분명한가? ("판매가를 반환")
  • [ ] 언제 쓰는가가 적혀 있는가? ("가격/얼마 질문에 사용")
  • [ ] 인자에 무엇을 넣어야 하는지 알 수 있는가? ("상품명")
  • [ ] 비슷한 다른 도구와 구별되는가? (다음 절 주제)

마지막 항목 — "비슷한 도구와 구별되는가" — 가 다음 절의 핵심입니다.

핵심 정리

  • 함수 코드가 같아도 독스트링만 망가지면 도구 선택이 흔들린다.
  • 모델은 본문이 아닌 독스트링으로 판단하기 때문이다.
  • 독스트링은 "주석"이 아니라 도구 성능을 결정하는 코드다.
  • 다음 절에서 비슷하게 겹치는 도구를 구분하는 법을 배웁니다.
