좋은 도구 설계 원칙

한 줄 요약

좋은 도구는 다섯 가지 원칙을 지킵니다: 한 도구는 한 가지 일 · 이름이 곧 기능 · 인자가 명확 · 설명이 구체적 · 반환이 일관. 이 원칙들은 모두 "모델이 도구를 정확히 고르고 올바르게 쓰게" 하기 위한 것입니다.

1. 다섯 가지 원칙

원칙 나쁜 예 좋은 예
한 도구는 한 가지 일 do_everything() get_price, get_stock 분리
이름이 곧 기능 func1, helper get_order_status
인자가 명확 q: str("뭐든 넣어") product_name: str
설명이 구체적 "정보를 준다" "상품명을 받아 판매가(원)를 반환한다"
반환이 일관 때론 dict, 때론 None 항상 사람이 읽는 문자열

하나씩 봅시다.

2. 원칙 ① — 한 도구는 한 가지 일

도구 하나가 여러 일을 하면, 모델은 "이 도구를 언제 써야 하지?"를 판단하기 어렵습니다.

# 나쁨 — 한 도구가 가격·재고·주문을 다 처리
def product_tool(query: str, mode: str) -> str:
    """mode에 따라 가격/재고/주문을 처리한다."""   # 모델이 mode를 잘못 줄 수 있음
    ...

# 좋음 — 일마다 도구를 나눔
def get_price(product_name: str) -> str: ...
def get_stock(product_name: str) -> str: ...
def get_order_status(order_id: str) -> str: ...

도구를 나누면 각 도구의 역할이 또렷해져, 모델이 고르기 쉽습니다.

3. 원칙 ② — 이름이 곧 기능

함수 이름만 봐도 무슨 일을 하는지 알 수 있어야 합니다. 모델은 이름도 선택 근거로 씁니다.

def func1(x): ...          # 나쁨 — 이름에 정보가 없음
def get_order_status(order_id): ...   # 좋음 — 이름이 곧 설명

get_(조회), search_(검색), update_(수정) 같은 동사 접두사를 일관되게 쓰면 더 명확합니다.

4. 원칙 ③ — 인자가 명확

인자 이름과 타입이 명확해야 모델이 올바른 값을 채웁니다.

def lookup(q: str): ...                    # 나쁨 — q가 뭘 넣는 건지 모름
def get_price(product_name: str): ...      # 좋음 — '상품명'을 넣으라고 명확
def get_order_status(order_id: str): ...   # 좋음 — '주문번호'를 넣으라고 명확

인자 이름이 product_name이면 모델은 질문에서 상품명을 뽑아 넣고, order_id면 주문번호를 뽑아 넣습니다.

5. 원칙 ④ — 설명이 구체적

가장 중요한 원칙입니다(02번에서 강조). 설명은 무엇을 + 언제를 담습니다.

def get_price(product_name: str) -> str:
    """상품명(일부만 입력해도 됨)을 받아 판매가(원)를 반환한다. 가격/얼마 질문에 사용."""
    # 독스트링 = '무엇을'(상품명→판매가) + '언제'(가격/얼마 질문)

"정보를 반환한다" 같은 모호한 설명은 모델을 헷갈리게 합니다.

6. 원칙 ⑤ — 반환이 일관

도구는 항상 같은 형태로 결과를 돌려줘야 합니다. 이 과정에서는 사람이 읽는 문자열로 통일합니다.

# 나쁨 — 때론 dict, 때론 None, 때론 숫자
def get_price(name):
    if found: return {"price": 59000}   # dict
    else: return None                    # None ← 모델이 처리하기 곤란

# 좋음 — 항상 문자열 (없을 때도 안내 문자열)
def get_price(name):
    if found: return "승승 슬림핏 청바지 판매가 59,000원"
    else: return "'슬림핏 청바지' 가격 정보를 찾지 못했습니다."   # 없어도 문자열

모델은 문자열을 읽고 답을 만듭니다. 반환이 일관되면 모델이 결과를 안정적으로 다룰 수 있습니다.

7. 한 줄로 외우는 원칙

"도구 설명은 모델을 위한 프롬프트다." 동료 개발자가 아니라 모델이 읽는다고 생각하고, 이름·인자·설명·반환을 모두 또렷하게 만드세요.

이 원칙들은 raw SDK든 LangChain이든 똑같이 적용됩니다. "설명을 잘 쓰는 사람" 이 좋은 도구를 만듭니다.

핵심 정리

  • 다섯 원칙: 한 가지 일 · 이름이 곧 기능 · 명확한 인자 · 구체적 설명 · 일관된 반환.
  • 모두 "모델이 도구를 잘 고르고 올바르게 쓰게" 하기 위한 것이다.
  • 반환은 항상 사람이 읽는 문자열(없을 때도 안내 문자열)로 통일한다.
  • 다음 절에서 이 원칙대로 도구 4개를 만들어 등록하고 관찰합니다.
