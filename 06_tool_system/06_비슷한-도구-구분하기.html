비슷한 도구 구분하기

한 줄 요약

설명이 비슷하게 겹치는 두 도구를 두면, 모델이 어느 걸 써야 할지 헷갈립니다. 입력 형태(ID vs 키워드)와 결과 건수(1건 vs 여러 건)를 독스트링에 명확히 못 박으면, 비슷한 도구도 또렷이 구분됩니다.

1. 문제 — 헷갈리게 비슷한 두 도구

실무에서는 비슷한 일을 하는 도구가 여럿 생깁니다. 예를 들어 "상품을 찾는" 도구가 두 개 있다고 합시다.

def get_product_info(query: str) -> str:
    """상품을 조회한다."""        # ← 모호! 언제 쓰는지 모름
    ...

def search_product(query: str) -> str:
    """상품을 찾는다."""          # ← 위와 거의 같은 설명!
    ...

"상품을 조회한다" 와 "상품을 찾는다" — 사람이 봐도 차이를 모르겠죠. 모델은 더 헷갈립니다. "상품 정보 알려줘"라는 질문에 둘 중 뭘 골라야 할지 갈팡질팡합니다.

비유: 회사에 "고객지원팀"과 "고객서비스팀"이 따로 있는데, 둘 다 설명이 "고객을 돕는다"라면? 전화를 어디로 돌려야 할지 아무도 모릅니다. 역할 경계가 모호하기 때문입니다.

2. BEFORE — 모호한 설명으로 헷갈리는 모습

(실습 파일: 코드분석만)

def get_product_info(query: str) -> str:
    """상품을 조회한다."""        # [경고] 모호
    row = products[products["product_id"] == query]
    ...

def search_product(query: str) -> str:
    """상품을 찾는다."""          # [경고] 위와 거의 같은 설명
    hit = products[products["product_name"].str.contains(query, na=False)]
    ...

# 두 도구로 질문 → 모델이 헷갈림
which_tool("상품ID P0001 상세정보 알려줘.", [get_product_info, search_product])
which_tool("이어버드 들어간 상품들 다 찾아줘.", [get_product_info, search_product])

예상 출력 (BEFORE) 단, 요즘 모델은 구별해서 옳바른 결과를 출력해 줄수 있음

  '상품ID P0001 상세정보 알려줘.' → search_product({'query': 'P0001'})   ← 틀린 선택!
  '이어버드 들어간 상품들 다 찾아줘.' → get_product_info({'query': '이어버드'})  ← 틀린 선택!

둘 다 엉뚱하게 골랐습니다. ID로 1건 찾아야 할 질문에 키워드 검색 도구를, 키워드로 여러 개 찾아야 할 질문에 ID 조회 도구를 골랐죠.

3. AFTER — 경계를 못 박은 설명

해결책은 입력 형태와 결과 건수를 설명에 명확히 적는 것입니다.

def get_product_info_clear(product_id: str) -> str:
    """[정확검색] 상품ID(예: P0001)로 정확히 1건의 상세정보(이름/카테고리/가격)를 반환한다.
    상품ID를 이미 알 때만 사용. 상품명·키워드로는 사용하지 말 것."""
    ...

def search_product_clear(keyword: str) -> str:
    """[키워드검색] 상품명 일부(예: '이어버드', '청바지')로 여러 후보를 찾아 이름 목록을 반환한다.
    상품ID를 모르고 이름·키워드만 알 때 사용."""
    ...

세 가지 장치를 넣었습니다.

  • 태그: [정확검색] vs [키워드검색] — 한눈에 역할 구분
  • 입력 형태 명시: "상품ID(P0001)" vs "상품명 일부('이어버드')"
  • 언제 쓰지 말지: "상품명·키워드로는 사용하지 말 것" — 경계를 양쪽에서 못 박음

예상 출력 (AFTER)

  '상품ID P0001 상세정보 알려줘.' → get_product_info_clear({'product_id': 'P0001'})   ← 정확!
  '이어버드 들어간 상품들 다 찾아줘.' → search_product_clear({'keyword': '이어버드'})  ← 정확!

이제 모델이 정확히 구분합니다. 설명만 바꿨을 뿐인데 말이죠.

4. 비슷한 도구를 구분하는 3가지 기법

  1. 입력 형태를 명시: "ID로" vs "이름 일부로" → 입력이 다르면 도구가 다름이 분명해진다.
  2. 결과 건수를 명시: "정확히 1건" vs "여러 후보" → 기대 결과로 구분.
  3. 부정 조건을 추가: "~로는 사용하지 말 것" → 잘못된 선택을 막는 울타리.

특히 3번(부정 조건)은 강력합니다. "이 도구를 언제 쓰지 말아야 하는가"를 적으면, 모델이 경계를 더 또렷이 인식합니다.

5. 더 나은 해법 — 도구를 합치거나 줄이기

사실 가장 좋은 건, 애초에 헷갈리는 중복 도구를 만들지 않는 것입니다. 두 도구가 정말 비슷하다면:

  • 하나로 합칠 수 있는지 (인자로 구분)
  • 하나를 없앨 수 있는지

를 먼저 검토하세요. 도구 개수가 적을수록 모델의 선택이 쉬워집니다. 그래도 둘 다 필요하다면, 위의 "경계 못 박기" 기법을 씁니다.

핵심 정리

  • 설명이 비슷하게 겹치는 도구는 모델을 헷갈리게 한다.
  • 해결: 입력 형태 + 결과 건수 + 부정 조건(언제 쓰지 말지) 을 명시한다.
  • 더 근본적으로는 중복 도구를 합치거나 줄인다.
  • 핵심은 변함없다 — "도구 설명은 모델을 위한 프롬프트다."
