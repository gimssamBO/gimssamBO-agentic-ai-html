1. 시작부 & 설계 명세

code/ch28_design.py를 만듭니다.

# -*- coding: utf-8 -*-
# 실행: python code/ch28_design.py
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))  # code/ 를 import 경로에
from common import DATA, DOCS

from dataclasses import dataclass

# [왜 설계 먼저] 30강에서 RAG+도구+메모리를 한꺼번에 구현하기 전에, 이 파일로
#   '무엇을 만들지'를 코드 스켈레톤(시그니처+TODO)으로 못 박는다. 함수 이름·시그니처를
#   먼저 합의해두면 구현 단계에서 설계가 흔들리지 않는다('살아있는 설계 문서').


@dataclass
class AgentSpec:
    """통합 CS 에이전트의 설계 명세(요약). dataclass 로 설정값을 한눈에 본다."""
    name: str = "승승장구몰 통합 CS 에이전트"
    tools: tuple = ("get_order_status", "get_stock", "search_faq", "policy_search")
    use_rag: bool = True          # 정책/멤버십 PDF 검색에 RAG 사용
    use_memory: bool = True       # 단기 기억(thread 별 대화 세션)
    use_multi_agent: bool = False # [왜 단일] 도구가 4개뿐이라 역할 분리 불필요 → 단일로 시작

AgentSpec은 3단계의 판단 결과를 코드로 옮긴 것입니다. "RAG 쓴다(True), 멀티에이전트 안 쓴다(False)"가 한 곳에 박제돼, 나중에 "왜 이렇게 정했지?"의 답이 코드에 남습니다.

def print_design():
    spec = AgentSpec()
    print("=" * 60)
    print(f"[설계] {spec.name}")
    print("=" * 60)

5. "살아있는 설계 문서"의 가치

이 스켈레톤이 그냥 메모와 다른 점:

[죽은 문서]   워드/노션에 적은 설계 → 코드와 따로 놂 → 점점 안 맞아짐
[살아있는 문서] 코드 자체가 설계 → 실행하면 요약 출력 → 30강에서 TODO만 채움
              → 설계와 구현이 '같은 파일'에서 이어짐

관찰 포인트

  • 설계가 코드로 박제돼, 30강에서 시그니처를 그대로 채우면 됩니다.
  • AgentSpec 한 곳에 "무엇을 쓰는지"가 모여, 의사결정 근거가 남습니다.
  • 실행만 해도 설계 요약이 나오니, 팀원에게 공유하기 좋습니다.
  • 다음 절(06번)에서는 이 "구성요소 판단"을 규칙으로 자동화한 도우미를 만들어, 다른 프로젝트에도 적용해 봅니다.

핵심 정리

  • 설계를 코드 스켈레톤(@dataclass AgentSpec + 함수 시그니처 + TODO)으로 박제.
  • 도구 본문은 raise NotImplementedError("30강에서 구현") — "아직 안 만듦"을 명시.
  • 독스트링에 요구사항 번호([R1]~), TODO에 구현 방법 메모 → 30강의 나를 위한 안내.
  • print_design()으로 실행하면 설계 요약 출력 = 살아있는 설계 문서.
  • 설계와 구현이 같은 파일에서 이어져, 30강에선 TODO만 채우면 됨.
  • 다음 절에서 구성요소 판단을 규칙으로 자동화합니다.
