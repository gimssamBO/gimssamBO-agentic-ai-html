토큰과 비용 감각

한 줄 요약

LLM은 글자가 아니라 토큰(token) 단위로 글을 읽고 씁니다. 그리고 요금은 토큰 수로 매겨집니다. 토큰을 이해하면 "이 서비스 월 얼마 나올까?"를 숫자로 예측하고, 비용을 줄일 수 있습니다.

1. 토큰이란? — 글을 자르는 단위

LLM은 문장을 통째로 보지 않고, 토큰이라는 작은 조각으로 잘라서 처리합니다. 토큰은 대략 "단어 또는 단어의 일부"입니다.

  • 영어: "earbuds" → 보통 1~2개 토큰
  • 한국어: "이어버드" → 보통 더 잘게 쪼개져 여러 토큰

중요한 사실 하나: 같은 뜻이라도 한국어가 영어보다 토큰을 더 많이 먹습니다. 한글은 영어보다 잘게 쪼개지는 경향이 있기 때문입니다. 이건 비용에 직접 영향을 줍니다.

비유: 토큰은 택시 미터기입니다. 거리(글자 수)가 아니라 미터기가 찍는 횟수(토큰 수)로 요금이 매겨집니다. 그리고 한국어는 미터기가 더 자주 찍히는 길이라고 보면 됩니다.

2. 입력 토큰 vs 출력 토큰

요금은 두 가지로 나뉩니다.

  • 입력(prompt) 토큰: 우리가 보낸 것 — 시스템 지시 + 질문 + (나중엔) 대화 기록·검색 결과
  • 출력(candidates) 토큰: 모델이 생성한 답변

보통 출력 토큰이 입력보다 비쌉니다. 그래서 "답을 짧게" 시키는 것도 비용 절감의 한 방법입니다.

u = resp.usage_metadata
print(u.prompt_token_count)      # 입력 토큰 (내가 보낸 것)
print(u.candidates_token_count)  # 출력 토큰 (모델이 만든 것)
print(u.total_token_count)       # 합계

3. 직접 토큰을 세어 보자 (한국어 vs 영어)

같은 의미의 문장을 한국어와 영어로 각각 보내, 토큰 수를 비교해 보겠습니다. (실습 파일: sections/02_llm_api/04_토큰과-비용-감각.py)

from common import get_genai_client, GEMINI_MODEL
from google.genai import types

client = get_genai_client()

def count_tokens(text: str):
    """문장 하나를 보내 입력/출력/합계 토큰을 돌려준다."""
    resp = client.models.generate_content(
        model=GEMINI_MODEL,
        contents=text,
        config=types.GenerateContentConfig(temperature=0),
    )
    u = resp.usage_metadata
    return u.prompt_token_count, u.candidates_token_count, u.total_token_count

pairs = {
    "한국어": "승승장구몰의 무선 블루투스 이어버드를 한 문장으로 친절하게 홍보해줘.",
    "영어":   "Write one friendly sentence promoting SeungSeung Mall's wireless earbuds.",
}

for lang, text in pairs.items():
    in_tok, out_tok, total = count_tokens(text)
    print(f"[{lang}] 입력={in_tok} / 출력={out_tok} / 합계={total}")

예상 출력

[한국어] 입력=21 / 출력=18 / 합계=39
[영어]   입력=15 / 출력=16 / 합계=31

같은 뜻인데도 한국어 입력 토큰이 더 많죠? 이게 "한국어가 더 비싸다"의 실체입니다.

4. 비용을 숫자로 추정하기

토큰 수에 단가를 곱하면 비용이 나옵니다. 단가는 보통 "토큰 100만 개당 몇 달러" 형식입니다.

# [경고] 아래는 '예시 단가'입니다. 실제 요금은 모델·시점별 공식 단가표를 확인하세요.
PRICE_IN_PER_1M = 0.075   # 입력 100만 토큰당 $0.075 (예시)
PRICE_OUT_PER_1M = 0.30   # 출력 100만 토큰당 $0.30  (예시)

def estimate_cost(in_tok: int, out_tok: int) -> float:
    """1회 호출 비용(USD)을 예시 단가로 계산한다."""
    return in_tok / 1_000_000 * PRICE_IN_PER_1M + out_tok / 1_000_000 * PRICE_OUT_PER_1M

# 1회는 푼돈처럼 보이지만, 월 호출량을 곱하면 진짜 비용이 보인다
per_call = estimate_cost(21, 18)        # 한국어 기준
monthly  = per_call * 10_000            # 월 1만 건
print(f"1회 ≈ ${per_call:.6f}")
print(f"월 10,000건 ≈ ${monthly:.2f}  (약 {monthly * 1385:,.0f}원, 환율 1385 가정)")

예상 출력

1회 ≈ $0.000007
월 10,000건 ≈ $0.07  (약 97원, 환율 1385 가정)

flash 모델은 이처럼 매우 저렴합니다. 하지만 답변이 길어지거나(출력 토큰↑), 대화 기록·검색 결과가 쌓이면(입력 토큰↑) 비용은 빠르게 커집니다. 이 감각을 미리 가지고 있어야 나중에 RAG(13강)나 긴 대화(7·19강)에서 비용 폭탄을 피합니다.

5. 비용을 줄이는 실전 팁

  • 답을 짧게 시킨다: "3줄 이내로 답하라" → 출력 토큰 절감(가장 비싼 부분).
  • 시스템 지시를 간결하게: 매 호출마다 입력 토큰으로 따라붙는다.
  • 대화 기록을 다듬는다: 오래된 메시지는 잘라낸다(7강·19강에서 실습).
  • 싼 모델을 기본값으로: 어려운 작업만 큰 모델로(가성비 라우팅).

핵심 정리

  • LLM은 토큰 단위로 처리하고, 요금도 토큰으로 매긴다.
  • 입력/출력 토큰이 따로 있고, 보통 출력이 더 비싸다.
  • 같은 뜻이라도 한국어가 토큰을 더 많이 쓴다.
  • usage_metadata로 토큰을 확인하고, 단가를 곱해 월 비용을 예측할 수 있다.
  • 다음 절에서는 답변의 일관성을 조절하는 temperature를 배웁니다.
