요청-응답 구조

한 줄 요약

LLM 호출은 요청(Request) 을 보내면 응답(Response) 이 오는 단순한 왕복입니다. 요청에는 model·messages·temperature 세 가지를, 응답에서는 content·usage 두 가지를 꺼냅니다. 이 구조를 외우면 나머지는 응용입니다.

LLM 호출은 요청(Request) 을 보내면 응답(Response) 이 오는 단순한 왕복입니다. 요청에는 model·contents·config 세 가지를, 응답에서는 text·usage_metadata 두 가지를 꺼냅니다. 이 구조를 외우면 나머지는 응용입니다.

1. 그림으로 보는 한 번의 호출

우리가 채우는 요청(Request) 과 모델이 채워 주는 응답(Response) 은 각각 이렇게 구성됩니다.

요청(Request) — 우리가 채움 응답(Response) — 모델이 채움
model: "gpt-4o-mini" choices[0].message.content: "평균 3~5일 소요됩니다…"
messages: role, content, system, user "환불 얼마나 걸려요?" usage.prompt_tokens = 12
config:: temperature, max_tokens, tools resp.usage.completion_tokens = 30
resp.usage.total_tokens = 42
요청(Request) — 우리가 채움 응답(Response) — 모델이 채움
model: "gemini-3.6-flash" text: "평균 3~5일 소요됩니다…"
contents: "환불 얼마나 걸려요?" usage_metadata.prompt_token_count = 12
config: system_instruction, temperature usage_metadata.candidates_token_count = 30
usage_metadata.total_token_count = 42

이게 전부입니다. 우리가 채우는 건 요청 세 가지, 모델이 채워 주는 건 응답 두 가지(텍스트·사용량)입니다.

2. 요청 3종 세트

① model — 어떤 두뇌를 쓸까

사용할 모델 이름입니다. 이 과정에서는 common.py에 정해 둔 OPENAI_MODE(기본값 "gpt-4o-mini")을 씁니다. 

from common import OPENAI_MODEL
print(OPENAI_MODEL)  # 기본값: "gpt-4o-mini"

사용할 모델 이름입니다. 이 과정에서는 common.py에 정해 둔 GEMINI_MODEL(기본값 "gemini-3.6-flash")을 씁니다. flash는 빠르고 저렴한 모델이라 실습과 대부분의 실무에 적합합니다.

from common import GEMINI_MODEL
print(GEMINI_MODEL)   # gemini-3.6-flash

② contents — 모델에게 보낼 말

사용자의 질문이나 지시입니다. 가장 단순하게는 그냥 문자열을 넣습니다.

messages = [
    {"role": "user", "content": "환불 얼마나 걸려요?"}
]

contents = "환불 얼마나 걸려요?"

③ config — 생성 방식 설정

답변의 역할·말투·무작위성을 조절하는 설정 묶음입니다.


from common import OPENAI_MODEL, get_openai_client
client = get_openai_client()
messages = [
    {"role": "system", "content": "너는 승승장구몰의 친절한 CS 상담원이다."}
]
temperature = 0.3

답변의 역할·말투·무작위성을 조절하는 설정 묶음입니다. types.GenerateContentConfig로 만듭니다.

from google.genai import types

config = types.GenerateContentConfig(
    system_instruction="너는 승승장구몰의 친절한 CS 상담원이다.",  # 역할  
    temperature=0.3,                                          # 무작위성  
)

3. 세 가지를 합친 한 번의 호출

from common import get_openai_client, OPENAI_MODEL
client = get_openai_client()

resp = client.chat.completions.create(
    model=OPENAI_MODEL,                      # ① 모델
    messages=[                               # ② 입력 및 시스템 역할
        {"role": "system", "content": "너는 친절한 CS 상담원이다."},
        {"role": "user", "content": "환불 얼마나 걸려요?"},
    ],
    temperature=0.3,                         # ③ 설정
)

from common import get_genai_client, GEMINI_MODEL
from google.genai import types

client = get_genai_client()

resp = client.models.generate_content(
    model=GEMINI_MODEL,                      # ① 모델
    contents="환불 얼마나 걸려요?",            # ② 입력
    config=types.GenerateContentConfig(      # ③ 설정
        system_instruction="너는 친절한 CS 상담원이다.",
        temperature=0.3,
    ),
)

4. 응답 2종 세트

① resp.text — 생성된 답변

모델이 만든 텍스트입니다. 우리가 실제로 사용자에게 보여 줄 내용입니다.

print(resp.choices[0].message.content)   # "환불은 영업일 기준 평균 3~5일 정도 소요됩니다 ..."

print(resp.text)   # "환불은 영업일 기준 평균 3~5일 정도 소요됩니다 ..."

② resp.usage_metadata — 토큰 사용량

이번 호출에 토큰이 몇 개 쓰였는지 알려 줍니다. 토큰은 곧 요금이므로 비용을 가늠하는 핵심 정보입니다.

u = resp.usage
print(u.prompt_tokens)      # 입력(질문+시스템지시)에 쓴 토큰
print(u.completion_tokens)  # 출력(답변)에 쓴 토큰
print(u.total_tokens)       # 합계

u = resp.usage_metadata
print(u.prompt_token_count)      # 입력(질문+시스템지시)에 쓴 토큰
print(u.candidates_token_count)  # 출력(답변)에 쓴 토큰
print(u.total_token_count)       # 합계

토큰이 무엇인지, 비용은 어떻게 계산하는지는 04번 목차에서 자세히 다룹니다.

5. 직접 확인해 보기

resp = client.chat.completions.create(
    model=OPENAI_MODEL,
    messages=[{"role": "user", "content": "승승장구몰을 한 문장으로 홍보해줘."}],
    temperature=0.7,
)
print("답변:", resp.choices[0].message.content)
print("토큰:", resp.usage)

resp = client.models.generate_content(
    model=GEMINI_MODEL,
    contents="승승장구몰을 한 문장으로 홍보해줘.",
    config=types.GenerateContentConfig(temperature=0.7),
)
print("답변:", resp.text)
print("토큰:", resp.usage_metadata)

예상 출력

답변: 일상에 필요한 모든 것을 합리적인 가격에! 승승장구몰에서 만나보세요.
토큰: prompt_token_count=11 candidates_token_count=24 total_token_count=35 ...

핵심 정리

  • 요청 = model(모델) · messages(입력 및 역할) · temperature 등의 매개변수(설정).
  • 응답 = choices[0].message.content(답변) · usage(토큰).
  • 역할 = messages의 system 딕셔너리로 넣음.
  • 온도 = temperature 파라미터로 직접 담는다.
    • ---------------------------------------------------------------------------------
  • 요청 = model(모델) · contents(입력) · config(설정).
  • 응답 = text(답변) · usage_metadata(토큰).
  • config는 types.GenerateContentConfig(...)로 만들며, 역할과 온도를 담는다.
  • 다음 절에서는 config의 핵심인 시스템 지시로 말투를 바꿔 봅니다.
