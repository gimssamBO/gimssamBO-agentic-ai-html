왜 LLM API를 알아야 하는가

한 줄 요약

1강에서 generate_content를 한 번 써 봤습니다. 이제 그 내부 구조를 제대로 이해할 차례입니다. API를 정확히 다루면 비용을 아끼고(토큰), 말투를 제어하고(시스템 지시), 결과의 일관성을 조절(temperature) 할 수 있습니다. 이것이 앞으로 만들 모든 에이전트의 기본기입니다.

1. "그냥 질문하고 답 받으면 되는 거 아닌가요?"

처음엔 그렇게 느껴집니다. 1강에서 우리가 한 일은 이게 전부였으니까요.

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "안녕"}]
)
print(resp.choices[0].message.content)

resp = client.models.generate_content(model="gemini-3.6-flash", contents="안녕")
print(resp.text)

그런데 이걸 회사 서비스로 만들려는 순간, 질문이 쏟아집니다.

  • 상담봇 말투를 항상 친절한 존댓말로 고정하려면? → 시스템 지시
  • 사용자가 10만 명이면 요금이 얼마나 나올까? → 토큰
  • 똑같이 물어도 답이 매번 달라지는데, 일관되게 하려면? → temperature
  • GPT로 바꾸면 코드를 다 새로 짜야 하나? → 요청-응답 구조의 공통점

이 네 가지를 모르면, 동작은 하지만 통제할 수 없는 챗봇이 됩니다. 2강은 바로 이 통제력을 손에 넣는 강의입니다.

2. LLM을 '함수'로 보기

파이썬 개발자에게 가장 친숙한 비유는 함수입니다. LLM API 호출은 결국 이런 함수와 같습니다.

def llm(요청) -> 응답:
    ...
  • 요청(Request) 에는 세 가지를 담습니다: 어떤 모델(model), 무슨 말(contents), 어떤 설정(config — 역할·온도 등).
  • 응답(Response) 에는 두 가지가 옵니다: 생성된 텍스트(text), 그리고 사용량 정보(usage_metadata — 토큰 수).
# [요청] model(어떤 모델) + messages(무슨 말) + 파라미터(어떤 설정)
resp = client.chat.completions.create(
    model="gpt-4o-mini",                               # 모델
    messages=[{"role": "user", "content": "환불 얼마나 걸려요?"}],  # 입력
    temperature=0.7,                                  # 설정(온도, 시스템 역할 등)
)
# [응답] resp.choices[0].message.content(생성된 답) + resp.usage(토큰 사용량)
print(resp.choices[0].message.content)
print(resp.usage)  # prompt_tokens, completion_tokens, total_tokens 확인 가능

# [요청] model(어떤 모델) + contents(무슨 말) + config(어떤 설정)
resp = client.models.generate_content(
    model="gemini-3.6-flash",       # 모델
    contents="환불 얼마나 걸려요?",   # 입력
    config=...,                      # 설정(역할·온도 등)
)
# [응답] resp.text(생성된 답) + resp.usage_metadata(토큰 사용량)

이 "요청 3종 세트 → 응답 2종 세트" 구조는 Gemini든 OpenAI든 거의 똑같습니다. 그래서 하나만 제대로 익히면 다른 모델로 갈아타기도 쉽습니다(7번 목차에서 직접 비교합니다).

3. 이 강에서 손에 넣을 4가지 통제력

통제력 도구 효과
말투·역할 고정 시스템 지시 항상 일관된 페르소나
비용 예측·절감 토큰(usage) 요금을 숫자로 파악
일관성 ↔ 다양성 temperature 분류는 일관, 창작은 다양
모델 갈아타기 공통 요청-응답 구조 Gemini ↔ OpenAI

핵심 정리

  • LLM API 호출은 요청(model·contents·config) → 응답(text·usage) 구조의 함수다.
  • 이 구조를 통제하면 말투·비용·일관성을 마음대로 다룰 수 있다.
  • 이 구조는 모델이 달라도 거의 같아, 한 번 익히면 두루 쓰인다.
