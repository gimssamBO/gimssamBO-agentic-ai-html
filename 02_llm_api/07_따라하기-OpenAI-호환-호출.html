따라하기 — (보조) OpenAI 호출

목표

같은 "요청-응답" 구조를 OpenAI(GPT) 로도 호출해 봅니다. 핵심은 "모델 회사가 달라도 구조는 거의 같다" 를 직접 확인하는 것입니다. 이걸 알면 나중에 모델을 자유롭게 갈아탈 수 있습니다.

이 절은 보조입니다. OpenAI 키가 없어도 이 과정은 Gemini만으로 끝까지 진행됩니다. 키가 있는 분만 따라 하세요.

0. 실습 준비 (설치)

conda activate agentic

# 2강에서 처음 쓰는 라이브러리
#  - openai : OpenAI 공식 Python SDK (GPT 모델 호출용)
pip install openai

그리고 .env에 OPENAI_API_KEY를 추가합니다.

OPENAI_API_KEY=sk-...여러분의_키...

1. Gemini와 OpenAI, 무엇이 같고 다른가

구분 Gemini (google-genai) OpenAI (openai)
클라이언트 genai.Client(api_key=...) OpenAI() (키는 환경변수)
호출 client.models.generate_content(...) client.chat.completions.create(...)
입력 형식 contents="질문" + config에 시스템 지시 messages=[{role, content}, ...] 리스트
답 꺼내기 resp.text resp.choices[0].message.content
토큰 resp.usage_metadata resp.usage

가장 큰 차이는 입력 형식입니다. OpenAI는 시스템 지시와 질문을 messages 리스트에 role로 구분해 함께 담습니다.

2. 코드 — OpenAI로 같은 질문 던지기

import os

# OpenAI 키가 있을 때만 실행 (없으면 건너뜀)
key = os.getenv("OPENAI_API_KEY", "")
if key and not key.startswith("여기에"):
    from openai import OpenAI
    oai = OpenAI()                          # 키는 환경변수에서 자동으로 읽음

    # OpenAI 는 messages 리스트로 '시스템 지시'와 '질문'을 함께 보낸다.
    r = oai.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "너는 승승장구몰 상담원이다."},  # 시스템 지시
            {"role": "user",   "content": "환불 얼마나 걸려요?"},          # 사용자 질문
        ],
    )
    print("[OpenAI]", r.choices[0].message.content)   # 답 꺼내기
    print("토큰:", r.usage)                            # 토큰 사용량
else:
    print("[OpenAI] OPENAI_API_KEY 미설정 — 생략 (Gemini만으로 충분합니다)")

예상 출력

[OpenAI] 안녕하세요! 환불은 영업일 기준 평균 3~5일 정도 소요됩니다 ...
토큰: CompletionUsage(completion_tokens=28, prompt_tokens=24, total_tokens=52)

참고: OpenAI 최신 SDK는 system 대신 developer role도 지원합니다. 여기서는 호환성과 직관성을 위해 익숙한 system을 사용합니다 — 둘 다 정상 동작합니다.

3. messages 리스트, 왜 이렇게 생겼나

messages는 대화 기록 전체를 담는 그릇입니다. 그래서 멀티턴 대화를 만들 때 이렇게 쌓아 갑니다.

messages = [
    {"role": "system", "content": "너는 친절한 상담원이다."},
    {"role": "user",   "content": "안녕하세요"},
    {"role": "assistant", "content": "안녕하세요! 무엇을 도와드릴까요?"},  # 모델의 이전 답
    {"role": "user",   "content": "환불 얼마나 걸려요?"},                # 이어지는 질문
]

이 "리스트에 대화를 쌓는" 방식은 19강(메모리)에서 매우 중요해집니다. 지금은 "OpenAI는 대화를 리스트로 관리한다"만 기억하면 됩니다.

4. 핵심 교훈 — 구조는 같다

회사가 달라도 결국 요청(모델+입력+설정) → 응답(텍스트+토큰) 구조는 똑같습니다. 그래서 이 과정 8강부터는 LangChain이라는 도구를 써서, 이 차이마저 감춰 버립니다. get_chat(provider="gemini") 한 줄로 모델을 갈아끼우게 되죠. 그 바탕에는 지금 배운 "구조는 같다"는 원리가 깔려 있습니다.

핵심 정리

  • OpenAI 호출은 client.chat.completions.create(model, messages) 형태.
  • 입력은 messages 리스트(role: system/user/assistant)로 담는다.
  • 답은 resp.choices[0].message.content, 토큰은 resp.usage.
  • 모델 회사가 달라도 요청-응답 구조는 같다 → 모델 교체가 쉽다.
