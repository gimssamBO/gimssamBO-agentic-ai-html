왜 에이전트가 필요한가 — "답은 잘하는데, 일은 못한다"

이 강의를 시작하며

이 과정은 "파이썬은 써봤지만 LLM·에이전트는 처음" 인 분을 위해 만들었습니다. 머신러닝 이론이나 수학은 거의 다루지 않습니다. 대신 실제로 일을 해내는 AI 시스템을 내 손으로 조립하는 데 집중합니다. 모든 예제는 가상의 쇼핑몰 승승장구몰로, 현업에서 진짜로 마주치는 문제를 풉니다.

한 줄 요약 — LLM은 말은 잘하지만 스스로 행동(도구 사용)은 못 하는 갇힌 두뇌입니다. 여기에 도구·기억·반복 루프를 붙여 실제로 일을 끝내게 만든 것이 바로 에이전트(Agent)이고, 그걸 30강에 걸쳐 단계별로 만들어 갑니다.

1. 흔히 겪는 상황

ChatGPT 같은 LLM에게 "블루투스 이어버드 고르는 법 알려줘"라고 물으면 그럴듯한 답을 술술 내놓습니다. 그런데 우리가 운영하는 쇼핑몰 승승장구몰의 상담 현장에서 고객이 진짜로 묻는 건 이런 질문들입니다.

  • "제 주문(O000123) 지금 어디까지 왔어요?"
  • "이어버드 지금 재고 있어요?"
  • "어제 받은 제품 환불하면 언제 입금돼요?"

LLM은 이 질문에 답할 수 없습니다. 왜냐하면:

  • 주문 상태는 우리 회사 주문 DB에만 있고,
  • 재고 수량은 재고 시스템에만 있고,
  • 환불 규정은 사내 정책 문서에만 있기 때문입니다.

LLM은 이 데이터들에 접근할 손발이 없습니다. 학습할 때 본 적도 없습니다. 한마디로 "말은 잘하지만 스스로 아무것도 확인하지 못하는, 갇혀 있는 두뇌" 입니다.

비유하자면, LLM은 백과사전을 통째로 외운 신입사원입니다. 일반 상식은 막힘없이 답하지만, "우리 창고에 재고 몇 개 있어?"라고 물으면 창고에 갈 수가 없어서 답을 못 합니다. (혹은 더 위험하게, 그럴듯하게 지어냅니다. 이게 4장에서 배울 '환각'입니다.)

이 "답은 잘하는데 일은 못한다"는 간극(gap)이 바로 이 과정 전체가 메우려는 빈칸입니다. 30강이 끝나면, 위 세 질문에 실제 데이터를 조회해서 답하는 상담 에이전트를 여러분이 직접 만들 수 있게 됩니다.

2. 그래서 '에이전트'가 등장합니다

Agentic AI(에이전트형 AI) 는 이 두뇌(LLM)에 세 가지를 붙여, 실제로 일을 끝내는 시스템으로 만든 것입니다.

  • 도구(Tool) — 주문 DB 조회, 재고 확인, 계산, 웹 검색처럼 두뇌가 못 하는 "행동"을 대신해 줍니다.
  • 기억(Memory) — 방금 나눈 대화, 사용자 정보를 잊지 않게 해 줍니다.
  • 루프(Loop) — 한 번에 안 끝나는 일을 "생각 → 행동 → 관찰"을 반복하며 끝까지 처리합니다.

즉, 두뇌 + 손발 + 기억 + 끈기 를 갖춘 것이 에이전트입니다.

구분 LLM 단독 에이전트
구성 두뇌(말만) 두뇌(LLM) + 손발(도구) + 기억(메모리) + 끈기(루프)
결과 "확인은 못 해요" "확인해서, 끝까지 처리해요"

이 그림의 오른쪽을 직접 만들어 보는 것이 우리의 30강 여정입니다.

3. 코드로 확인하기

말로만 들으면 와닿지 않으니, LLM에게 직접 두 가지 질문을 던져 보겠습니다. 하나는 LLM이 답할 수 있는 일반 지식, 다른 하나는 답할 수 없는 실시간 사내 정보입니다.

# 가장 단순한 LLM 호출 한 번
from google import genai

client = genai.Client(api_key="여러분의_API_키")   # Gemini 클라이언트 생성

def ask(question: str) -> str:
    # generate_content = "한 번 묻고 → 한 번 답받기"의 가장 기본 호출
    resp = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=question,
    )
    return resp.text   # 모델이 생성한 답변(문자열)

# 질문 1: 일반 지식 → LLM이 잘 답함
print(ask("블루투스 이어버드를 고를 때 무엇을 봐야 하나요? 3가지만 짧게."))

# 질문 2: 실시간 사내 정보 → LLM 혼자서는 불가
print(ask("승승장구몰 주문번호 O000123은 지금 배송 어디까지 왔나요?"))

예상 출력

[질문 1] 음질, 배터리 지속시간, 연결 안정성을 보세요 ...   ← 잘 답함
[질문 2] 죄송하지만 실시간 주문 정보는 확인할 수 없습니다 ...  ← 답 못 함
         (혹은 그럴듯한 가짜 운송장 번호를 지어냄 = 환각)

질문 2를 제대로 답하려면 LLM에게 "주문 조회 도구" 를 쥐여 줘야 합니다. 바로 이 "도구를 붙이는 일"이 5강부터 우리가 직접 하게 될 작업입니다.

위 코드의 api_key는 실제로는 코드에 직접 쓰지 않고 .env 파일에서 안전하게 불러옵니다. 이 과정의 모든 실습은 common.py의 get_genai_client() 함수가 이 일을 대신해 줍니다. 자세한 건 「05 따라하기」 절에서 다룹니다. (지금은 "아, 이렇게 한 줄로 LLM을 부르는구나" 정도만 느끼면 충분합니다.)

4. 그래서, 30강 동안 우리는 무엇을 배우나? (전체 지도)

이 과정은 "빈 두뇌(LLM) → 진짜로 일하는 상담 에이전트" 까지를 5개의 큰 단계로 쌓아 올립니다. 각 단계는 바로 앞 단계 위에 올라타기 때문에, 순서대로 따라오면 "왜 이게 지금 필요한지"가 자연스럽게 이어집니다.

1단계. 두뇌 깨우기 — LLM을 다루는 법 (1~4강)

도구를 붙이기 전에, 먼저 LLM 자체와 대화하는 법부터 익힙니다. API를 호출하고(2강), 원하는 답이 나오도록 프롬프트를 설계하고(3강), 복잡한 문제는 단계적으로 생각하게(추론, 4강) 만듭니다.
왜 먼저 배우나? 에이전트의 "판단"은 결국 LLM이 합니다. 두뇌를 제대로 다루지 못하면, 손발(도구)을 달아도 엉뚱하게 씁니다.

2단계. 손발 달기 — 도구와 행동 (5~12강)

이 과정의 심장부입니다. LLM이 외부 함수를 호출하게 만들고(함수 호출, 5강), 도구를 여러 개 관리하고(6강), "생각 → 행동 → 관찰"을 스스로 반복하는 에이전트 루프(7강)를 직접 구현합니다. 이어서 계획 수립(8강), 웹 검색(9강), 코드 실행(10강), 데이터 분석(11강), 여러 도구 통합(12강)까지 — "말만 하던 LLM이 실제로 일을 하기 시작하는" 단계입니다.
왜 배우나? 3장에서 "답 못 했던" 질문 2를, 도구를 쥐여 주면 답할 수 있게 됩니다. 에이전트의 본질이 여기 있습니다.

3단계. 지식 주입하기 — RAG(문서 검색) (13~18강)

회사 정책·매뉴얼 같은 사내 문서를 LLM이 근거로 삼아 답하게 만듭니다. 문서를 잘게 쪼개고(청킹, 13강), 의미를 벡터로 바꾸고(임베딩, 14강), 벡터DB에 저장해(15강), 질문과 관련된 부분만 찾아 출처와 함께 답하게(16~18강) 합니다.
왜 배우나? "환불 규정이 뭐예요?" 같은 질문은 LLM이 지어내면 안 됩니다. 회사 문서에 적힌 그대로 근거를 대고 답해야 신뢰할 수 있는 상담이 됩니다.

4단계. 기억하게 만들기 — 메모리 (19~20강)

LLM은 기본적으로 방금 한 말도 잊는(stateless) 존재입니다. 대화 맥락을 유지하고(단기기억, 19강), 세션이 바뀌어도 사용자 정보를 기억하게(장기기억, 20강) 만듭니다.
왜 배우나? "아까 말한 그 주문이요"라고 했을 때 "어떤 주문이요?"라고 되묻는 봇은 쓸모가 없습니다. 진짜 상담원처럼 맥락을 이어가야 합니다.

5단계. 팀으로 키우고 제품으로 내보내기 — 협업·운영 (21~30강)

마지막은 규모와 완성도입니다. 흐름을 그래프로 선언하고(워크플로우, 21강), 리서치·코딩·비즈니스 같은 전문 에이전트를 만들고(22~24강), 여러 에이전트가 팀으로 협업하게(25~27강) 합니다. 그리고 실제 서비스를 위한 설계(28강)·배포·운영(29강)을 거쳐, 30강에서 모든 조각을 하나로 합친 완성형 상담 에이전트를 만듭니다.
왜 배우나? 혼자 다 하는 만능 에이전트는 어느 순간 한계에 부딪칩니다. 역할을 나눠 협업시키고, 내 PC 밖에서도 안정적으로 돌아가게 만들어야 비로소 "제품"이 됩니다.

단계 무엇을 붙이나 강 끝나면 할 수 있는 것
① 두뇌 깨우기 LLM 호출·프롬프트·추론 1~4강 LLM을 의도대로 부린다
② 손발 달기 도구·함수 호출·루프 5~12강 실시간 정보를 조회해 답한다
③ 지식 주입 RAG(문서 검색) 13~18강 사내 문서를 근거로 답한다
④ 기억하기 단기·장기 메모리 19~20강 맥락을 이어 상담한다
⑤ 협업·운영 멀티 에이전트·배포 21~30강 팀으로 일하는 제품을 낸다

5. 이 과정을 마치면 — 여러분이 얻는 것

  • 개념: "AI 에이전트가 대체 뭔데?"라는 질문에, 구조를 그림으로 그려가며 설명할 수 있습니다.
  • 기술: 도구 호출·RAG·메모리·멀티 에이전트를 직접 코드로 조립할 수 있습니다.
  • 판단력: "이 문제엔 RAG가 필요할까? 멀티 에이전트가 과한가?"를 트레이드오프로 따져 결정할 수 있습니다(28강).
  • 결과물: 작동하는 상담 에이전트가 손에 남습니다.

필요한 환경(파이썬 가상환경, 라이브러리 설치, API 키 설정)은 각 강의 「따라하기」절 맨 앞에서 그때그때 pip install ...까지 명시해 드립니다. 지금 당장 환경을 다 갖추지 않아도 됩니다.

핵심 정리

  • LLM은 일반 지식엔 강하지만, 실시간·사내 정보엔 무력합니다. ("답은 잘하는데 일은 못한다")
  • 그 한계를 도구·기억·루프로 메운 것이 에이전트입니다.
  • 30강은 두뇌 깨우기 → 손발 달기 → 지식 주입 → 기억하기 → 협업·운영의 5단계로, 빈 LLM을 진짜로 일하는 상담 에이전트로 키워 갑니다.
  • 오늘 "답 못 했던" 질문이 30강 뒤엔 술술 처리됩니다 — 그 전 과정을 내 손으로 만드는 것이 이 과정입니다.
