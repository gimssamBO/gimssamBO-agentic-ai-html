에이전트의 4요소 — LLM · 도구 · 기억 · 루프 | N8N으로 이해하면 쉬움

한 줄 요약

모든 에이전트는 두뇌(LLM)·손발(도구)·기억(메모리)·끈기(루프) 네 부품의 조합입니다. 이 과정 30강은 결국 이 네 가지를 하나씩 코드로 만드는 여정입니다.

1. 전체 그림

에이전트의 동작 흐름 (ReAct 루프)

  1. 사용자 질문 이 들어온다.
  2. LLM 두뇌 — "지금 무엇을 해야 하나?"를 판단해 쓸 도구를 결정한다.
  3. 도구(Tools) — 검색·DB·계산·코드 실행 등 실제 행동을 수행한다.
  4. 실행 결과 를 관찰해 기억에 쌓고, 다시 2번(LLM 판단)으로 돌아간다.
  5. 2~4를 목표가 끝날 때까지 반복한다(루프).
  6. 완료되면 최종 답변 을 내놓는다.

이 그림 한 장이 에이전트의 전부입니다. 네 부품을 하나씩 보겠습니다.

2. 네 가지 부품

① LLM (두뇌) — 판단하는 자

자연어를 이해하고 "지금 무엇을 해야 하는가" 를 결정합니다. 단, 두뇌일 뿐이라 직접 DB를 뒤지거나 계산을 정확히 하지는 못합니다.

# LLM은 "판단"을 한다 — 어떤 도구를 쓸지 고르는 일
resp = client.models.generate_content(
    model="gemini-3.6-flash",
    contents="주문 O000123 배송 상태 알려줘",
)
# → 모델은 "주문 조회 도구를 써야겠다"는 판단을 내릴 수 있다 (5강에서 구현)

② Tools (도구) — 행동하는 손발

LLM이 못 하는 능력을 보완합니다. 실시간 정보 조회, 정확한 계산, 코드 실행, 웹 검색 등. 에이전트의 능력 = 어떤 도구를 쥐여 주느냐로 결정됩니다.

# 도구는 그냥 '평범한 파이썬 함수'입니다 (5강에서 LLM에 연결)
def get_order_status(order_id: str) -> str:
    """주문번호로 배송 상태를 조회한다."""
    # 실제로는 DB/CSV를 조회 — 여기선 개념만
    return "배송중 (대구 허브 도착)"

③ Memory (기억) — 맥락을 잇는 자

LLM은 기본적으로 금붕어입니다. 방금 한 말도 다음 호출에서 잊습니다. 그래서 대화 기록과 사용자 정보를 따로 저장해 매번 같이 넘겨줘야 합니다. (19~20강)

# 기억이 없으면 — 매번 처음 보는 사람 취급
대화기록 = []
대화기록.append("내 이름은 임도현이야")
# 다음 호출 때 이 기록을 통째로 같이 넘겨야 LLM이 이름을 "기억"한다

④ Loop (루프) — 끝까지 해내는 끈기

한 번에 안 끝나는 일을 생각 → 행동 → 관찰을 반복하며 처리합니다. "재고 확인 → 부족하면 재주문 기준 조회 → 판단" 같은 다단계 작업이 가능해집니다. (7강)

# 루프가 핵심 — 목표가 끝날 때까지 반복
while not 완료:
    행동 = LLM_판단()
    결과 = 도구실행(행동)
    대화기록.append(결과)   # 관찰을 기억에 쌓고 다시 위로

3. 이 4요소가 30강에 어떻게 펼쳐지나

부품 핵심 강 배우는 것
LLM(두뇌) 1~4강 API 호출, 프롬프트, 추론
Tools(손발) 5~6강 함수 호출, 도구 설계
Loop(끈기) 7~8강 ReAct 루프, 계획
Memory(기억) 19~20강 단기/장기 기억
(지식 보강) 13~18강 RAG — 문서를 도구처럼

4. 한 문장으로 외우는 에이전트

"LLM이 목표를 보고, 어떤 도구를 쓸지 스스로 정해 실행하고, 그 결과를 관찰해 다음 행동을 다시 정하는 일을, 목표가 끝날 때까지 반복하는 시스템."

이 한 문장 안에 목표·도구·실행·관찰·반복이 모두 들어 있습니다. 앞으로 이 문장의 각 단어를 코드로 바꿔 나갑니다.

핵심 정리

  • 에이전트 = LLM + 도구 + 기억 + 루프.
  • LLM은 판단, 도구는 행동, 기억은 맥락, 루프는 끈기를 담당합니다.
  • 다음 절에서는 LLM이 모르면서도 아는 척 지어내는 환각이 왜 생기는지 봅니다.
