문제 1 — 계획에 담당팀 필드 추가

Plan 모델의 steps: list[str]를 steps: list[Step] 구조로 바꾸고, 새 Step 모델에 작업: str과 예상_담당팀: str 필드를 두세요.

  • make_plan의 프롬프트에도 "각 단계의 예상 담당팀도 함께 정하라"를 추가합니다.
  • 기대 결과: 각 단계가 1. 시장조사 (담당: 마케팅팀)처럼 작업+담당팀 쌍으로 출력되면 성공.
실습파일: code/ch08_planning_ex01.py
해답 보기 
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
from pydantic import BaseModel, Field
from common import get_chat

llm = get_chat(provider="openai")

# 단계 하나를 표현하는 중첩 모델
class Step(BaseModel):
    작업: str = Field(description="수행할 하위 작업")
    예상_담당팀: str = Field(description="이 작업을 맡을 예상 담당팀")

class Plan(BaseModel):
    goal: str = Field(description="원래 목표")
    steps: list[Step] = Field(description="작업과 담당팀을 담은 단계 목록(4~7개)")

def make_plan(goal: str) -> Plan:
    planner = llm.with_structured_output(Plan)
    prompt = (
        "너는 승승장구몰의 프로젝트 매니저다. 다음 목표를 실행 순서대로 "
        "4~7개의 구체적 하위 작업으로 분해하고, 각 단계의 예상 담당팀도 함께 정하라.\n"
        f"목표: {goal}"
    )
    return planner.invoke(prompt)

if __name__ == "__main__":
    plan = make_plan("가을 패딩 출시")
    print("목표:", plan.goal)
    for i, s in enumerate(plan.steps, 1):
        print(f"  {i}. {s.작업} (담당: {s.예상_담당팀})")
**예상 출력** 
목표: 가을 패딩 출시
  1. 타깃 고객·경쟁 패딩 시장조사 (담당: 마케팅팀)
  2. 상품 콘셉트·가격 확정 (담당: 기획팀)
  3. 상세페이지 제작 (담당: 디자인팀)
  4. 초기 재고 발주 (담당: 물류팀)
  5. 출시 마케팅 캠페인 (담당: 마케팅팀)
**해설**: Pydantic은 **모델 안에 모델을 중첩**할 수 있습니다. `Step`을 만들고 `steps: list[Step]`로 선언하니, 각 단계가 "작업 + 담당팀"을 가진 구조가 됐습니다. 구조화 출력의 힘이죠 — 복잡한 형태도 클래스로 선언하면 LLM이 그대로 맞춰 줍니다.

문제 2 — 마감 임박순 정렬 도구

list_tasks 도구를 수정해, 반환 직전에 df = df.sort_values("due_date")로 마감일이 가까운 순서로 정렬하세요.

  • 사용 파일: data/project_tasks.csv (컬럼: task_name, status, due_date, team)
  • "지금 가장 먼저 시작해야 할 대기 작업을 하나 추천해줘."를 정렬 전/후로 실행해 비교합니다.
  • 기대 결과: 정렬 후 에이전트가 마감이 임박한 작업을 우선 추천하는 변화가 보이면 성공.
실습파일: code/ch08_planning_ex02.py
해답 보기 
import sys, pathlib
sys.path.append(str(pathlib.Path(__file__).resolve().parent))
import pandas as pd
from langchain_core.tools import tool
from langchain.agents import create_agent
from common import get_chat, DATA

llm = get_chat(provider="openai")
tasks_df = pd.read_csv(DATA / "project_tasks.csv", encoding="utf-8-sig")

@tool
def list_tasks(status: str = "전체") -> str:
    """프로젝트 작업을 상태별로 조회한다(마감 임박순 정렬). '대기'/'진행중'/'완료'/'전체'."""
    df = tasks_df
    if status != "전체":
        df = df[df["status"] == status]
    if df.empty:
        return f"'{status}' 상태인 작업이 없습니다."
    df = df.sort_values("due_date")   # ← 마감 임박순 정렬 추가
    lines = [f"- [{r.status}] {r.task_name} (담당:{r.team}, 마감:{r.due_date})"
             for r in df.itertuples()]
    return "\n".join(lines)

agent = create_agent(llm, tools=[list_tasks],
                     system_prompt="너는 승승장구몰의 프로젝트 매니저다. list_tasks로 진행상황을 보고 한국어로 답하라.")

q = "지금 가장 먼저 시작해야 할 대기 작업을 하나 추천해줘."
result = agent.invoke({"messages": [{"role": "user", "content": q}]})
print(result["messages"][-1].content)
**예상 출력** 
대기 작업 중 마감이 가장 임박한 '앱 메인 배너 등록(마감 5/3)'을 가장 먼저
시작하시길 추천합니다.
**해설**: 도구가 데이터를 **마감 임박순으로 정렬**해 돌려주니, 에이전트가 "가장 급한 일"을 더 정확히 짚습니다. 핵심 교훈: **도구가 데이터를 잘 가공해 주면 에이전트의 판단도 좋아집니다.** LLM에게 정렬까지 시키는 것보다, 코드(도구)가 정렬해 주는 게 정확하고 쌉니다(계산은 코드, 판단은 LLM — 24강에서 더 다룹니다).

정리

  • 문제 1로 중첩 Pydantic 모델로 더 복잡한 구조화 출력을 만들었습니다.
  • 문제 2로 도구가 데이터를 가공하면 에이전트 판단이 좋아짐을 확인했습니다.
