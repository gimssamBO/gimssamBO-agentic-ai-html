ReAct vs Plan-and-Execute

한 줄 요약

ReAct(4~7강)는 한 스텝씩 생각·행동을 반복하는 즉흥형, Plan-and-Execute(8강)는 전체 계획을 먼저 세우고 실행하는 계획형입니다. 짧은 작업엔 ReAct, 단계 많고 순서 중요한 목표엔 Plan-and-Execute가 어울립니다.

1. 두 방식 비교표

구분 ReAct (4~7강) Plan-and-Execute (8강)
사고 방식 한 단계 생각→행동을 반복 전체 계획을 먼저 수립 후 실행
적합한 일 짧은 조회/계산 단계 많고 순서 중요한 목표
장점 단순·빠름 큰 그림 유지, 길 잃지 않음
단점 멀리 못 봄, 헤맬 수 있음 초기 계획이 틀리면 비효율

2. ReAct — 즉흥적 탐험가

ReAct는 매 스텝마다 "지금 뭘 할까?"를 정합니다. 멀리 내다보지 않고, 눈앞의 상황에 반응합니다.

ReAct: "재고 확인" → (결과 보고) → "기준 확인" → (결과 보고) → "판단"
       매 스텝 즉흥적으로 다음을 결정
  • 장점: 단순하고 빠릅니다. 상황 변화에 유연하게 반응합니다.
  • 단점: 멀리 못 봅니다. 단계가 많으면 "내가 지금 어디쯤?"을 잃고 헤맬 수 있습니다.

비유: 지도 없이 동네를 돌아다니는 것. 가까운 가게 찾기엔 충분하지만, 처음 가는 먼 도시에서는 길을 잃기 쉽습니다.

3. Plan-and-Execute — 계획적 전략가

Plan-and-Execute는 시작 전에 전체 그림을 그립니다.

Plan: [1.시장조사 → 2.콘셉트 → 3.상세페이지 → 4.발주 → 5.마케팅 → 6.리포트]
Execute: 1번 실행 → 2번 실행 → ... → 6번 실행
         계획대로 차례차례
  • 장점: 큰 그림을 유지합니다. 단계가 많아도 길을 안 잃습니다.
  • 단점: 초기 계획이 틀리면 비효율적입니다(잘못된 일정대로 움직임). 그래서 계획 검증·재계획이 필요합니다(07번).

비유: 여행 일정표를 짜고 움직이는 것. 길게 보는 데 강하지만, 일정이 틀어지면 다시 짜야 합니다.

4. 무엇을 언제 쓰나

정답은 "일의 성격에 맞게" 입니다.

  • 일이 짧고 단순한가?(재고 조회, 가격 계산) → 예: ReAct (빠르고 단순).

  • 단계가 많고 순서가 중요한가? → 예: Plan-and-Execute (큰 그림 유지).

  • "이어버드 재고 있어?" → ReAct (한두 스텝이면 끝)

  • "가을 패딩을 출시하라" → Plan-and-Execute (6단계 프로젝트)

실무에서는 둘을 섞기도 합니다. 큰 계획은 Plan으로 세우고, 각 단계 안에서는 ReAct로 도구를 쓰는 식이죠. 실제로 이 강의 Executor도 내부적으로 ReAct 에이전트(create_agent)입니다.

5. 둘 다 결국 "에이전트"

방식은 달라도, 둘 다 1강에서 배운 에이전트의 정의를 따릅니다 — "목표를 보고 도구를 써서 일을 끝낸다". 차이는 "계획을 먼저 세우느냐, 즉흥적으로 가느냐" 일 뿐입니다. 도구·관찰·반복이라는 본질은 같습니다.

핵심 정리

  • ReAct = 즉흥형(한 스텝씩), 짧은 작업에 강함.
  • Plan-and-Execute = 계획형(전체 먼저), 단계 많은 목표에 강함.
  • 일의 성격에 맞게 고르고, 실무에선 섞어 쓴다.
  • 둘 다 "도구로 목표를 끝낸다"는 에이전트의 본질은 같다.
