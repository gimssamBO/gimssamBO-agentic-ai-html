구조화 출력 — Pydantic 스키마

한 줄 요약

구조화 출력은 LLM의 답을 "정해진 형태(스키마)"로 강제로 받는 것입니다. LangChain에서는 Pydantic 클래스로 원하는 형태를 선언하고 with_structured_output에 넘기면, LLM 답이 그 클래스 객체로 바로 옵니다. 3강의 JSON 강제 출력을, 더 안전하고 편하게 만든 것입니다.

1. 3강 복습 — JSON 강제 출력

3강에서 우리는 답을 JSON으로 받는 법을 배웠습니다.

OpenAI

# OpenAI 방식 (raw SDK) — JSON Object 모드로 문자열을 받아 직접 파싱
resp = client.chat.completions.create(
    model=OPENAI_MODEL,
    messages=[...],
    response_format={"type": "json_object"},
)
data = json.loads(resp.choices[0].message.content)   # 문자열 → dict, 직접 파싱
print(data["category"])

Gemini

# 3강 방식 (raw SDK) — JSON 문자열을 받아 직접 파싱
resp = client.models.generate_content(
    ..., config=types.GenerateContentConfig(response_mime_type="application/json"))
data = json.loads(resp.text)   # 문자열 → dict, 직접 파싱
print(data["category"])

이 방식은 잘 작동하지만 두 가지 아쉬움이 있습니다.

  • 키 이름·타입을 보장 못 함: data["category"]가 있는지, 문자열인지 코드가 미리 알 수 없음.
  • 직접 파싱: json.loads를 매번 호출해야 함.

2. LangChain 방식 — Pydantic 스키마

LangChain은 Pydantic 클래스로 "원하는 출력 형태"를 미리 선언합니다.

from pydantic import BaseModel, Field

class Plan(BaseModel):
    """목표를 실행 가능한 하위 작업으로 분해한 결과."""
    goal: str = Field(description="원래 목표")
    steps: list[str] = Field(description="순서대로 실행할 하위 작업 목록(4~7개)")

이 클래스가 곧 "스키마(설계도)"입니다. goal은 문자열, steps는 문자열 리스트라고 못 박았죠. Field(description=...)는 각 필드가 무엇인지 LLM에게 알려 주는 설명입니다.

Pydantic이 처음이라면: Pydantic은 "데이터의 형태를 클래스로 정의하고 검증하는" 파이썬 라이브러리입니다. class Plan(BaseModel)은 "Plan은 goal과 steps를 가진 데이터"라고 선언하는 것입니다. 일반 클래스와 비슷하지만, 타입을 검사해 주는 게 다릅니다.

3. with_structured_output으로 강제하기

선언한 스키마를 with_structured_output에 넘기면, LLM 답이 그 클래스 객체로 바로 옵니다.

OpenAI

from common import get_chat

llm = get_chat(provider="openai")

# LLM 응답을 Plan 스키마에 맞춰 강제로 받아낸다
planner = llm.with_structured_output(Plan)
result = planner.invoke("가을 패딩 출시를 4~7단계로 분해하라")

print(type(result))      # <class 'Plan'>  ← dict가 아니라 Plan 객체!
print(result.goal)       # "가을 패딩 출시"
print(result.steps)      # ["시장조사", "콘셉트확정", ...]

Gemini

from common import get_chat

llm = get_chat(provider="gemini")

# LLM 응답을 Plan 스키마에 맞춰 강제로 받아낸다
planner = llm.with_structured_output(Plan)
result = planner.invoke("가을 패딩 출시를 4~7단계로 분해하라")

print(type(result))      # <class 'Plan'>  ← dict가 아니라 Plan 객체!
print(result.goal)       # "가을 패딩 출시"
print(result.steps)      # ["시장조사", "콘셉트확정", ...]

json.loads도, 키 존재 확인도 필요 없습니다. result.goal, result.steps로 객체 속성처럼 바로 씁니다. 타입도 보장됩니다(steps는 항상 리스트).

4. 3강 방식 vs LangChain 방식

구분 3강 (raw SDK) 8강 (LangChain)
형태 선언 프롬프트에 글로 설명 Pydantic 클래스로 명시
받는 법 json.loads(resp.text) planner.invoke() → 객체
결과 사용 data["key"] (dict) result.key (객체 속성)
타입 보장 없음 있음 (Pydantic이 검증)

본질은 같습니다 — "형식을 강제한다". LangChain은 그걸 Pydantic으로 더 안전하고 깔끔하게 만든 거죠. 3강에서 이미 원리를 배웠으니, 이게 마법처럼 느껴지지 않을 겁니다.

5. 왜 Planner에 구조화 출력이 필요한가

Planner는 목표를 단계 목록으로 분해합니다. 이 목록을 코드가 받아서 하나씩 실행해야 하죠.

plan = make_plan("가을 패딩 출시")
for i, step in enumerate(plan.steps, 1):   # steps가 리스트임이 보장되니 바로 반복!
    print(f"{i}. {step}")

만약 답이 자유 텍스트라면 "단계를 어떻게 뽑아내지?"가 골치 아픕니다. 구조화 출력으로 steps가 항상 리스트임을 보장하니, 코드가 안심하고 반복할 수 있습니다.

핵심 정리

  • 구조화 출력 = LLM 답을 정해진 형태(스키마)로 강제로 받기.
  • LangChain은 Pydantic 클래스로 형태를 선언하고 with_structured_output으로 강제.
  • 결과가 dict가 아니라 객체로 와서, result.steps처럼 바로 쓴다(타입 보장).
  • 3강의 JSON 강제 출력을 더 안전·편하게 만든 것이다.
