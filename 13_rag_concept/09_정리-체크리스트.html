정리 & 체크리스트

13강에서 배운 것

13강에서는 RAG의 개념과 첫 두 단계(로드·청킹)를 배웠습니다.

  • RAG: 답이 있는 문서를 검색해 근거로 삼아 답을 생성하는 기법.
  • LLM의 세 한계: 지식 컷오프·환각·사내 문서 모름 → RAG가 모두 보완.
  • 5단계 파이프라인: 로드 → 청킹 → 임베딩 → 저장/검색 → 생성.
  • 청킹: 긴 문서를 작은 조각으로 — chunk_size, chunk_overlap.
  • 다양한 로더: PDF·CSV·텍스트·마크다운 모두 같은 Document 구조.

한눈에 보는 핵심 코드

from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from common import DOCS

# ① 로드 — PDF를 페이지 단위 Document로
docs = PyPDFLoader(str(DOCS / "환불교환정책.pdf")).load()

# ② 청킹 — 작은 조각으로 (metadata 보존)
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(docs)

print(f"{len(docs)}페이지 → {len(chunks)}개 청크")
print(chunks[0].page_content)        # 본문
print(chunks[0].metadata)            # {'source': ..., 'page': 0}

RAG 5단계 진행 상황

✓ ① 로드      (13강 — 이번 강)
✓ ② 청킹      (13강 — 이번 강)
  ③ 임베딩    (14강 — 다음 강)
  ④ 저장/검색  (15강)
  ⑤ 생성      (16강)

체크리스트

  • [ ] RAG가 LLM의 세 한계를 어떻게 보완하는지 설명할 수 있다.
  • [ ] RAG 파이프라인 5단계를 순서대로 말할 수 있다.
  • [ ] 인덱싱(사전 배치)과 질의(매 요청)의 차이를 안다.
  • [ ] PyPDFLoader로 PDF를 로드하고 RecursiveCharacterTextSplitter로 청킹했다.
  • [ ] 청킹하는 이유(토큰·비용·검색 정확도)를 설명할 수 있다.

한 줄 핵심

RAG는 외부 문서를 검색해 근거로 답한다. 그 첫걸음은 문서를 로드하고, 검색하기 좋은 작은 조각(청크)으로 나누는 것이다.

다음 강 예고

13강에서 청크가 "단어 매칭"으로만 검색된다는 한계를 봤습니다. "돈 돌려받기"로는 "환불"을 못 찾았죠. 14강 임베딩에서 이 한계를 풉니다. 텍스트를 벡터(숫자) 로 바꾸면, 단어가 달라도 의미가 비슷하면 찾을 수 있습니다. RAG의 심장인 "의미 기반 검색"의 원리를 배웁니다.
